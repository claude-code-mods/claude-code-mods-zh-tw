# 作品資料庫 · 1.6.0 使用說明

TW 新增 `build-work-library`，把小說、原作設定、同人材料、聯網文字與圖片參考整理成可供二創檢索的資料庫。本能力隨 [TW 1.6.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v1.6.0) 正式提供。真實宿主發現、真實作品樣本/token 試驗和駕駛員體驗另行記錄，不由本地測試代替。

可以直接這樣說：

> 把這部作品整理成二創資料庫，先做人物、關係和世界規則。原作和同人分開，開局資料不要混進後期劇透。先跑代表樣本，核對質量和 token，再按本輪範圍分批繼續。

> 補充這部作品的官方設定和服裝圖片參考。先開啟原始頁面、核對版本並實際看圖，登記出處和使用邊界，再整理進對應人物。

> 從資料庫中整理開局階段的主角關係和場景參考，給我一份能回查出處的二創資料包。

預設產物是人能直接編輯的 Markdown 資料正文，以及工具能查詢、可重建的 JSONL 索引；需要時匯出 SQLite。原作、官方補充/參考、同人分支和不確定材料保留身份與來源，不合成無出處的統一設定。

第一次使用時，提供作品/版本、已有檔案或原始頁面、要做的創作，以及希望避免劇透的範圍。已有專案直接讀取續接和採證規則；工具支援全書分批，也支援按人物/專題定向整理，不強制先讀完整部作品才產出。

聯網採集由當前宿主的搜尋、網頁和影像檢視能力承擔；本地工具負責儲存來源、分段、精確引文校驗、任務計量、接續、索引與匯出。圖片預設登記來源卡和連結；實際下載、裁切和長期視覺庫匯入按已授權選材範圍進行，網頁可見不等於獲准再分發。

長任務先評估代表樣本，記錄實際 token 或明確的估算/不可見狀態，再按源單元、呼叫/批次和可觀察 token 上限執行。專案可以定義採集、精讀、人物整理、校核等職責；宿主支援原生子 Agent 時使用，不支援就序列。沒有真實後臺能力時，不能保證關閉對話後繼續執行；專案賬本用於之後恢復。

人改正文後，Agent 先讀最新檔案和雜湊，再重建索引。舊任務回寫遇到版本不同會停止，避免覆蓋人的新內容。遇到中斷用恢復命令檢查待寫內容，存在新的人工作業時保留衝突；人工查詢、索引重建和匯出不需要模型回覆。
