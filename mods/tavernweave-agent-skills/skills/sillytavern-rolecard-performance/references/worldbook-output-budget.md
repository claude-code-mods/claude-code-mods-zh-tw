# E06：原生、模板與控制器的共同輸出預算

[靜態體積指標](static-budget-contract.md)已有打包層預算；本節檢查各入口合併到一次實際模型請求中的輸出。原生、條目內條件、顯式讀取和多個控制器可以同時產生候選。一個控制器自己的 Set 去重，不等於最終提示已去重。

## 一份身份與一次仲裁

1. 從 [E05 目標對映](../../sillytavern-database-rolecards/references/worldbook-target-state-contract.md)取得穩定內容身份；同義別名歸同一實體，同一實體的不同資料仍有不同內容身份。書身份與 UID 保留，不重新編號。
2. 每個候選保留內容身份、權威來源/修訂、入口、接收模型、必要性、依賴組與專案選定優先順序。正文相同可提示重複，不能僅按文字雜湊合併語義不同的條目；正文不同卻聲稱同一權威版本應報衝突。
3. 在確能看見全部候選的階段，統一處理原生入口和全部模板/控制器的候選，按宣告的權威來源保留一份；候選未知或權威來源衝突時，不能靜默任選。優先順序是該專案的工程決定，不是固定 `order` 數字或模型品牌配方。
4. 若環境沒有可核驗的統一攔截點，先在設計上令兩條路徑互斥、由一個明確所有者輸出，或捕獲最終請求後檢測並修復。不要假定模板裡的區域性集合能刪除已經進入宿主的原生片段，也不要稱檢測器已阻止重複。
5. 對每個實際接收模型分別檢查最終請求；額外更新模型並不自動需要所有正文。相同資料按設計傳送給不同消費者，與同一請求重複是不同問題。

## 預算規格與失敗路徑

繼續只維護專案已有的預算記錄。宣告總上下文及保留給系統/卡/歷史/使用者輸入/回覆的空間，再確定世界書輸出能使用的份額。條數與字元數是可提前檢查的工程護欄，**不是關鍵詞數量配額**；具體上限按任務約定，不能把夾具數值當作通用上限。

- 先確保必要正文與其依賴組可整體保留，再依優先順序加入可選資料。相同優先順序的處理應穩定且可解釋，不暗借 UID 重排內容。
- 超額時採用已選策略：略去低優先順序可選項、替換為作者批准的摘要，或停止依賴材料不足的生成。保留被省略內容身份及原因；不能截半條規則、刪掉否定/條件，或自動把摘要寫回存檔。
- 必需內容自身放不下時報告預算不足，不能悄悄捨棄它後宣佈透過。內容缺失與預算捨棄是不同診斷。
- 記錄處理前後候選數、唯一內容數、輸出字元數和最終 token 數。字元計數需說明單位；隨包示意用 Unicode 碼點而非 JavaScript UTF-16 長度。
- 必須使用目標模型對應的分詞器測量實際最終請求的 token 數，記錄模型/分詞器身份、聊天包裝及計量範圍；字元數、檔案位元組數或粗估比例不能冒充實測 token。只測世界書片段也不能證明總請求未超限。
- `ignore_budget=false` 僅描述一個配置值，不證明顯式讀取已經計入宿主預算或按理想粒度裁剪。具體計數階段按 [E03](../../sillytavern-api-reference/references/worldbook-version-verification.md)核驗。

## 投影只改變本輪檢視

完整狀態由原所有者持久儲存；輸出層只讀所需欄位，構造副本/明確的只讀檢視。將持久狀態、生成投影、UI呈現分開，不為了少佔上下文修改存檔。

0、false、缺失、null、空字串按欄位語義分別處理。摺疊一個離場模組時，如果其中仍有有意義的值，保留專案要求的摺疊標記或概要；不能把 0/false 都判空，導致有意義的模組被隱藏卻沒有提示。投影前後比對完整儲存，不只看顯示值。

自寫隔離例讓 `archivedModule` 含 `count=0`、`completed=false`：投影可只保留摺疊標記，完整狀態仍保留這兩個有效值。另讓原生入口和兩個模板選擇器同時提出橋樑規則，檢查同一請求的去重；單個選擇器自己的別名集合不能證明跨入口預算。

## 最小驗收

複用 [E07 隔離夾具與觀察](../../sillytavern-runtime-debug/references/worldbook-isolated-runtime-checks.md)：同義別名、兩個控制器、原生+模板分別命中同一內容；再放入超額可選項和放不下的必要項。檢查仲裁與降級原因、最終請求是否只留應有的一份、狀態是否保持。靜態示意透過只能證明示意規則一致，最終提示、實際分詞和真實宿主執行仍單獨驗收。

欄位、匯出和 ID 保護仍由原負責技能處理。不接受固定位置萬能論、品牌深度、固定順序或關鍵詞配額。
