# 編輯範圍

表達規則見[去八股與自然表達](natural-chinese-review.md)，改寫示例見[示例](paragraph-examples.md)。

## 不同文字

- 說明和報告：先交代讀者需要的結果，保留證據、適用條件、嚴重程度和未驗證項。規定的報告欄目照常使用。
- 敘事：保留視角、事件順序和敘述距離。數值與考據說明可以移到合適的位置，不省掉影響後續行動的事實。
- 對話：保留人物的用詞、身份、知情範圍和說話意圖，不把所有人改成同一種聲音。
- 角色設定和世界書：讓明確事實與可執行約束容易找到，別合併不同條件或混淆人物的知情範圍。
- 指令和提示詞：保留必須、可以、禁止之間的區別，以及條件、例外和責任範圍。

世界書正文只放接收模型理解、扮演或執行任務所需的內容。作者用的設計說明和維護記錄放在作者文件中。按實際處理用途保留必要的 EJS 和宏，參照[世界書正文邊界](../../tavern-card-builder/references/lorebook-and-prompts.md#model-facing-body-and-processed-source)。

潤色已有內容須保留原意；獲授權的共同構思或委託創作可按約定範圍新增內容。不要把新增提案當成已有事實。創作流程可呼叫這些表達規則檢查草稿，不因此開啟持續模式。根據樣本制定非角色文風時，沿用[開場表達流程](../../tavern-card-builder/references/opening-strategies.md#non-character-presentation-handoff)。

## 混合檔案

先確認維護的是原始檔還是生成產物，以及允許改動的文字欄位。程式碼、宏、EJS、正則、變數路徑、ID、JSON 鍵和結構欄位按原樣保留。只有使用者明確要求修改對應技術內容時，才改變它們。

編輯 JSON、YAML、HTML 或角色卡元件時，使用已有格式工具，核對改動前後的鍵、型別及受保護內容。另行核對數值、否定、因果和不確定性。引文保持原樣，除非使用者要求改寫引文字身。
