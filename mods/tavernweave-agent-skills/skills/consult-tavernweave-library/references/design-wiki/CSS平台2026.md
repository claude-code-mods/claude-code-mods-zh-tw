# CSS平臺2026

本頁不是已採用皮膚，也不是工坊必須換原生控制元件的工單。檢索日 2026-08-14。賬本樞紐是 [[queries/第五批蒸餾目標]] B5-CSS26；採集行仍在 [[10-收件箱/寫回候選/第五批-B5-CSS26]]。

不重寫 [[concepts/視覺CSS與設計token]] 已有的 `grid-lanes` / `@scope`，也不重抄 B2-Layout 的 `field-sizing`、B2-VT 的 View Transitions。本頁只蒸 2026 平臺新面：錨點、Popover、Invoker、可定製 select、換行與切盒、樹計數、入場過渡與固有尺寸插值。

## 一句話定義

2026 平臺 CSS 新面是瀏覽器已開啟規範入口、成熟度參差的一組能力：浮層怎麼錨、誰宣告式開啟、原生控制元件怎麼 opt-in 換皮、文字怎麼換行切盒、樹序怎麼計數、入場和固有尺寸怎麼過渡。它們不是一套設計系統，也不是 Rec 清單。

## 為什麼重要

HUD、選項選單、開局頁表單會碰到「浮層貼按鈕」「原生 select 換皮」「標題平衡換行」「高度從 none 過渡到 auto」。先認清哪份規範、哪條 Baseline、哪兩個關鍵字不是同一合同，再談落地。跨文件根見已有對照頁；本頁不上可定製 select 當已採用。

## 如何運作

### 錨點是 WD，Popover 可給隱式錨

[CSS Anchor Positioning 1](https://www.w3.org/TR/css-anchor-position-1/)（WD 2026-03-27）：絕對定位盒用 `position-anchor` / `position-area` 和 `anchor()` / `anchor-size()` 相對錨盒。`anchor-name` 是樹作用域名，預設不被 containment 擋住。規範寫：用 Popover API 時，宿主會設 `position: fixed` 並建立隱式錨，不必再寫 `anchor-name` / `position-anchor`。

[[queries/第二批蒸餾目標]] B2-Layout 當時記「錨點仍草案」。現已是 2026-03 WD，仍不是 Rec。兩邊留，不把 WD 寫成已完成標準。

### Popover ≠ dialog；三套呼叫面不要並

[Popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API)：平臺 popover **永遠非模態**。要模態走 `<dialog>`。可以把 `popover` 掛到 `dialog` 上疊語義，合同仍是兩條。`:popover-open`、`::backdrop`、`showPopover()` / `hidePopover()` / `togglePopover()`。

[WHATWG](https://html.spec.whatwg.org/multipage/popover.html)：`auto` 開時關其他 popover、有 light dismiss；`manual` 不關別人、不 light dismiss；`hint` 只關其他 hint。空值預設 `auto`，非法值預設 `manual`。無障礙語義不足時作者補 ARIA。

[Invoker Commands](https://developer.mozilla.org/en-US/docs/Web/API/Invoker_Commands_API)（2025-12 Baseline Newly）：`commandfor` + `command` 宣告式驅動目標。內建含 `show-popover` / `hide-popover` / `toggle-popover`、`show-modal` / `close` / `request-close`。自定義必須以 `--` 開頭，在目標上聽 `command` 事件。

[Open UI Invokers](https://open-ui.org/components/invokers.explainer/)：**同時寫 `popovertarget` 與 `command`/`commandfor` 時，忽略 `popovertarget`，`command` 優先。** explainer 寫「意圖最終由 `commandfor` 取代 `popovertarget`」。表單參與 / `type=submit` 的按鈕上 `command` 必須被忽略。`command` 事件不冒泡、composed、可取消。這是 explainer；衝突以 HTML / MDN 為準時兩邊都留。

MDN Popover 另列 **interest invokers**（`interestfor` / hover·focus），**不是** `commandfor`。三套呼叫面：`popovertarget`、`commandfor`、`interestfor`。Invoker 是更廣的按鈕合同，不是 Popover 的新名字。跨文件根仍看 [[concepts/酒館宿主與iframe分層]]，本頁不重寫。

### 可定製 select：opt-in 關鍵字衝突

[Open UI](https://open-ui.org/components/customizable-select.explainer/) 與 [MDN Learn](https://developer.mozilla.org/en-US/docs/Learn_web_development/Extensions/Forms/Customizable_select)：元素與 `::picker(select)` **都要** `appearance: base-select`。解析器放寬，允許幾乎所有子代；作者 `<button>` + `<selectedcontent>` 可換按鈕面。Chromium 已出；鍵盤行為「因其他引擎要跟平臺慣例，**未寫入標準**」。`multiple` / `size` 仍在原型，**不在現行規範**。`selectedcontentelement` 未隨首批發。不推薦拿它做 split button。

[CSS Forms 1](https://www.w3.org/TR/css-forms-1/)（FPWD 2025-03-25）通用 opt-in 是 **`appearance: base`**。全文無 `base-select`。`::picker()` 要渲染，起源元素與 picker **計算值都必須是 `base`**。同一條「雙處 opt-in」規則，關鍵字兩邊留，不靜默合成。select 定製走 CSS opt-in，不是新元素。工坊不上它當已採用。

### 換行與切盒

[CSS Text 4](https://www.w3.org/TR/css-text-4/)（WD 2026-06-08）：`text-wrap` 是 `text-wrap-mode` + `text-wrap-style` 的簡寫。`balance` 給標題/題注，儘量不改行數，**超過十行 UA 可當 `auto`**。`pretty` 偏質量、可貴，給正文。另有 `stable`（編輯時上行不動）和 `avoid-orphans`（MDN 簡寫頁未列此值）。MDN 寫 Chromium `balance` 限六行、Firefox 十行——實現上限與規範「可當 auto」兩邊留。`pretty` ≠ `balance`。

[CSS Inline 3](https://www.w3.org/TR/css-inline-3/)：`text-box-trim`（`none` / `trim-start` / `trim-end` / `trim-both`）切首末行半 leading；切多少看 `text-box-edge`。簡寫 `text-box`。Limited，不是 Baseline。

### 樹計數、入場、固有尺寸

[CSS Values 5](https://www.w3.org/TR/css-values-5/)：`sibling-index()` 從 1 起；`sibling-count()` 含自己。走扁平樹，不是選擇器。`interpolate-size` 預設 `numeric-only`；`allow-keywords` 才允許長度 ↔ `auto` / `min-content` / `max-content` / `fit-content`。規範寫：若有時光機就不需要此屬性——存量表假定固有關鍵字不能動畫，**不能預設開**。兩端都是固有關鍵字仍不能插。`calc-size()` 才能對固有尺寸做算術。

[CSS Transitions 2](https://www.w3.org/TR/css-transitions-2/)（WD 2026-02-04）：`transition-behavior: allow-discrete` 才給離散屬性開過渡；`@starting-style` 只在沒有 before-change style 時當起點（新插入或從 `display: none` 出來）。規則不引入新層疊序，獨立塊要寫在「目標態」**之後**才生效。`@starting-style` 只管 transition，不管 `@keyframes`。

MDN：popover / top layer 進出還要把 `display` 與 `overlay` 列入過渡，並加 `allow-discrete`，否則出場直接消失。`interpolate-size` 標 Experimental / Limited。`allow-discrete` ≠ `allow-keywords`。View Transitions 皮膚不在本頁，見 [[concepts/動畫庫與動效管線]]。

## 必須保留的衝突

- **`appearance: base`（Forms 1 FPWD）≠ `appearance: base-select`（Open UI / MDN / Chrome 135）。** 雙處 opt-in 一致，關鍵字兩邊留。
- `popovertarget` 與 `command`/`commandfor` 並存；同時寫時 command 優先。Open UI 寫最終取代，HTML / MDN 仍兩套都活。
- Popover 永遠非模態；模態是 `dialog`。`interestfor` ≠ `commandfor`。
- `pretty` ≠ `balance`；`balance` 行數上限規範與 Chromium/Firefox 實現不一致。
- `interpolate-size` 不能預設開。`allow-discrete` ≠ `allow-keywords`。
- 錨點是 2026-03 WD，不是 Rec；B2「仍草案」與現 WD 兩邊留。可定製 select 鍵盤與 `multiple`/`size` 未進規範。
- 本頁對映工坊 HUD / 選單 / 開局表單會碰到的**平臺合同**；**不是**「工坊已採用這些皮膚」。

## 例子

- 正例：選單用 Popover + 隱式錨；要模態用 `<dialog>`，不要把 popover 當模態對話方塊。
- 正例：宣告式開關寫 `commandfor` + `command="toggle-popover"`；自定義命令以 `--` 開頭。
- 正例：標題 `text-wrap: balance`，正文 `pretty`；不要對長文開 `balance` 當已保證。
- 正例：入場過渡把 `@starting-style` 寫在目標態之後，並把 `display` / `overlay` 列入 `allow-discrete`。
- 反例：把 `appearance: base` 與 `base-select` 合成一個關鍵字交差。
- 反例：同時寫 `popovertarget` 與 `command` 卻按舊屬性解釋。
- 反例：預設開啟 `interpolate-size: allow-keywords`，或把 `allow-discrete` 當成固有尺寸開關。
- 反例：因本頁出現可定製 select 就寫進 recipe / 髮卡依賴。
- 反例：重寫 `grid-lanes` / `@scope` 當本頁新發現。

## 邊界與易混概念

- 不包括：masonry / `grid-lanes`、`@scope` / Cascade 6、`field-sizing`、滾動狀態查詢、View Transitions 皮膚。
- 不包括：某張卡的皮膚 token、把實驗值打進 PNG。
- 易混：Popover ≠ `<dialog>`；可疊，不是一詞。
- 易混：`popovertarget` ≠ `commandfor` ≠ `interestfor`。
- 易混：`pretty` ≠ `balance`；`allow-discrete` ≠ `allow-keywords`。
- 易混：`appearance: base` ≠ `appearance: base-select`。
- 易混：錨點 WD ≠ Rec；B2「仍草案」與現 WD 兩邊留。
- 區分：Invoker 是按鈕命令合同；Popover 是非模態頂層；錨點是定位合同。三者可疊用，不是三個名字同一件事。
