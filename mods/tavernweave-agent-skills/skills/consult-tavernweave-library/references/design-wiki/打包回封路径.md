# 打包回封路徑

Source-first：改元件源，再組成卡，不手改匯出 JSON/PNG。指南格式面是 A2；工坊執行面是 `card_workflow` 和模組化元件庫。

## 主鏈

```text
profile / recipe
  → 校驗（卡型、依賴、正則、區域 loader）
  → compose（按 registry 拼世界書 / MVU / 正則 / 指令碼 / 開場）
  → pack（JSON，可選 PNG 嵌入）
  → 世界書版本與卡繫結同步
  → 嵌入載荷對賬
```

創意庫專案停在 `04-原始檔` 和 `allow_release: false`，本 Vault 不產出髮卡物。

工作區入口（在 `<local-workspace>/` 下跑，不是 AFV 裡）：

```text
node card_workflow/tools/workflow.mjs --profile xingyue
node card_workflow/tools/workflow.mjs --profile xingyue --action validate
node card_workflow/tools/workflow.mjs --profile crossed-zone --action validate
node card_workflow/tools/workflow.mjs --profile xingyue --action full --mode release
```

增量：`workflow_targeted.mjs --changed <path>`。中文檔案用 `utf8_edit.mjs --spec … --dry-run`。

README 裡 xingyue / crossed-zone 的驗證版本字可能停在舊號（攝入時見過 2.5.0 / 2.6.0）。2026-08-13 總監裁定：實際使用時動態改 profile，**不必**把 README 版本字對齊到產品頭。命令入口不變。怪談不在該 README 的 profiles 表裡，走 `card_families.json` 的 `kaidan-note`。

## 兩套清單不要混

| 清單 | 管什麼 |
|---|---|
| `card_families.json` 三族 | 工作區哪幾條產品線、白名單 |
| 模組化元件 `registry` + `recipe` | 一版卡由哪些元件、哪個版本拼出來 |

卡A目錄頭是 4.0.0，元件庫 recipe 仍可能停在 3.9.6。怪談髮卡 1.0.9，回落記載 0.9.7。對賬時兩套都寫，不靜默覆蓋。

## 回封時容易漏的

- 卡B 2.6.2：`insertion_order` / `display_index` / `cfSortKey` 要一次寫齊，見 [[concepts/世界書快取排序]]。
- git-mount 殼：`BASE` / `BASE_CF` 版本段必須和本次 runtime 一致。
- 正則 `placement` / `markdownOnly` / `promptOnly` 決定它進渲染還是進 prompt，見 [[concepts/訊息渲染與正則管線]]。
- 出卡後不要再往 JSON 裡補「最後一刀」；下一刀改源再 pack。

## 邊界

- A2 覆蓋 SillyTavern 官方匯入匯出欄位；工坊額外欄位以專案 manifest 為準。
- 本頁不替代 `sillytavern-card-pipeline` skill 的逐步操作。
- 卡D、卡C沒有穩定 pack 產物，只有設計檔和階段源。
