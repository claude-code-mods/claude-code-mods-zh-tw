# 世界書注入路徑

世界書是生成前的動態字典：掃描聊天，命中則把條目推進 prompt。它保證進上下文，不保證模型聽話。指南：`A3_世界書最佳化.md`。快取字首專頁見 [[concepts/世界書快取排序]]。

## 生成前發生什麼

```text
掃描緩衝（深度、額外源）
  → 關鍵詞 / 常亮 / 濾鏡 / 分組
  → 按 position + insertion_order 插入
  → 受 token budget 裁切
  → 和角色描述、預設、歷史拼成 prompt
```

穩定卡用角色繫結 Lorebook（character_book），不是靠玩家手動開全域性書。

## 條目上必須想清楚的欄位

創意庫 Source-first 也要求同一組語義：

| 語義 | 常見欄位 | 穩定卡怎麼用 |
|---|---|---|
| 策略 | constant / 關鍵詞 | MVU 規則條目常亮；設定條目多數關鍵詞 |
| keys | 主詞 / 次級濾鏡 | 常亮也要寫明空陣列，別用「高頻」糊弄 |
| 位置 | position、role、depth | 規則淺深度前置；每樓摘要往後 |
| 排序 | insertion_order、display_index、cfSortKey | 卡B 2.6.2 回封時統一 |
| 遞迴 | 是否被觸發 / 是否觸發別人 | 預設收緊，避免書打書 |
| 內容 | content | 真正進模型的字 |

`[mvu_update]` 標記的條目專門送變數規則和輸出格式。Zod 指令碼會等 `XingyueWorldbookReady`（及卡B等同名）再拉 bundle，避免書還沒亮就註冊。

## 和別的路徑的介面

- 開局/工坊改身份、地理、來源：經世界書管理器寫條目，不直接改匯出 JSON。
- 控制中心 `updateWorldbookWith`：事務寫入，API 以 C2 / C1 為準。
- 變數摘要若插在 prompt 最前，快取全廢。卡B把這件事做成 `promptCacheOrdering`。

## 邊界

- Chat / Persona Lorebook 是較新 ST 能力；三張穩定卡主路徑仍是角色書。
- 向量化匹配、Outlet、`@@activate` 以 A3 為準，不是這三張卡的主用法。
- 卡D `世界書_v2/` 是素材，不是已按 3.9.6 協議排完的製作層。
