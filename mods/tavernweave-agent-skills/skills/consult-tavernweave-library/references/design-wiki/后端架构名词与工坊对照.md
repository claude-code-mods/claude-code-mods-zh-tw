# 後端架構名詞與工坊對照

後端名詞先判斷規模、團隊和一致性要求，再決定付不付分散式稅。本頁按行業合同寫。工坊只是其中一條產品對映，見文末；產品禁令表見 [[comparisons/工坊架構該上與不該上]]。行業總表見 [[comparisons/行業架構方案何時用]]。

Gateway token、OAuth 金鑰、物件儲存憑證不進本 Vault。

## 小應用閘道器不是微服務 API Gateway

「Gateway」在行業裡常指門後一排服務的路由/鑑權/限流。一個同進程小應用服務管生命週期、所有權和稽核，不是那種門。聽成「已經微服務」，或因此要上 distributed monolith，都是用錯詞。Azure 的 [gateway routing](https://learn.microsoft.com/en-us/azure/architecture/patterns/gateway-routing) 與 [Newman BFF](https://samnewman.io/patterns/architectural/bff/) 是兩種不同的門。

## 部署形態

| 名詞 | 優點 | 缺點 | 代價 |
|---|---|---|---|
| 模組化單體 | 事務簡單、一條棧、部署一次、邊界可後抽 | 邊界靠紀律；擴縮只能整包 | 架構測試/包可見性，不是零成本微服務 |
| 微服務 | 獨立擴縮、團隊自治、故障隔離（做對時） | 分散式事務、觀測、版本、運維稅 | 複雜度不夠就淨虧 |
| Modulith | 先強制模組，再按需抽服務 | 名字讓人以為已經分散式 | 真拆程序立刻付網路稅 |

英文裡 Modulith 幾乎等於模組化單體，不是第三種分散式風格。來源：[Monolith First](https://martinfowler.com/bliki/MonolithFirst.html)、[Microservice Premium](https://martinfowler.com/bliki/MicroservicePremium.html)、[Microservices](https://martinfowler.com/articles/microservices.html)、[Spring Modulith](https://docs.spring.io/spring-modulith/reference/index.html)。

微服務該上的條件是獨立擴縮/釋出的收益大於溢價，不是「以後可能很大」。Modulith 先強制模組，真拆程序立刻付網路稅。

## 怎麼切核心

|  | 怎麼切 | 依賴 | 一句話差 |
|---|---|---|---|
| 三層 | UI → 業務 → 資料 | 從上往下，領域常綁 ORM | 好上手；橫切變更貴 |
| 六邊形 | 核心 + 埠/介面卡 | 外依內；UI 與 DB 對稱 | 核心可無 UI/DB 測 |
| 整潔 | 實體→用例→介面卡→框架 | 只許朝內 | 比六邊形多顯式用例圈 |

三層按技術分層；後兩者按依賴倒置保護核心。系統變大後應按業務模組切，模組內部再分層，不要永遠三大包。小服務用模組 + 所有權邊界即可，別先上四層專案。

來源：[Fowler layering](https://martinfowler.com/bliki/PresentationDomainDataLayering.html)、[Hexagonal](https://alistair.cockburn.us/hexagonal-architecture)、[Clean Architecture](https://blog.cleancoder.com/uncle-bob/2012/08/13/the-clean-architecture.html)。

## 寫讀分離與事件

**CQRS**：寫模型與讀模型分開，可以沒有事件。讀寫不對稱、讀側要單獨擴或單獨最佳化時該上。多數 CRUD 是高風險複雜度。來源：[Fowler CQRS](https://martinfowler.com/bliki/CQRS.html)。

**事件溯源**：狀態由不可變事件序列重建。審計、重放、時間旅行強；版本與查詢都難。常和 CQRS 組合，**不繫結**。來源：[Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html)。

對稱的包 CRUD + 狀態機不必上雙模型。這不是「CQRS 不存在」。

## Saga 三義

「Saga」不是一詞：microservices.io 的資料模式、Temporal 工作流裡的補償程式碼棧、BPMN 2.0.2 的補償事件，三框不同義。詳頁見 [[concepts/Saga三義與補償]]。

Inbox 的正式名是 Idempotent Consumer。Fowler 無 Saga / Outbox 專文。熔斷 / 艙壁 / 重試不併進本詞。

來源：[Richardson Saga](https://microservices.io/patterns/data/saga.html)、[Temporal Saga](https://docs.temporal.io/design-patterns/saga-pattern)、[OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/)。

## 怎麼說話

| 名詞 | 一句話 | 何時用 |
|---|---|---|
| 同步 REST | 現在就要答案 | 釋出 / 稽核 / 詳情 / 大多數 CRUD |
| 訊息佇列 | 分活、削峰、一個消費者 | 後加通知、匯出、郵件；不當同步 API 替身 |
| 事件匯流排 | 廣播事實、釋出者不認訂閱者 | 扇出；主路徑要同步可見時不該當骨架 |
| API Gateway | 多後端的一扇門 | 後面沒有一排服務時過重 |
| BFF | 一個 UI 一個後端 | 多客戶端形狀差很多時該上；只有一個客戶端時不必再套 |

來源：[Sam Newman BFF](https://samnewman.io/patterns/architectural/bff/)、[Azure BFF](https://learn.microsoft.com/en-us/azure/architecture/patterns/backends-for-frontends)、[Gateway routing](https://learn.microsoft.com/en-us/azure/architecture/patterns/gateway-routing)、[Pub/Sub](https://learn.microsoft.com/en-us/azure/architecture/patterns/publisher-subscriber)。模式總表：[Azure Cloud Design Patterns](https://learn.microsoft.com/en-us/azure/architecture/patterns/)。

## 限流 ≠ 節流 ≠ 令牌桶

微軟 Azure 架構中心把三件事分開寫，不能併成一個「限流演算法」。

| 詞 | 誰做 | 管什麼 |
|---|---|---|
| Rate Limiting（限流） | 呼叫方 | 控制自己發出請求的速率，以免撞上對方的節流上限 |
| Throttling（節流） | 被呼叫方 / 工作負載 | 封頂資源消耗，負荷下仍保 SLO |
| Token bucket（令牌桶） | 一種計量演算法 | 桶容量 + 補充速率；節流頁裡與漏桶、固定窗、滑動窗並列 |

來源：[Rate Limiting](https://learn.microsoft.com/en-us/azure/architecture/patterns/rate-limiting-pattern)、[Throttling](https://learn.microsoft.com/en-us/azure/architecture/patterns/throttling)。

## 十二因素與 CAP

[12factor.net](https://12factor.net/) 現網仍是 2011 年 Adam Wiggins 正文。2024-11 起社群修訂倉是 [twelve-factor/twelve-factor](https://github.com/twelve-factor/twelve-factor)，預設枝 `next`，**尚未**替換現網站。

Brewer 2012 把 CAP「三選二」標為誤導：分割槽少見時不必先放棄 C 或 A；選擇可以按操作、資料、子系統細分。CAP 只禁止分割槽存在時同時要完美的 C 和 A。Gilbert/Lynch 2002 證明文無合法免費全文，本頁不鏈盜版。

來源：[Twelve-Factor](https://12factor.net/)、[修訂倉](https://github.com/twelve-factor/twelve-factor)、[CAP Twelve Years Later](https://www.infoq.com/articles/cap-twelve-years-later-how-the-rules-have-changed/)。

## JS Temporal 未進現行 ECMA-262

這是 ECMAScript 日期時間 API，**不是** Temporal.io 工作流引擎。提案已 Stage 4（TC39 2026-03）。活稿仍在 [proposal-temporal](https://tc39.es/proposal-temporal/)。併入 [ECMA-262 PR #3759](https://github.com/tc39/ecma262/pull/3759) 截至 2026-08-13 仍開。外文「已經進 ES2026」在併入 PR 合入前不可信。

Cookie 管瀏覽器會話；JWT 管宣告信封；OAuth 管誰來證明人。三件可疊，不是三選一。

## Auth 三件不是三選一

| 名詞 | 管什麼 | 優點 | 坑 |
|---|---|---|---|
| Session Cookie | 瀏覽器會話 | 可立刻作廢；HttpOnly 時 JS 偷不到 | CSRF；要存會話 |
| JWT | 宣告信封 | 服務間傳宣告、少查庫 | 難提前作廢；別當無狀態瀏覽器會話 |
| OAuth 委託 | 誰來證明人 | 不存密碼；釋出者可偽匿名 | 回撥 / state 是攻擊面；OAuth ≠ 授權模型 |

來源：[OWASP session](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[OWASP JWT](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_Cheat_Sheet.html)、[OWASP OAuth2](https://cheatsheetseries.owasp.org/cheatsheets/OAuth2_Cheat_Sheet.html)。安全驗收清單用 [OWASP ASVS](https://owasp.org/www-project-application-security-verification-standard/)，不是攻擊手冊。

業界常見把 JWT 塞 `localStorage` 當登入態；[OWASP JWT](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_Cheat_Sheet.html) 不贊成。本頁兩邊都留：會話建議跟 OWASP，JWT 仍正當用於服務間宣告。

## 契約一句

|  | 取捨 |
|---|---|
| OpenAPI | 跨語言 HTTP 合同。公共 API 合適。要生成客戶端再補檔案。 |
| tRPC | 單一 TS 倉、前後端一起改時爽。離開 TS 或要對外文件就痛。 |
| GraphQL | 多客戶端要自選欄位、少 over-fetch 時該上。N+1、授權、快取都更難，不是 REST 的預設升級。詳釘見 [[concepts/GraphQL與非同步事件合同]]。 |

## HTTP 問題詳情與冪等鍵

RFC 9457（2023-07）廢止 RFC 7807，是現行 HTTP API 問題詳情。媒體型別仍是 `application/problem+json` / `application/problem+xml`。欄位、協商和型別 URI 見 [[concepts/HTTP合同與問題詳情]]。

IETF `Idempotency-Key` 草案 `draft-ietf-httpapi-idempotency-key-header-07` 已於 2026-04-18 過期，IESG 標 Expired，暫無繼任 RFC。

來源：[RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html)、[冪等鍵草案 datatracker](https://datatracker.ietf.org/doc/draft-ietf-httpapi-idempotency-key-header/)。

## 工坊已經在用（對照）

| 名詞 | 工坊怎麼落 |
|---|---|
| 模組化單體 | Gateway 同進程：包生命週期 + 所有權 + 稽核 API |
| 靜態站 + 物件儲存 + 小寫面 | 目錄 / schema / 索引靜態；包檔案進儲存；Gateway 只管寫與鑑權 |
| OAuth 委託 | 證明發布者，偽匿名；不是玩家追蹤 |
| 同步 REST | list / detail / create / update / withdraw / review |
| 稽核狀態機 | pending → approved / rejected / withdrawn |
| 弱多租戶 | 多釋出者共享一套目錄，隔離靠所有權 |

詳細 schema 以工作區 `rolecard-diy-workshop/schemas/` 為準，本頁不復制。卡內 fail closed 見 [[concepts/創意工坊與安全契約]]。

## 例子

- 正例：讀寫對稱的包服務用模組化單體 + 同步 REST；讀側要單獨擴再考慮 CQRS。
- 正例：瀏覽器會話用 Cookie；資源伺服器之間傳 JWT 宣告。
- 反例：為「以後可能很大」先拆微服務；用事件匯流排冒充同步稽核結果。
- 反例：把「工坊現在不上」寫成「GraphQL / CQRS 不是正當方案」。

## 邊界與易混概念

- 本頁檔名帶「工坊對照」，正文以行業名詞為主；工坊落點見「工坊已經在用」與文末對映。
- API Gateway ≠ BFF ≠ 同進程小應用閘道器。
- CQRS ≠ 事件溯源。
- OAuth ≠ 授權模型。
- RFC 7807 已被 9457 廢止；問題詳情欄位見 [[concepts/HTTP合同與問題詳情]]。
- 「Saga」三義不可併成一詞；詳頁 [[concepts/Saga三義與補償]]。
- 微軟限流 ≠ 節流 ≠ 令牌桶。
- CAP「三選二」已被 Brewer 2012 標為誤導；十二因素現網仍是 2011。
- JS Temporal Stage 4 ≠ 已寫入現行 ECMA-262。
- `Idempotency-Key` 草案 -07 已過期，暫無繼任 RFC。

## 對映到本倉庫

當前工坊：Gateway 同進程管包生命週期 + 所有權 + 稽核；目錄靜態；包進物件儲存；同步 REST（list / detail / create / update / withdraw / review）；狀態機 `pending → approved / rejected / withdrawn`；OAuth 只證明發布者；弱多租戶靠所有權。卡內 fail closed 見 [[concepts/創意工坊與安全契約]]。
這是產品落點，不是對微服務 / CQRS / GraphQL / 佇列的行業否定。
RFC 9457、Saga、限流演算法、十二因素修訂、JS Temporal 都是行業句，不是工坊已採用清單。釋出/稽核主路徑不必先上問題詳情信封、跨服務 Saga 或令牌桶。
