# 控制中心與狀態列

## 一句話定義

控制中心是卡內功能容器與設定/寫入入口；狀態列是前臺 HUD，負責讀變數、分頁展示和重互動，不承擔控制中心那類指令碼入口職責。

## 為什麼重要

同源三卡的玩家能看見的「前端」主要就是這兩塊，外加開局頁。重互動（製造、地圖）放 HUD tab，不塞進控制中心。

## 如何運作

### 控制中心 Control Center

英文標識常見 `control_center.js`。卡B指令碼 id 為 `crossed-zone-control-center`。入口只用 Tavern Helper 指令碼按鈕 API（魔棒下級選單），不在輸入框上方插 DOM。卡B按鈕名是 `卡B控制中心`，監聽必須 `getButtonEvent('卡B控制中心')`。卡A控制中心 ScriptTree 上沒有按鈕，改掛 `#extensionsMenu`；ST 切聊天會拆掉頂欄，要訂 `CHAT_CHANGED`，延時約 250ms 再 `ensureWandEntry()`。

熱過載：指令碼頂先 `previous.destroy()`，再掛新 runtime，否則監聽疊加。

它負責：HUD 設定持久化、媒體 I/O、OMNI 預設、創意工坊載入時序、世界書管理器的 handler。面板 head 可拖動，限制在可視範圍。

卡A 4.0.0：創意工坊安全契約隨控制中心內嵌；必須等契約驗證完成再載入工坊執行時。見 [[concepts/創意工坊與安全契約]]。

### 狀態列 Status Bar / HUD

顯示層常見輸出名 `status_bar_regex.html`。後期卡A改為卡內薄殼 + git-mount 真身：殼約 4KB，真身 `status-bar.html` 放 runtime，push 即可熱修。

殼與真身不在同一 window。Tavern Helper 的 `$` / `Mvu` / `eventOn` 不會自動進 blob iframe。`injectBridge` 給真身補 jQuery/lodash 與頂層 MVU 橋，否則 `readCurrentHudVariables` 靜默返回空、介面全是 `--`。

`window.XY_RT_BASE` 本應把 runtime 基址從控制中心傳給狀態列殼；實測 CC 的 script-iframe 與狀態列 message-iframe 隔離，殼往往走內聯 `BASE` / `BASE_CF`。出卡時必須改對版本段。

## 例子

- 正例：卡B Tab 切換先啟用目標容器再強制渲染，避免 `renderedTabSignatures` 命中後停在上一頁。
- 反例：模擬殼不復現「殼→blob→真身」三層鏈，模擬綠、真機紅。

## 邊界與易混概念

- 控制中心不是狀態列，也不是開局頁。開局頁是 `first_message_opening.html`，死守 first_mes 不塞大 HTML。
- 狀態列遠端掛載殼與全量本地版互斥，同名輸出 `status_bar_regex.html`，二選一。
- OMNI 美化是訊息樓顯示層，由 `media_library.js` 的 `renderOmniMounts` 掛載，按鈕再交給控制中心 `handleOmniButton`。
