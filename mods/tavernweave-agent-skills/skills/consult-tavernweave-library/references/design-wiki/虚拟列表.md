# 虛擬列表

本頁不是已採用技術，也不是成品列表殼。檢索時間：2026-08-14。蒸餾自 [[queries/第三批蒸餾目標]] **B3-Virt**。只談公開文件與規範旁註，不寫攻擊步驟或憑證。

## 一句話定義

虛擬列表（windowing）只把視口附近的行做成真實節點，其餘用佔位高度撐開捲軸。TanStack 的心是 **`Virtualizer` 座標器**：算 `start` / `size` / 可見區間，**不是元件**，不交付 markup 或樣式。react-window 才是元件庫。沒有 W3C「虛擬列表」規範。

## 為什麼重要

幾千行世界書、樓層、控制中心表若全量掛 DOM，會拖長任務、傷 INP。行業解法分兩路：JS 視窗化（卸掉屏外節點）與 CSS `content-visibility`（節點還在，跳過屏外排繪）。前者沒有標準 API；後者在 css-contain-2，不能當成虛擬列表專章。酒館 iframe 裡滾動容器往往不是 `window`，座標器的 `getScrollElement` 指錯窗，列表會空滾或錯位。

## 如何運作

### 座標器不是元件

[引言](https://tanstack.com/virtual/latest/docs/introduction) 原話：TanStack Virtual 是 headless UI utility，**因此不交付、也不渲染**任何 markup 或樣式。心是 `Virtualizer`：預設可豎、可橫，兩軸疊起來才像網格。

呼叫方必須自己準備三層，引言示例寫死了：

1. **滾動盒**：`overflow: auto` 的元素，經 `getScrollElement` 交給座標器。
2. **內層佔位**：高度（或寬度）= `getTotalSize()`，`position: relative`，用來撐捲軸。
3. **可見行**：只 map `getVirtualItems()`，`position: absolute` + `transform: translateY(start)`。

[Virtualizer](https://tanstack.com/virtual/latest/docs/api/virtualizer) 必填是 `count`、`getScrollElement`、`estimateSize`。介面卡「通常替你 new」，但你拿到的仍是這個類，不是 React 元件。`@tanstack/react-virtual` 的 hook 返回同一例項；`useWindowVirtualizer` 只是把滾動元素換成 `window`。

不要把 `useVirtualizer` 讀成「已經有一個列表元件」。無頭行為層見 [[concepts/無頭元件與根節點]]；本頁的無頭是**座標**，不是選單/對話方塊的焦點合同。

### react-window v1 / v2 分站

[README](https://github.com/bvaughn/react-window) 現行句：文件在 [react-window.vercel.app](https://react-window.vercel.app/)；**version 1.x** 在 [react-window-v1.vercel.app](https://react-window-v1.vercel.app/)。這是**兩個站**，不是同一站點的版本開關。

兩邊合同也不是同一套匯出：

| | v2 現行站 | v1 文件（README 指向的分站） |

| 自稱 | component library | 同樣是元件，不是座標器 |
| 列表面 | `List`：`rowComponent` / `rowCount` / `rowHeight` | 常見面是 `FixedSizeList` / `VariableSizeList`，`itemCount` / `itemSize`，children 當行渲染器 |
| 網格 | `Grid` + `cellComponent`；單元格尺寸必須事先可知 | `FixedSizeGrid` / `VariableSizeGrid` |
| 活頁 | 2026-08-14 可開啟 | 同日 WebFetch **404** |

[#897](https://github.com/bvaughn/react-window/issues/897)（2026-01，已關）：作者說 Next 會刪舊部署，並改口 v1 文件看 [versions](https://react-window.vercel.app/versions) 鏈到的 Wayback（`20241225003549` 快照）。衝突保留：README 仍寫分站 URL；活頁已死；Wayback 是存檔不是現行站。不要用 v1 的 `FixedSizeList` 示例去填 v2 的 `List`。

web.dev 舊文 [Virtualize large lists with react-window](https://web.dev/articles/virtualize-long-lists-react-window) 教的是 v1 面。當教程，不當現行 API。

### 無 W3C 虛擬列表規範

沒有「Virtual List」TR。css-contain-2 §4.2 只在 `content-visibility: auto` 下寫了一句旁註：在許多情況下可用來代替複雜的 "virtual list" 手法。那是**跳過屏外排繪**，節點仍在 DOM，讀屏與頁內查詢仍看得到。JS 視窗化則卸掉屏外節點，省的是記憶體和提交量，不是同一合同。

兩邊都留：規範認為 CSS 能替代「許多」虛擬列表；萬級行、回收節點、測高快取仍是庫的事。`content-visibility` 不能寫成「W3C 版 react-window」。

## 必須保留的衝突

- **座標器不是元件。** TanStack 引言明文不交付 markup；react-window 自稱 component library。不要併成「都是虛擬列表元件」。
- **v1 / v2 分站。** README 仍寫兩個 Vercel 主機。v2 活；v1 分站本輪 404。作者 #897 改指 Wayback，並承認 Next 會刪舊部署。
- **無 W3C 虛擬列表規範。** css-contain-2 只旁註 CSS 可替代許多手法；不是 List / Virtualizer 的 API 合同。
- **web.dev 舊文是 v1 面**，不能當 v2 真源。
- 工坊「現在不用」≠「視窗化不正當」。本頁對映 ≠ 採用。

## 例子

- 正例：TanStack 只問座標器要 `getVirtualItems()`，行節點自己寫。
- 正例：react-window v2 用 `List` + `rowComponent`，去現行站抄，不去 v1 分站。
- 正例：長文流、獨立卡片塊先試 `content-visibility: auto`，不必上視窗化。
- 反例：把 `Virtualizer` 當成 `<VirtualList>` 去找 children / `rowComponent`。
- 反例：v1 的 `FixedSizeList` 與 v2 的 `List` 混抄。
- 反例：在 TH iframe 裡 `useWindowVirtualizer`，卻以為滾的是宿主聊天區。
- 反例：因本頁出現庫名就寫進 recipe / 髮卡依賴。

- 不包括：本倉庫已採用宣告、成品錶殼、攻擊或憑證。
- 不包括：Virtuoso 全家、react-virtualized 全文；要蒸另開賬本。
- 易混：座標器 ≠ 列表元件。TanStack 算位置；react-window 交元件。
- 易混：v1 分站 ≠ v2 現行站；README 有 URL ≠ 該 URL 仍 200。
- 易混：`content-visibility` ≠ 視窗化。前者留節點，後者卸節點。
- 易混：`useWindowVirtualizer` 的 `window` 是**當前瀏覽上下文**的窗，不是「瀏覽器大窗」的口頭禪。
- 區分：先問「誰畫節點」；再問滾動元素在哪份 document。

## 對映到本倉庫

對映 ≠ 採用。穩定卡今天的長列表多半是普通 DOM。若在宿主抽屜、控制中心或訊息 iframe 裡做視窗化：

1. `getScrollElement` / 列表高度必須對著**實際 overflow 盒**。指令碼在 TH iframe 裡時，預設 `window` 是框內窗，不是 ST 主頁。分層見 [[concepts/酒館宿主與iframe分層]]。
2. 行高估計錯會讓捲軸和錨點一起漂；動態測高是庫選項，不是規範。
3. 視窗化卸節點會讓「整表 querySelector / 讀屏數行數」失效；需要完整可訪問樹時，先看 `content-visibility`，不要預設 JS 視窗化。
4. 效能指標仍走 [[concepts/Web效能與INP]]；本頁不重寫 INP。
