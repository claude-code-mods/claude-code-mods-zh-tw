# 訊息渲染與正則管線

模型吐出的是文字。玩家看見的樓，是 ST 宏 → 正則 → Markdown → DOMPurify → `.mes_text`。卡要插 UI，只能接到這條管線上，不能假裝自己是另一張網頁。指南：`A5_渲染管線與宏.md`、`A6_正則機制.md`。

## 管線（A5 對 v1.14.0 `messageFormatting` 的直讀）

```text
LLM 原文
  → 剝 prompt-bias
  → 正則（placement = AI_OUTPUT 且 markdownOnly 時，這一步就跑）
  → encode_tags / 引號處理
  → Markdown（Showdown）
  → 淨化
  → 寫入 .mes_text
```

宏求值在更前面。自定義 XML 標籤 + 換行有歷史坑（A5 §8.2）。指南曾推斷 DOMPurify 會剝內聯 `style`；生產 OMNI 靠內聯且真機能看，AFV 按誤報處理，細則見 [[concepts/OMNI正則與data屬性選擇器]]。

## 正則指令碼存在哪

| 型別 | 位置 | 穩定卡 |
|---|---|---|
| SCOPED | 卡 `data.extensions.regex_scripts` | 主用 |
| GLOBAL | `settings.json` | 不依賴 |
| PRESET | API 預設 | 不鎖 |

執行順序：Global → Scoped → Preset，鏈式，上一條輸出是下一條輸入。`A6` 訂正過舊草稿的順序。

關鍵欄位：`findRegex`、`replaceString`（`$1` / `{{match}}`）、`placement`、`markdownOnly`、`promptOnly`、`minDepth` / `maxDepth`。

顯示美化：`markdownOnly: true`，`promptOnly: false`。框出現在聊天裡 ≠ 進模型上下文。

## 穩定卡接到哪幾截

| 目的 | 卡A 4.0.0 元件 | 替換結果 |
|---|---|---|
| 變數同步完成 | `update_variable_omni_done_regex.html` | `data-xy-omni="done"` 掛載點 |
| 預分析 / 進度 | 元件庫 OMNI 模組；進度版曾因吞正文刪過 | `data-xy-omni="analysis"` / `progress` |
| 對話氣泡 | `dialog_bubble_regex.html` | `data-xy-dialog-render` + 隱藏 textarea |
| CoT 對話 | `dialog_cot_bubble_regex.html` | `data-xy-cot-dialog-render` |

| 開局 prompt 剝離 | `opening_prompt_strip_regex.html` | 不讓大 HTML 進上下文 |
| 狀態列 | 卡A後期是薄殼；卡B是整頁 `status_bar_regex.html` | ` ```html ` 程式碼塊 → TH iframe |

TH 看見訊息裡的 ` ```html ` 程式碼塊，就渲成 iframe（`srcdoc` = 塊內容）。這是狀態列的容器，不是普通 Markdown。

## 和 JS 橋怎麼接

正則只負責**佔位**。真正畫按鈕、拉遠端模板、填輸入框的是：

- `media_library.js`：掃 `[data-xy-omni]`、氣泡
- `options_bridge.js`：掃 `[data-xyopt-root]`
- 控制中心：開局遠端、OMNI 按鈕

舊樓選項會被另一條「舊樓選項隱藏」正則清掉，橋只服務最新樓。見 [[concepts/行動選項橋]]。

## 避坑（卡側已焊）

- 訊息樓選擇器走 `data-*`。ST 給 class 加 `custom-`。
- 預分析禁止裸 `[\s\S]*?` 跨同名標籤。
- `findRegex` 空字串等於不執行。
- 不要用正則寫變數。寫變數是 MVU 的事。
