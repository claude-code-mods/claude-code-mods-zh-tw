# 通行金鑰規範入口

本頁不是已採用登入方案，也不是工坊必須改鑑權的工單。檢索時間：2026-08-14。只收 WebAuthn / Passkeys 規範與官方指南入口。不寫攻擊步驟、繞過、PoC 或憑證。

## 一句話定義

通行金鑰（passkeys）是面向人的產品名：一份可發現的 FIDO 公鑰憑證，用來替代口令登入。瀏覽器側合同是 [WebAuthn](https://www.w3.org/TR/webauthn-3/)；客戶端與漫遊認證器之間的合同是 FIDO [CTAP](https://fidoalliance.org/specs/fido-v2.3-ps-20260226/fido-client-to-authenticator-protocol-v2.3-ps-20260226.html)。兩者合稱 FIDO2，不是同一份文字。

## 為什麼重要

口令是共享金鑰，伺服器一旦漏庫就能被複用。通行金鑰把私鑰留在認證器，依賴方只存公鑰。規範還要求憑證按來源（origin / RP ID）收窄，瀏覽器和作業系統負責核對站點身份，而不是讓人自己辨認真假站。工坊現網鑑權仍是 Cookie / JWT / OAuth 三件，見 [[concepts/後端架構名詞與工坊對照]] 與 [[concepts/OAuth與OIDC]]；本頁只給規範入口，不改那一頁的落點。

## 如何運作

### 三層合同，不要併成一份

1. **宿主憑證 API**：[Credential Management](https://www.w3.org/TR/credential-management-1/) 提供 `navigator.credentials.create()` 與 `get()`。截至檢索日仍是 Working Draft。
2. **Web 公鑰憑證**：WebAuthn 把 `PublicKeyCredential` 接到上述宿主。註冊走 `create({ publicKey })`，斷言走 `get({ publicKey })`。
3. **認證器通道**：漫遊認證器（USB / NFC / BLE / hybrid）走 CTAP。平臺認證器走作業系統介面，不經過 CTAP 文字的每一節。

[FIDO](https://fidoalliance.org/passkeys/) 寫明：同一套 FIDO2（WebAuthn + CTAP）既可部署同步通行金鑰，也可部署裝置繫結通行金鑰。跨裝置出示常見走 CTAP 的 `hybrid` 傳輸；那是客戶端與認證器的事，不是依賴方再實現一份 CTAP。

### 現行 Level 與短名

[W3C history：webauthn-3](https://www.w3.org/standards/history/webauthn-3/) 最新一行是 2026-05-26 Candidate Recommendation Snapshot。[W3C 新聞](https://www.w3.org/news/2026/proposed-advancement-of-webauthn-3-to-w3c-recommendation/) 宣佈提議升 Recommendation；提議 ≠ 已是 Rec。`/TR/webauthn-3/` 文首仍寫 CR，並寫明 CR 不代表 W3C 與會員背書。

[W3C history：webauthn-2](https://www.w3.org/standards/history/webauthn-2/) 釘 2021-04-08 Recommendation。檢索日訪問未帶 Level 的 [`/TR/webauthn/`](https://www.w3.org/TR/webauthn/) **仍落到 Level 2**，不是 Level 3。新工作引用 Level 3 必須寫 `/TR/webauthn-3/`。

編輯稿 [`w3c.github.io/webauthn`](https://w3c.github.io/webauthn/) 檢索日仍標題 Level 3，日期 2026-07-30。活稿可以新於 CR 快照，**不能**代替 TR 引用。

### 兩場儀式，不是一次 API

WebAuthn 自己分兩場儀式：

| 儀式 | 宿主呼叫 | 結果 |
|---|---|---|
| 註冊 Registration | `create({ publicKey })` | 認證器生成並收窄到該依賴方的公鑰憑證 |
| 認證 Authentication | `get({ publicKey })` | 依賴方收到斷言，證明使用者在場且同意 |

L3 把多裝置憑證（文中稱 synced passkeys）寫進用例。裝置繫結憑證仍是通行金鑰，只是不同步。不要把「同步」寫成通行金鑰的定義條件。

依賴方、使用者代理、認證器各有一節安全與隱私考慮。本頁到此為止，不摘利用面、不寫繞過。

### 相鄰草案不是本家族

[FedCM](https://www.w3.org/TR/fedcm/) 讓人用聯邦賬號登入，保護的是聯邦流程裡的隱私，不是 FIDO 公鑰憑證。[DBSC](https://www.w3.org/TR/dbsc/) 把瀏覽器會話綁到裝置持有的金鑰，目標是降低會話 cookie 被挪走後的冒用。二者檢索日都是 First Public Working Draft。可以並列收藏，不能寫成「通行金鑰的下一版」。

## 必須保留的衝突

- `/TR/webauthn/` 短名現仍是 **L2 Rec**，不是 L3。
- L3 是 **2026-05-26 CR Snapshot**；2026-07 新聞只是提議升 Rec，**還不是 Recommendation**。
- L3 編輯稿（2026-07-30）≠ CR 快照；引用以 TR 為準。
- 外文百科仍寫 L3 = FPWD，與 history 頁衝突，以 W3C history 為準。
- WebAuthn ≠ 通行金鑰 ≠ CTAP ≠ FIDO2。FIDO2 是前兩者成對；通行金鑰是可發現憑證的產品名。
- 同步通行金鑰 ≠ 裝置繫結通行金鑰；FIDO 兩者都叫 passkeys。
- Credential Management 仍是 **WD**；L1/L2 WebAuthn 已是 Rec，卻接在這份 WD 宿主上。兩邊都留。
- CTAP 現行是 **2.3 PS（2026-02-26）**，不是 2.2。
- FedCM / DBSC 都是 **FPWD**，不是通行金鑰規範。
- 平臺指南（Google / Apple / Microsoft）不是 W3C 或 FIDO 規範。
- 本頁對映工坊鑑權詞表；**不是**「工坊必須上通行金鑰」。

## 例子

- 正例：新站點引用寫 `/TR/webauthn-3/`，並標明它是 CR，不是 Rec。
- 正例：產品文案說「通行金鑰」，實現清單同時寫 WebAuthn（瀏覽器）與是否需要 CTAP（僅漫遊認證器）。
- 正例：同時支援同步通行金鑰與安全鑰匙上的裝置繫結通行金鑰，並在文件裡分開寫，不把同步當成定義。
- 反例：把 `/TR/webauthn/` 或百科的「L3 = FPWD」當成現行 Level。
- 反例：把 2026-07 提議升 Rec 寫成「L3 已是 Recommendation」。
- 反例：把 FedCM 或 DBSC 叫做通行金鑰；或把 OAuth 委託寫成 WebAuthn。
- 反例：把本頁當成攻擊、繞過或 PoC 手冊。

## 邊界與易混概念

- 不包括：攻擊步驟、繞過、PoC、Gateway token、OAuth 金鑰、物件儲存憑證、卡 JSON/PNG。
- 不包括：支付確認（SPC）、數字憑證（Digital Credentials）、已過期的 Token Binding 草案。
- 通行金鑰 ≠ 授權模型。WebAuthn 回答「人是不是這個依賴方的持有者」；角色與許可權另寫。
- 通行金鑰 ≠ 會話。登入成功之後的瀏覽器會話仍常是 Cookie；DBSC 若採用也是另一份草案。
- OAuth ≠ WebAuthn。OAuth 管誰來證明人；WebAuthn 管公鑰憑證儀式。見 [[concepts/OAuth與OIDC]]。
- 生物識別材料按平臺指南不離開本機；依賴方校驗的是簽名，不是指紋模板。本頁不寫採集或比對步驟。
- 易混：聽到「無密碼」就以為只有通行金鑰。魔法連結、OTP、聯邦登入都是無密碼，合同不同。

## 對映到本倉庫

當前工坊：Gateway 同進程管包生命週期 + 所有權 + 稽核；OAuth 只證明發布者，見 [[concepts/後端架構名詞與工坊對照]] 與 [[concepts/OAuth與OIDC]]。卡內 fail closed 見 [[concepts/創意工坊與安全契約]]。酒館 iframe 無獨立 OS 安裝面，見 [[concepts/酒館宿主與iframe分層]]。

本頁只回答「通行金鑰的規範入口在哪、哪一級成熟」。不把工坊釋出者登入改成 WebAuthn，也不把卡內 HUD 寫成必須註冊通行金鑰。這是資料庫入口，不是已採用清單。
