# 媒體格式與編解碼

本頁不是已採用媒體棧，也不是髮卡媒體庫。檢索時間：2026-08-14。蒸餾 [[queries/第二批蒸餾目標]] **B2-Media**、[[queries/第三批蒸餾目標]] **B3-Codec** / **B3-PiP**。B3-RTC、B3-Spch 不併進本頁。只談公開格式與 API 邊界，不寫盜版片源、繞過 DRM 或攻擊步驟。

## 一句話定義

瀏覽器媒體合同分四層：容器與編碼怎麼投遞（AVIF/WebP、HLS/MSE）、幀怎麼編解碼（WebCodecs）、窗怎麼浮（影片 PiP 與文件 PiP 是兩套 API）、屏怎麼不滅（Screen Wake Lock）。格式表不是卡內 `media_library.js`。

## 為什麼重要

同一段「放一張圖 / 播一段片」會落到完全不同的合同：`<picture>` 管格式回退，`srcset` 管解析度，MSE 管分段餵給 `<video>`，WebCodecs 只管幀、不管封裝。視窗層再拆：影片 PiP 只抬 `HTMLVideoElement`；文件 PiP 另開一份始終置頂的 HTML 文件。混成一詞，就會把 iPhone 的 HLS、Chrome 的非標準軌生成器、或宿主 HUD 浮窗寫成同一條 API。

## 如何運作

### 影像：格式回退 ≠ 解析度切換

[MDN 影像型別](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types) 把 AVIF / WebP 寫在同一張能力表。AVIF 無漸進渲染，必須準備 JPEG/PNG 回退。WebP 現版四大瀏覽器都有，歷史仍淺，正文仍建議用 `picture` 回退。`<picture>` 的 `type` 選格式；`srcset` / `sizes` 選解析度或藝術指導。兩套選擇器不要併成「響應式一張圖」。原生 `loading="lazy"` 只寫在 `img` 上，CSS `background-image` 不能用；首屏 / LCP 圖禁 lazy。關 JS 時瀏覽器不推遲載入（防追蹤）。

JXL 裝載、PNG-3 HDR、以及「Safari 已裝 JXL / Chrome Stable 預設無」見 [[concepts/JPEG XL與HDR靜圖]]。本頁只記 AVIF/WebP 投遞與 `<picture>` / `srcset` 分工，不重抄那一頁。

### 流媒體：原生 HLS ≠ MSE 喂片 ≠ 託管源

桌面 Chrome / Firefox 不能只丟 `.m3u8` 給 `<video src>`，要 MSE + JS（或播放器庫）。Safari / iOS 與多數 Android 可原生播 HLS。DASH 靠 dash.js + MSE。常見可互操作基線是 H.264 + AAC + MP4；容器與編解碼器參差，不是「有 MSE 就能播任意包」。

iPhone 長期沒有完整 MSE。官方接法是 [ManagedMediaSource](https://developer.mozilla.org/en-US/docs/Web/API/ManagedMediaSource)：UA 可隨時驅逐緩衝，適合省電流。Safari 上必須把 `HTMLMediaElement.disableRemotePlayback` 設為 `true`，或提供 HLS AirPlay 備源，否則 **`sourceopen` 不觸發**。這是實驗性介面，不是 Baseline。

### WebCodecs：幀合同，不是播放器

[WebCodecs](https://www.w3.org/TR/webcodecs/) 給 `VideoEncoder` / `VideoDecoder` / `VideoFrame` 等介面，對接**已有**編解碼實現。規範不點名 H.264 / AV1，實現可以一個都不支援。解碼配置要完整 codec string（如 `avc1.64001F`），禁寫光禿 `h264`。先 `isConfigSupported()` 再配；HEVC 面窄，不要當預設檔。`VideoFrame` 佔編解碼系統資源，用完必須 `close()`。無內建混流；音訊不自動接 Web Audio。封裝、清單、自適應位元速率仍歸 MSE / HLS / `<video src>`，不要用 WebCodecs 替代播放器。登記冊只防字串撞名，不是專利或實現承諾。

軌進出另走 Insertable Streams（`MediaStreamTrackProcessor` / 規範名 `VideoTrackGenerator`）。Chrome 主執行緒長期暴露非標準 `MediaStreamTrackGenerator`，對不上規範 `VideoTrackGenerator`。這是鄰接衝突，本頁不蒸 WebRTC；對等通話與信令見 [[concepts/WebRTC信令邊界]]。

### 影片 PiP ≠ 文件 PiP

[Picture-in-Picture](https://www.w3.org/TR/picture-in-picture/) 擴充套件 `HTMLVideoElement`：`requestPictureInPicture()`、`document.exitPictureInPicture()`、`pictureInPictureEnabled`、`pictureInPictureElement`。浮的是**那一路影片**，不是任意 DOM。規範建議進全屏時退出影片 PiP。

[Document Picture-in-Picture](https://wicg.github.io/document-picture-in-picture/) 是另一套 API：`window.documentPictureInPicture.requestWindow()`，得到一份始終置頂、與 opener 同origin 的空白文件，可塞任意 HTML。它不是 W3C `/TR`，也不是影片 PiP 的超集。文件 PiP 窗：不能設位置、不能導航到新文件、不能活過 opener、**禁止再全屏**（`requestFullscreen()` 必須停用）。API **只在頂層 traversable 上可用**；窗裡可以再嵌 iframe，包括跨源。

兩套不要寫成「PiP」。宿主 HUD / 抽屜 / 浮窗外殼也不是文件 PiP。桌面殼自己的 OS 視窗同樣不是文件 PiP，見 [[concepts/桌面殼Electron Tauri]]。

### 全屏與喚醒鎖

全屏真源是 [WHATWG Fullscreen](https://fullscreen.spec.whatwg.org/)，不是 PiP 規範的一章。iframe 要單獨的 fullscreen 許可（策略預設 allowlist 常是 `'self'`）。切頁 / 切應用會退出全屏。影片 PiP 的 Permissions-Policy 名是 `picture-in-picture`（MDN 冊記預設 allowlist `*`）；喚醒鎖是 `screen-wake-lock`（預設 `'self'`）。三道閘不要抄成同一條 `allow`。頭與框策略的總合同見 [[concepts/CSP與Trusted Types]]，本頁只記這三道媒體閘。

[Screen Wake Lock](https://www.w3.org/TR/screen-wake-lock/) 只有 `screen` 一種鎖，且只有**可見文件**能拿到。隱藏文件自動釋放，須聽 `visibilitychange` 再申請。策略名 `screen-wake-lock`，預設 allowlist 是 `'self'`。規範正文仍寫「extremely unstable」；實現普及不等於已升 Rec。`web.dev/articles/wake-lock` 已死，指南看 Chrome 文。

## 必須保留的衝突

- **影片 PiP ≠ 文件 PiP**：W3C WD 只管 `HTMLVideoElement`；文件 PiP 是 WICG CG 草案、無 `/TR`、禁全屏、只頂層可申請。賬本與本頁都不得併成一詞。
- **Chrome `MediaStreamTrackGenerator` ≠ 規範 `VideoTrackGenerator`**：規範名在 mediacapture-transform；Chrome 非標準舊名仍在主執行緒。MDN `VideoFrame` 鄰接頁若仍寫舊名，以 TR 為準。
- **`web.dev/articles/wake-lock` 已 404**（2026-08-14 直讀）。活源是 Chrome 能力文。`web.dev/wakelock` 會跳轉，不要當獨立正文。
- **Wake Lock TR 自稱極不穩**，與「實現已較常見 / MDN 曾標 Baseline Newly」並存；成熟度以 TR 狀態為準，不升 Rec。
- **iPhone MSE**：完整 MSE 長期缺席；JS 喂片走 ManagedMediaSource，且缺 `disableRemotePlayback` / HLS 備源則 `sourceopen` 不觸發。不要寫「移動 Safari 已有桌面 MSE」。
- **HLS 投遞分叉**：Safari / iOS 可原生；Chrome / Firefox 桌面必須 MSE + JS。web.dev 無 HLS 專文，不要用壓縮圖文冒充流媒體合同。
- **WebCodecs 仍是 WD（2026-07-08）**：不規定演算法，實現可零支援。過期 dated TR 與 `webcodecs.org` 映象偏舊，以 `/TR/webcodecs/` 為準。
- **文件 PiP 窗禁全屏**；影片 PiP 規範建議進全屏時退出 PiP。方向相反，不要抄錯。
- 本頁對映投遞、幀、窗與鎖；**不是**「已採用 AVIF / hls.js / WebCodecs / 任一種 PiP」。

## 例子

- 正例：英雄圖用 `<picture>` 先 AVIF 再 WebP 再 JPEG；`srcset` 只負責密度；LCP 圖不寫 `loading="lazy"`。
- 正例：桌面 HLS 走播放器 + MSE；iPhone 走原生 `.m3u8`，或 `ManagedMediaSource` 且關掉 Remote Playback。
- 正例：自定義濾鏡管線用 WebCodecs 出 `VideoFrame`，封裝仍交給 MSE 或 `<canvas>` 繪製。
- 正例：只想讓影片貼在別的窗上，用影片 `requestPictureInPicture()`；要帶控制元件/歌詞/進度條，才考慮文件 PiP。
- 反例：給 Chrome / Firefox 桌面只掛 `src="…/master.m3u8"`，指望原生播。
- 反例：在 TH iframe 裡調 `documentPictureInPicture.requestWindow()`，或把文件 PiP 當成宿主 HUD。
- 反例：把 `MediaStreamTrackGenerator` 寫成規範名，或把 WebCodecs WD 寫成 Recommendation。
- 反例：引用 `web.dev/articles/wake-lock` 當活源。

## 邊界與易混概念

- 不包括：卡內媒體庫槽位、工坊物件儲存、WebRTC 信令、語音 / MIDI、盜版片源、繞過 DRM。
- [[concepts/媒體庫路徑]] 管型別 / 槽 / 變體 / 來源，不是本頁的 MIME 與編解碼合同。
- AVIF 能頻寬色或 HDR 元資料，不等於 Display P3 就是 HDR；色域合同見 [[concepts/視覺CSS與設計token]]。靜圖 HDR 編碼面見 [[concepts/JPEG XL與HDR靜圖]]。
- WebCodecs ≠ MSE ≠ `<video src>` ≠ WebRTC。幀、分段、檔案、對等傳輸是四條路。對等層見 [[concepts/WebRTC信令邊界]]。
- 影片 PiP ≠ 文件 PiP ≠ 全屏 ≠ 宿主浮窗 ≠ [[concepts/小手機與宿主橋|小手機]] 抽屜。
- 喚醒鎖 ≠ 防休眠整機；它只擋螢幕熄滅，且文件一隱藏就掉。
- 三維資產格式見 [[concepts/WebXR與glTF]]，不併進本頁的 AVIF / HLS / WebCodecs。
- 桌面殼 OS 視窗 ≠ 文件 PiP，見 [[concepts/桌面殼Electron Tauri]]。
- B3-RTC、B3-Spch 是鄰接賬本，本頁不收。

## 對映到本倉庫

對映放最後，不當過濾器。行業合同對獨立站和嵌入 UI 都成立，**不是「卡不能談媒體格式」**。本倉是否接線、真機是否驗收，都不在本頁宣佈。

- **媒體庫**：[[concepts/媒體庫路徑]] 的 GIF / data URL 上限是產品配額，不是 AVIF/WebP 能力表。外鏈 `url-external` 不當 AFV 真源。
- **靜圖編碼**：JXL / AVIF / PNG-3 與現網裝載分叉見 [[concepts/JPEG XL與HDR靜圖]]。本頁管 `<picture>` / `srcset`、流、幀、窗、鎖，不宣佈採用哪一種靜圖編碼。
- **iframe**：TH 訊息框不是頂層 traversable，**申請不了文件 PiP**。影片 PiP / 全屏 / 喚醒鎖要看框上的 `allow` / Permissions-Policy（`picture-in-picture`、`fullscreen`、`screen-wake-lock`）。切樓、隱藏框會掉 Wake Lock。分層見 [[concepts/酒館宿主與iframe分層]]。
- **HUD**：[[concepts/入口外殼與HUD宿主]] 的抽屜 / 浮窗掛宿主 document，不是 Document PiP 新窗。不要用文件 PiP 替換 C13。[[concepts/小手機與宿主橋]] 同樣掛宿主 body，也不是文件 PiP。
- **LCP 圖**：投遞合同可回 [[concepts/Web效能與INP]]；本頁只記格式與懶載入邊界。

本頁不寫「已採用 AVIF / hls.js / WebCodecs / 任一種 PiP」。蒸餾目標仍在 [[queries/第二批蒸餾目標]]、[[queries/第三批蒸餾目標]]。

## 來源與證據

- 影像型別與 `picture`：MDN Image types；MDN `picture`。AVIF 無漸進、須回退；`type` 選格式、`srcset` 選解析度。
- HLS / MSE：MDN MSE；MDN 自適應流配置。桌面 Chrome / Firefox 不能只掛 `.m3u8`；Safari / iOS 可原生。
- iPhone 喂片：MDN ManagedMediaSource；缺 `disableRemotePlayback` / HLS 備源則 `sourceopen` 不觸發。
- WebCodecs：`/TR/webcodecs/` WD 2026-07-08；登記冊 2026-02-12 DRY。不規定演算法；完整 codec string；`close()`。
- 軌生成器舊名：Chrome `MediaStreamTrackGenerator` ≠ 規範 `VideoTrackGenerator`。
- 影片 PiP：`/TR/picture-in-picture/` WD 2026-06-16，只覆蓋 `HTMLVideoElement`。
- 文件 PiP：WICG CG 草案 2026-02-04，無 `/TR`；Chrome 文：`requestWindow()`、要手勢、Limited、禁全屏、只頂層。
- 全屏：WHATWG Fullscreen 活標準。
- 喚醒鎖：`/TR/screen-wake-lock/` WD 2024-10-24，自稱極不穩；`web.dev/articles/wake-lock` 2026-08-14 已 404，活源是 Chrome 能力文。
- 查詢賬本：[[queries/第二批蒸餾目標]] B2-Media；[[queries/第三批蒸餾目標]] B3-Codec、B3-PiP。鄰接 B3-RTC 見 [[concepts/WebRTC信令邊界]]；靜圖編碼見 [[concepts/JPEG XL與HDR靜圖]]。
