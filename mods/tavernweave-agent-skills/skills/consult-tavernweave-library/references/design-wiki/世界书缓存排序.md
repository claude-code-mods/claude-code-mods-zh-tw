# 世界書快取排序

## 一句話定義

用穩定常亮規則當前綴、把每樓動態摘要和關鍵詞設定往後放，提高 prompt 快取命中。卡B 2.6.2 把這套策略寫成 `promptCacheOrdering`。

## 為什麼重要

每樓都變的變數摘要若排在最前，整段字首每輪失效，快取無意義。機甲/探索卡世界書條目多，這個問題更尖。

## 如何運作

回封時統一：

- 燈（常亮 / 關鍵詞）
- 深度 depth
- `insertion_order`
- `display_index`
- `cfSortKey`

排序原則：

1. `[mvu_update]變數更新規則` 與 `[mvu_update]變數輸出格式`：常亮、淺深度、前置。
2. 探索、戰鬥、資源、基地、裝備、關係、任務、數值等常亮規則：同樣前置淺深度。
3. `[mvu_context]每樓變數摘要`：後置高排序。
4. 世界設定細分：關鍵詞觸發，貼近上下文後置。
5. 原版參戰作品與原版錨定機體：預設滅燈，只留刪減版。

門停用 `validate_card.mjs` 與 `check_crossed_zone_2_6_0.mjs` 卡住。

## 例子

- 正例：2.6.2 把動態摘要從快取字首裡拿掉。
- 反例：所有設定常亮且深度相同，每輪 token 與快取一起爛。

## 邊界與易混概念

- 這是裝配/回封策略，不是狀態列 CSS。
- 卡A也有世界書 insertion 欄位，但不等於已經落地同一套 `promptCacheOrdering` 門禁。
