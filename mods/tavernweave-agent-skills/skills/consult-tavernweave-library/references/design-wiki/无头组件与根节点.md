# 無頭元件與根節點

檢索日 2026-08-14。賬本樞紐是 [[queries/第二批蒸餾目標]] 的 **B2-Head**。不是已採用技術，也不是成品皮膚。

## 一句話定義

無頭元件（headless）只交付行為、焦點、鍵盤和 ARIA，不交付視覺；根節點是這套行為去哪份 `document` / ShadowRoot 查節點、掛 Portal、鎖焦點。錯了根，浮層會出現在另一扇窗裡。

## 為什麼重要

選單、對話方塊、下拉、工具提示都要：查觸發器、把浮層傳送到某份文件、在正確的瀏覽上下文裡做焦點陷阱。行業庫用 `getRootNode`、`EnvironmentProvider` 或 Portal 的 `container` 顯式交代「根在哪」。酒館裡同一套控制元件可能掛宿主 `document`，也可能跑在 TH iframe 的框內文件——這是對映，不是選型。

## 如何運作

### 無頭管行為，不管皮膚

[Base UI About](https://base-ui.com/react/overview/about) 寫：元件 unstyled、不捆 CSS、不規定用 Tailwind 還是 CSS Modules。[Radix Styling](https://www.radix-ui.com/primitives/docs/guides/styling) 更硬：功能樣式也歸你，Dialog Overlay 預設不會鋪滿視口。

因此：**無頭元件 ≠ 無樣式設計系統。** 設計系統還要 token、色板、間距、字型和元件皮膚。無頭只保證開合、焦點、鍵盤、`aria-*`；按鈕長什麼樣仍要自己寫。把 headless 當成「開箱即用的灰皮膚」會漏掉視覺層，也誤讀了庫的合同。

行為合同對齊的是 [WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/) 那類模式（選單、對話方塊、combobox），不是某家皮膚。Radix 站點上的 **Themes** 是帶樣式的一層，和 **Primitives** 無頭層不是同一份合同；不要用 Themes 的預設外觀反推「無頭已經有設計系統」。

Zag 的 Menu 只給 `data-part` / `data-state`，樣式指南是選擇器提示，不是主題包。Ark 包一層 React/Solid/Vue/Svelte，行為仍來自 Zag。

### Radix → Base UI 是產品線遷移

[About](https://base-ui.com/react/overview/about) 自稱來自 Radix、Material UI、Floating UI 的作者。[useRender](https://base-ui.com/react/utils/use-render) 專設「Migrating from Radix UI」：Radix 用 `asChild` + `Slot`，Base UI 用 `render`。這是**同一作者群的後繼產品線**，API 換了組合面。

不要寫成「Radix 已死」。2026-08-14 仍能開啟 [Introduction](https://www.radix-ui.com/primitives/docs/overview/introduction)、[Composition](https://www.radix-ui.com/primitives/docs/guides/composition)、[Portal](https://www.radix-ui.com/primitives/docs/utilities/portal)；文件仍教 `radix-ui` 單包和 `@radix-ui/react-*` 分包裝。既有卡或工坊若已用 Radix，它還在；新棧若跟作者後繼，才看 Base UI。並存，不是訃告。

Ark 走另一條：Zag 狀態機 + `asChild`。三套組合面不要混抄。

### 兩個 `getRootNode`，不要併成一個

| 名字 | 是什麼 | 返回 |
|---|---|---|
| DOM [`Node.getRootNode()`](https://developer.mozilla.org/en-US/docs/Web/API/Node/getRootNode) | 瀏覽器方法。普通頁給 `HTMLDocument`；影子樹預設給 `ShadowRoot`；`composed: true` 可越過影子到文件 | 現有樹上的根 |
| Zag / Ark 的 `getRootNode` | **機器上下文裡的函式**，告訴庫去哪份根做 `querySelectorAll` / `getElementById` | 文件裡寫 `() => ShadowRoot \| Document \| Node` |

Zag [Composition](https://zagjs.com/guides/composition) 原話：自定義環境（iframe、Shadow DOM、Electron）裡全域性 `document` 可能不對；把 `getRootNode` 傳進 `useMachine`。影子樹裡可用元素上的 DOM `getRootNode()` 推出根。官方 iframe 例：`useFrame()` 拿到框內 `document`，再 `getRootNode: () => document`。

Ark [Environment](https://ark-ui.com/docs/utilities/environment) 承認內部就是 Zag。`EnvironmentProvider` 可自動探測，也可 `value={document}` 或 `value={() => shadowRoot}`。`useEnvironmentContext()` 再取出 `getRootNode`。

Radix / Base UI 不叫這個名字，但 Portal 做同一件事：預設掛**當前 JS 看到的** `document` / `document.body`；要換文件就傳 `container`。

## 對映到酒館 iframe 分層

這一節是把行業合同對照 [[concepts/酒館宿主與iframe分層]] 和 [[comparisons/嵌入三路徑對照]]。**對映 ≠ 本倉庫已採用 Zag / Ark / Base UI / Radix。** 穩定卡今天的殼是宿主掛載、TH 訊息 iframe、git-mount blob，不是這些庫的安裝宣告。

先認誰造窗，再談根：

| 窗 | 這份文件是誰 | 浮層 / 焦點 / Portal 必須對著誰 |
|---|---|---|
| 宿主頁 | SillyTavern 主 `document` | 入口、懸浮球、抽屜、浮窗、小手機。Overlay 掛這裡才能蓋聊天區、摸 `#send_textarea` |
| 指令碼框 `TH-script--…` | TH 注入的獨立 iframe 文件 | 控制中心等整頁尾本若在此框跑，根是**框內** document，不是宿主 |
| 訊息框 `TH-message--…` | 另一份 TH iframe 文件 | 卡B整頁 HUD、卡A薄殼。`vh`、焦點、Portal 預設都在框內 |
| 卡內 blob / `#xy-sb-inner` | 再隔一層；預設無 TH 全域性 | 根是內層 document；要摸宿主必須 `injectBridge` / `hostDocument()`，不能假定 `document.body` 是 ST 主頁 |
| `.mes_text` 碎片 | 不是 iframe | OMNI / 氣泡 / 選項走 DOMPurify，沒有無頭庫的瀏覽上下文 |

規則：

1. **入口掛宿主 `document` 時**，浮層、焦點陷阱、Portal 必須拿到**宿主根**。預設 `document.body` 若取自指令碼所在窗，而指令碼其實在 TH iframe 裡，選單會傳送到框內 `body`：宿主看不見、磨砂糊不到聊天區、焦點鎖在小框。應對：`hostDocument()` / `hostWindow()`，或把 Portal `container` / Zag `getRootNode` 指到宿主文件（同源才合法；跨域會 `SecurityError`）。
2. **整頁尾本在 TH iframe 裡跑時**，根就是**框內 document**。框內選單對框內 `getRootNode: () => document` 是對的；不要強行掛到宿主，除非產品明確要「框內按鈕、框外浮層」。
3. 指令碼框和訊息框**不是同一個 `window`**。`window.XY_RT_BASE` 到不了狀態列殼，同一條根函式也不能兩邊共用而不問窗。
4. 不要在訊息 iframe 裡 `position: fixed` 裝全屏浮窗。殼掛宿主，見 [[concepts/入口外殼與HUD宿主]]。
5. Shadow DOM 只抗樣式，不是安全邊界。影子內的無頭機器仍要 `getRootNode` 指向該 `ShadowRoot`，否則查不到觸發器。

跨文件還有兩條視覺合同，根選錯時會一起炸：[backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) 糊不到另一份文件的聊天區；iframe 裡的 `1vh` 是框高不是瀏覽器視口。濾鏡和全屏殼必須與「根在哪」同一條決策，見 [[concepts/視覺CSS與設計token]]。

行業庫的 `getRootNode` 正好對應「先認窗再查節點」。本倉庫沒有因此改用 Zag。

## 例子

- 正例：Zag 官方在 `react-frame-component` 裡把框內 `document` 傳給 `getRootNode`。
- 正例：Ark 在 iframe 裡包 `EnvironmentProvider`，或 `value={document}` 手寫框內文件。
- 正例：Radix `Dialog.Portal container={el}` / Base UI `Popover.Portal` 的 `container` 指到與觸發器同一份文件（或產品指定的那份）。
- 正例（對映）：小手機、魔棒、抽屜掛宿主；整頁 HUD 的框內控制元件用框內根。
- 反例：把 headless 當成「已經有一套灰皮膚的設計系統」。
- 反例：寫成「Radix 已死，只剩 Base UI」。
- 反例：在 TH 訊息 iframe 裡 `createPortal(..., document.body)`，卻以為 `document` 是 ST 主頁。
- 反例：因本頁出現 Zag 就寫進 recipe / 髮卡依賴。

## 邊界與易混概念

- 不包括：某張卡的元件庫選型、皮膚 token、把無頭庫打進 PNG。
- 不包括：Headless UI（Tailwind 團隊）、React Aria 的全文；要蒸另開賬本。
- 易混：DOM `node.getRootNode()` 與 Zag 上下文 `getRootNode`。前者讀樹，後者是庫的查詢範圍鉤子；Zag 在影子裡會**呼叫**前者。
- 易混：無頭、無樣式、設計系統。無頭 ⊂ 無樣式行為層；設計系統 = 行為 + 視覺語言。Radix Themes ≠ Radix Primitives。
- 易混：TH Blob URL 渲染（仍是 TH 前端介面）與卡A git-mount blob（預設無 TH 全域性）。
- 區分：先問「指令碼在哪個 `window`」，再問 Portal / 焦點 / `querySelector` 用哪份根。

### 已知衝突（不靜默覆蓋）

- **對映 ≠ 採用。** B2-Head 與總監口徑：Zag `getRootNode` 與酒館 iframe 分層直接相關，這是對照，不是「本倉庫已採用 Zag」。
- **Radix 未死。** 作者群把後繼寫在 Base UI，並提供 `asChild` → `render` 遷移頁；Radix Primitives 文件與包裝仍在。採用「後繼」或「並存」必須分開寫。
- **無頭 ≠ 設計系統。** 庫自己說不捆 CSS；視覺仍要作者寫。
- **Zag 文件路徑。** 活頁是 `https://zagjs.com/guides/composition`。Ark Environment 鏈到 `https://zagjs.com/overview/composition#custom-window-environment`，同日 WebFetch 返回伺服器錯誤。衝突保留：以 guides 活頁為準，overview 舊錨點標待核。
- **`getRootNode` 返回型別。** 官方 Menu 上下文寫 `ShadowRoot | Document | Node`。GitHub PR `chakra-ui/zag#3127` 主張改成 `Element`，理由是 `Node` 沒有 `querySelectorAll`。本頁採用文件現場型別，PR 只作版本差，不把未釋出簽名寫成現行合同。
- **自動探測 vs 顯式根。** Ark 說 `EnvironmentProvider` 可自動探測；Zag 例程顯式傳框內 `document`。巢狀 iframe / 宿主橋不要賭自動探測。
- **Portal 預設值。** Radix 寫預設 `document.body`；Base UI Popover 寫預設掛到文件，再用 `container`。語義同屬「當前瀏覽上下文的文件」，API 字面不同。
- **組合面三套。** Radix / Ark：`asChild`。Base UI：`render`。Zag：spread props + `mergeProps`。不能把一份示例改三個庫名交差。
