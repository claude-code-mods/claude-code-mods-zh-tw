# 角色卡升格

## 一句話定義

升格把「一張可匯入的角色卡」做成「一套可移植、可被同源卡取用的系統」：功能先在驗收卡上做穩，再回落元件庫，再裝配到其它卡。

## 為什麼重要

同源卡若各自改控制中心、狀態列和變數鏈，會分叉。升格用同一套元件、recipe 和驗收門，避免每張卡重寫一遍前端。

## 如何運作

驗收卡是 [[entities/示例學園|示例學園]]。技術做穩後回落 `模組化元件/`，再裝配到其它同源卡。[[entities/卡B|卡B]] 最新頭已是已驗證穩定髮卡。[[entities/卡D|卡D]] 仍是未出生設定設計檔，不是已裝配穩定頭。

四條驗收同時滿足才算「做穩」：

1. 離線校驗全綠；
2. 模擬器注入資料透過（開發期主力）；
3. 留相容餘量；
4. 可移植到其它同源卡。

真機 SillyTavern 匯入是最終門，不是每個小功能的開發節奏。節奏是：閉合鏈路圖 → 實現 → 模擬 → 回落元件庫。一次只做穩一個功能。

層序：變數系統與變數根分片 → 世界書管理器與卡族白名單 → 狀態列正規化 → 卡內功能 → 平臺線（創意工坊 / 創作平臺）。

## 例子

- 正例：狀態列先當正規化樣板，自包含 UI、動效、變數根、更新規則，過四條門再給別的卡用。
- 反例：一次整吞開局頁、懸浮球、工坊、地圖，缺止損點，最後哪張卡都裝不回去。

## 邊界與易混概念

- 它不包括把 JSON/PNG 當真源。真源是元件、registry、recipe 與版本目錄裡的 Markdown/原始檔。
- 不要和「發一張新卡」混淆。髮卡是裝配與回封；升格是讓功能可複用。
- 怪談筆記後來也回落進元件庫，但是卡族專屬模組，不混裝進卡A / 卡B的變數與狀態列。
