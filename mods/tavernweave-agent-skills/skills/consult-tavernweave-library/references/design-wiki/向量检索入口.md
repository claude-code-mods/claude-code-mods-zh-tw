# 向量檢索入口

本頁不是已採用技術，也不改工坊或角色卡棧。檢索日 2026-08-14。賬本樞紐是 [[queries/第三批蒸餾目標]] **B3-Vec**（約 7 條，樞紐 [OpenSearch Vector search](https://docs.opensearch.org/latest/vector-search/)）與 **B3-CDC**（約 15 條，樞紐 [Debezium `/stable/`](https://debezium.io/documentation/reference/stable/index.html)）。CDC / FTS 只作相鄰對照，**不映象**整路 15 行。不收權重映象。

## 一句話定義

向量檢索是把文字（或圖、音）先編成固定維的**嵌入向量**，再按距離找近鄰。它回答「語義上像什麼」，不是倒排詞項命中，也不是把庫變更從日誌裡掏出來。

## 為什麼重要

口語常把「語義搜 / RAG / pgvector / OpenSearch kNN / 全文 / CDC」併成一種「搜尋」。合同不同：誰生成向量、存在哪、查詢是精確 kNN 還是近似（ANN）、要不要和詞項分混合。選錯的典型後果是：用 `tsvector` 當語義檢索、把變更捕獲當索引重新整理器，或把演示裡的 Hugging Face 模型登記寫成必須自建權重倉。工坊和卡 iframe **現在都不因此改棧**；行業入口仍值得留。

## 如何運作

先分四層，避免併成一個「搜」：

| 層 | 管什麼 | 本批入口 | 不管什麼 |
|---|---|---|---|
| 嵌入 | 文字 → 向量 | OpenSearch 可自帶生成，也可自帶向量 | 權重檔案、盜版映象 |
| 索引 | 向量怎麼存、怎麼近鄰 | `knn_vector` / pgvector | WAL、詞項倒排 |
| 查詢 | 原始向量 / `neural` / 混合 | kNN DSL、語義檢索頁 | 分面 UX、站內靜態包 |
| 相鄰 | 詞項 FTS、變更捕獲 | PG 第 12 章、Debezium | 不是向量合同 |

[OpenSearch 總覽](https://docs.opensearch.org/latest/vector-search/) 寫明：向量可和既有欄位同索引；用法包括語義檢索、RAG、推薦。兩條進數路：**自帶向量**，或讓引擎在攝入時生成嵌入。查詢面至少四類：原始向量（`knn`）、語義（`neural`）、混合、神經稀疏；多模態是同一棵文件樹的另一枝，不是本頁第四套真源。

[近鄰技法](https://docs.opensearch.org/latest/vector-search/vector-search-techniques/index/) 把 **ANN** 和精確 kNN 拆開。舊外掛樹 `/search-plugins/knn/` 採集日已重定向到此頁；外掛倉主頁若仍掛舊址，不當現行入口。[kNN 查詢](https://docs.opensearch.org/latest/query-dsl/specialized/k-nn/index/) 採集日記：`nmslib` 已棄用；gRPC 檢索 3.2 GA。[欄位對映](https://docs.opensearch.org/latest/mappings/supported-field-types/knn-vector/) 管 `knn_vector`、HNSW / IVF、`in_memory` / `on_disk`。

**pgvector** 沒有獨立文件站，[倉庫 README](https://github.com/pgvector/pgvector) 即真源。它是 Postgres 擴充套件：列存向量、建索引、用距離運算元查近鄰。採集日記安裝示意 v0.8.6、PG 13+。它**不是** CDC 聯結器，也**不是** `tsvector`。

**CDC** 是變更捕獲。Debezium `/stable/` 採集日等於 **3.6**（3.7 為 development）；`/2.4/` 仍活但已過時，勿釘舊樹。Postgres 聯結器預設 `pgoutput`。邏輯複製是手冊第 29 章；邏輯解碼是第 47 章。二者都不是全文、也不是向量。

**FTS** 是手冊第 12 章：`tsvector` / `tsquery` / `@@`。GIN 優先，GiST 有損。`/docs/current/` 採集日指向 **PostgreSQL 18.6**。詞項命中 ≠ 嵌入近鄰。

## 例子

- 正例：文件站要「問意思」時，先選定嵌入合同，再選 OpenSearch `knn_vector` 或 pgvector，查詢用近鄰而不是 `@@`。
- 正例：只要詞項、拼寫、中文分詞，走 PG FTS 或 B2-Search 靜態包，不上向量引擎。
- 正例：要把訂單行變更送到下游，走 Debezium / 邏輯複製，不把 CDC 當成「自動重建向量索引」的規範。
- 反例：把 `tsvector` 寫成「Postgres 的向量檢索」，或把 pgvector 寫成 CDC 外掛。
- 反例：引用已重定向的 `/search-plugins/knn/` 當現行 API。
- 反例：因演示登記了某個句向量模型，就把權重檔案或映象寫進本倉。
- 反例：因本頁出現 OpenSearch / pgvector 就寫進 recipe 或髮卡依賴。

## 邊界與易混概念

- 不包括：接入逐步實現、叢集運維、金鑰、攻擊檢索介面、盜版語料、權重映象、成品 RAG 皮膚。
- 向量檢索 ≠ 全文檢索。前者比距離，後者比詞項。
- 向量檢索 ≠ CDC。CDC 運的是變更流；最多當索引重新整理的上游，本身不定義近鄰。
- 語義檢索 ≠ 原始向量查詢。前者查詢側還要嵌入模型；後者你自己送向量。
- ANN ≠ 精確 kNN。近似換召回/延遲，不是同一種保證。
- pgvector ≠ 獨立「向量資料庫產品站」。真源在 GitHub README。
- 邏輯複製 ≠ 邏輯解碼 ≠ 事務隔離。隔離頁在 B2-Data，不在本頁。
- 站內搜尋（B2-Search）是構建後倒排或託管引擎；分面（B3-Facet）是篩選互動。都不替代嵌入近鄰。
- 瀏覽器推理（B3-ML）是端上跑模型，不是向量庫。

## 對映到本倉庫

對映放最後，不當過濾器。

[[concepts/世界書注入路徑]] 寫過：向量化匹配、Outlet、`@@activate` 以 A3 為準，**不是**三張穩定卡的主用法。那是酒館世界書啟用面，不是 OpenSearch / pgvector 執行時。卡 iframe 沒有「向量索引 + 嵌入服務」這層合同，見 [[concepts/酒館宿主與iframe分層]]。工坊目錄與包閘道器是所有權與稽核，不上向量庫，見 [[concepts/後端架構名詞與工坊對照]]。

因此：

1. **不要**把 OpenSearch kNN 或 pgvector 寫成狀態列 / 控制中心 / 世界書的執行時依賴。
2. Wiki 或獨立文件站若談語義檢索，用本頁當入口對照；**不等於**本倉已建向量索引。
3. 世界書「向量化匹配」與本頁行業向量庫不是同一條實現。
4. CDC / FTS 正文不在本頁展開；隔離與多租戶不在本頁。

本頁不寫「已採用 OpenSearch / pgvector / Debezium」。
