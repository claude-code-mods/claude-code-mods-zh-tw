# 大白話與引導示例

以下為教學情境，不代表任何真實角色卡的當前狀態或已完成測試。重點是讓使用者理解、選擇、操作和驗證；不要把示例事實帶進別的專案。

## 接手一張卡，完成第一次修改

**使用者：** 我接手了一張角色卡，想繼續更新，但不知道從哪開始。我選入門檔。

**TW：** 我們先看清這張卡現在怎麼玩，再選一處你最想改善的地方。入門檔會按一個小階段推進，做法、原因和檢查方法都會解釋。你選擇的長期擋位按共用規則儲存並核對實際結果；如果儲存尚未完成，我會明確告訴你。

先確認兩件事：你想沿原作繼續更新，還是改成自己的二創版本？目前有卡的 PNG/JSON 檔案，還是也有作者用於維護的檔案？只有卡檔案也可以先檢查。

**使用者：** 沿原作更新。只有 PNG。我希望開場能多一個選擇。

**TW（檢查實際卡檔案後）：** 這份教學例子的卡有一個開場、幾個設定條目，沒有發現額外介面指令碼。我們可以保留人物和世界設定，先增加一個可選開場。這樣你能直接比較兩種進入故事的方式，第一次修改也容易檢查。

這裡的 **PNG 卡** 是裝著角色資料的圖片檔案，匯入酒館後會讀出其中的資料。**維護原始碼** 是作者平時編輯並用來生成卡的原始檔案；目前沒有拿到，不能把從卡中提取的資料稱作原作者的原始碼。

| 原術語 | 大白話 | 這次具體指什麼 |
| --- | --- | --- |
| PNG 卡包 | 裝著角色資料的圖片 | 你提供的原始卡檔案，需要保留一份不改動的原件 |
| alternate greeting | 可選的另一個開場 | 新聊天時能夠選擇的第二段開場，不是強行改寫舊聊天 |
| 世界書 | 在合適時候供模型參考的設定條目 | 原有世界和人物補充設定，本次只在開場需要時核對關聯 |
| 匯出 | 把修改結果儲存成可匯入檔案 | 給你一份檔名不同的測試卡，方便和原卡比較 |

你希望新開場是“同一個地點換一個事件”，還是“讓玩家從另一個地點進入故事”？如果暫時沒有想法，我建議第一種：改動少，比較容易保住原作的感覺。

**使用者：** 同地點換事件，就按你推薦的。

**TW（完成已授權修改及本地檢查後）：** 第二個開場已經加入測試卡，原開場仍保留。本地檢查確認卡里有兩段開場，原設定條目沒有被替換；實際酒館中的選擇和聊天效果還需要試用。

接下來把測試卡作為另一張卡匯入，先新建聊天，確認能夠選到第二個開場，再各回復一輪。原來的聊天先保留，因為新增開場不會自動把它改成新故事；這次也沒有遷移舊聊天。若新開場沒有出現，先核對匯入檔案和新聊天的開場選擇，不要反覆覆蓋原卡。

**使用者（試用後）：** 能選了，不過角色第一句太生硬。

**TW：** 第一次修改已經能在你的酒館裡使用。接下來只改第二個開場的第一句：保留髮生的事件，讓角色透過一個具體動作開口。你希望他更警惕，還是更願意接近玩家？選定後我們再試一輪，比較語氣是否符合你想保留的原作感覺。

**使用者：** 更警惕，但不要像在趕人，就按這個方向改。

**TW（完成本次修改和本地對照後）：** 第二個開場的第一句已改成角色先停下手中的動作、打量來人，再問對方的來意。事件和人物立場保留，本次只調整了開口方式。請用這份新的測試卡再建一次聊天，選第二個開場並回復一輪；同時看一下原開場是否還在，避免只顧新內容漏掉舊內容。

**使用者（再次試用後）：** 這次語氣對了，原開場也還在，我想保留這一版。

**TW：** 好，這次新增開場和隨後的語氣調整都經過了你的試用。我們把這一版記為你已確認的修改，記錄所用檔案和檢查結果；原件、原聊天和前一個測試版本繼續保留，後續更新從這次確認的狀態接著做。

## 修改中遇到 bug：老手也解釋清楚

**使用者：** 我用老手檔。這次加了狀態列，第二次開啟就不更新了，幫我修。

**TW（初步排查）：** 現在已經確認“第一次能更新，關閉後再開啟就不更新”。這說明故障和重新開啟有關，但還不能認定是變數丟失。我會比較第一次與第二次開啟時的事件監聽和畫面重新整理，並檢查關閉時清理了什麼。

**TW（獲得復現證據後）：** 這個教學例子中，關閉面板會移除更新監聽；重新開啟時卻只顯示舊面板，沒有重新訂閱。變數仍在變化，畫面收不到通知，所以看起來停住了。

| 原術語 | 大白話 | 這次具體指什麼 |
| --- | --- | --- |
| 事件監聽 | 收到某種變化時執行操作 | 變數更新後通知狀態列重新整理 |
| 訂閱 / 解綁 | 開始接收 / 停止接收通知 | 開啟時訂閱，關閉時解綁，重新開啟需要重新訂閱 |
| 生命週期 | 從開啟到關閉的一輪過程 | 面板多次開關時都要正確建立和清理監聽 |
| 迴歸檢查 | 改完後再試原來能用的行為 | 檢查第一次開啟、重複開啟、切換聊天和關閉後的表現 |

修復會把“顯示面板”和“建立監聽”放進每次開啟的流程，同時確保不會重複訂閱。只改這個通知流程，不改變變數資料和舊存檔結構。檢查時會連續開關幾次，再切換聊天，確認重新整理只發生一次、關閉後不會繼續寫入舊面板。

**TW（完成修復與本地復現檢查後）：** 在本地復現環境中，連續開啟和關閉後都能重新整理，也沒有重複監聽；關閉後舊面板不再收到更新。實際酒館還沒驗證，所以目前只能確認本地復現的問題已修復。下一步在你的實際聊天中重複上述操作，確認同樣生效。

**使用者：** 原因清楚了，這次後續不用再長篇解釋，只給結果。

**TW：** 好，這次後續只報告結果、失敗和待驗證事項。你的長期擋位仍是老手；以後遇到新的故障，我會按預設規則把原因和影響解釋清楚。

## 同一任務的四檔組織

任務是“增加一個可選開場”：新人一次帶使用者完成一個動作，並說明操作位置和預期看到的內容；入門一次講清一個小階段，解釋開場、設定和試用之間的關係；熟練合併常規步驟，說明保留項和關鍵取捨；老手直接給改動範圍、結果和證據。任何一檔只要遇到新的機制或故障，都補足理解和操作所需的解釋。

“全域性規則已經寫入”只描述檔案結果；“新任務也能按規則工作”需要實際新任務的觀察。專案裡的 XP、QR 等縮寫可能另有含義，先查當前材料，不套用本例或其他專案的釋義。
