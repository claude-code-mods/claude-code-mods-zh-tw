# TavernWeave 外掛執行合同

本合同在 TavernWeave 作為外掛被呼叫，或任務運行於 dots 雲端、連線的本機時生效。它只決定怎樣識別宿主、選用工具、續接長任務和報告證據；具體工作仍由當前 Skill、使用者授權、專案規則及原有驗收門決定。普通本地獨立 Skill 使用不必額外進入雲端流程。

## 先認清任務實際執行位置

1. 在任務入口確認當前是 dots 雲端電腦、Codex 雲端環境、已連線的使用者電腦，還是其他本地宿主；再確認眼前實際提供的終端、Node/Python、Git、瀏覽器、應用連線和可寫工作區。雲端電腦有自己的檔案與瀏覽器，本機連線是另一條訪問路徑；僅在本機可見的 Skill 需要實際連線並被當前任務載入。只按當前可見能力行動，不憑外掛已安裝推斷某個工具、賬號或目錄可用。
2. `E:\...`、PowerShell、客戶端全域性 `AGENTS.md`/`CLAUDE.md`、本地安裝和真實 SillyTavern，都是原文所述本機條件下的步驟。雲端不能照搬本機絕對路徑；專案檔案和隨包指令碼只有在當前工作區實際存在且工具可執行時才可讀寫或執行。可用雲端終端時使用該環境支援的命令，勿把命令示例當作宿主能力證明。
3. 沒有終端或可寫工作區時，仍可依據使用者已提供的材料做文字分析、設計、審查與交接。將未執行的指令碼、構建、瀏覽器動作和檔案寫入明確標為未驗證；不聲稱已完成持久化。應用連線、登入態、許可權與瀏覽器可達性逐項核對，不能由另一臺電腦上的登入推斷。

## 使用現有許可權與資料

- 專案續接或擬寫入時，先讀當前專案已有的 `AGENTS.md`、`NEXT.md`、總設計、任務賬本或等效唯一續接指標；只讀實際存在且屬於本次工作區的檔案。已有狀態源繼續作為唯一權威，不為雲端另造第二套進度文件。缺失時用本次對話中可核對的使用者材料建立工作範圍，並如實標記尚無持久續接檔案。
- TavernWeave 隨包庫快照是公開資料。重新整理快照需要原維護流程指定的私有源、allowlist 和檢查，不能在雲端憑空重建或從不明網頁拼出缺失內容。使用者作品、私有源、憑證、聊天記錄及工作區檔案只在已授權範圍處理；不得因雲端執行而寫進公開外掛、示例或釋出包。
- 引導擋位與全域性入口偏好持久化只適用於確有對應客戶端配置、可預覽目標且已獲直接授權的本機適配流程。雲端沒有已核實的正式偏好儲存能力時，僅按使用者本任務的明確選擇引導，說明沒有儲存；不推斷、更改長期擋位，也不為了外掛首次使用寫全域性規則。
- 已授權的獨立工作繼續按原範圍推進。寫入、聯網、外部應用、付費呼叫、部署、釋出、安裝和真實宿主操作仍各守原有許可權與驗收門；外掛或雲端執行不自行擴大許可權。

## 有界長任務與恢復

1. 開始前從使用者目標和現有續接材料定下可檢查的範圍、預算或批次，以及完成、故障、預算耗盡、許可權邊界和需使用者決定時的停止條件。工作量大時按原 Skill 的樣本、批次和質量檢查繼續；不要因為預計耗時就中斷已經授權且可以獨立推進的部分。
2. 每個階段在實際可持久的專案工作區更新真實產物、來源/輸入版本、已執行的驗證、未驗證項和下一步；保留原專案的唯一續接指標。若當前只有對話可儲存，就用訊息交接並明確檔案狀態未持久化。檔案存在不等於雲端任務已載入，也不等於真實酒館、裝置或人工驗收透過。
3. 任務恢復後重讀產物與續接證據，核對源版本、未完成批次和上次外部操作的實際結果，再決定重試，避免重複寫入、傳送、付款或部署。對於無法查證的外部結果，報告不確定性並停在相應執行門。
4. dots 的雲端持續執行、任務排程與關機後可用性由平臺及當前連線條件提供；外掛本身不安裝常駐伺服器、定時器或後臺程序，也不新增收費服務。不要許諾賬戶套餐、執行時長或工具一定可用。只能按已觀察到的平臺能力報告繼續執行狀態。

交付時分別報告：原始碼或文字產物、自動檢查、雲端/瀏覽器觀察、真實 SillyTavern 或裝置驗證、人工接受、Git 與釋出狀態。一個層級的證據不能替代另一個；按原 Skill 給出下一道門。

官方依據：[OpenAI 外掛打包說明](https://developers.openai.com/plugins/build/plugins)；[dots 雲端電腦與應用連線說明](https://learn.chatgpt.com/docs/dots/computers-and-apps)。這裡的操作規則是 TavernWeave 對這些宿主邊界的實現約定，實際能力以當前任務觀察為準。
