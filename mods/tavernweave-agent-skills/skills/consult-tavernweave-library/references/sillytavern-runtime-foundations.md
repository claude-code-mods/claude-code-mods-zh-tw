# 酒館與角色卡：從一輪輸入到下一輪

這是共用的概念起點，不是第二份 API 手冊。制卡判斷、世界書首次聯合規劃或藍圖涉及酒館執行依賴時，先檢查當前上下文；已有完整理解就直接接著做，缺哪一段只讀哪一段。純文字專案不必載入後面的全部擴充套件與驗證矩陣。

## 誰負責什麼

| 參與者 | 本輪職責 | 不能由此推定 |
| --- | --- | --- |
| 酒館宿主 | 管理會話、配置、請求組織、訊息與擴充套件入口 | 宿主不是模型；各處理器的精確時序要查目標版本 |
| 角色卡容器 | 攜帶文字、開場白、關聯世界書與可選擴充套件資料 | 匯入不等於每個欄位進請求，指令碼存在不等於執行 |
| 預設 | 按所用介面配置提示組織、訊息結構和生成引數 | 排在後面或使用標籤，不會憑空取得更高許可權 |
| 世界書 | 提供按原生條件或已核驗擴充套件路徑選入的資料 | 存在、啟用、命中、處理、進入最終請求分別檢查 |
| 擴充套件 | 提供模板、狀態處理、介面等所選能力 | 不要求所有卡安裝；作用域與生命週期各有合同 |
| 模型 | 根據這一次實際收到的請求生成輸出 | 不自行讀卡檔案、完整書庫、存檔或玩家專用 UI |
| 玩家 | 輸入訊息和作選擇 | 點選或說出選擇不必然寫狀態、發訊息或觸發生成 |
| UI/渲染 | 展示資料，並連線已定義的互動動作 | 顯示不等於儲存，儲存不等於下一輪已注入 |

## 最小貫通：橋樑的純文字回合

用同一條自寫規則理解整條鏈：“橋正常開放；漲水時關閉。”不需要模板、MVU 或前端。

1. 玩家輸入“我要過橋”，當前材料另有可靠的“正在漲水”。
2. 宿主按本次配置選擇卡文字、歷史和適用世界書，組裝實際請求。檢查相關請求片段是否同時包含橋樑規則與當前水位；只有檔案裡存在規則還不夠。
3. 模型收到這些材料後生成回應。若回應說“橋已關閉”，這只是生成的文字，本身不證明任何外部狀態已改寫，也不證明規則總會被遵守。
4. 宿主及已啟用處理器分別處理輸出、儲存訊息並展示。這裡描述職責，不規定所有版本的儲存、處理和顯示先後。玩家看到的 HTML 可能不同於儲存文字，也可能不同於發給模型的文字。
5. 下一輪玩家問“等水退了再過呢？”宿主根據新輸入、選中歷史、配置和可用狀態重新組裝。重新檢查橋樑規則、水位與前一輪相關事實是否仍在實際請求中，不能用螢幕上的上一段回應代替證據。

教學或驗收保留六樣東西即可：輸入、選中資料、本輪請求相關片段、輸出、儲存/展示結果、下一輪請求相關片段。實際執行的記錄與邊界用 [E07 隔離觀察](../../sillytavern-runtime-debug/references/worldbook-isolated-runtime-checks.md)；未捕獲請求時標“執行待驗證”。

## 只在需要時接入

- **模板**：在已核驗入口讀取材料或狀態，按條件輸出或顯式讀取條目，再進入目標請求。條件為真但入口沒到，仍不會輸出；模板顯示成功也不證明模型收到。精確入口、作用域、讀取行為由 [E03 版本核驗](../../sillytavern-api-reference/references/worldbook-version-verification.md)負責。
- **MVU/結構化狀態**：初始化與 schema 先確定可用狀態；本輪讀取並按需投影；模型按所選協議提出更新補丁；處理器解析、校驗、成功回寫；UI 和下一輪再讀正確作用域。補丁是提議，回寫證據才是更新；schema 的結構約束不自動替代玩法結算，也不保證所有值會被夾緊或修復。精確規則仍在 [變數合同](../../tavern-card-builder/references/variable-systems.md)和[狀態消費者合同](../../sillytavern-database-rolecards/references/worldbook-target-state-contract.md)。
- **UI**：按鈕可能只切頁面、寫狀態、傳送聊天訊息，也可能組合；逐項說明動作、寫入者、持久化、是否生成以及模型可見路徑。實現歸 [embedded-ui](../../sillytavern-embedded-ui/SKILL.md)，這裡只接回資料鏈，不另增 UI 文案案例。

[text / mvu_zod / hybrid](../../tavern-card-builder/references/card-types-and-runtime-dependencies.md) 是整卡執行型別，與原生、模板、區域性混合世界書不是同一分類。文字和歷史已夠用，就停在最小回合。

## 重生成、swipe、編輯與回退

同一訊息可以有不同候選；重生成、切換 swipe、編輯歷史、回退到早期分支可能改變材料與狀態來源。按專案實際支援的操作檢查：

- 當前會話、訊息與選中候選是什麼；狀態屬於訊息、會話還是另一明確作用域？
- 舊補丁是否會重複結算；誰負責重算、恢復或拒絕不支援的操作？
- 操作後的持久狀態、UI 與下一輪請求是否指向同一有效分支？

保留操作前後狀態、選中候選標識與下一輪相關請求片段。不承諾所有擴充套件自動回滾、重算或隔離 swipe；不支援時寫清限制和安全路徑。沿用 E07 的適用行，不另建一套測試工程。
