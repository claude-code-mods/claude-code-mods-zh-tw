## 1. 執行層與總體架構

### 1.1 四種容易混叫“外掛”的東西

| 執行層 | 載體 | 負責 | 本冊 |
|---|---|---|---:|
| ST UI Extension | 瀏覽器宿主擴充套件 | manifest、設定、事件、prompt、宿主 UI | 否，D5 |
| ST Server Plugin | Node.js 服務端 | 路由、檔案系統、服務端能力 | 否，D5 |
| TH 卡內指令碼 | `about:srcdoc` iframe / ScriptTree | 隨卡指令碼、Wand、世界書橋、卡內執行時 | 是 |
| 創意工坊 | 卡內客戶端 + Gateway + 儲存 | 內容瀏覽、預覽、安裝、釋出、稽核、撤回 | 是 |

四層 API 不可互換：

- `SillyTavern.getContext()` 是 UI Extension 宿主入口；
- `eventOn/getButtonEvent/getScriptTrees/updateWorldbookWith` 是當前 TH iframe 全域性函式；
- Gateway HTTP API 只提供包和釋出產品鏈，不可獲得本地世界書寫許可權；
- 卡內 bridge 把使用者已確認的有限動作從工坊 iframe交給 TH 指令碼執行。

### 1.2 工坊三方雲端 + 卡內客戶端

```text
GitHub Pages
  schemas / examples / read-only index / fixed runtime
             ↓
卡內 TH 啟動器 → 宿主模態框 → 工坊 iframe
             ↕             ↕
Worldbook Bridge       Workshop Gateway
             ↓             ↓
聊天世界書          釋出/稽核/owner/revision
                           ↓
                     Cloudreve 包/媒體
```

- GitHub Pages：只讀機器契約和靜態基線；
- Gateway：動態包索引、稽核狀態、publisher ownership、revision 和撤回；
- Cloudreve：公開 JSON 包與可選媒體；
- TH 卡內指令碼：唯一擁有本地世界書寫入能力的一側；
- 工坊包：內容資料，不是任意指令碼、prompt patch 或 MVU patch。

### 1.3 核心鐵律

工坊匯入只寫受控聊天世界書條目，例如 `[世界因子]當前設定`、`[創意工坊][型別]標題`；**絕不直接修改 MVU 存檔變數**。Zod/MVU 核心、開局主流程、prompt patch 和宿主主題留在卡內受信版本，不從通用遠端包熱替換。

## 2. Tavern Helper 當前指令碼樹契約

### 2.1 ScriptTree 型別

本地 2026-05-08 型別快照與生產卡使用陣列樹結構：

```typescript
type ScriptButton = {
  name: string;
  visible: boolean;
};

type Script = {
  type: 'script';
  enabled: boolean;
  name: string;
  id: string;
  content: string;
  info: string;
  button: {
    enabled: boolean;
    buttons: ScriptButton[];
  };
  data: Record<string, unknown>;
  export_with: {
    data: boolean;
    button: boolean;
  };
};

type ScriptFolder = {
  type: 'folder';
  enabled: boolean;
  name: string;
  id: string;
  icon: string;
  color: string;
  scripts: Script[];
};

type ScriptTree = Script | ScriptFolder;
```

規則：

- `id` 是機器穩定標識；`name` 是可變顯示名；
- 一個指令碼可有多個 `button.buttons[]`；
- 陣列順序就是顯示/執行樹順序；
- `export_with.data` 與 `export_with.button` 分別控制匯出；
- 資料夾內仍要遞迴處理指令碼，不能只掃頂層；
- 寫回保留未知欄位，避免舊/新版本擴充套件欄位被刪。

舊式 scripts 鍵值物件、`displayName`、`button:true`、`export_with:true` 只作為歷史遷移輸入，不再是當前正規化。

### 2.2 管理 API 必須帶作用域

```javascript
const scope = { type: 'character' };

const trees = getScriptTrees(scope);

replaceScriptTrees(nextTrees, scope);

const updated = await updateScriptTreesWith(async (currentTrees) => {
  return migrateOrPatchTrees(currentTrees);
}, scope);
```

當前 `type` 可為 `global | preset | character`。示例操作角色卡指令碼，必須顯式 `{type:'character'}`；無參呼叫或把 scope 寫成 `chat` 都不符合當前型別契約。

### 2.3 歷史格式遷移

```text
read raw scripts
→ detect object vs ScriptTree[]
→ backup original
→ assign stable ids
→ displayName → name
→ button:true → button.enabled + buttons[]
→ export_with:true → {data:true,button:true}
→ preserve order/content/data/unknown fields
→ validate tree
→ replace once with {type:'character'}
→ reread and compare
```

重名顯示名不能當 ID。遷移產生 ID 時需要穩定對映和衝突報告，不能每次匯入重新隨機生成導致升級找不到原指令碼。

## 3. 卡內指令碼初始化、API 與解除安裝

### 3.1 初始化與單例

卡內 iframe 可能在宿主頁面 ready 後才建立，不只依賴一次性 `DOMContentLoaded`。按當前 TH 指南使用 `$(() => init())` 或目標版本推薦的就緒方式。

```javascript
const RUNTIME_KEY = '__MY_WORKSHOP_RUNTIME__';
window[RUNTIME_KEY]?.destroy?.();
window[RUNTIME_KEY] = createWorkshopRuntime();

window.addEventListener('pagehide', () => {
  window[RUNTIME_KEY]?.destroy?.();
}, { once: true });
```

新例項必須先銷燬舊例項，防熱過載後重覆按鈕、重複 message listener 和重複世界書寫入。

### 3.2 宿主視窗定位

```javascript
function hostWindow() {
  try {
    if (window.parent && window.parent !== window && window.parent.document) {
      return window.parent;
    }
  } catch (_error) {}
  return window;
}

function hostDocument() {
  return hostWindow().document || document;
}
```

多層巢狀可按能力評分，但必須明確來源：有 ST DOM、目標 TH API、URL 不是 `about:srcdoc`。不要在迴圈中吞掉所有異常後靜默選錯視窗。

### 3.3 事件與提示詞

```javascript
const subscription = eventOn(tavern_events.CHAT_CHANGED, () => {
  resetChatContext();
});
disposers.push(() => subscription.stop());

injectPrompts([{
  id: 'my-workshop-note',
  position: 'in_chat',
  depth: 0,
  role: 'system',
  content: '...',
  should_scan: false,
}], { once: true });
```

當前型別中 `eventOn` 返回 `{stop()}`；`injectPrompts` 第二引數精確為 `{once?:boolean}`。TH `injectPrompts` 與 ST UI Extension 的 `setExtensionPrompt` 引數結構不同，不能互換。

### 3.4 Worldbook 是當前推薦 API

當前型別方向：Worldbook API 推薦；`getLorebookEntries/...` 是 deprecated 相容層。

| API | 當前簽名要點 | 返回 |
|---|---|---|
| `getCharWorldbookNames('current')` | 引數必填，返回 primary/additional | `CharWorldbooks` |
| `getChatWorldbookName('current')` | 引數必填 | `string|null` |
| `getOrCreateChatWorldbook('current', name?)` | 獲取/建立聊天世界書 | `Promise<string>` |
| `getWorldbook(name)` | 條目是陣列，不是鍵值物件 | `Promise<WorldbookEntry[]>` |
| `updateWorldbookWith(name, updater, options?)` | updater 收/返陣列 | 更新後的陣列 |
| `createWorldbookEntries(name, entries, options?)` | 批次建立 | `{worldbook,new_entries}` |
| `deleteWorldbookEntries(name, predicate, options?)` | 第二引數是 predicate，不是 UID 陣列 | `{worldbook,deleted_entries}` |

`updateWorldbookWith/replaceWorldbook/createWorldbookEntries/deleteWorldbookEntries` 的 `render` 為 `'debounced' | 'immediate'`；預設用效能更好的 debounced，使用者正在檢視且需要同步反饋時再 immediate。

按 UID 更新：

```javascript
const updated = await updateWorldbookWith(targetWorldbook, (entries) => {
  const index = entries.findIndex((entry) => entry.uid === targetUid);
  if (index < 0) throw new Error(`entry not found: ${targetUid}`);
  const next = entries.map((entry) => ({ ...entry }));
  next[index] = { ...next[index], content: newContent };
  return next;
}, { render: 'debounced' });
```

刪除：

```javascript
const result = await deleteWorldbookEntries(
  targetWorldbook,
  (entry) => ownedUids.has(entry.uid),
  { render: 'immediate' },
);
```

UID 只在單個世界書內部有效；跨世界書不能複用。按 `entries[targetKey]` 訪問會把 UID/字串誤當陣列下標，禁止作為更新正規化。

### 3.5 跨指令碼全域性與完整清理

`initializeGlobal(name, api)` 會寫入 window 並觸發 `global_${name}_initialized`；`waitGlobalInitialized` 可等待。銷燬時要撤銷：

- `eventOn` subscription；
- 父/當前 window 的 `message`、click、keydown；
- timer、rAF、observer；
- popup、iframe、宿主 DOM/style；
- AbortController；
- prompt 注入；
- 全域性 API 引用；
- 未完成的 bridge request。

TH 只會清理自己管理的 iframe 生命週期資源；掛到父視窗的監聽仍由指令碼負責。

## 4. 魔棒與功能入口

### 4.1 TH 原生按鈕（優先）

元資料：

```json
{
  "button": {
    "enabled": true,
    "buttons": [
      { "name": "開啟創意工坊", "visible": true }
    ]
  }
}
```

監聽：

```javascript
const buttonName = '開啟創意工坊';
const eventName = getButtonEvent(buttonName);
const subscription = eventOn(eventName, () => openWorkshop());
disposers.push(() => subscription.stop());
```

`getButtonEvent()` 匹配 `button.buttons[].name`，不是指令碼 `name`，更不是歷史 `displayName`。一個指令碼可以註冊多個按鈕。

### 4.2 直接掛載 ST 魔棒選單（版本敏感）

卡A生產元件還會尋找 `#extensionsMenu`、`.extensionsMenu`，最後回退 `document.body`。這條路線依賴 ST 私有 DOM，不是穩定公共 API；必須：

- 用穩定容器/按鈕 ID 防重複；
- 點選只路由到統一 command registry；
- CHAT_CHANGED/宿主重繪後重掛；
- destroy 刪除節點和 listener；
- 目標 ST 版本複核選擇器；
- TH 原生按鈕或頁面按鈕作為可恢復入口。

不要在 E5 複製控制中心業務程式碼。控制中心案例見 C2，懸浮球/輪盤/命令登錄檔見 C11。

## 5. 創意工坊 Bridge 協議

### 5.1 能力動作

當前生產架構可抽象為：

```text
handshake
getContext
getEntries
createWorldbook
createEntries
updateEntry
deleteEntries
upsertWorkshopEntries
```

Bridge 只暴露有限動作，不把宿主 window 或任意函式交給 iframe。

### 5.2 請求/響應包絡

```javascript
// request
{
  protocol: 1,
  requestId: crypto.randomUUID(),
  action: 'getEntries',
  payload: { worldbookName: '...' }
}

// response
{
  protocol: 1,
  requestId: 'same-id',
  ok: true,
  result: {},
  error: null
}
```

強制要求：

- 固定雙向 origin allowlist；
- `event.source === expectedIframe.contentWindow`；
- 禁止 `postMessage('*')`；
- requestId 配對、超時、一次性 resolve；
- action/payload/result schema 校驗；
- handshake 交換協議版本和能力；
- 未識別 action 明確拒絕；
- iframe 過載/銷燬時 reject 舊 pending 請求；
- OAuth 登入 URL 固定 origin/path，禁止任意跳轉。

### 5.3 最小 Context

工坊 iframe 通常只需：

- cardScope/作品 ID；
- 非敏感當前聊天標識；
- 目標世界書名與可用能力；
- 已安裝來源摘要；
- 客戶端協議/執行時版本。

不預設傳送完整聊天、所有世界書、宿主物件、Cookie、API key 或 Gateway token。

## 6. 工坊包契約與內容邊界

### 6.1 機器契約優先

`rolecard-diy-workshop/schemas/workshop-package.schema.json` 與 `shared/workshop-package-contract.js` 是包結構真相源。文件示例只幫助理解，不覆蓋 schema。

```json
{
  "packageVersion": "1.0.0",
  "id": "publisher.package-id",
  "type": "world_factor",
  "cardScope": "xingyue",
  "title": "示例世界因子",
  "revision": 3,
  "contentHash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "reviewStatus": "approved",
  "payload": {
    "worldFactors": [
      {
        "title": "示例世界因子",
        "content": "示例內容"
      }
    ]
  }
}
```

`contentHash` 是 Gateway 管理的整包欄位，格式為 **64 位小寫十六進位制**，不帶 `sha256:` 字首。客戶端不應讓釋出者手填並信任它。

### 6.2 內容白名單

當前允許：

- `character`
- `user_identity`
- `world_factor`
- `shop_item`
- `blueprint`
- `recipe`
- `skill`
- `function`

拒絕：

- `opening_pack`
- `prompt_patch`
- `ui_theme`

這些拒絕型別會繞過卡內受信開局、提示詞或全域性主題主鏈，影響範圍遠大於普通世界書內容。禁止換型別名後塞入 payload。

### 6.3 開局內容的現有合法路線

`opening_pack` 仍是拒絕型別；當前機器契約已經為開局內容定義了更窄的合法路線：

```json
{
  "packageVersion": "1.0.0",
  "id": "publisher.opening-example",
  "type": "world_factor",
  "cardScope": "xingyue-opening-v1",
  "title": "開學日示例",
  "revision": 1,
  "contentHash": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "reviewStatus": "approved",
  "payload": {
    "target": "xingyue.opening_day_body",
    "schemaVersion": 1,
    "compatibility": {
      "minRuntimeVersion": "3.4.9"
    },
    "gradeScope": ["all"],
    "worldFactors": [
      {
        "title": "開學日示例",
        "content": "受約束的開局正文"
      }
    ]
  }
}
```

硬邊界：

- `type` 必須是 `world_factor`，`cardScope` 必須是 `xingyue-opening-v1`；
- `target` 固定為 `xingyue.opening_day_body`，`schemaVersion` 固定為 `1`；
- `worldFactors` 恰好一項，條目標題必須與包標題一致；
- `gradeScope` 按 schema 列舉校驗；含 `all` 時不能再混入其他年級；
- `compatibility.minRuntimeVersion` 與正文宏都按當前 contract 校驗。

客戶端必須把四個動作拆開：

1. **詳情預覽**：只讀校驗 schema、相容性、信任級別和 diff；零寫入。
2. **本地匯入草稿**：當前卡A 3.4.9 會立即寫入開局草稿的 `packages/worldFactors`，並預設關閉該包；它屬於未稽核開發輸入，不等於安裝了可信來源。
3. **安裝為來源**：開局包必須來自帶有效正整數 `revision` 的可信工坊詳情；寫成預設停用的單個世界書來源，保留來源元資料，但不改當前 `openingDay` 正文。
4. **應用到當前草稿**：先確認來源已安裝、未被本地修改，且詳情 revision 與已安裝 revision、實際 hash、記錄 hash、預期 hash 全部一致；再校驗聊天上下文、年級範圍和正文宏並展示 diff。使用者再次確認後才寫當前開局草稿，仍不傳送訊息、不修改 MVU。真正開始遊玩繼續走 C10 的確認傳送鏈。

上面的 JSON 是 **Gateway approved 詳情形狀**。若去掉 Gateway 管理欄位，它仍可作為本地匯入草稿透過 schema，但不能安裝為開局來源。

因此，“支援開局內容”不等於允許工坊包直接插入聊天或替換首樓。

### 6.4 安裝前校驗

- packageVersion；
- id/type/cardScope；
- runtime/協議範圍；
- payload schema 與大小；
- 來源身份與信任級別；
- Gateway approved 包的 revision、contentHash 與 reviewStatus；
- revision 與重複安裝；
- 目標世界書能力和使用者授權。

來源必須分流處理：

- **Gateway approved 包**：必須有正整數 `revision`、Gateway 生成的 64 位 `contentHash`，且 `reviewStatus === 'approved'`；三者參與遠端更新身份與衝突檢查。
- **本地 JSON**：schema 允許省略上述 Gateway 管理欄位；即使檔案內自帶這些欄位，也不能據此信任。客戶端須標記為 detached / untrusted / development，不能宣稱 owner 身份、approved 狀態或遠端自動更新關係。

## 7. 預覽與帶條件補償的安裝事務

### 7.1 預覽零寫入

```text
選擇包
→ 拉取詳情/payload
→ schema/cardScope/version/hash 校驗
→ 讀取當前世界書和安裝清單
→ 計算 create/update/conflict/unchanged/remove
→ 展示 diff、來源和許可權
→ 使用者確認
```

預覽不建立世界書、不改 Persona、不寫 MVU、不插訊息。世界書不存在時只顯示“確認後將建立”。

這裡的“預覽”專指只讀詳情/diff 路徑；呼叫卡A 3.4.9 的 `importPackageToDraft()` 已經會寫開局草稿，不能把該函式命名中的 import 當成零寫入預覽。

### 7.2 Diff 分類

| 分類 | 條件 | 預設動作 |
|---|---|---|
| create | 本地無相同 packageIdentity | 新建一條包條目 |
| unchanged | revision 與條目基線一致 | 跳過 |
| update-safe | 當前本地仍等於 installedEntryHash | 更新 |
| modified-local | 玩家已改條目 | 衝突，人工選擇 |
| collision | 名稱相同、來源不同 | 不覆蓋，改名/選目標 |
| remove | 使用者明確解除安裝該 packageIdentity | 先保留使用者副本，再移除受管條目 |

名稱不是穩定所有權；包級 hash 也不能判斷某一個條目是否被玩家修改。

卡A 3.4.9 的生產模型是 **一包一條世界書條目**：`worldFactors[]` 等 payload 內容先由 `packageToWorldbookText(pkg)` 合成為單條正文。穩定身份 `packageIdentity` 是三元組：

```text
packageId + packageType + packageTarget
```

其中 `packageTarget = payload.target || packageTarget || type`。當前 v1 schema 的內容項沒有 `slot` 或穩定 item id；不得讀取 `item.slot`，也不得按 `worldFactors[]` 下標建立多條受管世界書條目。陣列插入、刪除或重排只會改變這一包合成後的預期正文 hash，再按整條 entry 做安全升級判斷。

### 7.3 兩類 hash、穩定身份與條目元資料

必須分開：

- `packageContentHash`：整個遠端包的 Gateway hash，用於確認拿到的遠端詳情；
- `installedEntryHash`：當前生產程式碼中的 `entry.extra.contentHash`，是安裝後世界書正文的 hash，不等於 Gateway 整包 hash；
- `expectedEntryHash`：把新包透過同一 `packageToWorldbookText()` / canonical 規則轉換後得到的預期正文 hash；
- `packageId + packageType + packageTarget + revision`：受管來源身份與版本；
- `uid`：當前世界書中的實際條目 UID。

卡A 3.4.9 由示例工坊私有適配層把安裝清單寫進單條世界書 entry 的 `extra` 欄位（TH `WorldbookEntry` 只有 `extra`、沒有 `meta`，`@types.txt:2906`；後文 `meta.*` 即指這份安裝清單物件，與 C2 的 `extra` 用法一致）：

```javascript
entry.extra = {
  source: 'xingyue-workshop',
  kind: 'workshop_package',
  packageId: pkg.id,
  packageType: pkg.type,
  packageTarget: pkg.payload?.target || pkg.packageTarget || pkg.type,
  programOnly: pkg.payload?.target === 'xingyue.opening_day_body',
  revision: pkg.revision,
  contentHash: hashWorldbookContent(entry.content),
  installedAt: new Date().toISOString(),
};
```

`uid` 保留在 entry 本體。條目 hash 必須使用穩定正文/canonical 規則，並排除 `installedAt` 等每次變化的診斷欄位。Gateway `packageContentHash` 可另存於來源/草稿記錄，但不能冒充 `entry.extra.contentHash`。

### 7.4 世界書 API 只有更新回撥，不提供跨系統原子事務

本冊所說“事務”是 **帶條件補償的應用層事務**：

```javascript
const previewSnapshot = await getWorldbook(target);
const previewPlan = buildPreviewPlan(previewSnapshot, pkg, installManifest);

const written = await updateWorldbookWith(target, (latestEntries) => {
  // 併發視窗收口：按 latestEntries 重新核對 packageIdentity/UID/installedEntryHash。
  const checkedPlan = revalidatePlan(previewPlan, latestEntries);
  if (checkedPlan.conflicts.length) throw new Error('worldbook changed since preview');
  return applyPlan(latestEntries, checkedPlan);
}, { render: 'debounced' });

assertWrittenState(written, previewPlan.expectedWrites);
```

原則：

1. 預覽快照只用於展示，真正 updater 內必須對當前陣列重驗；
2. updater 返回完整陣列；
3. 寫後重讀/返回值校驗；
4. 同一 packageIdentity 的舊 revision 拒絕；同 revision 但預期 hash 不同也拒絕；
5. 雙擊/網路重試不能建立第二套條目；
6. 回滾只在目標仍等於“本事務剛寫入的 entry hash”時執行；
7. 併發修改或不可逆步驟出現時停止，展示部分提交 diff，不用舊整本世界書覆蓋。

跨 Persona、世界書、Gateway 和聊天的操作沒有原生原子性。不可逆動作最後執行，每一步記錄結果和補償條件。

## 8. 來源所有權、升級、解除安裝與遷移

### 8.1 條目來源元資料

使用 7.3 的當前生產形狀：`source/kind/packageId/packageType/packageTarget/programOnly/revision/contentHash/installedAt`。匹配受管條目時同時要求：

```text
meta.source === 'xingyue-workshop'
meta.kind === 'workshop_package'
packageId、packageType、packageTarget 三者全部相等
```

顯示名、comment 和 payload 內陣列位置都不能證明所有權。先生成合並後的世界書正文並求 `installedEntryHash`，再加入時間戳等診斷欄位，避免自引用和每次 hash 改變。

### 8.2 安全升級是三方比較

```text
條目 meta 中記錄的 installedEntryHash
vs 當前本地 canonical entry hash
vs 新包轉換後的 expectedEntryHash
```

- 當前仍等於安裝基線：可自動更新；
- 當前正文或行為已改：顯示“覆蓋 / 保留當前 / 脫離為使用者副本”；
- `incomingRevision < installedRevision`：拒絕回滾；
- revision 相同但新包預期 hash 與已記錄來源不一致：拒絕並要求重新整理詳情；
- packageContentHash 只證明包，不證明某條本地內容未改。

### 8.3 安全解除安裝

刪除必須同時滿足：

1. 明確 `packageId + packageType + packageTarget`；
2. entry meta 能對應 UID/基線；
3. 當前條目仍等於 installedEntryHash，或使用者明確確認刪除修改版；
4. updater 內再次核對；
5. 刪除後重讀驗證；
6. 失敗補償不覆蓋併發修改。

卡A 3.4.9 解除安裝前會先生成 detached 使用者副本，再移除受管條目；若開局草稿仍記錄該來源，則僅移除來源繫結，保留當前開局正文。雲端包 withdrawn 不會遠端刪除玩家已安裝內容。

### 8.4 歷史 `🧩mod ` 字首

字首只能作為舊條目候選，不能證明所有權。遷移時透過已知包、內容與 `packageId/type/target` 高置信匹配並讓使用者確認，再補 source metadata；不得批次刪除所有同字首條目。

## 9. 釋出、稽核、owner 與撤回鏈

### 9.1 產品狀態

```text
本地草稿
→ 登入 + Discord 伺服器成員校驗
→ POST 釋出（pending）
→ 管理員稽核
   ├─ approved → 進入公開索引
   └─ rejected → owner 可見原因並修訂
→ owner PUT 更新（revision 保護）
→ owner DELETE 撤回（withdrawn）
```

未登入仍可瀏覽 approved 公開索引、匯入/匯出本地 JSON；釋出、更新、撤回才要求登入。

### 9.2 Gateway 契約摘要

| 路徑 | 用途 |
|---|---|
| `GET /api/workshop/health` | 健康檢查 |
| `GET /api/workshop/packages` | approved 公開索引與過濾 |
| `GET /api/workshop/packages/:id` | 包詳情，保留 payload |
| `GET /api/workshop/me` | publisher 登入/成員狀態 |
| `GET /api/workshop/me/packages` | owner 的全部發布和稽核狀態 |
| `POST /api/workshop/packages` | 新發布，預設 pending |
| `PUT /api/workshop/packages/:id` | owner 更新，帶 revision 防併發 |
| `DELETE /api/workshop/packages/:id` | owner 撤回，移出公開索引 |
| `/api/admin/review/...` | 管理員稽核佇列/決定 |

舊 revision 更新應返回 `409 package-conflict`。客戶端重新整理遠端詳情並重新比較，不能最後寫入者靜默覆蓋。

### 9.3 撤回語義

- 從公開索引移除；
- 保留最小 ownership/稽核記錄；
- owner UI 顯示 withdrawn；
- 不刪除玩家本地世界書；
- 恢復/再發布按 Gateway 契約，不由客戶端猜。

## 10. 安全、鑑權與隱私

### 10.1 Bridge 與 CORS

- 生產 Gateway 配置固定 CORS allowlist；預設 `*` 只能視為未收口風險，不是生產安全配置；
- iframe 雙向驗證 origin + source；
- 禁止 `postMessage('*')`；
- payload、包大小、schema、type、cardScope、hash 全校驗；
- OAuth 登入 URL 固定 origin/path；
- 工坊 iframe 不獲得任意 Worldbook updater 或宿主 window。

### 10.2 Bearer token

當前 Gateway 使用無狀態 HMAC Bearer token，卡內客戶端儲存在 localStorage 並隨鑑權請求傳送。必須明確：

- localStorage 不是安全金鑰庫，同源 UI Extension/TH 指令碼可讀；
- token 不進入角色卡匯出、聊天、世界書、指令碼 `data`、錯誤報告或日誌；
- 前端不把 token postMessage 給非固定工坊 origin；
- 文件說明 TTL、過期、退出清除、SESSION_SECRET 輪換和服務端撤銷邊界；
- XSS/惡意同源擴充套件可能竊取 token，不能用“在 iframe/localStorage”宣稱隔離；
- 認證失敗要回到未登入瀏覽態，不無限重試。

### 10.3 隱私表述要收窄

publisher 身份登錄檔長期持久化只保留 salted Discord hash、生成的 publisherId，以及最小 provider/createdAt/lastLoginAt；不存郵箱、暱稱、頭像、原始 Discord ID、IP 或行為畫像。

Gateway 業務上仍會存包、稽核狀態、revision、拒絕原因、撤回/最小審計等資料，因此不能籠統寫“Gateway 只存 publisherId/hash”。不同表的資料保留和刪除策略要分別說明。

### 10.4 生產指令碼不能直接當安全正規化

`參考案例/4.2_1.components/tavern_helper_scripts/05_創意工坊.js` 可證明架構與 API 可行，但當前審計發現：

- 世界書 bridge 已有 origin 檢查，可保留思路；
- Discord auth listener 缺完整 origin/source 校驗；
- 認證轉發存在 `postMessage('*')`；
- 登入 URL 需要固定 allowlist；
- `removePanel()` 未完整登出 message/TH button listener；
- 工坊主鏈被無關 MVU 等待阻斷。

新實現必須修正，不能因為“生產在用”就原樣複製。

## 11. 高頻錯誤與版本敏感項

| 錯誤 | 後果 | 正確方向 |
|---|---|---|
| 把 E5 寫成第二份外掛教程 | 與 D5 漂移 | ST 外掛統一轉 D5 |
| 舊 scripts 物件當主格式 | 當前 TH 無法按契約管理 | `ScriptTree[]` + scope |
| `getButtonEvent(scriptName)` | 按鈕無響應 | 傳 `button.buttons[].name` |
| 把 Worldbook 稱舊 API | 新舊方向反了 | Worldbook 推薦，Lorebook deprecated |
| `entries[targetKey]` | 把 UID/字串當陣列下標 | `find/findIndex` + uid/packageIdentity |
| `deleteWorldbookEntries(name, ids)` | 引數型別錯誤 | predicate |
| 包級 hash 判斷條目未改 | 誤覆蓋玩家修改 | installedEntryHash |
| 預覽計劃直接寫舊快照 | 併發覆蓋 | updater 內重驗 latestEntries |
| 回滾整本世界書 | 覆蓋併發/使用者內容 | 僅補償本事務剛寫入且未變化的條目 |
| iframe 當安全沙盒 | 過度授權 | 最小 bridge + 主動程式碼審查 |
| `postMessage('*')` | token/動作洩漏 | 固定 origin + source |
| token 進指令碼 data/世界書 | 隨卡/存檔洩露 | 僅受控 localStorage，明確同源風險 |
| 工坊硬等 MVU | 無關依賴導致入口失效 | 最低能力依賴 |
| `🧩mod ` 字首批次刪除 | 誤刪使用者條目 | 只作遷移候選 |
| withdrawn 自動遠刪本地 | 破壞玩家存檔 | 只移除公開索引 |

版本敏感項：

- TH 當前上游版本與 `minimum_client_version`；
- ScriptTree 和 Worldbook 型別；
- `#extensionsMenu/.extensionsMenu` 私有 DOM；
- `tavern_events` 常量與 payload；
- Gateway package schema、API 和 CORS；
- OAuth/token TTL/交接協議；
- ST/TH iframe 同源與 CSP 行為。

施工記錄“目標版本/commit、能力檢測、核驗日期和降級路徑”，不寫“最新版通用”。
