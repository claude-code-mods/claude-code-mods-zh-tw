## 〈置信度分級體系〉

每條結論採用 **置信度等級 + 依據型別** 雙軸標註。

**收集日期統一宣告**：本手冊全部條目收集於 **2026-06-28**。回源核實基於本地 SillyTavern **v1.14.0** + 本地成熟卡（卡A 2.5.0 / 卡B 2.6.0）生產原始碼；線上文件來源均為 docs.sillytavern.app 與 deepwiki.com 原始頁面（具體 URL 見末尾「來源彙總」）。

### 置信度三級

| 級別 | 含義 | 判定標準 |
|------|------|----------|
| **high** | 已坐實，可直接施工 | 有執行時證據（真機實測 / 讀到執行時實現原始碼 / 生產卡驗證）；非 beta 未合併特性；結論不含跨步推導；不在懸案清單 |
| **medium** | 待驗證，施工前須實測 | 強制二選一子標籤：`medium·單源孤證`（單一來源、無第二源、無實測）/ `medium·推導未驗證`（邏輯推導成立但未跑通，須隨附真機驗證路徑） |
| **low** | 孤證無源，禁止據此施工 | 零來源猜測 / 純歷史快照（須標年份 + 窄縮適用範圍） |

### 依據型別標籤（與置信度正交，強制標註）

`[執行時原始碼]` `[真機]` `[文件·多源]` `[文件·單源]` `[社群]` `[推斷]`

### 兩條鐵規

1. **僅由 `[推斷]` 支撐的「執行時行為 / 可用性」結論，最高只能 `medium·推導未驗證`**——除非另有 `[執行時原始碼]` 或 `[真機]` 佐證才升 high。
2. **節級標註 = 節內條目下確界**——禁止整節標 high 卻內含懸案條目；衝突即拆節。

## 1 TTS（文字轉語音）系統

### 1.1 機制總覽與雙佇列架構

**核心結論**

ST 的 TTS 系統採用**提供商外掛化架構**：中央 TTS Manager 負責文字解析、佇列管理、播放控制，各 Provider 實現統一介面對接不同語音引擎。

**雙佇列機制：**

| 佇列 | 作用 |
|------|------|
| `ttsJobQueue` | 等待語音合成的文字訊息佇列 |
| `audioJobQueue` | 已完成合成、等待播放的音訊 blob 佇列 |

兩佇列序列處理：`文字 → 語音合成 → audioJobQueue → 播放`

來源：[執行時原始碼] | 適用版本：ST v1.14.0+ | 置信度：**high**

### 1.3 Provider 介面規範與 Manager 公開函式

**核心結論**

每個 Provider 必須實現的介面：

| 方法 | 簽名 | 說明 |
|------|------|------|
| `loadSettings` | `(settings) => void` | 初始化 Provider 設定 |
| `fetchTtsVoiceObjects` | `() => Promise<VoiceObject[]>` | 獲取可用語音列表 |
| `generateTts` | `(text, voiceId) => Promise<Response>` | 生成 TTS 音訊，返回 HTTP Response |
| `processText` | `(text) => string`（可選） | 文字預處理/清洗 |

TTS Manager 公開函式：

| 函式 | 用途 |
|------|------|
| `registerTtsProvider()` | 註冊自定義 TTS 提供商 |
| `playFullConversation()` | 播放整個對話歷史 |
| `tts_preview()` | 預覽單個語音樣本 |
| `getPreviewString()` | 獲取語言特定預覽文字 |

Voice Map 結構：

```javascript
voiceMap = {
  "CharacterName": "voiceId",          // 正常對映
  "CharacterName": "[Default Voice]",  // 使用預設語音
  "CharacterName": "disabled"          // 停用該角色 TTS
}
```

來源：[執行時原始碼] | 適用版本：ST v1.14.0+ | 置信度：**high**

**避坑**：Voice Map 必須配置，否則 TTS 不知道用哪個語音。`[Default Voice]` 和 `disabled` 是兩個特殊標記值，不可寫錯。

### 1.4 TTS 事件系統

**【降級：high → low·孤證無源】校準說明**：本地 v1.14.0 執行時原始碼（`public/scripts/extensions/tts/index.js`）全文 grep 未找到 `TTS_JOB_STARTED`、`TTS_AUDIO_READY`、`TTS_JOB_COMPLETE` 任何一個事件型別定義；同文件也不在 `event_types` 上註冊這三個名稱。草稿標註"ST v1.17.0+ 新增"但手冊適用範圍宣告為 v1.14.0+，屬於超版本宣告且無來源佐證。本節全部內容降為 low，禁止據此施工。

**⚠️ 待核實：** 若需在更新版本（v1.17.0+）使用 TTS 事件，須讀取對應版本 `extensions/tts/index.js` 實際 `event_types` 列舉或查官方 changelog 確認。

v1.14.0 TTS 擴充套件實際監聽的事件（執行時原始碼確認）：
- `event_types.MESSAGE_SWIPED` → 重置 TTS 播放
- `event_types.CHAT_CHANGED` → 切換聊天
- `event_types.MESSAGE_DELETED` → 訊息刪除
- `event_types.GROUP_UPDATED` → 群組更新
- `event_types.GENERATION_STARTED` / `GENERATION_ENDED` → 生成開始/結束
- `event_types.CHARACTER_MESSAGE_RENDERED` / `USER_MESSAGE_RENDERED` → 訊息渲染後觸發 TTS

（此列表為正面替換參考，來源：[執行時原始碼]，適用版本：ST v1.14.0）

下方程式碼塊為草稿原始內容，**置信度：low**（超版本宣告，v1.14.0 無此事件，來源：[推斷]）：

```javascript
// ⚠️ 以下為 v1.17.0+ 才可能存在的事件，v1.14.0 不可用，禁止施工
const { eventSource, event_types } = getContext();

eventSource.on(event_types.TTS_JOB_STARTED, () => {
  // TTS 合成任務開始
});
eventSource.on(event_types.TTS_AUDIO_READY, (audioData) => {
  // 音訊資料就緒，即將播放
});
eventSource.on(event_types.TTS_JOB_COMPLETE, () => {
  // 單個 TTS 任務完成
});
```

來源：[推斷] | 適用版本：未知（v1.14.0 不存在，可能為 v1.17.0+） | 置信度：**low**

**懸案交叉引用**：事件回撥的具體 payload 格式（訊息 ID？文字內容？）見 11 節懸案 P1。

### 1.5 STscript 命令

**核心結論**

```
/speak voice="CharacterName" 要朗讀的文字   # 觸發 TTS（別名：/narrate, /tts）
/beep                                       # 播放通知音
```

`voice` 引數匹配 voice map 中的角色名（不是 voiceId），引數引號內為角色名，後續內容為要朗讀的文字。

**【校準說明】** `/speak` 命令（含 `/narrate`、`/tts` 別名）在 v1.14.0 `tts/index.js` 中有完整 `SlashCommand.fromProps` 註冊實現，原始碼已驗證，升級為 high。`/beep` 命令官方文件有記載但 v1.14.0 本地原始碼未找到註冊程式碼，保持單源孤證。

來源：`/speak` [執行時原始碼]；`/beep` [文件·單源] | 適用版本：ST v1.14.0+ | 置信度：`/speak` **high**；`/beep` **medium·單源孤證**

### 1.7 TTS 與立繪同步

**核心結論**

當 TTS 播放時，系統呼叫：

```javascript
globalThis.vrmLipSync(audioBlob, character)
```

用於 VRM 模型口型同步（須安裝對應 VRM 擴充套件）。

表情自動更新透過情緒分類事件驅動，**流式傳輸時**以 `STREAMING_UPDATE_INTERVAL = 10000ms` 為節流間隔，防止過頻率 API 呼叫。

來源：[執行時原始碼] | 適用版本：ST v1.14.0+ | 置信度：**high**

**避坑**：表情分類在 streaming 期間以 10 秒為節流間隔，不是每 token 觸發——這是效能保護措施，不是 bug。

## 2 表情立繪（Expression/Sprite）系統

### 2.1 機制總覽

**核心結論**

ST 的表情系統透過 NLP 情緒分類驅動角色立繪切換，支援本地模型執行或呼叫 LLM API 進行分類。

分類器可配置為：

| 模式 | 模型 | 情緒數量 |
|------|------|----------|
| Local | `distilbert-base-uncased-go-emotions-onnx`（約 100MB） | 28 個 |
| Local | `bert-base-uncased-emotion-onnx`（via config.yaml） | 6 個 |
| Main API (LLM) | 主模型做分類，可加自定義 prompt | 可變 |
| WebLLM | 本地推理擴充套件 | — |
| Extras | （已廢棄） | — |

來源：[文件·多源] + [執行時原始碼] | 適用版本：ST v1.14.0+ | 置信度：**high**

## 7 本地實戰：media_library.js 架構分析

> **來源**：`<local-user-path>/<local-drive>/<local-workspace>/卡A/卡A 2.5.0/components/media_library.js`（本地生產原始碼）

### 7.1 設計要點與 Tavern Helper 介面

**核心結論**

這是角色卡內建**自管理影像資產庫**，不依賴 ST 內建表情系統，透過 Tavern Helper 的變數介面自管理持久化儲存：

```javascript
// 與 Tavern Helper 的介面對接（關鍵！）
function scriptVariableOption() {
  return { type: 'script', script_id: SCRIPT_ID };  // 'crossed-zone-media-library'
}

function readRawLibrary() {
  if (typeof getVariables !== 'function') return defaultLibrary();
  return getVariables(scriptVariableOption()) || {};
}

function writeRawLibrary(value) {
  if (typeof replaceVariables !== 'function') throw new Error('酒館助手變數介面不可用');
  replaceVariables(value, scriptVariableOption());
}
```

**關鍵發現**：`getVariables` / `replaceVariables` 是 **Tavern Helper 擴充套件暴露的全域性函式**，透過 `{ type: 'script', script_id: string }` option 物件區分變數名稱空間。這是本角色卡訪問持久化變數的核心機制。

來源：[執行時原始碼] | 適用版本：卡A 2.5.0 + Tavern Helper | 置信度：**high**

**避坑**：`getVariables` / `replaceVariables` 是 Tavern Helper 擴充套件介面，不是 ST 原生介面。卡內指令碼呼叫前必須檢查 `typeof getVariables !== 'function'`，否則在未安裝 Tavern Helper 的環境中會報錯。

- `window.setSpriteSlashCommand`：v1.14.0 `expressions/index.js` 中 `setSpriteSlashCommand` 是模組內部函式，**未掛載到 `window`**（grep 確認無 `window.setSpriteSlashCommand` 賦值），此呼叫在任何版本均無效。

正確替代路徑：監聽 `CHARACTER_MESSAGE_RENDERED` / `GENERATION_ENDED` 事件，用 `/expression-set` STscript 命令或 ST 官方 `/api/sprites` 介面控制表情。

以下程式碼塊**僅供參考結構，整體不可用，禁止施工**（置信度：**low**）：

```javascript
// ⚠️ 以下程式碼在 v1.14.0 中無效：TTS_JOB_STARTED 不存在，setSpriteSlashCommand 未全域性暴露
(function() {
  if (typeof getContext !== 'function') return;

  const ctx = getContext();
  const { eventSource, event_types } = ctx;

  // TTS 開始時切換到"speaking"表情
  eventSource.on(event_types.TTS_JOB_STARTED, () => {
    if (window.setSpriteSlashCommand) {
      window.setSpriteSlashCommand({ expression: 'joy' });
    }
  });

  // TTS 結束時恢復
  eventSource.on(event_types.TTS_JOB_COMPLETE, () => {
    if (window.setSpriteSlashCommand) {
      window.setSpriteSlashCommand({ expression: 'neutral' });
    }
  });
})();
```

來源：[推斷] | 適用版本：不適用（v1.14.0） | 置信度：**low**（TTS 事件不存在 + `setSpriteSlashCommand` 未全域性暴露，雙重失效）

## 10 高頻避坑

**[high][文件·多源]** Extras API 已於 2024 年 4 月停止維護，**不要再基於 Extras 構建新卡功能**（Coqui-TTS、Vosk、Whisper 舊路徑、talkinghead 均已死亡）。

**[high][執行時原始碼]** `getVariables` / `replaceVariables` 是 Tavern Helper 擴充套件介面，不是 ST 原生介面。卡內指令碼呼叫前必須檢查 `typeof getVariables !== 'function'`，否則在未安裝 Tavern Helper 的環境中會報錯。

**[high][執行時原始碼]** 媒體庫整庫大小上限 24MB；單張 data URL 上限 4MB；GIF 額外限制 3MB。超出需清理未使用資產或改用外鏈 URL（`external: true`）。

**[high][執行時原始碼]** GIF 圖片不進行裁剪/壓縮（保留動畫幀），但超大 GIF 會被拒絕匯入——這是主動防卡死措施，移植時須保留此邏輯。

**[high][文件·多源]** TTS Voice Map 必須配置，否則 TTS 不知道用哪個語音。`[Default Voice]` 和 `disabled` 是兩個特殊標記值。

**[high][執行時原始碼]** TTS 表情分類在 streaming 期間以 10 秒為節流間隔，不是每 token 觸發——這是效能保護，不是 bug。

**[high][文件·多源]** `Send inline images` 預設關閉，必須手動在 Chat Completion 設定中開啟，且後端模型必須是視覺模型，否則圖片會被忽略。

**[medium·單源孤證][文件·單源]** ScreenShare 擴充套件依賴瀏覽器 ImageCapture API，**Firefox 不支援**，Safari 支援有限，主要在 Chrome 上可靠執行。

**[high][文件·多源]** Dynamic Audio 的 BGM 情緒命名必須與表情系統的 28 個情緒英文名完全一致（如 `anger_0.mp3`），大小寫敏感，拼寫錯誤將導致靜默失敗。【提升：草稿標 medium·推導未驗證，但官方文件 dynamic-audio 頁面給出了明確示例（`anger_0.mp3`、`joy_0.mp3`）且屬多源文件，非推導，提升至 high。】

**[high][執行時原始碼]** `importUrlAsset` 失敗時（CORS 被拒）會自動降級為外鏈模式（`external: true`），不會報錯，但匯出庫時會有 `warnings` 列表，外鏈資產在離線場景無效。
