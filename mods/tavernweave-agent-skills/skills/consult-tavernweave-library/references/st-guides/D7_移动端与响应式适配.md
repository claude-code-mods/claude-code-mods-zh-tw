## 1. 機制總覽

### 1.1 ST 宿主層（非卡片作者控制）

SillyTavern 宿主在移動端的行為由五個子機制決定。

#### A. 視口宣告（index.html）

```html
<meta name="viewport" content="width=device-width, viewport-fit=cover,
  initial-scale=1, maximum-scale=1.0, user-scalable=no,
  interactive-widget=resizes-content">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="mobile-web-app-capable" content="yes">
```

`user-scalable=no` 禁止使用者手勢縮放；`interactive-widget=resizes-content` 使虛擬鍵盤彈出時 viewport 收縮而非僅覆蓋內容，整體佈局隨之壓縮。

**來源：** ST v1.14.0 `public/index.html` | **置信度：high** `[執行時原始碼]`

---

#### B. 移動端主斷點：1000px

ST 在 `mobile-styles.css` 裡以 `@media (max-width: 1000px)` 為核心斷點做全面 reflow：

- 所有側邊欄切換為 `width: 100dvw; max-width: 100dvw; position: fixed; left: 0`（覆蓋全屏抽屜）
- 面板 pin 按鈕隱藏（`display: none`）
- body 固定：`touch-action: none; overflow: hidden; position: fixed`
- 導航面板強制 `min-width: 100dvw !important`
- 次斷點 `@media (max-width: 450px)` 管窄屏手機（如 320px 豎屏）額外調整

**來源：** ST v1.14.0 `public/css/mobile-styles.css` | **置信度：high** `[執行時原始碼]`

---

#### C. iOS 專項

```css
@supports (-webkit-touch-callout: none) {
  #sheld {
    padding-right: max(env(safe-area-inset-right), 0px);
    padding-left:  max(env(safe-area-inset-left),  0px);
    padding-bottom: 0;
  }
  /* PWA 模式（body.PWA 類）額外應用底部安全區 */
  body.PWA #sheld {
    padding-right:  max(env(safe-area-inset-right), 2px);
```

**來源：** ST v1.14.0 `public/css/mobile-styles.css` 第 498–570 行 | **置信度：high** `[執行時原始碼]`

### 1.2 卡片層（角色卡作者可控）

卡片的 HTML 內容（透過正則擴充套件替換）被注入到 `.mes_text` 內。ST v1.14.0 原始碼中**不存在由 ST 框架層建立 iframe 的邏輯**（已 grep 全部 .js 檔案確認）；卡片內的 `<iframe>` 是卡片自身 HTML 建立的（如掛載殼自含 `<iframe id="xy-sb-inner">`）。這個卡片自創的 iframe 在 ST 聊天氣泡內執行，其 `window.frameElement` 返回的是 ST `.mes_text` 內卡片 HTML 自己的外層 iframe 元素，從而卡片 JS 可控制其高度。**ST 框架層不施加 `sandbox` 屬性**（原始碼層無該邏輯），卡片 iframe 可自由訪問 `document`。

**來源：** 本地實戰生產卡 3.0.2（status_bar_regex.html 實際程式碼）+ ST v1.14.0 全指令碼 grep 確認 | **置信度：medium·單源孤證** `[執行時原始碼]`

> **校準備註（2026-06-28）：** 原描述「ST 以 iframe 形式渲染」有誤——是卡片 HTML 自含 iframe，不是 ST 框架建立。sandbox 問題（原懸案 U2）經原始碼 grep 可排除「ST 主動施加 sandbox」，但瀏覽器自身對 blob: 來源的限制行為未做真機測試，保留 U2 供驗證。

## 3. 完整可用正規化程式碼

### 3.1 iframe 高度自適應（卡A 3.0.x 生產用法）

**來源：** `<local-guide-db>/本地證據/卡A歷史/3.0.2/components/status_bar_regex.html` | **置信度：high** `[執行時原始碼]`

機制：外層「掛載殼」fetch 遠端真實 HTML → Blob URL 掛到內層 iframe → ResizeObserver 持續同步高度到 ST 控制的最外層 iframe。

```html
<!-- 掛載殼 body -->
<style>
  html, body { margin: 0; padding: 0; overflow: hidden; }
  #xy-sb-inner {
    display: block;
    width: 100%;
    border: 0;
    overflow: hidden;
  }
</style>

<iframe id="xy-sb-inner" scrolling="no"></iframe>

<script>
(function () {
  var inner = document.getElementById('xy-sb-inner');

  /* ── 高度同步：把內層 iframe 真實高度同步到 ST 外層 iframe ── */
  function syncHeight() {
    try {
      var fe = window.frameElement;   // ST 控制的外層 iframe 元素
      if (!fe) return;
      var doc = inner.contentDocument ||
                (inner.contentWindow && inner.contentWindow.document);
      if (!doc) return;

      /* 量高前禁橫向溢位，避免橫向捲軸撐高 */
      try {
        if (doc.body) {
          doc.body.style.overflowX = 'hidden';
          doc.body.style.maxWidth  = '100%';
        }
      } catch (_) {}

      var h = Math.max(
        doc.documentElement ? doc.documentElement.scrollHeight : 0,
        doc.body            ? doc.body.scrollHeight            : 0
      );

      if (h > 0 && Math.abs((parseInt(fe.style.height, 10) || 0) - h) > 2) {
        fe.style.height    = h + 'px';
        fe.style.minHeight = h + 'px';
        inner.style.height = h + 'px';
        try { fe.setAttribute('height', String(h)); } catch (_) {}
      }
    } catch (_) {}
  }

  function mountInner(html) {
    var blob    = new Blob([html], { type: 'text/html' });
    var blobUrl = URL.createObjectURL(blob);

    inner.addEventListener('load', function onLoad() {
      inner.removeEventListener('load', onLoad);
      syncHeight();
      // 非同步渲染補償（內部指令碼延遲填充內容）
      [100, 400, 900, 1800, 3000].forEach(function (t) {
        setTimeout(syncHeight, t);
      });
      // ResizeObserver 持續同步
      try {
        var doc = inner.contentDocument ||
                  (inner.contentWindow && inner.contentWindow.document);
        if (doc && doc.body) new ResizeObserver(syncHeight).observe(doc.body);
      } catch (_) {}
    });

    inner.src = blobUrl;
  }

  // 順序嘗試主 CDN → 備源 → fail
  fetch('https://cdn.example.com/status-bar.html')
    .then(function (r) { if (!r.ok) throw new Error('HTTP ' + r.status); return r.text(); })
    .then(function (html) { mountInner(html); })
    .catch(function () { /* 備源邏輯 */ });
})();
</script>
```

**關鍵要點：**

- 量高前先強制 `overflowX: hidden; maxWidth: 100%`，避免橫向滾動條幹擾 scrollHeight
- 容差 `> 2px` 防止高頻無意義 DOM 寫入
- 多個延遲 `setTimeout([100, 400, 900, 1800, 3000])` 補償內部非同步渲染（動畫/資料填充）
- `ResizeObserver` 兜底持續同步，覆蓋內容動態變化

### 3.2 響應式 CSS 變數設計系統（卡A 2.5.0 生產用法）

**來源：** `卡A/卡A 2.5.0/components/status_bar_regex_beauty_r5.html` | **置信度：high** `[執行時原始碼]`

核心思路：**所有尺寸錨定到一個根變數 `--hud-base-font`**，使用者透過 settings slider 調整後自動縮放所有元素。

```css
:root {
  --hud-base-font:  12px;   /* 錨點；使用者可透過設定滑塊調節 */
  --hud-base-width: 100%;
  --cut: 10px;              /* 切角尺寸 */
}

body {
  margin: 0; padding: 0;
  font-size: var(--hud-base-font);
}

/* 容器：寬度 100% 不設固定 max-width，由使用者設定的 widthPercent 動態注入 */
.hud-container {
  width: 100%;
  max-width: var(--hud-base-width);
  margin: 0 auto;
  box-sizing: border-box;
}

/* 字型比例關係（全部用 calc 相對於錨點） */
.hud-title    { font-size: calc(var(--hud-base-font) * 1.64); }
.hud-subtitle { font-size: calc(var(--hud-base-font) * 0.82); }
.hud-tag      { font-size: calc(var(--hud-base-font) * 0.92); }
.settings-note { font-size: calc(var(--hud-base-font) * 0.86); }
```

JS 端動態注入（響應使用者調節）：

```javascript
var hudSettings = { fontSize: 12, widthPercent: 100 };

function applyHudSettings(s) {
  var root = document.documentElement;
  root.style.setProperty('--hud-base-font',  s.fontSize + 'px');
  root.style.setProperty('--hud-base-width', s.widthPercent + '%');
}

// 繫結 slider
document.getElementById('opt-fontsize').addEventListener('input', function () {
  applyHudSettings({ fontSize: +this.value, widthPercent: hudSettings.widthPercent });
});
```

JS 端彈出框定位（防止溢位螢幕右/下邊緣）：

```javascript
function positionPopover(anchor, $popover) {
  var rect = anchor.getBoundingClientRect();
  var pw   = $popover.outerWidth()  || 310;
  var ph   = $popover.outerHeight() || 260;
  var left = Math.max(8, Math.min(window.innerWidth - pw - 8, rect.left));
  var top  = rect.bottom + 6;
  // 下方空間不足時翻轉到上方
  if (top + ph > window.innerHeight - 8) top = Math.max(8, rect.top - ph - 6);
  $popover.css({ left: left + 'px', top: top + 'px' });
}
// 視窗 resize 時重新定位
$(window).on('resize', function () { positionPopover(anchor, $popover); });
```

### 3.6 動態網格寬度檢測（容器查詢替代方案）

```javascript
// 用 getBoundingClientRect 做執行時響應（以容器寬度判斷，而非 viewport 寬度）
function updateMediaLayoutBlocks() {
  document.querySelectorAll('.cz-media-block').forEach(function (el) {
    var width = el.getBoundingClientRect().width;
    el.classList.toggle('is-narrow', width > 0 && width < 560);
  });
}

window.addEventListener('resize', updateMediaLayoutBlocks);
```

## 4. 高頻避坑

### P1 iframe 高度在移動端卡 0 或撐不開

**原因：** 量 `scrollHeight` 時若有橫向溢位，`body.scrollHeight` 會包含溢位寬度導致計算異常；移動端系統字型放大時 layout 可能延遲完成。

**解法（已驗證）：** 量高之前強制 `doc.body.style.overflowX = 'hidden'; doc.body.style.maxWidth = '100%'`，多輪 `setTimeout [100, 400, 900, 1800, 3000]` + `ResizeObserver` 持續跟蹤。

**來源：** 本地實戰原始碼 3.0.2 | **置信度：high** `[執行時原始碼]`

---

### P2 `100vh` 在移動端 Safari 比實際可用高度高

**原因：** `100vh` 包含被瀏覽器工具欄遮擋的區域（Safari 底部工具欄約 56–80px）。

**解法：** ST 宿主已在 `mobile-styles.css` 改用 `100dvh`（dynamic viewport height）。卡片內部彈出框用 `min(N px, calc(100vh - 偏移))` 兜底；若需精確貼合，改用 `100dvh`。

**來源：** 執行時原始碼（ST 使用 `100dvh` 已確認）+ 推斷（卡片內解法未真機驗證，Safari 工具欄高度為社群通識） | **置信度：high（ST 宿主用 dvh 部分）** + **medium·推導未驗證（卡片內 dvh 應用建議）** `[執行時原始碼]` `[推斷]`

### P3 固定寬度 px 值在窄屏被截斷

**原因：** 狀態列面板 `width: 328px` 在 320px 寬手機上溢位螢幕右側。

**解法（已驗證）：** `width: min(328px, calc(100vw - 24px))`，`24px` 為兩側各留 12px 安全邊距。

**來源：** 本地實戰原始碼 2.5.0 | **置信度：high** `[執行時原始碼]`

---

### P4 媒體查詢在 iframe 內以 iframe 寬度為參照而非 window

**原因：** iframe 內的 `@media (max-width: 600px)` 響應 iframe 自身渲染寬度，不是宿主 window 寬度（Web 標準行為）。

**影響（正向）：** 即使宿主 window 是大屏，只要 iframe 被 ST 聊天氣泡約束到窄寬度，媒體查詢也會正確觸發；卡片內斷點可直接以氣泡/訊息容器寬度為設計基準。

**注意：** ST 是否對 iframe 施加 `sandbox` 屬性覆蓋此行為尚未完整驗證（見 6 懸案 U2）。

**來源：** Web 標準規範 + 推斷 | **置信度：medium** `[推斷]`（需真機驗證 sandbox 模式）

---

### P5 `backdrop-filter: blur()` 在移動端低配機型效能危險

**解法：** 參考 ST 官方 `No Blur Effect` toggle 的存在。狀態列若使用 `backdrop-filter`，須提供 fallback：用 `@supports (backdrop-filter: blur(4px))` 條件包裹，或提供可關閉的配置項。

**來源：** 文件單源 + 推斷 | **置信度：medium** `[文件·單源]` `[推斷]`

### P6 觸控點選熱區太小（< 44px）

**ST 觀測值：** 移動端 menu toggle 按鈕實測約 30px，ST 自身也存在不達標的情況。

**建議：** 可互動元素最小尺寸 44×44px（iOS HIG 標準）；卡片內按鈕加 `padding: 8px 12px` 通常可達標。

**來源：** 執行時原始碼觀測 + iOS HIG | **置信度：medium** `[執行時原始碼]` `[推斷]`

### P7 `position: fixed` 在 iframe 內相對於 iframe 視口而非宿主 window

**原因：** iframe 建立獨立 stacking context，`fixed` 相對 iframe 視口定位，而非宿主頁面視口。

**影響：** 卡片內 `position: fixed` 的彈出框/設定面板在移動端可能被卡片自身 iframe 的高度限制截斷（iframe 高度由 syncHeight 同步到內容高度，彈出框若超出可視區則被裁切）。注意：ST 框架層不直接限制 iframe 高度，高度由卡片自身 JS 控制。

**解法（已驗證）：** 改用 `position: absolute` + 父容器 `position: relative; overflow: visible`；或動態檢測下方剩餘空間，不足時翻轉彈出方向（見 3.3 JS 定位程式碼）。

**來源：** Web 標準 + 本地實戰原始碼翻轉邏輯 | **置信度：high** `[執行時原始碼]` `[推斷]`

---

### P8 移動端卡片內無法呼叫 ST 內部函式 `isMobile()`

**原因：** `isMobile()` 以 `export function` 形式定義在 ST 宿主 `RossAscends-mods.js` 中（已原始碼確認），屬於宿主 ES module scope，卡片內 iframe JS 無法透過 `window.isMobile()` 直接呼叫（不同 document 上下文且 module export 不掛載到 window）。

**替代方案：**

```javascript
// 方案 A：視口寬度判斷
var isMobileLayout = window.innerWidth < 1000;

// 方案 B：媒體查詢物件
var isMobileLayout = window.matchMedia('(max-width: 600px)').matches;

// 方案 C：UA 檢測（粗略）
var isMobileUA = /Mobi|Android|iPhone|iPad/i.test(navigator.userAgent);
```

**來源：** 執行時原始碼（isMobile 定義位置已確認）+ 推斷（iframe 跨 scope 不可訪問，理論層面無真機實測） | **置信度：medium·推導未驗證** `[執行時原始碼]` `[推斷]`

---

### P9 橫豎屏切換時 iframe 高度不更新

**原因：** 裝置旋轉後視口寬高互換，內容重排，但若沒有監聽 resize/orientation 事件，iframe 高度停留在旋轉前的值。

**解法：**

```javascript
window.addEventListener('resize', syncHeight);
if (screen.orientation) {
  screen.orientation.addEventListener('change', function () {
    setTimeout(syncHeight, 300); // 旋轉動畫完成後再量
  });
}
```

**來源：** 推斷 | **置信度：medium** `[推斷]`（需真機驗證）

## 5. ST 宿主 CSS 變數速查

| 變數 | 用途 | iframe 內可讀 |
|---|---|---|
| `--SmartThemeBodyColor` | 主文字色 | 否（跨文件，同源時可透過 `window.parent` 讀） |
| `--SmartThemeBorderColor` | 邊框色 | 否 |
| `--SmartThemeBlurStrength` | blur 係數 | 否 |
| `--sheldWidth` | 聊天窗寬度（vw 值），可讀不可寫 | 否 |
| `--fontScale` | 使用者字型縮放比例 0.5–1.5 | 否（見懸案 U3） |

**重要說明：** 這些變數定義在宿主 `document.documentElement`，iframe 內**不繼承**（跨文件邊界）。需要主題適配時，需在卡片 JS 裡讀 `window.parent.document.documentElement.style.getPropertyValue(...)` — 此操作僅在同源（ST 本地部署）時有效，雲端部署可能跨域失敗。

**來源：** 執行時原始碼 + Web 標準 | **置信度：high** `[執行時原始碼]`
