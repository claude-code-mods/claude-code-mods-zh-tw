### 2.1 狀態列 / HUD 四層實現鏈路

**核心結論**

```
正則匹配變數塊（Find Regex 匹配 AI 輸出中的變數塊標記）
    ↓
TavernHelper 檢測程式碼塊語法（```html 開頭）→ 渲染為 iframe（srcdoc = HTML 內容）

### 2.2 控制中心執行上下文與雙視窗穿透

**核心結論**

ST 裡的卡內 JS（透過正則指令碼注入）執行在訊息渲染 iframe 內。控制中心採用**雙視窗穿透**策略——始終優先訪問 `window.parent`（ST 主視窗），失敗則回落到 `window` 自身。真實 DOM（擴充套件選單欄、聊天輸入框等）在父視窗中，必須透過 `hostWindow()` / `hostDocument()` 訪問。

```javascript
// 來自 control_center.js v2.9.9 第 49-54 行（最高可信）
function hostWindow() {
  try {
    if (window.parent && window.parent !== window && window.parent.document) return window.parent;
  } catch (_) {}
  return window;
}
function hostDocument() {
  try { return hostWindow().document || document; } catch (_) { return document; }
}
```

**核心原則**：所有需要訪問 ST 主視窗 DOM 或全域性 API 的操作，均透過 `hostWindow()` / `hostDocument()`，不直接用 `window` / `document`。

詳見《C1_前端基礎-TavernHelper與iframe.md》§10（window.parent 防禦訪問模式）。

來源：`control_center.js` v2.9.9 第 49-54 行 ｜ 置信度：high `[執行時原始碼]`

### 2.5 入口層、外殼層與內容層選擇

2026-07-14 起，狀態列/控制中心按三層拆分，避免把“按鈕長什麼樣”“面板在哪裡”和“狀態怎麼讀”混成一份巨型實現：

```text
入口層：Wand / 懸浮球 / 頁面按鈕
                 ↓ command registry
HUD Host Core：phase / generation / abort / contextRevision / dirty
                 ↓ ShellAdapter
             移動抽屜 / 桌面浮窗
                 ↓
     iframe + bridge + 狀態列內容與資料鏈

訊息樓層生命週期 → 每樓/末樓 inline iframe → 同一內容協議/資料適配
```

| 選擇 | 適合 | 不適合 | 專冊 |
|---|---|---|---|
| 訊息內聯狀態列 | 每樓或末樓緊貼劇情，天然跟隨訊息 | 需要長期懸浮、跨樓操作 | 本冊 |
| Wand 入口 | 最穩妥的既有功能選單入口 | 想常駐螢幕和拖動 | E5 |
| 懸浮球入口 | 常駐、可吸邊、多功能分發 | 直接承載完整狀態內容 | C11 |
| 抽屜外殼 | 窄屏、粗指標、軟鍵盤環境 | 任意拖動/縮放 | C12 |
| 浮窗外殼 | 桌面邊聊邊看、可拖動縮放 | 手機預設方案 | C13 |

內容層仍由本冊負責：變數讀取、事件重新整理、Tab/分割槽渲染、寫回與控制中心業務。C12/C13 應複用同一個頂層 HUD Host Core 與 iframe 真身，只替換 ShellAdapter；訊息內聯通常是每樓/末樓自己的 iframe 生命週期，只共享內容協議和資料適配，不預設加入同一個活動 singleton session。C11 的入口只 dispatch 命令，不復制業務處理器。

卡A 3.4.9 已把抽屜與浮窗納入共享 `hudSession`。抽屜是已落地的移動端生產路線，不得因舊模組化 fragment 未同步而標成待驗證。具體視口、手勢、幾何和非同步競態分別由 C12/C13 維護。

### 3.3 statRoot 相容層與 safeGet 正規化

**核心結論**：生產卡統一使用 `statRoot` 處理兩種傳入格式，`safeGet` 自動剝離 `stat_data.` 路徑字首。

```javascript
// stat_data 相容層：允許傳入完整 MvuData 或裸 stat_data
function statRoot(all) {
  if (!all || typeof all !== 'object') return {};
  return all.stat_data || all;
}

// 安全路徑讀取：自動剝離 'stat_data.' 字首 + 空值處理
function safeGet(obj, path, def) {
  var root = statRoot(obj);
  var p = String(path || '');
  if (p.indexOf('stat_data.') === 0) p = p.slice(10);  // 相容帶字首的 path
  var val = _.get(root, p);
  if (!shouldRenderValue(val)) return def;
  return displayValue(val, def);
}
```

**呼叫慣例**：外部呼叫建議統一傳不帶字首的路徑（如 `'user.等級'`），兩種格式均支援。

來源：`status_bar_regex_beauty_r5.html` L1916-1918, L2324-2330 ｜ 置信度：high `[執行時原始碼]`

### 4.3 跨 iframe API 發現鏈（控制中心）

**核心結論**：卡內程式碼不能直接 `import` ST 擴充套件 API，只能透過全域性物件發現。每個外部依賴走"本視窗 → 父視窗"雙檢。

```javascript
// Tavern Helper（核心依賴）
function helperHost() {
  const candidates = [window, hostWindow()];
  for (const target of candidates) {
    if (target?.TavernHelper) return target.TavernHelper;
    if (target?.generateRaw || target?.getChatMessages) return target;
  }
  return null;
}

// MVU（變數讀寫）
function mvuHost() {
  return window.Mvu || hostWindow().Mvu || null;
}

// 媒體庫（同級模組）

### 5.3 防抖重新整理排程器（schedulePopulate）

**核心結論**：`schedulePopulate` + 資料簽名機制防止短時間內頻繁重渲染。

```javascript
var lastPopulateSignature = '';
var populateTimer = null;
var populateRaf = null;

function schedulePopulate(delay, force) {
  if (populateTimer) clearTimeout(populateTimer);
  var raf = window.requestAnimationFrame || function(cb) { return setTimeout(cb, 16); };
  var caf = window.cancelAnimationFrame || clearTimeout;
  populateTimer = setTimeout(function() {
    if (populateRaf) caf(populateRaf);
    populateRaf = raf(function() {
      populateRaf = null;
      populate(null, { force: !!force });
      updateAllWideThresholdGrids();
    });
  }, delay || 50);
}

function populate(all, options) {
  options = options || {};
  all = all && hasStatData(all) ? all : readCurrentHudVariables();
  if (hasStatData(all)) lastGoodHudData = cloneHudValue(all);

  // 簽名：stat_data + media + settings 三者聯合簽名
  var sig = JSON.stringify({ stat: statRoot(all), media: getMediaData(), settings: settings });
  if (!options.force && sig === lastPopulateSignature) return;  // 簽名未變則跳過
  lastPopulateSignature = sig;

  // 活躍 tab 立即同步渲染，其餘 tabs requestIdleCallback 延遲渲染
  var activeId = activeTabId();
  renderTabIfNeeded(activeId, all, sig, true);
  renderAllTabsDeferred(all, activeId);
}
```

**注意**：使用者觸發操作後若資料已更新但簽名快取未變，須傳 `{ force: true }` 強制重新整理，否則 UI 不重新整理（見避坑 7.11）。

### 5.6 多 iframe 去重機制

**核心結論**：每次樓層重渲染（swipe、edit）都會注入新 iframe。去重機制**優先保留當前 iframe 自身**，只有當自身不在 hudFrames 列表中時才降級為保留最後一個，並移除其餘。

```javascript
function normalizeDuplicateHudInMessage() {
  var frame = window.frameElement;
  var message = frame && frame.closest ? frame.closest('.mes') : null;
  if (!frame || !message) return 0;

  var frames = Array.prototype.slice.call(message.querySelectorAll('iframe'));
  var hudFrames = frames.filter(function(item) {
    var doc = item.contentDocument;
    return !!(doc && doc.querySelector('.hud-container .hud-title'));
  });

  if (hudFrames.length <= 1) return 0;

  var keep = frame;  // 優先保留自身
  if (hudFrames.indexOf(keep) < 0) keep = hudFrames[hudFrames.length - 1];
  hudFrames.forEach(function(item) {
    if (item !== keep) item.remove();
  });
}

### 5.11 custom- 字首對策——MutationObserver 動態補齊

**核心結論**：檢測到 `custom-` 字首存在後，用 MutationObserver 即時給新增節點補全 `custom-` 版本類名。

```javascript
function applyCustomPrefix(root) {
  const XY_PX = /(^|\s)custom-xy-/.test(root.className || '') ? 'custom-' : '';
  if (!XY_PX) return; // 離線預覽模式，無需處理

  const prefixEl = (el) => {
    if (!el || el.nodeType !== 1 || !el.className) return;
    el.className.split(/\s+/).forEach(token => {
      if (!token || token.indexOf(XY_PX) === 0) return;
      const prefixed = XY_PX + token;
      if (!el.classList.contains(prefixed)) el.classList.add(prefixed);
    });
  };
  const prefixTree = (el) => {
    prefixEl(el);
    if (el.querySelectorAll) el.querySelectorAll('[class]').forEach(prefixEl);
  };

  prefixTree(root);  // 處理現有節點

  if (!root.__xyPrefixObs && typeof MutationObserver === 'function') {
    root.__xyPrefixObs = new MutationObserver(muts => {
      muts.forEach(m => {
        if (m.type === 'attributes') { prefixEl(m.target); return; }
        m.addedNodes.forEach(n => { if (n.nodeType === 1) prefixTree(n); });
      });
    });
    root.__xyPrefixObs.observe(root, {
      childList: true, subtree: true,
      attributes: true, attributeFilter: ['class'],
    });
  }
}
```

來源：`control_center.js` v2.9.9 第 1758-1789 行 ｜ 置信度：high `[執行時原始碼]`

## 7. 高頻避坑

### 7.1 custom- 字首導致動態注入內容丟樣式

**來源**：`public/scripts/chats.js` DOMPurify 鉤子直讀 + `control_center.js` v2.9.9 ｜ 置信度：high `[執行時原始碼]`

**機制（已回源 `public/scripts/chats.js` `addDOMPurifyHooks` / `encodeStyleTags` / `decodeStyleTags` 確認）**：
- **`class` 屬性**：ST DOMPurify 鉤子對每個 class token 加 `custom-` 字首（`fa-`、`note-` 開頭及 `monospace` 豁免）。
- **`<style>` 標籤**：被替換為 `<custom-style>編碼內容</custom-style>`，CSS 選擇器中的 class 名加 `custom-` 字首；**`id` 選擇器不受字首處理**。
- **`style=""` 屬性**：未觀察到被重新命名為 `custom-style=""`；是否保留受 ST/DOMPurify 版本與配置影響，不能寫成全版本“必然剝除”。
- **JS 注入**：不經過訊息靜態 class 字首管線，但仍必須區分受信本地模板與不可信遠端 HTML。

**對策（按可靠性排序）**：
1. **受信本地控制面板**：可由本地指令碼注入受審模板，CSS 寫裸類名；禁止把使用者/模型文字直接拼入 HTML。
2. **遠端開局頁面**：必須走 C10 的“完整性驗證 → DOM 淨化 → 結構校驗 → 注入 → 本地 binder”，不能直接 `innerHTML = remoteHtml`。
3. **訊息靜態內容**：使用已核 `<style>`/class 規則，或 MutationObserver 動態補齊（見正規化 5.11）。
4. **宿主面板兜底**：使用穩定 ID 限定作用域（`#my-panel .xy-row { ... }`）。

### 7.2 整面板空白（分割槽渲染拋錯未隔離）

**來源**：`control_center.js` v2.5.0 vs v2.9.9 對比 ｜ 置信度：high `[執行時原始碼]`

```
