# 酒館介面美化

> 文件版本：v1.0.0 ｜ 最後更新：2026-07-15
>
> **定位**：美化 SillyTavern 宿主介面本身，包括主題、Custom CSS、聊天畫布、輸入區、選單、抽屜、彈窗和移動端宿主佈局。
>
> **硬邊界**：宿主主題是使用者級配置，通常影響所有角色和聊天。角色卡不得靜默接管或永久改寫使用者全域性主題。訊息正文、卡內 HTML、正則渲染和 iframe 內 CSS 歸 **《C3_HTML美化與CSS.md》**；需要 JS 動態行為時升級為 **《D5_ST擴充套件開發完整指南.md》** 的 UI Extension。

## 1. 定義與三條實現路線

### 1.1 什麼叫“酒館美化”

本冊的“酒館”指 ST 頂層宿主 UI，而不是某條訊息或某張卡片的前端：

```text
SillyTavern 宿主 document
  ├─ 頂欄 / 選單
  ├─ 左右抽屜
  ├─ 聊天畫布與訊息外殼
  ├─ 輸入與傳送區
  ├─ Popup / Modal / Toast
  └─ 使用者主題和 Custom CSS
```

因此它的影響範圍更大、回滾要求更高，也更容易與其他擴充套件和主題衝突。

### 1.2 三條路線與選擇順序

| 路線 | 適合 | 優先順序 |
|---|---|---:|
| ST 原生 UI Theme | 顏色、字型、寬度、模糊、訊息佈局等官方可配置項 | 首選 |
| Theme 內 Custom CSS | 原生設定無法覆蓋的靜態樣式 | 次選 |
| UI Extension | 動態 DOM、設定面板、事件、執行時切換、複雜行為 | 僅必要時 |

原則：能用主題令牌解決，不寫深層選擇器；能用 CSS 解決，不注入 JS；必須動態操作時才轉 D5。

### 1.3 與 C3 的判定表

| 判斷項 | C9 酒館美化 | C3 卡內 HTML/CSS |
|---|---|---|
| DOM | ST 頂層宿主 | `.mes_text` 或卡內 iframe |
| 影響範圍 | 使用者主題，通常跨聊天 | 某卡/某樓層 |
| 首選載體 | UI Theme / Custom CSS | 正則 HTML / iframe |
| 動態行為 | UI Extension | Tavern Helper / iframe 指令碼 |
| 分發 | 使用者顯式匯入/啟用 | 可隨角色卡攜帶 |
| 回滾 | 恢復主題/刪除 Custom CSS | 關閉正則/指令碼/重導卡 |

卡內 CSS 能否穿透宿主不是授權問題。即使技術上能訪問父文件，也不得把角色卡載入等同於使用者同意修改全域性主題。

## 2. 影響範圍與許可權邊界

### 2.1 使用者顯式啟用

主題、美化擴充套件或 Custom CSS 包必須要求使用者主動：

- 預覽影響範圍；
- 匯出現有主題或生成回滾點；
- 匯入/安裝；
- 選擇啟用；
- 確認外部字型、圖片和網路來源；
- 知道如何恢復預設。

角色卡可以在 creator notes 或開局依賴門中推薦主題，但不能：

- 靜默寫入使用者 Custom CSS；
- 把全域性主題改成角色專屬配色後不恢復；
- 隱藏設定、擴充套件管理或傳送按鈕阻止退出；
- 用遠端樣式在使用者不知情時追蹤或載入資源；
- 把“顯示最佳”寫成“必須授予任意宿主 DOM 許可權”。

### 2.2 主題是全域性表面

在不同 ST 配置中，主題可能是使用者級、賬號級或當前例項級。不要假定它隻影響當前角色。設計時必須用其他普通卡、群聊、長聊天和設定頁驗證，避免角色專屬視覺汙染全域性。

### 2.3 何時用卡片專屬樣式

若要求僅影響某張卡的訊息內容，應留在 C3；若必須影響宿主，但只在目標卡啟用，應使用按目標 ST 版本宣告 `activate/enable/disable/clean/delete` 等真實 manifest hooks 的 UI Extension，並以當前聊天身份為作用域。擴充套件內部可以另設冪等 `destroy()` 統一清理監聽、DOM 和樣式，但它不是 manifest hook。純 Custom CSS 沒有可靠的卡片生命週期，不適合實現複雜卡片專屬宿主換膚；精確 hook 版本邊界見 D5。

## 3. 宿主 DOM 穩定性分級

### 3.1 三層穩定度

| 層級 | 示例 | 策略 |
|---|---|---|
| A：官方主題變數/設定 | `--SmartTheme*`、字型縮放、模糊強度、聊天寬度 | 優先依賴 |
| B：長期存在的語義區域 | 聊天根、訊息、輸入區、抽屜、Popup | 小範圍選擇器 + 相容矩陣 |
| C：內部結構/自動生成類 | 深層 nth-child、圖示內部節點、第三方擴充套件 DOM | 避免；必要時能力檢測 |

不要因為某個選擇器在一版裡存在，就把它寫成永久公共 API。

### 3.2 選擇器紀律

```css
/* 較穩：根令牌 */
:root {
  --my-theme-radius: 14px;
}

/* 可接受：限定宿主區域 */
#chat .mes {
  border-radius: var(--my-theme-radius);
}

/* 脆弱：依賴深層位置和主題內部結構 */
#sheld > div:nth-child(2) > div:nth-child(4) span:nth-child(1) {
  display: none;
}
```

Custom CSS 直接進入宿主樣式層；訊息渲染中的 `custom-*` 類改名機制屬於卡內淨化/格式化鏈，不應當成宿主主題選擇器規範。

### 3.3 不復制整份官方 CSS

只覆寫需要改變的表面。複製整份 `mobile-styles.css`、核心主題或擴充套件 CSS 會凍結一份舊結構，後續 ST 更新時既覆蓋新修復，又讓衝突難以定位。

## 4. 主題令牌與視覺系統

### 4.1 令牌先行

先定義語義令牌，再對映到具體區域：

```css
:root {
  --my-bg: #11131a;
  --my-surface: rgba(26, 29, 39, 0.92);
  --my-surface-strong: #202431;
  --my-text: #f3f5fb;
  --my-text-muted: #aeb5c7;
  --my-accent: #9bb8ff;
  --my-danger: #ff8c9a;
  --my-border: rgba(255, 255, 255, 0.12);
  --my-radius-sm: 8px;
  --my-radius-lg: 16px;
  --my-shadow: 0 12px 34px rgba(0, 0, 0, 0.34);
}
```

需要覆蓋：

- 背景、表面、強調錶面；
- 主文字、次文字、停用文字；
- 連結、強調、成功、警告、錯誤；
- 邊框、焦點環、選中態；
- 小/中/大圓角；
- 陰影、模糊、間距；
- 字型族、字號比例和行高。

### 4.2 對接 ST 變數

ST 主題已經暴露多組 `--SmartTheme*`、字型縮放、模糊強度、聊天寬度等變數。實際欄位集合隨版本變化，匯出目標版本主題後再對映；不要憑舊版變量表硬寫。

推薦：

```css
:root {
  --my-text: var(--SmartThemeBodyColor, #f3f5fb);
  --my-bg: var(--SmartThemeBlurTintColor, #11131a);
  --my-shadow-strength: var(--shadowStrength, 1);
}
```

使用 fallback，避免變數缺失時整塊文字透明或背景消失。

### 4.3 Flat / Bubble / Document 模式

官方聊天顯示模式會改變訊息外殼、頭像和寬度。美化包至少明確：

- 只支援某一種模式；或
- 為三種模式分別提供選擇器；或
- 僅改令牌，不假定具體外殼結構。

不要在 Bubble 模式調好後宣稱“全模式相容”。

## 5. 宿主各區域美化策略

### 5.1 背景與聊天畫布

- 背景圖必須有純色 fallback；
- 保證文字區域有足夠遮罩，不讓高對比圖片穿透；
- `background-attachment: fixed` 在移動端可能掉幀，應降級；
- 超大圖片按目標解析度壓縮；
- 明確全域性背景與角色背景的疊加規則。

### 5.2 使用者/AI 訊息

檢查：

- 使用者與 AI 是否仍可區分；
- 編輯、複製、Swipe、刪除等訊息操作是否可見；
- 程式碼塊、引用、表格、長 URL 是否溢位；
- 系統訊息、錯誤訊息、群聊角色名是否有單獨語義；
- hover-only 操作在觸控裝置是否可達。

### 5.3 頭像

頭像形狀、尺寸、邊框和線上/說話狀態要獨立。不要透過隱藏頭像父節點的方式省空間，可能連帶隱藏角色名和訊息操作區。

### 5.4 輸入與傳送區

輸入區是逃生主鏈，不允許為了視覺而犧牲：

- 輸入文字對比度；
- placeholder 可讀性；
- 傳送、停止生成、附件、快捷回覆按鈕；
- 多行擴充套件與軟鍵盤；
- focus ring；
- 停用/生成中狀態。

### 5.5 抽屜、頂欄、Popup 與 Toast

這些區域通常使用獨立層級和 z-index。美化時需驗證：

- 左右抽屜不會被聊天畫布蓋住；
- Popup 遮罩和主體對比足夠；
- Toast 不被固定底欄遮擋；
- 魔棒/擴充套件選單仍能滾動和點選；
- 第三方擴充套件設定面板繼承的變數不會變成黑底黑字。

## 6. Custom CSS 層疊與衝突控制

### 6.1 分層組織

```css
@layer my-theme.reset, my-theme.tokens, my-theme.layout,
       my-theme.components, my-theme.utilities;
```

若目標瀏覽器支援 cascade layers，可用層控制優先順序；否則仍按“令牌→佈局→元件→修補”順序組織檔案。避免從頭到尾堆 `!important`。

### 6.2 作用域

純主題通常直接作用宿主。若是 UI Extension 動態啟用，先給根節點加標誌類：

```javascript
document.documentElement.classList.add('my-theme-enabled');
```

```css
.my-theme-enabled #chat .mes { /* ... */ }
```

停用/解除安裝時移除標誌類和注入 style。這樣比給每條規則盲目提高 specificity 更可控。

### 6.3 衝突定位

遇到樣式不生效，按順序檢查：

1. 目標元素是否仍存在；
2. 規則是否命中正確宿主 document；
3. computed style 的勝出來源；
4. 主題切換是否替換了 Custom CSS；
5. 第三方擴充套件是否後注入更高優先順序；
6. 移動斷點是否覆蓋桌面規則；
7. 屬性內聯樣式是否來自執行時 JS。

不要先加 `!important`，否則只會掩蓋錯誤選擇器或錯誤層級。

### 6.4 禁止隱藏關鍵控制元件

任何主題都不應全域性隱藏：

- 使用者設定與主題恢復入口；
- 擴充套件管理；
- 輸入框、傳送、停止生成；
- Popup 關閉/取消；
- 訊息編輯/刪除的唯一入口；
- 無障礙焦點指示。

如果設計確需視覺隱藏，仍要保留可訪問替代與“安全模式”恢復路徑。

## 7. 響應式、動態視口與安全區

### 7.1 斷點不是永久常量

當前核驗快照中 ST 核心移動樣式存在約 1000px 主斷點，但這屬於版本敏感實現，不能作為永遠不變的 API。自定義主題應根據自身內容設定少量斷點，並在目標 ST 版本複核核心佈局。

### 7.2 `dvw/dvh` 與 visualViewport

宿主固定表面優先使用動態視口單位，並在必須 JS 定位時讀取 `visualViewport`。尤其驗證：

- 手機瀏覽器位址列收放；
- 軟鍵盤；
- PWA standalone；
- 橫屏；
- 瀏覽器縮放；
- 桌面窄窗。

### 7.3 Safe Area

```css
.my-bottom-surface {
  padding-bottom: max(8px, env(safe-area-inset-bottom));
  padding-left: max(8px, env(safe-area-inset-left));
  padding-right: max(8px, env(safe-area-inset-right));
}
```

不要只測豎屏底部 Home 條；橫屏左右劉海和 PWA 頂部區域同樣需要驗證。

### 7.4 移動端不復制核心佈局

只覆蓋顏色、間距、圓角等必要表面。若重新定義整個抽屜寬度、頂欄定位和傳送區高度，等於自行 fork ST 移動佈局，後續升級成本極高。

## 8. 可訪問性與低效能模式

### 8.1 必驗項

- 正文和背景對比度；
- 連結與普通文字不僅靠顏色區分；
- 清晰 focus-visible；
- 200% 字型下不截斷關鍵按鈕；
- 粗指標熱區至少約 44px；
- 錯誤/成功不只用紅綠；
- 動畫不會導致眩暈或阻塞操作。

### 8.2 尊重使用者設定

官方提供 Reduced Motion、No Blur、No Text Shadow 等低效能/可訪問設定。主題不應透過更高優先順序把這些效果強行加回來。

```css
/* ST 內部 Reduced Motion 開關 */
body.reduced-motion *,
body.reduced-motion *::before,
body.reduced-motion *::after {
  animation: none !important;
  transition-duration: 1ms !important;
  scroll-behavior: auto !important;
}

/* 作業系統偏好 */
@media (prefers-reduced-motion: reduce) {
  .decorative-animation {
    animation: none !important;
  }
}
```

純 UI Theme 不依賴 `.my-theme-enabled` 這類只有 UI Extension 才會動態新增的根類。若用擴充套件控制主題，可額外加作用域，但仍須響應 `body.reduced-motion`。

### 8.3 模糊降級

```css
.my-surface {
  background: rgba(25, 28, 37, 0.96);
}

@supports (backdrop-filter: blur(8px)) {
  .my-surface {
    background: rgba(25, 28, 37, 0.76);
    backdrop-filter: blur(8px);
  }
}

body.no-blur .my-surface { backdrop-filter: none !important; }
body.noShadows .my-surface { box-shadow: none !important; }
```

低端機長聊天滾動掉幀時，先關閉 blur、陰影、固定背景和粒子；不能以降低文字對比度換效能。

## 9. 字型、圖片和外部資源

### 9.1 字型

推薦本地系統字型棧或使用者顯式安裝的字型。外部字型要考慮：

- 載入失敗 fallback；
- CORS/CSP；
- 首屏閃爍；
- 字形是否覆蓋中日韓；
- 許可；
- 外部請求暴露 IP、Referer 和使用時間。

```css
font-family: "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif;
```

### 9.2 不預設推薦 `@import`

遠端 `@import` 隱藏了供應鏈和載入順序；在當前 ST 實現中，**匯入含 `@import` 的主題**會彈出安全確認。優先把審計後的 CSS 隨主題包分發；確需遠端載入時列出固定來源、版本、完整性策略和離線 fallback。

### 9.3 圖片

- 背景圖壓縮並提供多尺寸；
- 使用穩定 HTTPS；
- 斷網時不影響關鍵 UI；
- 不用外鏈畫素作為追蹤；
- 不把含敏感 token 的 URL 寫入主題；
- 明確作者、許可和再分發權。

## 10. 打包、匯入匯出與版本遷移

### 10.1 包內容

建議包含：

```text
my-theme/
  README.md
  theme.json              # ST 匯出的主題快照
  custom.css              # 如需單獨審計
  assets/
  compatibility.md
  CHANGELOG.md
  preview/
```

README 必須寫：目標 ST 快照、啟用方式、外部資源、影響範圍、已知衝突、恢復步驟。

### 10.2 匯入前備份

官方主題管理支援儲存、匯入、匯出。匯入第三方主題前先：

1. 儲存當前設定為主題；
2. 匯出備份；
3. 擷取關鍵設定；
4. 再匯入新主題；
5. 驗證關鍵控制元件；
6. 有問題立即回滾。

主題切換會使用目標主題記錄的 Custom CSS 替換當前 Custom CSS，這是預期行為。重要修改要先儲存回主題或匯出，不應當成隨機丟失。

### 10.3 版本遷移

每次 ST 大版本更新：

- 比較官方主題欄位；
- 檢查已刪除/重新命名變數；
- 用 DevTools 找失效選擇器；
- 複測移動斷點、抽屜和 Popup；
- 記錄 `ST版本 / 主題版本 / 核驗日期 / 已知衝突`；
- 不用“最新版通用”代替相容矩陣。

## 11. 安全回滾

### 11.1 發行必須提供逃生路徑

- 匯入前備份原主題；
- 提供一鍵關閉美化擴充套件；
- 不隱藏使用者設定；
- 保留純 CSS 檔案，便於定位壞規則；
- UI Extension 實現 `destroy` 並移除標誌類/style；
- 外部資源失敗回退系統字型和純色；
- 文件列出恢復預設主題步驟。

### 11.2 頁面已被美化“弄壞”

恢復順序：

1. 嘗試進入使用者設定切回已知可用主題；
2. 停用對應 UI Extension；
3. 清空/替換 Custom CSS；
4. 重新整理並確認原生輸入、傳送和設定恢復；
5. 逐段重新啟用 CSS，定位最小故障塊；
6. 不在故障狀態繼續堆覆蓋規則。

具體檔案級恢復依部署方式而異，見 D4；本冊不建議直接修改 ST 核心 CSS。

## 12. 高頻錯誤

| 錯誤 | 後果 | 修復方向 |
|---|---|---|
| 把卡內 CSS 當宿主主題 | 影響範圍和許可權混亂 | C3/C9 分層 |
| 卡片靜默改全域性主題 | 汙染所有聊天 | 使用者顯式匯入/啟用 |
| 複製整份核心 CSS | 升級後大量衝突 | 令牌和最小覆寫 |
| 深層 nth-child | 小更新即失效 | 語義區域 + 能力檢測 |
| 無腦 `!important` | 無法維護、擴充套件互相打架 | 分層與 computed style 定位 |
| 隱藏設定/傳送 | 使用者無法恢復或聊天 | 關鍵控制元件禁止隱藏 |
| 只在 Bubble 測試 | Flat/Document 破版 | 明確支援矩陣 |
| 只測桌面 | 手機軟鍵盤/安全區遮擋 | 真機移動矩陣 |
| 強制 blur/動畫 | 低端機掉幀、違背使用者偏好 | No Blur/Reduced Motion 降級 |
| 遠端字型無 fallback | 斷網白字/錯位 | 系統字型棧 |
| 主題切換後 CSS“丟失” | 未儲存的修改被替換 | 先儲存/匯出主題 |
| 把宿主選擇器當永久 API | ST 更新後失效 | 版本快照 + 相容測試 |

## 13. 驗收矩陣

| 維度 | 必驗場景 |
|---|---|
| 主題生命週期 | 新建、儲存、更新、匯出、匯入、切換、刪除、恢復預設 |
| 表面覆蓋 | 背景、三種聊天模式、頭像、訊息、輸入區、抽屜、Popup、Toast、Wand |
| 桌面 | 1366/1920、窄聊天寬度、全寬、瀏覽器縮放 |
| 移動 | 320/375/430、橫屏、軟鍵盤、PWA safe-area |
| 可訪問性 | 鍵盤焦點、對比度、200% 字型、44px、Reduced Motion |
| 效能 | No Blur、低配機滾動、長聊天、動畫關閉 |
| 失敗 | 外部字型/背景斷網、CSS 語法錯誤、第三方主題/擴充套件衝突 |
| 回滾 | 始終能進入設定並恢復；關鍵互動未隱藏 |
| 隔離 | 切角色/聊天不出現角色卡私有樣式意外汙染 |
| 相容 | 最低支援版與當前核驗版各跑一次並記錄日期 |

穩定完成門：只有在“啟用、正常使用、停用、恢復預設”四條鏈都可復現時，主題才可分發；視覺截圖不能替代互動、效能和回滾驗收。

### 14.2 當前核驗快照

2026-07-14 核驗時，SillyTavern release 頁面顯示 `1.18.0`。這只是當日快照，不是本冊永久基線。既有指南中的 `1.14.0` 結論應視為歷史觀察，施工必須以目標例項為準。

### 14.3 版本敏感項

- Theme JSON 欄位和 `--SmartTheme*` 變數集合；
- 宿主 DOM ID/class、Popup 和抽屜結構；
- 核心移動斷點與 safe-area 規則；
- Custom CSS 與第三方 UI Extension 的載入先後；
- 外部 CSS、CSP、字型跨域和 Safari `backdrop-filter`；
- 主題切換對 Custom CSS 的替換行為。

### 14.4 待目標環境驗證

- 最低支援 ST 版本與當前釋出版的主題欄位差異；
- 第三方擴充套件同時修改輸入區、Wand、訊息操作區時的優先順序；
- iOS Safari/PWA 的模糊、fixed 背景和 safe-area；
- 目標中文字型在 Windows、Android、iOS 的字重與行高；
- 使用者啟用高對比、No Blur、Reduced Motion 後是否仍可用。

結論置信度：官方主題/Custom CSS 行為為 **high** `[官方文件]`；具體宿主選擇器和當前斷點為 **medium** `[當前原始碼快照]`，必須隨版本複核。
