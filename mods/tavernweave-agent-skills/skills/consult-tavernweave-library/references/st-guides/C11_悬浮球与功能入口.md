## 1. 定義與邊界

### 1.1 什麼是“功能入口”

功能入口是宿主介面中的 **launcher**。它不自己實現人物面板、狀態列、控制中心、開局頁或媒體庫，只把使用者意圖轉換成穩定命令：

```text
Wand / 懸浮球 / 頁面按鈕 / 快捷鍵
                 ↓
          command registry
                 ↓
     openHud / openNpc / openWorkshop ...
```

因此入口層的驗收標準不是“面板內容是否豐富”，而是：

- 入口在正確的宿主文件中只存在一份；
- 每個動作只觸發一次；
- 不可用功能有明確停用或說明；
- 換入口不會複製業務處理器；
- 切聊天、熱過載、切卡後不會殘留舊節點和舊監聽。

### 1.2 四個容易混淆的概念

| 概念 | 職責 | 本冊是否負責 |
|---|---|---:|
| Wand / 魔棒按鈕 | 使用 ST/酒館助手既有選單作為入口 | 只講統一路由；掛載細節轉 E5 |
| 懸浮球 | 可移動、可吸邊的常駐 launcher | 是 |
| 抽屜式狀態列 | 從視口邊緣展開的 HUD 外殼 | 否，見 C12 |
| 浮窗式狀態列 | 可拖動、可縮放的 HUD 外殼 | 否，見 C13 |

“懸浮球開啟浮窗”不代表二者是同一種元件。懸浮球消失時，已經開啟的浮窗仍可獨立存在；浮窗失敗時，懸浮球也不應被拖死。

## 2. 總體架構

推薦把“入口、命令、外殼、內容”拆成四層：

```text
EntryAdapter
  ├─ WandEntry
  ├─ OrbEntry
  └─ PageButtonEntry
          ↓ dispatch(actionId)
CommandRegistry
          ↓
HudHostCore / OtherFeatureHost
          ↓
DrawerShell / FloatingShell / ModalShell
          ↓
Feature body / iframe / 狀態列真身
```

這套分層解決三個常見退化：

1. Wand、懸浮球各寫一套 `if (action === ...)`，日後行為不一致；
2. 入口指令碼直接引用另一個閉包裡的私有函式，點選時才出現 `ReferenceError`；
3. 功能內容過載時入口也被重複建立，最後一擊觸發兩次。

入口層只能依賴公開命令，不應跨閉包呼叫未匯出的頁面內部函式。

## 3. 入口登錄檔

### 3.1 最小契約

```javascript
const commandRegistry = new Map();

export function registerCommand(definition) {
  const { id, label, icon, available, handler } = definition;
  if (!id || typeof handler !== 'function') {
    throw new TypeError('command requires id and handler');
  }
  if (commandRegistry.has(id)) {
    throw new Error(`duplicate command: ${id}`);
  }
  const availability = typeof available === 'function'
    ? available
    : () => available === false ? '功能已停用' : true;
  commandRegistry.set(id, {
    id,
    label: label || id,
    icon: icon || '',
    available: availability,
    handler,
  });
  return () => commandRegistry.delete(id);
}

export async function dispatchCommand(id, context = {}) {
  const command = commandRegistry.get(id);
  if (!command) throw new Error(`unknown command: ${id}`);
  const result = await command.available(context);
  if (result !== true) {
    const reason = typeof result === 'string' ? result : '當前功能不可用';
    throw new Error(reason);
  }
  return command.handler(context);
}
```

`available` 不只返回布林值，最好允許返回原因。入口介面卡可以把原因渲染為 `disabled`、tooltip 或 toast，而不是點選後靜默無響應。

### 3.2 單一命令源

推薦命令定義：

```javascript
const unregisterHud = registerCommand({
  id: 'hud.toggle',
  label: '狀態列',
  icon: 'fa-chart-simple',
  available: () => hostWindow().CardRuntime?.hudReady
    ? true
    : '狀態列執行時尚未就緒',
  handler: ({ source }) => hostWindow().CardRuntime.hud.toggle({ source }),
});
```

三個入口只傳來源：

```javascript
dispatchCommand('hud.toggle', { source: 'wand' });
dispatchCommand('hud.toggle', { source: 'orb' });
dispatchCommand('hud.toggle', { source: 'opening-page' });
```

來源欄位用於日誌與埋點，不應用來分叉業務語義。確需不同能力時，註冊不同命令 ID。

### 3.3 入口健康狀態

每次開啟選單前重新計算 `available()`，不要在初始化時永久快取。聊天、卡片、依賴和生成狀態都可能變化。

建議至少區分：

- `ready`：可直接觸發；
- `busy`：正在載入或生成，暫時停用；
- `missing_dependency`：缺少 Tavern Helper、MVU 或遠端資源；
- `wrong_context`：當前不是目標卡/目標聊天；
- `failed`：上次初始化失敗，允許重試；
- `hidden`：當前裝置或配置不展示該入口。

## 4. 懸浮球狀態機

### 4.1 推薦狀態

```text
unmounted
  → free-idle / docked-idle
  → pointerdown
      ├─ 位移超過閾值 → dragging → settle → free / docked
      ├─ 吸附態長按 → half-hidden / hidden
      └─ 未移動 → menu-open
  → action-dispatch → menu-close
  → destroyed
```

執行態建議至少儲存：

```javascript
const orbState = {
  side: 'right',
  top: 0.5,
  open: false,
  dockDepth: 'full',
  fx: 0.92,
  fy: 0.55,
  docked: true,
};
```

`fx/fy/top` 使用相對視口的歸一化座標，便於在桌面、窄屏和旋轉後恢復；實際繪製前仍須重新夾取。

### 4.2 點選與拖動仲裁

不要依靠瀏覽器自動產生的 `click` 判斷。一次指標序列中明確記錄：

- `pointerId`；
- 起點與當前點；
- 是否已超過拖動閾值；
- 長按計時器；
- 是否發生 `pointercancel`；
- 是否已經 dispatch。

```javascript
const DRAG_THRESHOLD = 5;
let gesture = null;

function onPointerDown(event) {
  if (!event.isPrimary || (event.pointerType === 'mouse' && event.button !== 0)) return;
  if (gesture) return;
  event.currentTarget.setPointerCapture(event.pointerId);
  gesture = {
    pointerId: event.pointerId,
    startX: event.clientX,
    startY: event.clientY,
    startRect: getOrbRect(),
    dragging: false,
    cancelled: false,
  };
}

function onPointerMove(event) {
  if (!gesture || event.pointerId !== gesture.pointerId) return;
  const distance = Math.hypot(
    event.clientX - gesture.startX,
    event.clientY - gesture.startY,
  );
  if (distance > DRAG_THRESHOLD) gesture.dragging = true;
  if (gesture.dragging) {
    moveOrb(
      gesture.startRect.x + event.clientX - gesture.startX,
      gesture.startRect.y + event.clientY - gesture.startY,
    );
  }
}

function finishPointer(event, cancelled = false) {
  if (!gesture || event.pointerId !== gesture.pointerId) return;
  const wasDrag = gesture.dragging;
  clearLongPressTimer();
  try { event.currentTarget.releasePointerCapture(event.pointerId); } catch (_error) {}
  gesture = null;
  if (cancelled) return;
  if (wasDrag) settleAndPersist();
  else toggleOrbMenu();
}
```

iOS 系統邊緣手勢、通知中心和瀏覽器導航可能產生 `pointercancel`。它必須和 `pointerup` 一樣清計時器、釋放臨時態，但不能當作點選。

### 4.3 長按與半隱藏

長按只能在“仍未拖動、仍為同一 pointer、懸浮球處於吸附態”時切換收納深度。進入拖動、取消、抬起或銷燬時都必須取消計時器。

半隱藏不能把可點選面積一併縮到螢幕外。視覺主體可移出一部分，但觸控熱區仍應至少 44×44 CSS px，並保留可見提示。

## 5. 位置、吸附與持久化

### 5.1 可用視口

優先使用 `visualViewport`，同時保留無該 API 的回退：

```javascript
function hostWindow() {
  try {
    if (window.parent && window.parent !== window && window.parent.document) {
      return window.parent;
    }
  } catch (_error) {}
  return window;
}

function visibleViewport() {
  const host = hostWindow();
  const vv = host.visualViewport;
  return vv
    ? { x: vv.offsetLeft, y: vv.offsetTop, w: vv.width, h: vv.height }
    : { x: 0, y: 0, w: host.innerWidth, h: host.innerHeight };
}
```

入口掛在宿主 document 時，視口、`matchMedia`、`getComputedStyle`、儲存和跨過載單例也必須從 `hostWindow()` 取得。裸 `window` 在 TH iframe 中只代表指令碼 iframe。

夾取時還應減去：

- `env(safe-area-inset-*)`；
- ST 頂欄或側欄實際佔用；
- 底部輸入區；
- 懸浮球自身尺寸與可觸控熱區。

### 5.2 吸附策略

常見策略：

- 距離左右邊緣小於閾值時吸邊；
- 四角附近優先保留輪盤展開淨空；
- 使用者關閉吸附時儲存自由座標；
- 切橫豎屏後重新夾取，不直接相信舊畫素；
- settle 時只計算一次目標真值並立即持久化；CSS 只從當前視覺位置過渡到目標，動畫幀不得反寫業務狀態。

“靠最近邊”不是唯一目標。若右邊已有 ST 浮動控制元件，應允許避讓或選擇淨空更大的邊。

### 5.3 儲存格式

```javascript
const STORAGE_VERSION = 1;

function saveOrbPlacement(state) {
  hostWindow().localStorage.setItem('my-card:orb-placement', JSON.stringify({
    version: STORAGE_VERSION,
    fx: state.fx,
    fy: state.fy,
    side: state.side,
    dockDepth: state.dockDepth,
    docked: state.docked,
  }));
}
```

讀取時必須：

1. `try/catch` 處理壞 JSON；
2. 校驗版本和欄位型別；
3. 對 `fx/fy` 夾到 `[0,1]`；
4. 無法遷移時回到安全預設值；
5. 不把角色卡可匯出的秘密或賬戶資料放入 `localStorage`。

若位置需要按裝置保留，瀏覽器本地儲存即可；若需要隨聊天同步，應放聊天級元資料，並明確它會汙染存檔和多裝置合併。

## 6. 輪盤選單與視口夾取

### 6.1 展開方向

固定一個扇形角度會在四角越界。應根據懸浮球四周淨空，從上、下、左、右或對角方向中選擇可容納最多按鈕的一組角度。

```text
availableLeft / availableRight
availableTop  / availableBottom
              ↓
chooseArc(centerAngle, radius, itemCount)
              ↓
measure → clamp → render
```

### 6.2 測量紀律

動畫中的元素被 `scale()` 後，`getBoundingClientRect()` 會返回視覺縮放尺寸，容易低估按鈕寬度。選單佈局測量優先使用穩定佈局尺寸：

- `offsetWidth/offsetHeight`；
- 關閉 transform 後的離屏測量；
- 明確的 CSS 變數尺寸。

最終每個按鈕的位置仍須獨立夾取，不能只保證圓心在螢幕內。

### 6.3 DOM 語義

```html
<button id="card-orb" type="button"
        aria-label="開啟角色卡功能選單"
        aria-controls="card-orb-menu"
        aria-expanded="false"></button>

<div id="card-orb-menu" role="menu" hidden>
  <button type="button" role="menuitem" data-action="hud.toggle">狀態列</button>
</div>
```

不要用無 `tabindex`、無鍵盤事件的 `div` 假裝按鈕。選單開啟時同步 `aria-expanded`；關閉後把焦點還給懸浮球。

## 7. 輸入、無障礙與移動端

### 7.1 統一 Pointer Events

優先使用 `pointerdown/move/up/cancel` + pointer capture，不要分別維護滑鼠和觸控兩套狀態機。樣式需按實際手勢設定 `touch-action`，但不要粗暴停用整個頁面的縮放和滾動。

### 7.2 鍵盤

- `Enter` / `Space`：開啟選單或觸發當前按鈕；
- `Escape`：關閉選單並歸還焦點；
- 方向鍵：在輪盤項間移動焦點；
- `Tab`：遵循自然順序，選單關閉時隱藏內部焦點；
- 不用只靠顏色表示可用/不可用。

拖動是增強能力，不能成為唯一操作。應提供“重置位置”“固定左側/右側”設定，讓鍵盤和輔助技術使用者也能恢復入口。

### 7.3 Reduced Motion

```css
@media (prefers-reduced-motion: reduce) {
  .card-orb,
  .card-orb-menu > button {
    animation: none !important;
    transition-duration: 1ms !important;
  }
}
```

Canvas 桌寵、粒子和週期搖晃都應在 reduced-motion 下停用；不只是縮短 CSS 動畫。

## 8. 生命週期與資源清理

### 8.1 單例安裝

```javascript
const RUNTIME_KEY = '__MY_CARD_ENTRY_RUNTIME__';
const host = hostWindow();

host[RUNTIME_KEY]?.destroy?.();
const api = installEntryRuntime();
host[RUNTIME_KEY] = api;
```

宿主節點使用穩定 ID，並在安裝前主動移除失去所有者的舊節點。只檢查 `if (node) return` 不夠：舊節點可能仍在，但監聽器已經指向被銷燬的閉包。

### 8.2 必須清理的資源

- 懸浮球、選單、樣式、提示氣泡；
- `requestAnimationFrame`；
- 長按、啟動重試、週期提示等 timer；
- `resize`、`orientationchange`、`visualViewport` 監聽；
- 文件空白點選監聽；
- `ResizeObserver` / `MutationObserver`；
- 命令註冊返回的 disposer；
- 仍在執行的非同步初始化與 AbortController。

```javascript
function destroy() {
  if (destroyed) return;
  destroyed = true;
  try { abortController?.abort(); } catch (_error) {}
  try { hostWindow().cancelAnimationFrame(rafId); } catch (_error) {}
  try { hostWindow().clearTimeout(longPressTimer); } catch (_error) {}
  while (disposers.length) {
    try { disposers.pop()?.(); } catch (error) { console.warn('entry cleanup failed', error); }
  }
  try { root?.remove(); } catch (_error) {}
  try { style?.remove(); } catch (_error) {}
  try {
    const host = hostWindow();
    if (host[RUNTIME_KEY] === api) delete host[RUNTIME_KEY];
  } catch (_error) {}
}
```

在 `pagehide`、卡片執行時銷燬和熱過載前執行清理。`CHAT_CHANGED` 是否銷燬取決於入口是否卡片專屬：卡片專屬入口必須複核當前聊天身份，不能在別的卡繼續顯示。

## 9. 卡A生產樣本

> 樣本狀態：`rolecard-diy-workshop/runtime/xingyue/3.4.9/control-center.js`，2026-07-14 本地核驗。以下結論是生產實現觀察，不是通用 API 保證。

卡A樣本已經實現：

- 宿主級固定懸浮球、Canvas 視覺與 reduced-motion；
- `side/top/fx/fy/docked/dockDepth` 狀態；
- Pointer Events、拖動、吸附、長按和 `pointercancel` 清理；
- 根據四向淨空選擇扇形選單；
- 使用穩定佈局尺寸測量按鈕後再夾取；
- 執行時銷燬、`pagehide` 清理和熱過載前銷燬舊例項；
- 懸浮球路由到狀態列、NPC、控制中心等多個功能。

需要通用指南補強的部分：

- 把專案內 `if/else` 動作分發抽成公開命令登錄檔；
- 為懸浮球位置補齊 `visualViewport`、旋轉後的統一重夾取；
- 補全鍵盤導航、選單角色與 ARIA 狀態；
- 將具體點陣桌寵、時段文案、粒子引數和 `xingyue-*` ID 留在專案層。

歷史失敗經驗同樣重要：跨閉包呼叫開局頁私有函式會在點選時出現 `ReferenceError`；Canvas 自身圓形裁剪會切斷拖尾。這兩類問題都不能靠吞異常修復。

## 10. 高頻錯誤

| 錯誤 | 症狀 | 修復方向 |
|---|---|---|
| 拖動仍觸發點選 | 鬆手後輪盤誤開 | 用統一手勢狀態機仲裁 |
| `pointercancel` 不清長按 | 系統手勢後自動半隱 | 所有終止路徑清 timer |
| 動畫與座標寫入競爭 | 吸邊時抖動、回彈 | settle 階段單寫穩定位置 |
| 固定弧度 | 角落按鈕越界 | 按四向淨空選弧並逐項夾取 |
| 測動畫態 rect | 按鈕寬度被低估 | 用穩定佈局尺寸測量 |
| 只存畫素 | 換屏幕後球消失 | 存歸一化座標，恢復時夾取 |
| 入口呼叫私有閉包 | 點選才報未定義 | 公開命令登錄檔 |
| 熱過載不銷燬 | 兩個球、動作觸發兩次 | 全域性單例 + destroy |
| Canvas 裁剪特效 | 拖尾/粒子被切斷 | 擴大緩衝區或移除錯誤裁剪 |
| 只支援滑鼠 | 手機無法拖動 | Pointer Events + coarse pointer |
| `div` 假按鈕 | 鍵盤和讀屏器不可用 | 原生 button + ARIA |
| 業務塞進入口 | 入口小改牽連整套 HUD | launcher/content surface 分層 |

## 11. 驗收矩陣

| 維度 | 必驗項 |
|---|---|
| 輸入 | 單擊、慢拖、快拖、長按、`pointercancel`、滑鼠與觸控 |
| 位置 | 中央、四邊、四角、吸附/自由、半隱/恢復 |
| 視口 | 320/375/768 寬、橫豎屏、瀏覽器縮放、軟鍵盤 |
| 選單 | 所有按鈕不越界，空白點選收起，每次動作只觸發一次 |
| 路由 | Wand、懸浮球、頁面按鈕呼叫同一命令並得到同一業務結果 |
