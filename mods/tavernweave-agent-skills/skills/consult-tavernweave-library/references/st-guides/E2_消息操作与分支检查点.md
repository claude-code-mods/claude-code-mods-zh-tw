## 2. Message 物件完整欄位參考

**來源：** `script.js`（raw GitHub）、DeepWiki 5.2、SillyTavern.NET-File-Converter  
**適用版本：** v1.14.0  
**置信度：high [執行時原始碼] [文件·多源]**

### 2.1 頂層欄位

```jsonc
{
  "name": "CharacterName",        // 傳送者名稱（必填）
  "is_user": false,               // 是否使用者訊息（必填）
  "is_system": false,             // 是否系統/註釋訊息（/sys /comment）
  "mes": "訊息正文",              // 主文字（必填）
  "send_date": "April 26, 2024 6:06am",  // 時間戳（格式不一致，見避坑 8.1 節）
  "swipes": ["版本A", "版本B"],   // 所有划動變體的文字陣列
  "swipe_id": 0,                  // 當前顯示的 swipe 索引（0-based）
  "extra": { /* 見 2.2 */ },      // 元資料物件
  "variables": {},                // per-message 變數（來自正則/指令碼寫入）
  "force_avatar": "",             // 強制使用的頭像路徑
  "title": ""                     // 訊息標題
}
```

### 2.2 extra 子欄位完整表

```jsonc
{
  "api": "openai",                // 生成來源 API
  "model": "gpt-4o",             // 使用的模型名
  "display_text": "...",          // 格式化後的顯示文字（覆蓋 mes 渲染）
  "bias": "",                     // 生成偏置
  "token_count": 123,             // token 數
  "gen_started": "...",           // 生成開始時間戳
  "gen_finished": "...",          // 生成結束時間戳
  "reasoning_duration": 0,        // 推理時長（ms）
  "time_to_first_token": 0,      // TTFT（ms）
  "media": [],                    // 附件陣列（圖片/影片/音訊）
  "media_display": "...",         // 媒體顯示模式
  "media_index": 0,               // 當前顯示媒體索引
  "files": [],                    // 檔案附件（Data Bank）
  "title": "",                    // 附加標題
  "bookmark_link": "chatname",    // 連結到的檢查點檔名（由 bookmarks.js 寫入）
  "branches": [],                 // 從該樓建立的分支列表
  "type": "",                     // 訊息型別標記
  "hidden": false,                // /hide 命令寫入，true = 不進 LLM prompt
  "tool_invocations": [],         // 工具呼叫記錄
  "uses_system_ui": false         // 是否使用系統 UI
}
```

**extra.hidden 與 is_system 區別：**

- `extra.hidden = true` — 使用者主動隱藏（/hide 命令），訊息仍顯示在 UI 中（有幽靈圖示），不發給 LLM
- `is_system = true` — `/sys` 或 `/comment` 發出的中性敘述/註釋，也不進 LLM prompt，但 UI 渲染方式不同

**【重要更正】`/messages` 命令的過濾邏輯：** `slash-commands.js:3428` 直讀：`if (!includeHidden && msg.is_system)` —— 實際過濾的是 `is_system=true` 的訊息，而 **`extra.hidden=true` 的訊息不受影響**（除非該訊息同時有 `is_system=true`）。加 `hidden=true` 引數後，`is_system=true` 的訊息也會被放行。換言之，"兩者都會被 `/messages` 排除"的說法有誤：hidden 訊息（`extra.hidden=true` 但 `is_system=false`）仍會出現在 `/messages` 輸出中。

注意 PR #5040 修復了 hidden 訊息 `is_system` 被強制清零的 bug，該 bug 會導致深度檢測失效，v1.14.0 已修復。

**來源：** `slash-commands.js`（本地直讀 3428行）、PR #5040 | **置信度：high [執行時原始碼]**（過濾邏輯已直讀原始碼確認）

## 5. 分支/檢查點機制詳解

**來源：** `bookmarks.js`（raw GitHub）  
**適用版本：** v1.14.0  
**置信度：high [執行時原始碼]**

### 5.1 資料模型

```
主聊天檔案：CharacterName - 2024-01-01@12-00-00.jsonl
├── 第 N 樓 message.extra.bookmark_link = "某自定義名 - January 1, 2024 12:00pm"
└── 第 M 樓 message.extra.branches = ["Branch #M - January 1, 2024 12:01pm"]

檢查點檔案命名：使用者輸入名稱 + " - " + humanizedDateTime()（bookmarks.js 第100行）
└── 第1行 chat_metadata.main_chat = "CharacterName - 2024-01-01@12-00-00"

分支檔案命名：`Branch #${mesId} - ${humanizedDateTime()}`（bookmarks.js 第174行直讀，mesId 是訊息樓層號）
└── 第1行 chat_metadata.main_chat = "CharacterName - 2024-01-01@12-00-00"
```

- `extra.bookmark_link` — 字串，指向檢查點 JSONL 檔名（不含副檔名）
- `extra.branches` — **純字串陣列**，每條為一個分支檔名（bookmarks.js 第189行直讀：`lastMes.extra['branches'].push(name)`，name 是字串）；**懸案已解除，見第9章**

### 5.2 關鍵實現函式

```javascript
// 建立檢查點（bookmarks.js）
createNewBookmark(mesId, { forceName = null })
// 1. 獲取已有聊天名 getExistingChatNames()
// 2. 生成唯一名 "{mainChat} - Checkpoint #{N}"
// 3. 儲存為獨立 JSONL 檔案（含訊息到 mesId 為止）
// 4. 在 chat[mesId].extra.bookmark_link 寫入檢查點檔名
// 5. saveChat()

// 建立分支（bookmarks.js）
createBranch(mesId)
// 1. 生成名稱格式：`Branch #${mesId} - ${humanizedDateTime()}`（bookmarks.js 第174行直讀，是 mesId 非遞增N）
// 2. 儲存為獨立 JSONL 檔案（含訊息到 mesId 為止）
// 3. 在 chat[mesId].extra.branches 追加分支檔名（字串 push）
// 注意：createBranch() 本身不切換聊天，切換由上層 branchChat() 呼叫 openCharacterChat()/openGroupChat()

// 返回主聊天
backToMainChat()
// 讀取 chat_metadata['main_chat'] → 呼叫 openCharacterChat()/openGroupChat()
```

**避坑：** 分支命名使用 `Branch #${mesId} - humanizedDateTime()`（mesId 為樓層號），不使用 `getUniqueName()`，無遞增編號邏輯。若手動刪除分支檔案，`extra.branches` 陣列中仍保留檔名，切換時會出現死鏈錯誤。[high，執行時原始碼]

**避坑：** `/branch-create` 執行後會立即切換聊天，觸發 `CHAT_CHANGED` 事件。角色卡的所有狀態需在 `CHAT_CHANGED` 回撥中重新初始化，否則舊狀態殘留。[high，推斷+真機]

### 7.3 擴充套件 API 事件監聽正規化（角色卡正則指令碼上下文）

**來源：** `control_center.js`（生產卡實戰程式碼，真機驗證）  
**置信度：high [真機]**

```javascript
function bindEvents() {
    const on = typeof eventOn === 'function' ? eventOn : null;
    const events = window.tavern_events || {};
    const disposers = [];

    // 監聽 swipe 事件（用於同步狀態）
    if (on && events.MESSAGE_SWIPED) {
        disposers.push(on(events.MESSAGE_SWIPED, (messageId) => {
            // messageId 為被 swipe 的樓層索引
            handleSwipeChange(messageId);
        }));
    }

    // 監聽 AI 訊息渲染完成
    if (on && events.CHARACTER_MESSAGE_RENDERED) {
        disposers.push(on(events.CHARACTER_MESSAGE_RENDERED, (messageId) => {
            updateStatusBar(messageId);
        }));
    }

    // 監聽聊天切換（切換角色/分支時觸發）
    if (on && events.CHAT_CHANGED) {
        disposers.push(on(events.CHAT_CHANGED, () => {
            reinitialize();
        }));
    }

    // 監聽 MVU 變數初始化完成（自定義變數系統）
    if (Mvu?.events?.VARIABLE_INITIALIZED) {
        disposers.push(eventOn(Mvu.events.VARIABLE_INITIALIZED, () => {
            refreshDisplay();
        }));
    }

    // 清理（元件解除安裝時呼叫返回函式）
    return () => disposers.forEach(d => typeof d === 'function' ? d() : d?.off?.());
}
```

## 8. 高頻避坑

**來源綜合：** `slash-commands.js` / `script.js` / `bookmarks.js` / 本地生產卡 / 社群 issue

### 8.1 send_date 格式不一致

**置信度：medium [文件·單源]** | 來源：Issue #2151

ST 的 `send_date` 欄位歷史上存在多種格式：`"April 26, 2024 6:06am"`、Unix 毫秒時間戳、ISO 8601 等。不要用 `new Date(send_date)` 直接解析，需做格式檢測。官方 issue #2151 承認此問題但已 Stale（未修復）。

### 8.2 /addswipe 不能給使用者訊息或系統訊息新增 swipe

**置信度：high [執行時原始碼]** | 來源：`slash-commands.js`（本地直讀 3860-3866行）

【重要更正】`addSwipeCallback` 內部檢查的是 `is_user`（行3860）和 `is_system`（行3865），**不是** `extra.hidden`。違反條件時會觸發 `toastr.warning` 彈出提示，**並非靜默失敗**。`extra.hidden=true` 的訊息不受此限制。

### 8.3 /delswipe 的 swipe-id 是 1-based，LALib 是 0-based

**置信度：high [執行時原始碼]** | 來源：`slash-commands.js`（本地直讀 1534行 `description: '1-based swipe id'`）

- `/delswipe 1` — 刪除第一個 swipe（1-based）
- `/delswipe`（無引數）— 刪除**當前**swipe（deleteSwipeCallback 第3910行：無引數時 swipeId=null，deleteSwipe 內部取當前 swipe_id）
- `/swipes-del 0` — 刪除第一個 swipe（LALib，0-based，需安裝 LALib 擴充套件）

混用時必須換算，否則刪錯位置。

### 8.4 extra.hidden 和 is_system 行為差異

**置信度：medium [執行時原始碼]** | 來源：`slash-commands.js`、PR #5040

兩者都排除在 LLM prompt 和 `/messages` 命令之外，但 UI 渲染方式不同。PR #5040 修復了 hidden 訊息 `is_system` 被強制清零的 bug（深度檢測失效），v1.14.0 已修復。

### 8.5 檢查點檔案命名：空名自動遞增，使用者自定義名加時間戳

**置信度：high [執行時原始碼]** | 來源：`bookmarks.js`（本地直讀 82-101行）

【更正】草稿說使用 `getUniqueName()`，實際不是。`getBookmarkName()` 的邏輯：
- 使用者輸入名稱 → 最終名稱 = `"使用者名稱 - humanizedDateTime()"`（每次生成新時間戳，幾乎不重複）
- 使用者輸入空字串 → 自動生成 `"Checkpoint #N"` 迴圈遞增查詢未被使用的編號（bookmarks.js 第89-94行）
- 分支命名格式：`"Branch #${mesId} - humanizedDateTime()"`，無去重邏輯

手動刪除檢查點檔案後，空名自動遞增編號可能跳躍，但已存在的 bookmark_link 連結會變成死鏈（跳轉時 404/無法開啟）。

### 8.6 context.chat 陣列是可變引用

**置信度：high [文件·多源]** | 來源：官方擴充套件 API 文件

擴充套件 API 文件明確：`"Messages are mutable, so any changes you make to the array will be reflected"`。在 `GENERATION_AFTER_COMMANDS` 事件中修改 `chat` 陣列會真實影響發給 LLM 的內容，但修改必須在回撥中**同步完成**（非同步修改可能無效）。

### 8.7 getChatMessages 返回的欄位名不統一

**置信度：high [真機]** | 來源：`control_center.js`（生產卡）

不同版本 ST 或不同訊息來源的欄位名存在差異，必須做三重相容：

```javascript
msg?.message || msg?.mes || msg?.text || ''
```

### 8.8 分支切換會觸發 CHAT_CHANGED

**置信度：high [推斷+真機]** | 來源：本地實戰

`/branch-create` 執行後立即切換聊天，觸發 `CHAT_CHANGED` 事件。角色卡的所有狀態需在 `CHAT_CHANGED` 回撥中重新初始化，否則舊狀態殘留。

### 8.9 swipe 切換隻觸發 MESSAGE_SWIPED，不觸發 MESSAGE_UPDATED

**置信度：medium [推斷]**

需要同時監聽兩個事件才能覆蓋所有訊息變化場景。

### 8.10 /hide 無引數預設末尾，range 是包含區間

**置信度：high [執行時原始碼]** | 來源：`slash-commands.js`

`3-7` 表示下標 3、4、5、6、7 共 5 條訊息（包含兩端）。
