## 0. 置信度分級體系（全手冊適用）

> **收集日期統一宣告**：本手冊全部條目收集於 **2026-06-28**，交叉驗證跨 14 個獨立來源。原始碼級斷言的回源核實基於本地 **SillyTavern v1.14.0** + 本地成熟卡（**卡A v2.5.0 / 卡B v2.6.0**）；ST 原始碼引用的 PR/commit 號為採集時快照，行號可能隨版本漂移。

每條結論採用 **置信度等級 + 依據型別** 雙軸標註。

### 1 置信度三級

| 級別 | 含義 | 判定標準 |
|---|---|---|
| **high** | 已坐實，可直接施工 | 有執行時證據（真機實測 / 讀到執行時實現原始碼 / 生產卡驗證）；結論是原始碼/文件的直接事實而非下游推導；不在懸案清單 |
| **medium** | 待驗證，施工前須實測 | 強制二選一子標籤：`medium·單源孤證`（單一來源、無第二源、無實測）/ `medium·推導未驗證`（原始碼或邏輯推導成立但未跑通，須隨附真機驗證路徑）|
| **low** | 孤證無源，禁止據此施工 | 零來源猜測 / 純歷史快照（須標年份 + 窄縮適用範圍）|

### 2 依據型別標籤（與置信度正交，強制標註）

`[執行時原始碼]`、`[真機]`、`[文件·多源]`、`[文件·單源]`、`[社群]`、`[推斷]`、`[歷史孤證:年份]`、`[無源·待考]`

### 3 兩條鐵規

1. **「從原始碼事實再推一步」的下游推導，即使原始碼本身已直讀，該推導結論最高只能 `medium·推導未驗證`**——除非已真機驗證；原始碼內部事實仍標 `high [執行時原始碼]`。
2. **節級標註 = 節內條目下確界**——禁止整節標 high 卻內含懸案條目；衝突即在節內區域性降級，並交叉引用第 13 章。

## 2. ST 服務端：PNG tEXt Chunk 讀寫管道

### 2.1 讀取管道（三段快取）

**核心結論**：ST 角色卡讀取走**三級快取穿透**鏈路，命中越早則越快。

```
請求命中 MemoryLimitedMap（記憶體 LRU，預設 100 MB）
  ↓ 未命中
DiskCache（node-persist 磁碟快取，5 分鐘 SYNC_INTERVAL）
  ↓ 未命中
從 PNG 檔案提取 tEXt chunk（character-card-parser）→ 寫雙層快取
```

來源：DeepWiki ST 5.1 角色管理 ｜ 適用版本：v1.14.0 ｜ 置信度：high `[執行時原始碼]`

### 2.2 寫入管道

寫入時：

1. 呼叫 `writeCharacterData`
2. `applyAvatarCropResize` 將頭像標準化到 **512×768**（Jimp 解碼 + 縮放；原始碼常量 `AVATAR_WIDTH=512, AVATAR_HEIGHT=768`，非 400×600）
3. `write-file-atomic` 原子寫入，防止資料損壞

**V2/V3 雙寫相容**：寫入時同時寫 `chara`（CCv2 base64）和 `ccv3`（CCv3，將 spec 改為 `chara_card_v3` 後編碼）兩個 tEXt chunk，保持向後相容；讀取時 ccv3 優先。V3 寫入在 try-catch 內，JSON 解析失敗時靜默跳過。

來源：`src/character-card-parser.js` write()/read() 函式 + `src/constants.js` AVATAR_WIDTH/AVATAR_HEIGHT ｜ 適用版本：v1.14.0 ｜ 置信度：high `[執行時原始碼]`

### 2.3 快取容量規劃

經驗估算（非官方承諾）：**每 3000 個角色卡 +100 MB 記憶體快取**。預設 100 MB 在大規模部署下容易觸發 LRU 淘汰，導致頻繁回落到磁碟/PNG 解析。

來源：ST 官方文件 config.yaml ｜ 適用版本：v1.14.0 ｜ 置信度：medium·單源孤證 `[文件·單源]`

## 4. 匯入堆溢位與防護

### 核心結論

**已知錯誤**（Issue #3406）：`FATAL ERROR: invalid table size Allocation failed - JavaScript heap out of memory`

復現環境：Node v22.11.0，Windows 10，Chromium 131，卡體積 26 MB。

**根本缺口**（截至 2026-06-28，部分修復狀態）：

| 缺口 | 狀態 |
|---|---|
| 無預匯入檔案大小校驗 | 未修復 |
| 無圖片解析度約束（Jimp 解碼高解析度圖時撐爆堆） | 未修復 |
| 無分塊/流式處理大檔案路徑 | 未修復 |
| Node.js 預設堆上限不足 | 可透過啟動引數緩解 |

來源：GitHub Issue #3406 ｜ 適用版本：v1.13.x 前後 ｜ 置信度：high `[文件·單源]`（Issue 復現過程已記錄）

### 4.1 實用緩解策略

**構建側（不依賴 ST 預設保護）**：

- 頭像解析度限制在 **512×768** 以內（對應 `applyAvatarCropResize` 使用的常量 `AVATAR_WIDTH=512, AVATAR_HEIGHT=768`；原文 400×600 有誤，已由 `src/constants.js` 原始碼直讀校正）
- JSON 內容最小化（minify），移除開發用註釋和多餘空白
- 世界書條目文字內聯壓縮（PList 格式比自然語言緊湊）

**服務端側**：

- 增大 Node.js 堆上限：`node --max-old-space-size=4096 server.js`
- 配置反向代理（Nginx）限制最大請求體，攔截超大上傳

置信度：medium·推導未驗證 `[推斷]`（構建側控制解析度有理論依據，但針對堆溢位的直接效果未實測驗證，見第 13 章 U-2）

## 5. 世界書 Token 預算機制

### 5.1 啟用與注入順序

**核心結論**：注入優先順序順序（高→低）：

1. **Constant 型別**條目（無條件注入，優先消耗 Budget）
2. **直接關鍵詞命中**的條目（Order 值大的先注入）
3. **遞迴掃描**命中的條目

**Budget 耗盡即截止**：一旦 token 預算用完，後續條目不啟用，即使關鍵詞命中。

來源：ST 官方文件 World Info ｜ 適用版本：v1.12.x+ ｜ 置信度：high `[文件·多源]`

### 5.2 關鍵配置引數

| 引數 | 作用 | 效能影響 |
|---|---|---|
| Scan Depth | 向前掃描訊息數（預設 2） | 越大 → 匹配越多 → 掃描開銷越大 |
| Min Activations | 最低啟用數（忽略 Depth 限制） | 配合 Max Depth 避免空掃 |
| Recursion Steps | 遞迴掃描輪數（0=無限） | 高遞迴 + 大 Lorebook = 嚴重卡頓 |
| Context % / Token Budget | Token 配額 | 建議固定 Budget 而非 % |
| Case-sensitive | 大小寫精確匹配 | 啟用可減少誤觸 |
| Match whole words | 全詞匹配 | 啟用可減少誤觸 |

來源：ST 官方文件 World Info ｜ 適用版本：v1.12.x+ ｜ 置信度：high `[文件·多源]`

### 5.3 Token 量化建議

| 建議 | 說明 | 置信度 |
|---|---|---|
| PList 碎片化條目 + 遞迴比單個大條目更省 token | 按需啟用，未命中時零開銷 | medium·單源孤證 `[社群]` |
| Non-Recursable 標記阻斷級聯注入 | 阻止該條目觸發進一步遞迴 | high `[文件·多源]` |
| Scan Depth=2 足夠大多數場景；戰鬥場景可升至 15 | 社群經驗值 | medium·單源孤證 `[社群]` |
| Constant 條目 ≤5 條 | 過多則過早耗盡 Budget，擠出高優先順序條目 | high `[文件·多源]` |

優先順序框架（社群建議，非官方）：核心身份/鐵律 → P9-10；常規背景 → P5-8；稀有細節 → P1-4

來源：World Info Encyclopedia (rentry.co) ｜ 置信度：medium·單源孤證 `[社群]`

## 6. 樓層 iframe 渲染效能

### 6.1 渲染節流總體架構

**核心結論**：卡B v2.6.0 生產狀態列實現了**雙緩衝節流**架構：

```
MVU 變數事件 → schedulePopulate(80ms 去抖)
  → setTimeout(delay) 延遲
    → requestAnimationFrame(幀同步)
      → populate()
        → 簽名比對（相同則跳過）
        → 當前 tab 立即渲染
        → 其餘 tab 分批 IdleCallback 延遲渲染
```

關鍵去抖時間：
- MVU 事件觸發：80ms 去抖（`VARIABLE_UPDATE_ENDED` / `VARIABLE_INITIALIZED`）
- 預設 `schedulePopulate` 延遲：50ms
- IdleCallback 超時上限：180ms
- IdleCallback fallback（不支援時）：setTimeout 45ms
- 每批延遲渲染 tab 數：2 個

來源：卡B v2.6.0 `status_bar_regex_r6.html` ｜ 適用版本：卡B v2.6.0 ｜ 置信度：high `[真機]`

### 6.2 簽名比對跳過無效渲染

**核心結論**：簽名僅序列化**頂層摘要物件**（`statRoot`），而非完整變數樹，避免深層 `JSON.stringify` 開銷。簽名相同時直接返回，不觸發任何 DOM 操作。

關鍵設計取捨：簽名包含 `statRoot(all)` + 媒體狀態摘要 + 設定項，不含完整 data blob。

來源：卡B v2.6.0 `status_bar_regex_r6.html` ｜ 適用版本：卡B v2.6.0 ｜ 置信度：high `[真機]`

### 6.3 摺疊狀態完全跳過渲染

**核心結論**：HUD 摺疊時，`renderAllTabsDeferred` 在入口直接 `return`，並在每批 nextBatch 執行前再次檢查摺疊狀態，確保已排隊的批次也能及時取消。

```javascript
if ($('#hud-body').hasClass('collapsed')) return;  // 入口檢查
// nextBatch 內再次檢查：
if (isCollapsed()) { cancelDeferredTabRender(); return; }
```

來源：卡B v2.6.0 `status_bar_regex_r6.html` ｜ 適用版本：卡B v2.6.0 ｜ 置信度：high `[真機]`

### 6.4 擴充套件 Hook 5 秒超時

**核心結論（已校準範圍）**：ST 擴充套件**生命週期 hook 函式**（`activate/install/update/delete/enable/disable/clean`）支援返回 Promise，但有 **5 秒超時**硬限制。超時後警告繼續執行（不阻塞主流）。**注意：此 5 秒限制作用於擴充套件 manifest hook，不是普通 `eventOn()` 監聽器，也不直接適用於 Tavern Helper eval 路徑**（eval 路徑走不同執行通道，見第 13 章 U-3）。

**大卡 eval 痛點（降級）**：狀態列 HTML 體積 >100 KB 時，Tavern Helper eval 是否受同一 5s 限制約束，目前無原始碼直證，見第 13 章 U-3。

**規避策略**（medium·推導未驗證，需實測）：
- Hook 內只做輕量排程，不做重計算
- 重計算移到 `requestIdleCallback` 或獨立 setTimeout 鏈
- 狀態列打包為**正則嵌入**（注入到訊息末尾 DOM），而非走 eval 路徑

來源：ST 官方文件擴充套件開發（lifecycle hook 超時條款） ｜ 適用版本：v1.14.0 ｜ 置信度：medium·單源孤證 `[文件·單源]`（5s 超時僅見於官方文件單一來源，v1.14.0 原始碼內未直接檢索到硬編碼 5000ms hook timeout；eval 路徑適用性，見第 13 章 U-3）

### 6.5 Tavern Helper iframe 事件體系

**核心結論**：iframe 與 ST 主體透過 postMessage 通訊，事件註冊用 `eventOn()`/`eventOnce()`，清理用 `eventRemoveListener()`。

關鍵事件速查：

| 事件 | 含義 |
|---|---|
| `MESSAGE_IFRAME_RENDER_STARTED` | 樓層 iframe 開始渲染 |
| `MESSAGE_IFRAME_RENDER_ENDED` | 樓層 iframe 結束渲染 |
| `GENERATION_STARTED` | 開始生成 |
| `STREAM_TOKEN_RECEIVED_FULLY` | 完整流式 token 到達 |
| `GENERATION_ENDED` | 生成完畢 |
| `VARIABLE_UPDATE_ENDED` | MVU 變數寫入完成 |
| `VARIABLE_INITIALIZED` | MVU 變數初始化完成 |

**記憶體洩漏防範（已校正）**：`eventOn()` 持續監聽；根據 JS-Slash-Runner `@types/iframe/event.d.ts` 註釋，**當 `eventOn` 所在的前端介面/指令碼關閉時，監聽將會自動解除安裝，不必手動呼叫 `eventRemoveListener` 來移除**。但狀態列 HTML 作為長期存活的 iframe（不會頻繁關閉），若在樓層重渲染回撥內部動態註冊而不清理，仍有累積風險；建議樓層級動態 hook 用完後主動 `eventRemoveListener()`，常駐 HUD 級監聽可依賴自動解除安裝。

來源：JS-Slash-Runner 本地 `@types/iframe/event.d.ts` 直讀 ｜ 適用版本：Tavern Helper v4.x（本地 v1.14.0 擴充套件目錄） ｜ 置信度：high `[執行時原始碼]`（事件體系）+ medium·推導未驗證（樓層動態 hook 累積路徑，見第 13 章 U-3）

## 10. 資源懶載入與離線 Vendor

### 10.1 無 CDN 依賴原則

**核心結論**：卡B v2.6.0 狀態列 HTML 內**無任何外部 `<script src>` 或 CDN 引用**。jQuery 和 Lodash 透過 Tavern Helper（js-slash-runner）全域性注入，iframe 內直接使用 `window.$` / `window._`，無 CDN 請求。

**效能意義**：ST 初始化卡死 30-45s（Issue #4290）的一個已知因素是外部連線超時。Vendor 從 Tavern Helper 擴充套件本地取，完全規避此風險。

來源：卡B v2.6.0 `status_bar_regex_r6.html` + GitHub Issue #4290 ｜ 置信度：high `[真機]`

### 10.2 媒體庫懶載入

**核心結論**：`media_library.js` 使用 `summaryOf()` 返回輕量狀態摘要（不含完整 blob）；簽名比對時只傳摘要物件；圖片僅在彈出預覽時透過 fetch 懶載入。

來源：卡B v2.6.0 `media_library.js` ｜ 適用版本：卡B v2.6.0 ｜ 置信度：high `[真機]`

## 12. 完整可用正規化程式碼

### 正規化 A：狀態列渲染節流（雙緩衝 + 簽名跳過）

來源：`status_bar_regex_r6.html` ｜ 置信度：high `[真機]`

```javascript
var lastPopulateSignature = '';
var populateTimer = null;
var populateRaf = null;

// 簽名只含頂層摘要，不含媒體 blob，避免深層 stringify 開銷
function hudDataSignature(all) {
  try {
    return JSON.stringify({
      stat: statRoot(all),
      settings: { key1: val1 }  // 影響渲染的設定項
    });
  } catch (e) { return String(Date.now()); }
}

// delay 預設 50ms；MVU 事件觸發時傳 80ms
function schedulePopulate(delay, force) {
  if (populateTimer) clearTimeout(populateTimer);
  var raf = window.requestAnimationFrame || function (cb) { return setTimeout(cb, 16); };
  var caf = window.cancelAnimationFrame || clearTimeout;
  var run = function () {
    if (populateRaf) caf(populateRaf);
    populateRaf = raf(function () {
      populateRaf = null;
      populate(null, { force: !!force });
    });
  };
  populateTimer = setTimeout(run, delay || 50);
}

function populate(all, options) {
  options = options || {};
  all = all || readCurrentData();
  var sig = hudDataSignature(all);
  if (!options.force && sig === lastPopulateSignature) return; // 無變化直接跳出
  lastPopulateSignature = sig;
  renderActiveTab(all);           // 當前 tab 立即渲染
  renderOtherTabsDeferred(all);   // 其餘 tab 延遲批次渲染
}

// MVU 事件掛載（init 階段）
eventOn(Mvu.events.VARIABLE_UPDATE_ENDED, function () { schedulePopulate(80); });
eventOn(Mvu.events.VARIABLE_INITIALIZED, function () { schedulePopulate(80); });
```

### 正規化 B：Tab 分批 IdleCallback 延遲渲染

來源：`status_bar_regex_r6.html` ｜ 置信度：high `[真機]`

```javascript
var deferredRenderHandle = null;
var deferredRenderUsesIdle = false;

function cancelDeferredTabRender() {
  if (!deferredRenderHandle) return;
  if (deferredRenderUsesIdle && window.cancelIdleCallback)
    window.cancelIdleCallback(deferredRenderHandle);
  else clearTimeout(deferredRenderHandle);
  deferredRenderHandle = null;
}

function scheduleDeferredTabRender(callback) {
  if (window.requestIdleCallback) {
    deferredRenderUsesIdle = true;
    deferredRenderHandle = window.requestIdleCallback(callback, { timeout: 180 });
  } else {
    deferredRenderUsesIdle = false;
    deferredRenderHandle = setTimeout(callback, 45);
  }
}

function renderOtherTabsDeferred(all) {
  cancelDeferredTabRender();
  if (isCollapsed()) return;       // 摺疊時直接返回，不排隊
  var ids = getNonActiveTabIds();
  var i = 0;
  function nextBatch() {
    if (isCollapsed()) { cancelDeferredTabRender(); return; }  // 批次間再次檢查
    var count = 0;
    while (i < ids.length && count < 2) {   // 每批最多 2 個 tab
      renderTabIfNeeded(ids[i++], all);
      count++;
    }
    if (i < ids.length) scheduleDeferredTabRender(nextBatch);
  }
  scheduleDeferredTabRender(nextBatch);
}
```

// 欄位截斷：超出 limit 字元則加省略號
const __czCtxShort = (value, limit = 80) => {
  const text = String(value || '').replace(/\s+/g, ' ').trim();
  return text.length > limit ? text.slice(0, limit) + '...' : text;

// Record 展示條數限制（預設每類最多 8 條）
const __czCtxRecordSummary = (path, mapper, limit = 8) =>
  Object.fromEntries(
    getEntries(path).slice(0, limit).map(([name, data]) => [name, mapper(data, name)])
  );
