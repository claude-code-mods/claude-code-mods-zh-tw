# A0 · 駕馭工程從零搭建檢查單（Harness Engineering · From Zero）

> 文件版本：v1.1.0 ｜ 最後更新：2026-07-17
> TW 本地修訂：2026-10-15，按使用者批准的主動釐清規則校正重複確認門檻；原始來源日期保留。

## 全域性最高優先順序工程原則

所有功能實現必須優先選擇：

1. 最簡單可維護方案
2. 最少檔案變更
3. 最少新增抽象層
4. 最少依賴

禁止：

- 為不存在的問題提前設計複雜架構
- 多層包裝同一功能
- 用補丁覆蓋架構問題
- 重複實現已有能力

如果發現已有架構不適合：
優先重構核心路徑，而不是繼續堆疊相容補丁。

> **給誰用**：任何想讓 AI 助手（Claude Code 等）長期、穩定替自己幹活的人——**不需要會寫程式碼**。
>
> **解決什麼問題**：同一個 AI 模型，有人用得像老搭檔，有人天天翻車返工。差別通常不在模型，在**駕馭層（harness）**——你圍繞 AI 搭起來的工作環境：規則檔案、記憶、檢查流程、硬護欄。一句話公式：**AI 助手的實際表現 ＝ 模型能力 × 駕馭層質量**。
>
> **怎麼用**：按階段推進，每階段末尾有「✔ 完成標誌」。**搭完一層就受益一層，不必一次全建**；卡住了就先停在當前層用著，等痛點出現再往上搭。

## 第 1 層 · 地基：常駐規則檔案（AI 的"崗位說明書"）

> AI 每輪對話都會自動讀的那份檔案（Claude Code 裡叫 `CLAUDE.md`）。沒有它，你每次開工都要口頭重新交代一遍自己是誰、要什麼。

- [ ] 在專案根目錄建規則檔案，先只寫三件事：**你是誰**（背景、會不會程式碼）、**專案是什麼**（一句話）、**溝通偏好**（語言、要不要先給結論、術語要不要解釋）。
- [ ] 保持短：**60 行以內起步**。它每輪都被讀一遍，越長越貴、越容易被忽略。
- [ ] 立一條元規則：**這檔案裡只放"每輪都要考慮"的規則**；只在特定場景用的知識放別的文件，需要時再讓 AI 去讀。
- [ ] 心法：**每條規則都應該能指著一次真實翻車說"就是因為那次"**。還沒翻過的車，先別寫規則防它——想象出來的規則會稀釋真規則。

**✔ 完成標誌**：新開一個對話，不做任何交代，AI 的第一反應就符合你的偏好（語言對、口吻對、知道專案是什麼）。

**✘ 常見坑**：把規則檔案寫成"風格指南"或願望清單。它的正確定位是**飛行員檢查單**——短、硬、每條都救過命。

## 第 2 層 · 開工同步：動手前的三格檢查（防"方向就錯了"）

> 大部分翻車不是 AI 幹得差，是它乾的根本不是你想要的。開工前先說清這三件事，減少因目標或邊界不明造成的返工。

開工前從當前與相關既有上下文檢查這三格。已經明確的內容直接沿用；只在關鍵缺項或衝突會改變方案、範圍、驗收或執行風險時詢問，低風險可逆的小缺口可以說明假設後繼續。具體提問門檻遵守[共用溝通規則](../communication-and-guidance.md)。

- [ ] **目標**：這次要做成什麼？一句話、做完能驗收的那種。順帶說清**不做**什麼。
- [ ] **紅線**：這個任務有什麼絕對不能碰的？（沒有就明說"沒有"）
- [ ] **驗收**：怎麼算做完？你打算怎麼驗證？

然後走最關鍵的一步：

- [ ] **必要時反饋理解**：有歧義時給一句可以糾正的理解，並問真正影響結果的問題。上下文已明確就推進，不要求每次三句話複述或逐句確認；理解與推定也不能代替寫入、釋出等動作所需的授權。

**✔ 完成標誌**：連續幾次任務，AI 交付的東西不再"能用但不是我要的"。

**✘ 常見坑**：忽略已有上下文，反覆確認已決定的事；或在關鍵衝突未解決時擅自開工。簡短理解反饋、材料核查和有針對性的問題都可幫助發現偏差，按當前需要選用。

## 第 3 層 · 記憶與交接：跨會話不失憶

> AI 的對話是有長度上限的，關掉就忘。不搭這層，每次新會話都從零開始，你就是它唯一的記憶體。

- [ ] 建一份**進度文件**（一個 md 檔案就行）：當前做到哪、下一步是什麼、有什麼坑。讓 AI 每次幹完活自己更新它。
- [ ] 立規矩：**進度只寫這一份**。多份文件各記各的進度 ＝ 很快沒有一份是真的。
- [ ] 每次會話結束前，讓 AI 留一段**交接摘要**：本次目標 / 完成了什麼 / 遺留什麼 / 下一步從哪繼續。
- [ ] 每次新會話開工，先讀進度與交接並核對實際產物。現狀明確就續接；只有關鍵缺項或衝突影響下一步時，簡短反饋理解並詢問，不要求再次確認已決定的事項。
- [ ] 進階（可選）：如果工具支援自動化（如 Claude Code 的 hooks），把"會話結束存交接、會話開始讀交接"做成自動的——機器兜底，不靠 AI 自覺。

**✔ 完成標誌**：隔了三天回來開新會話，兩分鐘內 AI 就能準確接上進度，不需要你重新講歷史。

**✘ 常見坑**：讓 AI"記在心裡"。它沒有心，只有檔案——**沒寫進檔案的等於沒發生**。

## 第 4 層 · 硬護欄：把"反覆犯的錯"交給機器攔（可選，需要一點配置）

> 第 1 層的規則靠 AI 自覺遵守，偶爾還是會忘。對反覆出現的同一種錯，升級成**機器強制**：工具在 AI 動手時自動檢查/攔截（如 Claude Code 的 hooks 機制），AI 忘了也犯不成。

- [ ] 盤點：過去一個月，AI 在你專案裡**重複犯過 2 次以上**的錯有哪些？
- [ ] 其中"機器能判定"的（寫錯地方、用錯命令、改完沒檢查語法），挑最痛的一兩個做成自動攔截/自動檢查。不會配置就讓 AI 自己給自己寫——描述清楚"什麼情況該攔"，讓它實現，然後你測一次。
- [ ] 原則：**能機器強制的，不靠自覺**。規則檔案管"該怎麼想"，護欄管"不許怎麼做"。

**✔ 完成標誌**：那個反覆犯的錯，再也沒成功犯出來過（AI 試圖犯的瞬間被攔下）。

## 第 5 層 · 驗證閉環：完工的定義不由 AI 說了算

> AI 有個天性：傾向於宣佈自己成功了。不搭這層，你會收到大量"已完成✅"但一用就壞的交付。

- [ ] 立規矩：**AI 說"做完了"之前，必須先證明它生效**——跑起來看結果、截圖、過測試，拿證據說話，不接受"應該沒問題"。
- [ ] 立規矩：**離線檢查透過 ≠ 交付**。凡是最終跑在真實環境裡的東西（網頁、卡片、指令碼），必須在真實環境裡驗過才算數。
- [ ] **階段門控**：大活完工時，AI 不許自己宣佈完成，必須列出「驗收對齊項」清單（做了什麼 / 怎麼驗證的 / 哪些還沒驗），逐項等你確認。
- [ ] 進階（可選）：關鍵改動讓**另一個獨立的 AI 視角**做對抗審查（換個會話或子 agent，專門挑毛病）。生成和評估分開，比讓它自查自糾有效得多。
- [ ] 止損規矩：同一個問題讓 AI 修了 **2–3 輪**還不穩，停——別再讓它打補丁，改問"要不要推倒重寫或砍掉這個功能"。越修越爛是強訊號，說明方向或架構錯了。

**✔ 完成標誌**："已完成"和"實際能用"這兩件事重新變成同一件事。

## 第 6 層 · 版本恢復：能回到"上一個好狀態"

> AI 會改壞東西，這無法避免；能避免的是改壞之後回不去。

- [ ] 給專案目錄開版本管理（git；不會用就讓 AI 幫你初始化並代管）。
- [ ] 讓 AI 養成習慣：**每完成一個可驗收的小塊就存一次版本**，附一句人話說明。
- [ ] 你只需要記住一句話的能力：「回到昨天那個還能用的版本」——有版本管理，這句話就能被執行。
- [ ] 沒條件上 git 的最低配：重要檔案改動前先複製一份帶日期的備份。

**✔ 完成標誌**：某次改崩了，你們在五分鐘內回到了已知好狀態，而不是花一晚上手工找回。

## 第 7 層 · 棘輪：讓系統只進不退

> 棘輪＝只朝一個方向轉的齒輪。前六層是設施，這一層是習慣：**每次翻車都變成設施的一部分，同一個坑不踩第二次**。

- [ ] 每次翻車後問一句："這次的教訓，落到哪一層？"——多數答案是：規則檔案加一條（第 1 層）/ 護欄加一道（第 4 層）/ 驗收清單加一項（第 5 層）。
- [ ] **口頭提醒不算落地**。"下次注意"是最貴的四個字——下次它一定不注意。
- [ ] 給重複犯的錯記個數。犯得越多的，越優先升級成硬護欄。
- [ ] 反向操作也要做：**模型升級變強後，定期刪掉不再需要的護欄**。駕馭層裡的假設會過時，臃腫的護欄和缺失的護欄一樣有害。

**✔ 完成標誌**：回看三個月前的翻車型別，現在一個都犯不出來了——不是因為你倆變小心了，是因為系統不允許了。

## 成熟度速查

| 層 | 你有了 | 效果 |
|---|---|---|
| L1 | 常駐規則檔案 | 不用每次重新自我介紹 |
| L2 | 開工三格 + 複述 | 乾的是你要的活 |
| L3 | 進度文件 + 交接 | 跨會話不失憶 |
| L4 | 硬護欄 | 重複錯犯不出來 |
| L5 | 驗證閉環 + 門控 | "完成"就是真完成 |
| L6 | 版本恢復 | 改崩了回得去 |
| L7 | 棘輪習慣 | 系統隨翻車變強 |

## 三條心法（全單濃縮）

1. **規則出自翻車，不出自想象**——沒踩過的坑不立規則，踩過的坑必須立。
2. **能機器強制的，不靠自覺**——寫進檔案不如掛上鉤子，口頭提醒等於沒提醒。
3. **檢查單要短**——長到沒人走完的檢查單，等於沒有檢查單。
