## 1. 定義、使用場景與非目標

### 1.1 定義

浮窗式狀態列是在 **ST 宿主 document** 中建立的獨立 content surface：

- 相對可視視口定位；
- 可以拖動和縮放；
- 內容通常由 iframe 或隔離容器承載；
- 關閉後可由 Wand、懸浮球或頁面按鈕重新開啟；
- 重新整理或過載後可恢復位置和尺寸；
- 切聊天時保留外殼，但內容必須切換到新上下文。

### 1.2 適用場景

- 桌面端需要邊聊天邊檢視較完整狀態；
- 狀態列有多個 Tab、人物、揹包、任務等較大內容；
- 不希望把控制中心鎖死在某條訊息樓層；
- 同一 HUD 真身還要複用到移動端抽屜；
- 需要網路載入、bridge 握手、失敗重試和內容熱更新。

### 1.3 非目標

- 不在訊息 iframe 內寫 `position:fixed` 假裝宿主浮窗；
- 不把 ST movingUI 當作角色卡穩定公開 API；
- 不在手機上強行保留細小 resize handle；
- 不透過浮窗外殼直接實現 MVU/資料庫讀寫；
- 不把“關閉浮窗”“收起浮窗內容”“狀態列內部摺疊區”混成一個狀態；
- 不把專案列舉名 `orb` 解釋為球形浮窗。專案中它可以只是“從懸浮球入口開啟 floating shell”。

## 2. 共享 HUD session

浮窗和抽屜應複用一個核心會話：

```javascript
const hudSession = {
  phase: 'idle',
  mode: 'floating',
  host: null,
  iframe: null,
  blobUrl: null,
  abortController: null,
  generation: 0,
  contextRevision: 0,
  visible: false,
  dirty: true,
  pendingChatReset: false,
  subscribers: new Set(),
  disposers: [],
};
```

職責分配：

| 模組 | 負責 |
|---|---|
| HudHostCore | phase、載入、bridge、上下文、重新整理、AbortController、Blob URL |
| FloatingShell | 浮窗 DOM、幾何、拖動、縮放、可見性、無障礙 |
| DrawerShell | top/bottom、visualViewport、手柄與單軸開合 |
| HudBody | 狀態列內容、Tab、欄位渲染、寫回 |
| EntryRegistry | Wand/懸浮球/頁面按鈕到命令的路由 |

共享 session 的意義不是“所有程式碼放一個大函式”，而是保證任意時刻只有一個活躍內容宿主、一套上下文訂閱和一份非同步真值。

## 3. 浮窗 DOM 與雙狀態機

### 3.1 推薦 DOM

```html
<section id="card-floating-hud"
         role="region"
         aria-label="角色狀態列"
         data-shell-state="visible"
         data-content-phase="ready">
  <header class="hud-drag-handle">
    <span class="hud-title">狀態列</span>
    <button type="button" data-action="collapse" aria-expanded="true">收起</button>
    <button type="button" data-action="close">關閉</button>
  </header>
  <div class="hud-body"></div>
  <div class="hud-resize-handle" aria-hidden="true"></div>
</section>
```

iframe 放入 `.hud-body`，拖動把手和關閉按鈕留在宿主外殼，確保內容載入失敗時仍可操作。這裡使用非模態 `region`；若產品改成真正模態 dialog，才增加完整焦點圈與 `aria-modal` 管理。

### 3.2 外殼狀態

```text
closed-hidden
  → opening
  → visible
     ├─ dragging
     ├─ resizing
     └─ collapsed-content
  → load-failed
  → destroyed
```

### 3.3 內容狀態

```text
idle → loading → ready
          └────→ failed → loading(retry)
ready → stale/dirty → refreshing → ready
any → destroyed
```

兩套狀態必須分開。浮窗可以 `visible + loading`，也可以 `collapsed-content + ready`。若只用 `open/closed`，通常會出現“收起後留下大塊空殼”或“載入失敗時關閉按鈕也消失”。

## 4. 幾何、夾取與持久化

### 4.1 絕對畫素真值

浮窗穩定真值建議為：

```javascript
const rect = { x: 240, y: 80, w: 430, h: 640 };
```

宿主 transform、長頁面和 CSS containing block 可能讓 `right/bottom` 或 `translate(-50%)` 定位跑到不可見區域。恢復後的穩定狀態使用明確 `left/top/width/height`：

```css
#card-floating-hud {
  position: fixed;
  left: var(--hud-x);
  top: var(--hud-y);
  width: var(--hud-w);
  height: var(--hud-h);
}
```

初始化居中可以臨時計算，但計算完成後立即落成絕對畫素，不把 transform 保留為持久化的一部分。

### 4.2 可視視口

```javascript
function hostWindow() {
  try {
    if (window.parent && window.parent !== window && window.parent.document) {
      return window.parent;
    }
  } catch (_error) {}
  return window;
}

function viewportRect() {
  const host = hostWindow();
  const vv = host.visualViewport;
  return vv
    ? { x: vv.offsetLeft, y: vv.offsetTop, w: vv.width, h: vv.height }
    : { x: 0, y: 0, w: host.innerWidth, h: host.innerHeight };
}
```

桌面通常 `offsetLeft/Top=0`，但瀏覽器縮放、移動模擬和嵌入 WebView 並不保證如此。浮窗掛宿主 document 時，視口、`matchMedia/getComputedStyle/localStorage`、事件和全域性單例都從 `hostWindow()` 獲取；TH iframe 的裸 `window` 不是宿主。

### 4.3 夾取函式

```javascript
const MIN_W = 280;
const MIN_H = 320;
const EDGE_GAP = 8;

function clampHudRect(input, viewport) {
  const availableW = Math.max(1, viewport.w - EDGE_GAP * 2);
  const availableH = Math.max(1, viewport.h - EDGE_GAP * 2);
  const minW = Math.min(MIN_W, availableW);
  const minH = Math.min(MIN_H, availableH);
  const w = Math.min(Math.max(input.w, minW), availableW);
  const h = Math.min(Math.max(input.h, minH), availableH);
  const minX = viewport.x + EDGE_GAP;
  const minY = viewport.y + EDGE_GAP;
  const maxX = viewport.x + viewport.w - w - EDGE_GAP;
  const maxY = viewport.y + viewport.h - h - EDGE_GAP;
  return {
    x: Math.min(Math.max(input.x, minX), maxX),
    y: Math.min(Math.max(input.y, minY), maxY),
    w,
    h,
  };
}
```

當可用視口小於正常最小值時，上例會臨時降低最小值以保證不出屏；產品更推薦直接返回 `useDrawer=true` 切換 C12，避免浮窗內容被壓到不可用。

### 4.4 儲存與恢復

```javascript
function saveHudRect(rect) {
  hostWindow().localStorage.setItem('my-card:hud-rect', JSON.stringify({
    version: 1,
    ...rect,
  }));
}
```

恢復流程：

1. 解析並校驗有限數字；
2. 處理版本遷移；
3. 用當前視口重新夾取；
4. 應用樣式；
5. 只在拖動/縮放結束後儲存，避免高頻寫儲存。

使用者從 4K 屏切到筆記本、瀏覽器縮小或側欄展開後，舊矩形必須重夾取。儲存成功不等於恢復可見。

## 5. 拖動、縮放與 iframe 指標仲裁

### 5.1 Pointer Events + pointer capture

拖動和縮放應使用統一 Pointer Events。開始時記錄起始指標和矩形，移動時基於起始值計算，避免累計誤差。

```javascript
function beginDrag(event) {
  if (event.button !== 0) return;
  event.currentTarget.setPointerCapture(event.pointerId);
  dragState = {
    pointerId: event.pointerId,
    startX: event.clientX,
    startY: event.clientY,
    startRect: { ...currentRect },
  };
  host.dataset.shellState = 'dragging';
  host.classList.add('hud-shell-busy');
}
```

`.hud-shell-busy iframe { pointer-events:none; }` 可避免指標進入 iframe 後丟失 `pointermove`。結束或取消時恢復 pointer events、夾取、儲存。

### 5.2 拖動區域

- 只從明確 drag handle 開始；
- 按鈕、輸入框、Tab、滾動區不觸發拖動；
- 雙擊標題欄可選執行“恢復預設尺寸”，但不要和收起衝突；
- 拖動時暫時停用文字選擇；結束後恢復；
- `pointercancel` 也要結束 busy 狀態。

### 5.3 縮放

根據左上角和當前視口動態計算最大寬高：

```javascript
const maxW = viewport.x + viewport.w - currentRect.x - EDGE_GAP;
const maxH = viewport.y + viewport.h - currentRect.y - EDGE_GAP;
```

縮放把手只適合精細指標。`(pointer:coarse)` 下應隱藏或放大，並優先自動切換 drawer。不要把桌面 `mousedown` 拖動工具直接當移動端模板。

### 5.4 寫入節流

pointermove 中只更新記憶體和 `requestAnimationFrame` 內的樣式；不要每幀寫 localStorage、觸發 iframe 重排或儲存聊天元資料。

## 6. iframe bridge 與內容載入

### 6.1 推薦載入鏈

```text
fetch primary source
  → failed? fetch fallback
  → validate protocol / content
  → inject trusted bridge bootstrap
  → create Blob URL
  → create iframe
  → wait iframe load
  → wait bridge + required libraries + app-ready marker
  → phase=ready
```

HTTP 200、`load` 事件和真正應用 ready 是三件不同的事。生產握手應由狀態列真身主動設定 `data-*-ready=1` 或傳送帶協議版本的 ready 訊息。

### 6.2 Bridge 最小協議

```javascript
const BRIDGE_PROTOCOL = 1;

const bridge = {
  protocol: BRIDGE_PROTOCOL,
  getContextSnapshot,
  getVariables,
  requestVariableAction(action) {
    // action 僅允許宿主註冊的有限型別；宿主校驗 schema、作用域和上下文後執行。
    return applyValidatedVariableAction(action);
  },
  subscribe,
  notifyReady(details) {
    validateReady(details);
    markHudReady();
  },
};
```

不要把 `replaceVariables` 或整個 `window.parent` 交給遠端內容。即使同源 iframe 能訪問父視窗，也應只注入最小能力。遠端內容只提交有限 action/patch；宿主限制為當前 message 變數，clone 舊值，二次檢查 chat/message/contextRevision，做 schema 驗證後才呼叫正式寫回。只有完全受信本地內容才可在宿主側使用 `updateVariablesWith` 一類 updater，而且 updater 不跨 bridge 傳遞。

### 6.3 Blob URL 與指令碼

Blob iframe 便於把已核 HTML 與本地 bridge 組合，但要注意：

- 切換內容前 revoke 舊 URL；
- CSP、字型和相對資源路徑可能變化；
- 遠端 `<script>` 不應預設執行；
- 如果執行可信本地 bundle，明確其版本與完整性；
- iframe 銷燬後刪除所有 bridge 引用，避免閉包保留聊天資料。

### 6.4 超時與重試

為 fetch、iframe load、bridge ready 分別設定合理超時。失敗狀態保留外殼上的“重試/關閉”，而不是隻在 iframe 內顯示錯誤——iframe 自己可能根本沒載入成功。

## 7. 非同步上下文與寫回守衛

### 7.1 為什麼需要 contextRevision

使用者可以在浮窗確認框、網路請求或 iframe 初始化期間：

- 切換聊天；
- Swipe 到另一分支；
- 刪除/編輯訊息；
- 切卡；
- 切換 drawer/floating 模式。

如果非同步回撥只記住 `messageId`，它可能把資料寫回舊聊天。

### 7.2 上下文令牌

```javascript
function captureHudContext() {
  return HudContextAdapter.capture({
    revision: hudSession.contextRevision,
    generation: hudSession.generation,
  });
}

function assertHudContext(token) {
  return HudContextAdapter.matches(token)
    && token.revision === hudSession.contextRevision
    && token.generation === hudSession.generation
    && hudSession.phase !== 'destroyed';
}
```

適配層負責從實際宿主/TH 上下文獲取 chat 與 message 身份；不要假定訊息 iframe 便利函式在宿主浮窗指令碼中也是全域性函式。

所有寫操作在“使用者點選”和“真正提交前”各檢查一次。若失敗，取消並提示“聊天已切換，請重新操作”，不要偷偷改成寫當前聊天。

### 7.3 隱藏 dirty

浮窗隱藏或內部收起時，資料變化只設置 `dirty=true`。再次可見時呼叫 C12/C13 共享的 `flushDirtyHud()`：await 重新整理成功且 contextRevision 未變化後才清 dirty；失敗保留 dirty，並用 `refreshing` 防重複併發。

## 8. 開啟、關閉、收起與失敗恢復

### 8.1 三種動作要分開

| 動作 | 外殼 | iframe | visible | 適用 |
|---|---|---|---:|---|
| 關閉浮窗 | 隱藏/移除 | 通常保留或按策略釋放 | false | 暫不檢視 |
| 收起內容 | 標題欄保留 | 保留 | 可視但內容 false | 節省空間 |
| 銷燬執行時 | 移除 | 銷燬 | false | 切卡/熱過載/解除安裝 |

“收起”時要把外殼高度縮到標題欄，而不是隻隱藏 iframe 留下整塊磨砂背景。

視覺關閉前若焦點在 host/iframe 內，先歸還給開啟入口；隨後設定 `host.inert=true`，必要時 `iframe.tabIndex=-1`。開啟時恢復 inert/tabIndex。`aria-hidden` 隻影響輔助技術樹，不能單獨阻止不可見控制元件進入 Tab 順序。

### 8.2 開啟流程

```javascript
async function openFloatingHud() {
  ensureFloatingShell();
  applyRect(clampHudRect(loadRect() || defaultRect(), viewportRect()));
  setShellVisible(true);
  hudSession.host.inert = false;
  if (hudSession.iframe) hudSession.iframe.tabIndex = 0;
  hudSession.visible = true;

  if (hudSession.phase === 'idle' || hudSession.phase === 'failed') {
    await loadHud();
  } else {
    await flushDirtyHud();
  }
}
```

入口可以重複呼叫，但 `ensureFloatingShell()` 與 `loadHud()` 必須冪等。雙擊入口不能建立兩個 host。

### 8.3 失敗恢復

失敗不應自動回退為靜默關閉。外殼顯示：

- 失敗階段（網路/iframe/bridge/依賴）；
- 簡短可理解原因；
- 重試；
- 切換到 drawer（若適用）；
- 關閉；
- 可選複製診斷資訊。

重試前先 abort 上一代任務、撤銷舊 Blob URL、清掉半掛載 iframe，再啟動新 generation。

## 9. 桌面/移動模式切換

### 9.1 自動模式

```javascript
function preferredShell() {
  const host = hostWindow();
  return host.innerWidth <= 768 || host.matchMedia('(pointer: coarse)').matches
    ? 'drawer'
    : 'floating';
}
```

當斷點跨越時：

1. 防抖確認新模式；
2. 儲存當前浮窗 rect；
3. 標記 session `switching`；
4. 中止舊載入並解除舊 shell 監聽；
5. 掛載新 shell；
6. 遷移或重建唯一 iframe；
7. 保持 `contextRevision` 和 dirty 語義；
8. 恢復可見狀態。

### 9.2 何時重建 iframe

可以直接移動 iframe 的條件：

- bridge 不捕獲舊宿主節點；
- 尺寸觀察器會重新繫結；
- CSS 和相對資源不依賴舊層級；
- 移動期間不會觸發錯誤 unload。

否則應銷燬重建。兩種路線都可以，但必須有明確協議；不能既保留舊訂閱又建立新 iframe。

### 9.3 強制浮窗

使用者可以選擇在平板橫屏強制浮窗，但設定頁需提示：粗指標縮放和軟鍵盤不屬於主支援路線。320–430px 手機不應把強制浮窗作為預設。

## 10. 安全、效能與無障礙

### 10.1 安全邊界

- 遠端狀態列 HTML/JS 是主動程式碼供應鏈，不因放進 iframe 就天然安全；
- bridge 只暴露最小能力，寫入須校驗上下文和資料 schema；
- `postMessage` 必須固定 origin 並校驗 `event.source`；
- 不把 API key、Cookie、完整聊天或宿主物件發給不可信來源；
- 載入源、協議版本和完整性快照應可診斷；
- 關閉/解除安裝時撤銷 Blob URL 和全域性 bridge。

### 10.2 效能

- 拖動/縮放樣式寫入合併到 rAF；
- busy 時停用 iframe pointer，不反覆重建 iframe；
- 隱藏期間暫停動畫、輪詢和高頻渲染；
- `backdrop-filter` 提供純色 fallback；
- 長列表由內容層虛擬化，外殼不截獲內部滾動；
- 載入超時有上限，不無限輪詢 ready。

### 10.3 無障礙

- 明確標題和 `role="dialog"` 或更合適的區域語義；
- 關閉、收起是原生按鈕，有可讀標籤；
- 鍵盤使用者可關閉和恢復預設位置；
- 不把拖動作為訪問內容的前置條件；
- `Escape` 關閉時不吞掉 ST 其他模態框的 Escape；
- 收起/展開同步 `aria-expanded`；
- reduced-motion 下關閉開場、吸附和縮放過渡。

## 11. 生命週期與資源清理

完整銷燬順序建議：

```text
mark destroyed / generation++
→ abort fetch
→ stop ready polling and timers
→ unsubscribe data and bridge events
→ remove pointer/resize/keyboard listeners
→ disconnect observers
→ remove iframe and host
→ revoke Blob URL
→ remove styles/global API references
```

```javascript
function destroyHudSession() {
  if (hudSession.phase === 'destroyed') return;
  hudSession.phase = 'destroyed';
  hudSession.generation += 1;
  hudSession.contextRevision += 1;
  try { hudSession.abortController?.abort(); } catch (_error) {}
  while (hudSession.disposers.length) {
    try { hudSession.disposers.pop()?.(); } catch (error) { console.warn('hud cleanup failed', error); }
  }
  try { hudSession.subscribers?.clear?.(); } catch (_error) {}
  try { hudSession.bridge?.destroy?.(); } catch (_error) {}
  try { hudSession.iframe?.remove(); } catch (_error) {}
  try { hudSession.host?.remove(); } catch (_error) {}
  try { hudSession.style?.remove(); } catch (_error) {}
  try {
    if (hudSession.blobUrl) hostWindow().URL.revokeObjectURL(hudSession.blobUrl);
  } catch (_error) {}
  hudSession.iframe = hudSession.host = hudSession.style = null;
  hudSession.blobUrl = hudSession.bridge = null;
}
```

在 `pagehide`、熱過載、切卡、指令碼停用和執行時替換前呼叫。普通 `CHAT_CHANGED` 通常不銷燬外殼，但必須遞增 `contextRevision`、取消舊互動並重新整理內容。

## 12. 卡A 3.4.9 生產樣本

> 已核檔案：`rolecard-diy-workshop/runtime/xingyue/3.4.9/control-center.js`。當前 runtime 比模組化 fragments 更新，HUD shell 取材必須以前者為準。

## 13. 高頻錯誤

| 錯誤 | 症狀 | 修復方向 |
|---|---|---|
| 在訊息 iframe 內 fixed | 被樓層邊界裁切 | 掛宿主 document |
| 用 right/bottom/translate 持久化 | 浮窗跑到長頁底部 | 儲存 left/top 畫素 |
| 拖動時 iframe 吃事件 | 指標中途丟失 | pointer capture + busy 禁 pointer |
| 不重夾舊矩形 | 換屏後窗體找不到 | 每次恢復按當前視口 clamp |
| 收起只隱藏 iframe | 留下整塊空磨砂殼 | 同步縮小外殼高度 |
| 關閉/收起/銷燬同一布林值 | 重開丟內容或洩漏 | 外殼與內容雙狀態機 |
| 內容源/外殼舊請求覆蓋新宿主 | 新 shell 顯示舊 bundle | AbortController + generation |
| 切聊天后舊互動仍寫回 | 資料落入舊聊天 | contextRevision + dirty + 寫回二次校驗 |
| 只等 iframe load | 空白但被判成功 | bridge + 依賴 + app-ready 握手 |
| Blob URL 不撤銷 | 重開越多記憶體越高 | 每代載入/銷燬 revoke |
| 寫回不校驗 chat | 資料落入舊樓層 | context token 二次校驗 |
| 移動端強用小把手 | 難以操作 | 自動切 drawer |
| 隱藏仍持續渲染 | CPU 佔用與掉幀 | visible/dirty 合併 |
| 雙入口各建一窗 | 出現兩個 iframe | 全域性單例 + 命令登錄檔 |
| 把 movingUI 當公共 API | ST 更新後失效 | 自有 shell + 能力檢測 |

## 14. 驗收矩陣

| 維度 | 必驗項 |
|---|---|
| 幾何 | 預設居中、拖動、縮放、四邊夾取、最小尺寸、瀏覽器縮放 |
| 恢復 | 儲存後重開；4K→筆記本、視口縮小後仍可見 |
| iframe | 拖動時不搶事件，內容操作和滾動時正常響應 |
| 外殼語義 | 關閉、內部收起、重開、失敗態不留下空殼 |
| 資料 | chat/message/contextRevision 守衛；隱藏 dirty；重開只補一次 |
| 載入 | 主源失敗→備用源；fetch/load/bridge 分階段超時；retry |
| 競態 | 切聊天后舊互動/寫回失效；shell/content 變化時該取消的載入被取消 |
| 桌面/移動 | 桌面完整；移動自動轉 drawer；使用者覆蓋有明確提示 |
| 安全 | origin/source、schema、最小 bridge、無敏感資訊外洩 |
| 無障礙 | 原生按鈕、標題、鍵盤關閉/重置、焦點、reduced-motion |
| 生命週期 | Blob、bridge、subscriber、observer、timer、DOM/style 全清 |

穩定完成門：最低支援版和當前核驗版 ST 各跑一次；Chrome/Edge 桌面必驗，目標發行若承諾 Firefox/Safari 也須加入；任何“偶發消失”都應先檢查幾何真值與宿主 transform，不能用增加重試掩蓋。
