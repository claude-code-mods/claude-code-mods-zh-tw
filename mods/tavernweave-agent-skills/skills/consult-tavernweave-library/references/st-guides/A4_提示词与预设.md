## 1. 機制總覽：Chat Completion vs Text Completion 雙軌

**high `[文件·多源]`**

ST 的 prompt 構建管線分為完全獨立的兩套：

```
API 型別                    Prompt 構建控制面板
──────────────────────────────────────────────────
Chat Completion             Prompt Manager（本文件主講）
  (OpenAI / Claude / etc.)
Text Completion             Advanced Formatting 面板
  (KoboldAI / tabbyAPI 等)   → Context Template (Story String)
                             → Instruct Mode（僅此模式需要）
──────────────────────────────────────────────────
```

兩套不互通。角色卡開發基本針對 Chat Completion（OpenAI 相容介面 + Claude API），故本文件重點覆蓋 Prompt Manager 路徑。

來源：docs.sillytavern.app/prompts + docs.sillytavern.app/advanced-formatting 交叉驗證  
適用版本：v1.14.0–v1.18.0

### 2.1 系統預設 Prompt 完整列表

**high `[執行時原始碼]`**

以下 identifier 為 ST 硬編碼的系統預設，順序參照 `PromptManager.js` 中 `promptManagerDefaultPromptOrder`（注意：Default.json 預設檔案的 character_id=100000 順序與此略有差異，且 Default.json 的 character_id=100000 中無 `personaDescription`，僅 character_id=100001 的全域性 group 預設順序才含此項）：

| identifier | 顯示名 | 型別 | 預設 role | 預設 enabled |
|---|---|---|---|---|
| `main` | Main Prompt | 內容型 | system | ✅ |
| `worldInfoBefore` | World Info (↑Char) | 標記型（marker） | — | ✅ |
| `personaDescription` | Persona Description | 標記型 | — | ✅（僅在 promptManagerDefaultPromptOrder 中；Default.json character_id=100000 無此項） |
| `charDescription` | Character Description | 標記型 | — | ✅ |
| `charPersonality` | Character Personality | 標記型 | — | ✅ |
| `scenario` | Character Scenario | 標記型 | — | ✅ |
| `worldInfoAfter` | World Info (↓Char) | 標記型 | — | ✅ |
| `dialogueExamples` | Chat Examples | 標記型 | — | ✅ |
| `nsfw` | Auxiliary Prompt | 內容型 | system | ✅ |
| `enhanceDefinitions` | Enhance Definitions | 內容型 | system | ❌（預設關） |
| `chatHistory` | Chat History | 標記型 | — | ✅ |
| `jailbreak` | Post-History Instructions | 內容型 | system | ✅ |

說明：
- `marker=true` 的條目是佔位符，內容由 ST 執行時動態填充，使用者**不能編輯正文**。
- `system_prompt=true` 的條目在 PromptManager.js 內受到特殊保護，不允許被角色卡 override 覆蓋。
- Default.json 實際預設順序（character_id=100000）為：main → worldInfoBefore → charDescription → charPersonality → scenario → enhanceDefinitions(關) → nsfw → worldInfoAfter → dialogueExamples → chatHistory → jailbreak。

來源：本地 v1.14.0 `PromptManager.js` `chatCompletionDefaultPrompts` + `promptManagerDefaultPromptOrder`（直讀）+ `default/content/presets/openai/Default.json`（直讀）  
適用版本：v1.14.0–v1.18.0

### 2.2 每個 Prompt 條目的完整欄位

**high `[執行時原始碼]`**

來源：`PromptManager.js` release branch

```json
{
  "identifier": "my_custom_prompt",    // string，自定義用 UUID 或自命名
  "name": "顯示名稱",                   // UI 顯示用，不發給模型
  "content": "實際注入內容，支援{{宏}}",
  "role": "system",                    // "system" | "user" | "assistant"
  "enabled": true,                     // bool，是否啟用
  "system_prompt": false,              // bool，系統預設才為 true；禁止使用者新建時設為 true
  "marker": false,                     // bool，標記型佔位符；使用者不能設為 true
  "injection_position": 0,             // 0=RELATIVE, 1=ABSOLUTE(In-Chat)
  "injection_depth": 4,                // injection_position=1 時生效，深度值
  "injection_order": 100,              // 同 role+depth 時的次序（數值越小越靠前）
  "forbid_overrides": false,           // bool，禁止角色卡 override
  "extension": false,                  // bool，是否由擴充套件外掛注入
  "injection_trigger": []              // string[]，限制觸發生成型別（見 2.4）
}
```

適用版本：v1.14.0–v1.18.0

### 2.3 injection_position 詳解

**high `[執行時原始碼]`**

來源：`PromptManager.js` INJECTION_POSITION 列舉

| 值 | 常量名 | 行為 |
|---|---|---|
| `0` | `RELATIVE` | 按 UI 拖拽順序放置，不進入聊天曆史區 |
| `1` | `ABSOLUTE`（In-Chat） | 按 `injection_depth` 插入聊天曆史中，忽略拖拽順序 |

**深度語義**（high `[文件·多源]`）：

```
depth=0 → 插在最後一條訊息之後（對話末尾）
depth=1 → 插在最後一條訊息之前（倒數第1條的上方）
depth=2 → 插在倒數第2條訊息之前
depth=N → 插在倒數第N條訊息之前
```

預設值 `injection_depth=4`（與世界書 DEFAULT_DEPTH 一致）。

**同 depth 的多條 prompt 排序**（**high `[執行時原始碼 + 文件·多源]`**）：  
按 `injection_order` **數值越小越靠前**（在最終輸出中更早出現）。官方文件原文："The lower the number, the earlier it is sent."。原始碼機制：`openai.js` `populationInjectionPrompts()` 中先以 order 降序(`b - a`)處理（大數值先 splice），再整體 `messages.reverse()`，淨效果是小數值 order 的 prompt 在最終 prompt 序列中靠前。同 injection_order 時，roles 按 `system → user → assistant` 順序推入（註釋"most important go lower"，反轉後靠後即更接近生成末端）。

來源：本地 v1.14.0 `openai.js` L760-791（直讀）+ docs.sillytavern.app/prompt-manager（多源交叉）  
適用版本：v1.14.0–v1.18.0

### 3.2 system_prompt / post_history_instructions 生效條件

**medium·單源孤證 `[文件·單源 + 執行時原始碼（預設值）]`**

- 角色卡的 `data.system_prompt` 欄位非空時，**僅在使用者 ST 設定中開啟「Prefer Character Prompt」**後才覆蓋 preset 的 main prompt；**該選項預設為開啟**（`[執行時原始碼]` 本地 v1.14.0 `power-user.js` L208：`prefer_character_prompt: true`）。
- 角色卡的 `data.post_history_instructions` 欄位非空時，同理需要開啟「Prefer Character Instructions」（`prefer_character_jailbreak`）；**該選項默認同樣為開啟**（`power-user.js` L209）。
- 若卡的這兩個欄位為空字串，則完全不影響使用者 preset 設定。
- `{{original}}` 宏可在角色卡 `system_prompt` 中引用全域性 preset 的 main prompt 內容（見 7.2 節宏表）。

來源：docs.sillytavern.app/prompt-manager（單源）+ 本地 v1.14.0 `power-user.js` L208-209（預設值）  
仍需真機驗證：override 的精確內容替換還是追加行為（見懸案 P2）。

## 4. Post-History Instructions（PHI）機制

**high `[執行時原始碼]`**（role 欄位原始碼直讀；"優先順序最高"為推斷，單獨標註見下）

PHI 在 Prompt Manager 中對應 `identifier="jailbreak"` 的條目（儘管 UI 顯示名是"Post-History Instructions"），其特殊之處：

- 作為 **system role 注入**（`[執行時原始碼]` 本地 v1.14.0 `chatCompletionDefaultPrompts` 直讀），按 UI 拖拽順序位於 chatHistory 之後，插在 prompt 末尾（最近的 assistant 回覆請求之前）
- 優先順序最高——因為緊靠生成請求，模型最後讀到它（**medium·推導未驗證 `[推斷]`**：此處為邏輯推斷，不同模型權重分佈可能不同）
- 可包含宏（`{{char}}`、`{{user}}` 等）

> **[執行時原始碼] 校準**：本地 v1.14.0 `openai.js` L2034-2038 與 `PromptManager.js` L2034-2038 均明確 `jailbreak` 的 `role` 為 `"system"` 而非 `"user"`。原文"user role 的不可見注入"為錯誤描述，已更正。使用者可自行在 Prompt Manager 中將 role 改為 user，但預設即 system。

標準 Chat Completion prompt 末端結構：

```
[...聊天曆史...]
[Post-History Instructions（system role，預設；使用者可改為 user/assistant）]
[最後一條 assistant 字首（或空 assistant 開頭訊息觸發回覆）]
```

來源：docs.sillytavern.app/prompt-manager + PromptManager.js `chatCompletionDefaultPrompts`（本地 v1.14.0 直讀）  
適用版本：v1.14.0–v1.18.0

## 5. Context Template（Text Completion 專用）

**high `[文件·多源]`**

Context Template **僅影響 Text Completion API** 的 prompt 格式化，Chat Completion 完全不用此配置。

### 5.1 Story String（Handlebars 語法）

正規化（**medium·單源孤證 `[文件·單源]`**）：

```handlebars
{{#if system}}{{system}}
{{/if}}{{#if description}}{{char}}'s personality: {{description}}
{{/if}}{{#if personality}}{{char}}'s persona: {{personality}}
{{/if}}{{#if scenario}}Scenario: {{scenario}}
{{/if}}{{#if persona}}[{{user}}'s persona: {{persona}}]
{{/if}}
```

可用 Handlebars 引數：

| 引數 | 說明 |
|---|---|
| `{{description}}` | 角色描述欄位 |
| `{{scenario}}` | 場景欄位 |
| `{{personality}}` | 角色性格欄位 |
| `{{system}}` | 系統提示詞內容 |
| `{{persona}}` | 使用者人設描述 |
| `{{char}}` | 角色名 |
| `{{user}}` | 使用者名稱 |

來源：docs.sillytavern.app/context-template  
適用版本：v1.14.0–v1.18.0

## 6. Instruct Mode（Text Completion 專用）

**high `[文件·多源]`**

Instruct Mode **僅適用於 Text Completion API**。Chat Completion（OpenAI/Claude）完全不需要也不支援此設定——配置了 Instruct Mode 對這些 API 沒有任何作用。

來源：docs.sillytavern.app/instructmode + 原始碼分析

### 6.1 核心序列欄位

**high `[文件·多源]`**

```json
{
  "name": "ChatML",
  "user_alignment_message": "",          // 使用者填充訊息（user-first 約束時使用）
  "system_prompt": "",                   // 獨立系統提示詞（已從序列中分離）

  // 訊息包裹序列
  "input_sequence": "<|im_start|>user\n",
  "input_suffix": "<|im_end|>\n",
  "output_sequence": "<|im_start|>assistant\n",
  "output_suffix": "<|im_end|>\n",
  "system_sequence": "<|im_start|>system\n",
  "system_sequence_suffix": "<|im_end|>\n",

  // 特殊序列
  "first_output_sequence": "",           // 第一條 assistant 訊息字首（聊天曆史專用）
  "last_output_sequence": "",            // 最後一條 assistant 訊息字首（實際生成用）
  "system_instruction_sequence": "",     // 後臺靜默生成時的系統字首

  "stop_sequence": "<|im_end|>",         // 停止序列（生成到此截斷）

### 8.3 atDepth 四步注入流水線

原始碼呼叫鏈 **high `[執行時原始碼]`**；最終 splice+reverse 落位 **medium·推導未驗證 `[推斷]`**

```

2. script.js 呼叫 setExtensionPrompt(id, content, IN_CHAT=1, depth, false, role)
3. openai.js populationInjectionPrompts() 在迴圈 depth=i 時讀取對應條目
4. splice() 進 newest-first messages 陣列 → 最後 reverse()

## 10. Claude API 的特殊處理（prompt-converters.js）

**high `[執行時原始碼]`**（原描述有兩處錯誤，已就地校準，見下）

來源：`<local-user-path>/<local-drive>\SillyTavern-1.14.0\src\prompt-converters.js`（本地 v1.14.0 直讀）

Claude 的 Messages API 對訊息角色有嚴格約束，ST 透過 `convertClaudeMessages()` 處理（路徑：server 側 `src/endpoints/anthropic.js` 呼叫）：

- **頭部 system 訊息提取**：messages 陣列最前端連續的 `role=system` 訊息被提取為 Claude API 的獨立 `system` 引數（僅在 `useSysPrompt=true` 時啟用）
- **後續 system 訊息轉換為 user**：messages 陣列中位於非頭部的 `role=system` 訊息一律被**轉換為 `role=user`**（原始碼 L257 `message.role = 'user'`），而非"合併"
- **PROMPT_PROCESSING_TYPE.CLAUDE** 已標註 `@deprecated`，實際 Claude 處理不走 `STRICT mergeMessages`

> **[執行時原始碼] 校準**：原文"連續同角色訊息透過 mergeMessages() 合併（STRICT 模式）"有誤——CLAUDE 型別對應的是 `strict: false` 的 merge，且該路徑已廢棄。實際生效的是 `convertClaudeMessages()` 的"提取頭部 system + 後續 system 轉 user"雙步邏輯。

**實踐影響**：atDepth 注入的 system role WI 條目，在 Claude API 下如果位於 messages 陣列非頭部位置，會被**靜默轉換為 user role**（非合併），看起來像使用者訊息混入對話流。是否與真實使用者訊息合併取決於 `mergeMessages` 後處理（懸案 P3 依然成立）。如需保持 system 語義，應確保該注入位於 messages 頭部。

適用版本：v1.14.0–v1.18.0（Claude API 路徑）

## 12. 高頻避坑

**high `[執行時原始碼 + 真機/生產卡 + 文件·多源]`**，個別條目見下方來源標註

1. **Preset 與角色卡同名陷阱**：Preset 若與某角色卡同名，開啟該角色時會自動切換到該 preset——通常為非預期行為。Preset 命名建議加字首區分（如 `[通用]寫實風格`）。

2. **Claude API system 訊息轉換（非合併）**：messages 陣列頭部連續的 `role=system` 訊息被提取為獨立 system 引數；頭部之後的 `role=system` 訊息被**逐條轉換為 `role=user`**（非合併成一條），會混入對話流（見懸案 P3）。原"合併"描述不準確——實為型別轉換。`[執行時原始碼]` 本地 v1.14.0 `src/prompt-converters.js` L257 直讀。

3. **depth=0 的歧義**：In-Chat depth=0 是"最末尾"（最新訊息**之後**），而非"最頂部"。Post-History Instructions 本質上就是 depth=0 的 user role 注入。

4. **marker 標記型條目不能編輯正文**：`chatHistory`、`charDescription`、`worldInfoBefore` 等 `marker=true` 的系統條目，只能設定 enabled/disabled，不能修改其 content——內容由 ST 執行時自動填充。

5. **AN 頻率=0 時 Top/Bottom of AN 的 WI 條目被靜默跳過**：不報錯，僅無效。使用 At Depth（position=4）代替。

6. **WI atDepth 同 depth+role 合併**：同一 depth+role 的多個 WI 條目在 prompt 中只產生一條訊息（內容用換行拼接）——無法透過 WI 在同深度產生多條獨立訊息。

7. **`{{original}}` 宏只在角色卡 override 上下文有效**：在角色卡的 `system_prompt` 欄位裡使用 `{{original}}` 可引用當前 preset 的 main prompt 內容；在其他地方行為未定義。**high `[文件·單源]`**

8. **`{{outlet::Name}}` 禁止放在 WI 內容裡**：文件明確不支援，僅在 Prompt Manager 的內容型條目正文中使用。**high `[文件·單源]`**

9. **Instruct Mode 僅對 Text Completion 生效**：Chat Completion（OpenAI/Claude）完全不走 Instruct 邏輯，配置了 Instruct Mode 對這些 API 沒有任何作用。

10. **`injection_trigger` 為空 `[]` ≠ 任何型別都不觸發**：空陣列是"全部型別均觸發"，相當於不過濾。若要只在特定型別觸發，必須顯式填寫型別列表。

11. **`system_prompt=true` 的條目不允許使用者新建時設為 true**：PromptManager.js 內對此有保護；新建的自定義條目務必保持 `"system_prompt": false`。

來源：PromptManager.js + prompt-converters.js + docs.sillytavern.app + A3_世界書最佳化.md  
適用版本：v1.14.0–v1.18.0
