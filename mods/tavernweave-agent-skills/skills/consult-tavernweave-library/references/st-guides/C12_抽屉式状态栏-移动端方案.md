## 1. 使用場景與非目標

### 1.1 為什麼移動端需要抽屜

桌面浮窗依賴可拖動、可縮放和持續可見的剩餘螢幕空間；在手機上會同時遇到：

- 視口窄，縮放把手和內容爭奪空間；
- 瀏覽器位址列動態伸縮，`100vh` 不等於真正可見高度；
- 軟鍵盤改變 `visualViewport`，底部浮窗容易覆蓋輸入區；
- 粗指標需要更大熱區，不能複用桌面小把手；
- ST 頂欄、底部發送區與 PWA 安全區都可能變化。

抽屜把互動簡化成“邊緣手柄 + 單軸開合”，更適合移動端作為完整 HUD 的終極外殼方案。

### 1.2 抽屜不是什麼

- 不是訊息樓層裡的 `<details>` 摺疊塊；
- 不是首樓同層前端內部的路由面板；
- 不是可以任意拖動、自由縮放的視窗；
- 不負責讀寫 MVU / 資料庫，也不定義狀態列欄位；
- 不應掛在訊息 iframe 內，否則無法可靠覆蓋宿主視口；
- 不等於“移動端把狀態列縮小一點”。

## 2. 共享 HUD 宿主架構

抽屜和浮窗應複用同一個 HUD Host Core，只替換 ShellAdapter：

```text
Wand / Orb / Page Button
          ↓ command registry
HUD Host Core
  phase / generation / AbortController
  contextRevision / visible / dirty / iframe
          ↓ ShellAdapter
       DrawerShell
          ↓
      iframe + bridge
          ↓
    狀態列真身 / 資料鏈
```

共享核心建議至少維護：

```javascript
const hudSession = {
  phase: 'idle',             // idle/loading/ready/failed/destroyed
  mode: 'drawer',
  host: null,
  iframe: null,
  blobUrl: null,
  abortController: null,
  generation: 0,
  contextRevision: 0,
  visible: false,
  dirty: true,
  pendingChatReset: false,
  disposers: [],
};
```

抽屜只實現：

- 建立/銷燬外殼；
- 設定 top/bottom 幾何；
- 開啟、關閉、手勢和可見性；
- 把 HUD body 容器交給共享核心；
- 通知共享核心 `visible` 變化。

載入遠端 HTML、注入 bridge、變數重新整理和上下文守衛不應在 DrawerShell 複製一份。

## 3. 抽屜 DOM 與狀態機

### 3.1 DOM 結構

```html
<aside id="card-status-drawer"
       data-placement="bottom"
       data-open="false"
       data-phase="idle">
  <button class="drawer-handle"
          type="button"
          aria-controls="card-status-drawer-panel"
          aria-expanded="false">
    <span class="sr-only">開啟狀態列</span>
  </button>
  <section id="card-status-drawer-panel"
           class="drawer-panel"
           aria-hidden="true">
    <div class="hud-body"></div>
  </section>
</aside>
```

外層 wrapper 可用 `pointer-events:none` 避免擋住酒館；手柄和開啟後的面板恢復 `pointer-events:auto`。

### 3.2 狀態機

```text
unmounted
  → closed-idle
  → opening → open-ready
  → closing → closed-idle(dirty? false/true)
  → failed → retrying
  → switching-shell
  → destroyed
```

外殼開合與內容載入是兩個正交狀態：抽屜可以已經開啟但內容還在 `loading`，也可以關閉但 iframe 仍為 `ready`。不要用一個 `isOpen` 同時表示兩者。

推薦分開：

```javascript
drawer.open;       // 外殼是否展開
hudSession.phase; // 內容是否 ready
hudSession.visible;
hudSession.dirty;
```

### 3.3 關閉不是銷燬

普通關閉應：

- 把 panel 移出可視區；
- 同步 `aria-hidden` / `aria-expanded`；
- 若焦點在 panel/iframe 內，先歸還給手柄；隨後設定 `panel.inert=true`，必要時把 iframe `tabIndex=-1`；
- 設定 `visible=false`；
- 保留 iframe，避免每次重拉資源；
- 隱藏期間把資料變化合併為一個 `dirty=true`。

只有切換外殼模式、切卡、熱過載、永久關閉功能或執行時銷燬時，才真正撤銷 iframe、bridge、Blob URL 和監聽。

## 4. Top / Bottom / Auto 策略

### 4.1 三種位置模式

| 模式 | 適合 | 主要風險 |
|---|---|---|
| `top` | 底部輸入區長期佔用；頂部留白穩定 | ST 頂欄測高錯誤產生空白或遮擋 |
| `bottom` | 頂欄複雜；使用者更習慣拇指下緣操作 | 傳送框、軟鍵盤和 Home 條競爭 |
| `auto` | 通用發行 | 必須穩定、可解釋並允許使用者覆蓋 |

`auto` 不應每次 resize 都來回跳。裝置策略確定後，只有在明確斷點、輸入區狀態或使用者設定變化時切換。

### 4.2 宿主模式自動選擇

```javascript
function hostWindow() {
  try {
    if (window.parent && window.parent !== window && window.parent.document) {
      return window.parent;
    }
  } catch (_error) {}
  return window;
}

function chooseHudShell() {
  const host = hostWindow();
  const coarse = host.matchMedia('(pointer: coarse)').matches;
  const narrow = host.innerWidth <= 768;
  return coarse || narrow ? 'drawer' : 'floating';
}
```

入口與抽屜掛在 ST 宿主時，`document/visualViewport/matchMedia/getComputedStyle/localStorage` 和全域性單例都必須從 `hostWindow()`/`hostWindow().document` 取得；TH iframe 的裸 `window` 不是宿主視口。

這只是最低能力規則。可進一步加入：

- 使用者強制選擇；
- PWA / 移動 WebView；
- 橫屏高度過低；
- 桌面觸控式螢幕但有足夠空間；
- ST 宿主 movingUI/側欄佔用。

自動模式必須允許使用者手動覆蓋，並提供“恢復自動”。

### 4.3 Top 位置

不能直接寫 `top:0`。應測量當前可見的 ST 頂部 chrome：

```javascript
function measureTopAnchor(doc, viewport, handleHeight = 44) {
  const host = doc.defaultView || hostWindow();
  const top = viewport.y;
  const bottom = viewport.y + viewport.height;
  const maxChromeHeight = Math.min(120, Math.max(24, viewport.height / 3));
  const candidates = [
    '#top-settings', '#navbar', '#sheld_header',
    '#top-settings-holder', '#top-bar', '.top-bar',
  ].flatMap((selector) => [...doc.querySelectorAll(selector)]);

  const anchors = candidates.flatMap((node) => {
    const style = host.getComputedStyle(node);
    const rect = node.getBoundingClientRect();
    const visible = style.display !== 'none'
      && style.visibility !== 'hidden'
      && rect.width > 0 && rect.height > 0
      && rect.height <= maxChromeHeight
      && rect.bottom > top && rect.bottom <= top + maxChromeHeight;
    return visible ? [rect.bottom + 4] : [];
  });

  const candidate = Math.min(
    anchors.length ? Math.max(...anchors) : top + 4,
    top + maxChromeHeight,
  );
  const upper = Math.max(top, bottom - handleHeight);
  return Math.round(Math.min(Math.max(candidate, top), upper));
}
```

返回值是 layout viewport 座標系中的絕對 `top` anchor，不是相對偏移。選擇器是脆弱觀察值，必須可配置並帶回退、可視性、相交與上限保護；若測得異常，應回到 `viewport.y + gap` 並記錄診斷，而不是留下大片空白。

### 4.4 Bottom 位置

底部模式應測量 `#form_sheld`、`#send_form`、`#send_textarea` 等實際可見輸入區的頂部，並取可見視口底邊與輸入區頂邊的差值作為避讓量。

不要把輸入區高度寫死。移動端軟鍵盤、快捷回覆欄、附件面板和主題都可能改變它。

## 5. 動態視口、安全區與軟鍵盤

### 5.1 使用 visualViewport

```javascript
function getViewportRect() {
  const host = hostWindow();
  const vv = host.visualViewport;
  if (!vv) {
    return { x: 0, y: 0, width: host.innerWidth, height: host.innerHeight };
  }
  return {
    x: vv.offsetLeft,
    y: vv.offsetTop,
    width: vv.width,
    height: vv.height,
  };
}
```

抽屜重排至少監聽：

- `window.resize`；
- `orientationchange`；
- `visualViewport.resize`；
- `visualViewport.scroll`；
- ST 頂欄或輸入區 `ResizeObserver`。

高頻事件合併到單個 `requestAnimationFrame`，避免每個 scroll 都同步測量和寫樣式。

### 5.2 CSS 安全區

```css
#card-status-drawer {
  position: fixed;
  left: max(8px, env(safe-area-inset-left));
  right: max(8px, env(safe-area-inset-right));
  z-index: var(--card-hud-z, 30000);
  pointer-events: none;
}

#card-status-drawer .drawer-panel {
  max-height: min(82dvh, 720px, var(--hud-available-height));
  background: rgba(20, 22, 30, 0.94);
  overflow: hidden;
}
```

橫屏時左右安全區尤其重要。底部還要處理 `env(safe-area-inset-bottom)`；頂部處理 `env(safe-area-inset-top)`，但不要和已經包含劉海高度的宿主頂欄測量重複相加。

### 5.3 `dvh` 與回退

優先使用 `dvh` 表示動態視口高度，併為不支援的 WebView 提供 `vh` 或 JS CSS 變量回退：

```css
.drawer-panel {
  height: min(76vh, 640px);
  height: min(76dvh, 640px);
}
```

不要只寫 `100vh`。移動瀏覽器位址列收放會使它大於實際可見區域。

### 5.4 軟鍵盤策略

底部抽屜和軟鍵盤同時出現通常會讓輸入區不可用。可選策略：

1. 傳送框獲得焦點時自動關閉 bottom drawer；
2. 抽屜改為 top；
3. 按 `visualViewport` 剩餘高度壓縮，但設最小可用高度；
4. 給使用者“保持開啟”高階選項。

預設推薦 1：聚焦傳送框時平滑關閉底部抽屜，並保留 `dirty` 狀態，鍵盤關閉後不自動搶焦點重開。

## 6. 點選、滑動與無障礙

### 6.1 手勢規則

- 點選手柄：開/關；
- top drawer 向下滑開啟、向上滑關閉；
- bottom drawer 向上滑開啟、向下滑關閉；
- 單軸位移超過閾值才判為滑動；
- 橫向滾動或輕微抖動不應誤觸；
- `pointercancel` 恢復到手勢前狀態。

```javascript
const SWIPE_THRESHOLD = 34;

function shouldOpenFromSwipe(placement, deltaY) {
  return placement === 'top'
    ? deltaY >= SWIPE_THRESHOLD
    : deltaY <= -SWIPE_THRESHOLD;
}
```

手勢結束後只提交一次目標狀態，不要一邊拖一邊改變業務 `open` 真值。

### 6.2 觸控熱區

在窄屏或 `(pointer:coarse)` 下，手柄可點選區域至少 44 CSS px。視覺線條可以只有 4–6px，但外層 button 不能同樣纖細。

### 6.3 無障礙

- 手柄使用原生 `button`；
- `aria-controls` 指向 panel；
- `aria-expanded` 與實際開合一致；
- panel 的 `aria-hidden` 同步；
- `Enter` / `Space` 開關；
- `Escape` 關閉並把焦點還給手柄；
- 開啟後不要強制把焦點劫持到 iframe；
- 讀屏文字說明“開啟/關閉狀態列”，不是隻讀出“按鈕”。

### 6.4 Reduced Motion 與低端裝置

```css
@media (prefers-reduced-motion: reduce) {
  #card-status-drawer,
  #card-status-drawer .drawer-panel {
    transition: none !important;
  }
}
```

`backdrop-filter` 必須有不支援和低效能時的純色回退。移動端掉幀時首先停用 blur、陰影和複雜背景，不應減少觸控熱區或破壞內容可讀性。

## 7. 載入、隱藏重新整理與失敗恢復

### 7.1 開啟流程

```text
open requested
  → ensure shell
  → shell visible
  → phase idle/failed ? start load : reuse ready iframe
  → bridge ready
  → dirty ? refresh once : no-op
```

可以先展示外殼和 loading 佔位，再等待 iframe；不要在網路完成前完全無反饋。

### 7.2 隱藏期間的 dirty 合併

```javascript
function onHudDataChanged() {
  hudSession.dirty = true;
  void flushDirtyHud();
}

function onDrawerOpened() {
  hudSession.visible = true;
  drawerPanel.inert = false;
  hudIframe.tabIndex = 0;
  void flushDirtyHud();
}

async function flushDirtyHud() {
  if (!hudSession.visible || !hudSession.dirty || hudSession.refreshing) return;
  hudSession.refreshing = true;
  const revision = hudSession.contextRevision;
  try {
    await refreshHudOnce({ revision });
    if (revision === hudSession.contextRevision) hudSession.dirty = false;
  } catch (error) {
    hudSession.dirty = true;
    hudSession.phase = 'failed';
    reportHudRefreshFailure(error);
  } finally {
    hudSession.refreshing = false;
  }
}
```

關閉期間不要繼續做每 token、每 MutationObserver 的完整渲染。只記錄“需要重新整理”，再次開啟補一次。

### 7.3 失敗狀態

至少區分：

- 遠端內容拉取失敗；
- bridge 注入失敗；
- iframe 載入超時；
- 依賴（jQuery/lodash/MVU/TH）未就緒；
- 當前聊天上下文已變化；
- 內容指令碼主動報告錯誤。

失敗面板必須提供：錯誤摘要、重試、關閉。不要自動無限重試；也不要以 HTTP 200 代替應用 ready。

## 8. 模式切換與非同步競態

### 8.1 Drawer ↔ Floating 單宿主原則

抽屜與浮窗必須共享同一個活動 HUD 內容例項，或在切換時明確遷移/重建；不能同時留下兩個 iframe 寫同一份變數。

```text
drawer active
  → request floating
  → mark switching
  → abort old load / detach old bridge
  → destroy drawer shell
  → mount floating shell
  → attach/reload one iframe
```

若內容 iframe 可安全移動 DOM，可複用；若 bridge 把宿主 window 捕獲在閉包中，應銷燬重建。必須由實現明確選擇，不能半遷移。

### 8.2 generation 防舊響應覆蓋

```javascript
async function loadHudContent() {
  const generation = ++hudSession.generation;
  hudSession.abortController?.abort();
  const controller = new AbortController();
  hudSession.abortController = controller;

  const html = await fetchHud({ signal: controller.signal });
  if (generation !== hudSession.generation) return;
  mountHudHtml(html);
}
```

三類失效必須分開：

- shell 或內容源變化：`generation++` 並 abort 舊載入；
- `CHAT_CHANGED` / Swipe / Message Updated：`contextRevision++`，設定 `dirty/pendingChatReset`，不無故中止與聊天無關的靜態 HUD bundle；
- destroy：generation 與 contextRevision 都失效並清全部資源。

只有 HUD bundle 本身與聊天繫結時，切聊天才取消並立即重啟載入。舊請求即使最後成功，也不能覆蓋新 shell。

### 8.3 上下文守衛

變數寫回前同時校驗：

- `chatId`；
- `messageId`；
- `contextRevision`；
- runtime 未銷燬；
- 仍是發起互動的同一 HUD generation。

否則使用者在非同步確認框開啟期間切聊天，結果可能寫進舊樓層。

## 9. 效能與生命週期

### 9.1 佈局讀寫分離

一次重排中先讀：

- visualViewport；
- 頂欄 rect；
- 輸入區 rect；
- panel 內容需要的最小高度。

然後在下一階段集中寫 CSS 變數。不要在迴圈中交替 `getBoundingClientRect()` 和 `style.*`。

### 9.2 資源清理

銷燬時必須處理：

- `ResizeObserver`；
- window / visualViewport 監聽；
- 手柄 Pointer Events；
- focusin/focusout 監聽；
- iframe 與 bridge subscriber；
- AbortController；
- Blob URL；
- animation frame / timer；
- 宿主 DOM 和 style。

普通關閉不銷燬這些資源，但切換到浮窗模式時要按共享核心策略處理，確保全域性仍只有一套訂閱。

## 10. 卡A 3.4.9 生產樣本

- `auto / drawer / orb` 宿主選擇；窄屏或 coarse pointer 自動選 drawer；

- 對低端裝置 blur 效能的明確降級開關。

## 11. 高頻錯誤

| 錯誤 | 後果 | 修復方向 |
|---|---|---|
| 抽屜掛訊息 iframe | 被樓層裁切，無法覆蓋宿主 | 掛宿主 `document.body` |
| 只用 `100vh` | 位址列/鍵盤遮擋 | `dvh` + visualViewport |
| 只看 `innerHeight` | 軟鍵盤彈出仍誤判高度 | 監聽 visualViewport |
| 頂欄選擇器誤命中 | 頂部出現大段空白 | 可見性、上限、回退與診斷 |
| bottom 覆蓋輸入框 | 無法繼續傳送訊息 | 測傳送區，聚焦時關閉或切 top |
| safe-area 重複相加 | 劉海裝置產生額外偏移 | 明確宿主 chrome 是否已包含安全區 |
| 手柄只有細線可點 | 移動端難以觸發 | 視覺細、熱區至少 44px |
| 關閉仍高頻渲染 | 掉幀耗電 | hidden 只記 dirty |
| top/bottom 同一 transform | 一邊開合方向反了 | placement 明確方向函式 |
| 切模式不 abort | 舊 iframe 覆蓋新 shell | generation + AbortController |
| `aria-hidden` 不同步 | 讀屏狀態錯誤 | 單一開合提交函式 |
| 無限自動重試 | 離線時持續請求 | 可見失敗態 + 使用者重試 |
| 移動端強用浮窗 | 小把手難用、內容過窄 | auto 路由到 drawer |

## 12. 驗收矩陣

| 維度 | 必驗項 |
|---|---|
| 自動模式 | `<=768px`、coarse pointer 進入 drawer；桌面回到 floating；使用者覆蓋有效 |
| 位置 | top/bottom 緊貼有效宿主 chrome，無額外空白或遮擋 |
| 瀏覽器 | 位址列展開/收起、PWA、WebView、縮放後仍在可視區 |
| 鍵盤 | 輸入框聚焦、軟鍵盤彈出、bottom drawer 正確關閉/避讓 |
| 安全區 | iPhone 劉海、Home 條、橫屏左右安全區 |
| 手勢 | 點選、正確方向滑開/滑關、輕微抖動不誤觸、pointercancel |
| 資料 | 關閉期間只記 dirty；重開補一次；切聊天、Swipe、編輯後重新整理 |
| 模式切換 | drawer ↔ floating 始終只有一個 host/iframe/訂閱鏈 |
| 失敗恢復 | 網路失敗、bridge 超時、依賴缺失、重試、切換途中取消 |
| 無障礙 | 44px、button、ARIA、鍵盤、焦點返回、reduced-motion |
| 生命週期 | listener、observer、Blob、iframe、timer 在銷燬後全清 |

穩定完成門：至少在一臺 iOS Safari/WebView 與一臺 Android Chrome/WebView 真機透過 top、bottom、軟鍵盤、旋轉和模式切換；桌面模擬觸控不能替代真機。
