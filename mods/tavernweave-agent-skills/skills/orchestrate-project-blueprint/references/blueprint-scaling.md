# 藍圖體量與權威鏈

## 選擇藍圖規模

這裡選擇的是專案文件的組織規模，不是使用者的新手程度，也不會修改新人/入門/熟練/老手引導擋位。向用戶解釋每種規模會增加哪些文件和維護工作，再按實際專案需要選擇。

| 檔位 | 條件 | 上限 |
|---|---|---|
| `single-blueprint` | 單一宿主、單一主迴圈、少量元件，可在一個實施檔案中清晰追蹤 | 深度 1，子藍圖 0 |
| `blueprint-set` | 多領域但仍是一個產品，存在獨立交付物與驗收門 | 深度 2，直屬領域藍圖最多 5 |
| `program-blueprint-set` | RPN 重置版一類多宿主、多階段、長期遷移工程 | 深度 3，直屬藍圖最多 9 |

檔案數量不是升級理由。只有當一個領域同時擁有獨立邊界、獨立交付物、獨立驗證門，並且主藍圖已無法清楚容納時，才提取子藍圖。

## 權威層級

1. 總設計案：目標、非目標、專案型別、使用者價值、系統邊界和四態決策；
2. 藍圖或藍圖索引：階段順序、依賴、退出條件、證據；
3. 領域藍圖：只描述一個領域的可交付執行合同；
4. `NEXT.md`：當前事實、活動階段、最近證據、下一道門。

總設計案回答“做什麼和為什麼”，藍圖回答“按什麼邊界做到什麼證據”，`NEXT.md` 回答“現在從哪裡繼續”。不得互相複製成三個版本的同一大文件。

## 漸進提取

藍圖集初始化時只建立索引，不建立空白 BP-01…BP-09。到達駕駛員確認門後按需提取。子藍圖 ID 一旦分配不得透過重排改義；廢棄時保留狀態與替代項。
