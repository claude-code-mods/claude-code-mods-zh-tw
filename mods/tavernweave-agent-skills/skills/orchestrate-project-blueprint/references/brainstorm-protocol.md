# 腦暴協議

## 一輪只推進一個相鄰方向

先恢復已知事實，確定本輪討論什麼、還缺什麼，再按共享[主動釐清需求](../../consult-tavernweave-library/references/communication-and-guidance.md#主動釐清需求)決定提問或繼續。把結果寫回原四態賬本，檢查本方向是否已到討論上限。資訊充分時直接推進；需要提問時優先 1–2 個必要決策，不必湊數。使用者不確定時給出推薦並說明理由。新人按小步驟、入門按小階段詳細解釋；熟練和老手也不能省略必要解釋。

四態賬本：

- `confirmed`：使用者已明確確認，可進入總設計案；
- `proposed`：Agent 提案，尚未授權；
- `pending`：缺少選擇或證據；
- `rejected`：已否決並保留理由，避免反覆復活。

目標、硬限制和候選手段使用同一套狀態與來源。合理但未確認的假設保留為 `proposed`；關鍵事實尚無證據則為 `pending`。使用者糾正後更新受影響的決定及後續規格，不另立需求賬本。確認過的選擇直接沿用，不因切換模組再次採訪。

不要把解釋性問題、同義選擇或純技術細節包裝成多個決策。三席聯席共享提問，優先 1–2 個，確有必要時合計最多 4 個，不是每席分別提問。

## 動態討論上限

| 方向級別 | 預設輪數 | 適用範圍 |
|---|---:|---|
| peripheral | 1 | 彩蛋、裝飾、非核心文案 |
| standard | 2 | 常規功能、獨立頁面、次級系統 |
| core | 3 | 核心迴圈、狀態架構、關鍵互動 |
| foundational | 4 | 專案定位、宿主、權威源、遷移策略 |

任何方向硬上限為 5。達到上限時只能：凍結當前最佳方案、停入 Parking Lot、切換方向，或由使用者明確批准 `+1`。不得自動追加。

方向記錄至少包含：`id`、`topic`、`level`、`roundLimit`、`roundsUsed`、`status`、`decisionIds`。進入下一輪前先顯示剩餘額度。

## 防跑偏

- 每輪只允許一個與當前方向直接相鄰的新方向；其餘記入 Parking Lot。
- 連續兩輪沒有新增確認項時，停止繼續發散並請求收束選擇。
- 發現規模、宿主或目標改變時，先寫變更提案，不靜默重寫已確認設計。
- 讚美要指出可複用的具體設計價值；吐槽要指向風險、替代方案或驗收方法。
