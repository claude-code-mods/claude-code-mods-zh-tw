# 第一版合同

向用戶說明時同時解釋原術語與本次具體含義：Core Spine 是不能缺的核心內容，First Playable / First Usable 是第一份能親手試用的成果，Growth Tracks 是後續更新方向，Parking Lot 是暫存想法。不要只交四個英文標題。

## Core Spine

專案沒有它就不成立的權威源、核心物件、主迴圈、關鍵狀態與最低宿主能力。每項必須能指向實現責任和驗證證據。

## First Playable / First Usable

第一版必須形成完整閉環：使用者從明確入口進入，完成一次核心動作，看見真實狀態變化，能處理至少一個失敗路徑，並得到可重複驗證的結果。

首次引導還要幫助使用者在試用後提出一次修改，並在其授權範圍內再次完成和試用；先解釋在哪裡操作、預期看到什麼、失敗時怎樣恢復。縮小首版規模時保留使用者最在意的體驗，不用空殼替代目標。

必須寫：

- 入口與目標使用者；
- 主路徑和最小資料/狀態源；
- 必交付檔案或介面；
- 明確不做的內容；
- 自動化、靜態、真實宿主和駕駛員驗收各自負責什麼；
- 完成後停在哪裡。

## Growth Tracks

首版驗證後才進入的長期方向。每項寫觸發條件，不預設排進當前藍圖。

## Parking Lot

有價值但本輪不解決的想法、爭議、外部依賴與高風險實驗。Parking Lot 不是暗中承諾。
