# 反遞迴執行合同

## 先區分三種結構

- **持久權威藍圖**：改變專案拓撲、完成分母、獨立交付物或驗收門，長期被 `NEXT.md` 引用。
- **正常步驟檢查單**：當前步驟原本就需要的命令、檔案、測試和修復項，不是子藍圖。
- **臨時問題支線**：由可觀察錯誤、失敗證據、未滿足的退出條件或實際阻塞觸發，只為解決該問題而臨時細分。

## 所有活動步驟的固定規則

- 開跑後 `runtimePersistentBlueprintBudget = 0`，只禁止執行期自行新增持久權威藍圖。
- 藍圖最大深度和子藍圖總數上限在設計確認門凍結。
- 任意活動步驟 `Pn` 都不得因為“還可以更細”“任務複雜”或“想規劃完整”而遞迴增殖。
- 沒有真實問題證據時，新想法進入現有檢查單、風險賬本或 Parking Lot；不能改寫 First Playable。

## 階段合同

每個活動階段只包含：輸入、輸出、允許修改範圍、禁止事項、退出條件、證據、失敗回退、下一道門。進入階段時凍結；退出時只更新證據和結果。

## 臨時問題支線

真實問題允許一層最小必要細分，但必須：

1. 繫結一個父步驟並記錄問題與觸發證據；
2. `persistent: false`，不得改變產品範圍、版本承諾、完成分母或獨立驗收門；
3. 同時最多開啟一條問題支線，支線內部不再遞迴建立問題支線；
4. 解決時記錄結果證據，阻塞時記錄下一道門；
5. 狀態變為 `resolved` 或 `blocked` 後關閉支線，並回到 `returnTo` 指定的父步驟。

例如 P3 可以遇到真實問題，但 P3 只是示例；該規則同樣適用於 P1、P7 或任何 `Pn`。

## 升級為持久藍圖

當問題已涉及獨立領域，需要單獨的交付物和驗收門，而父藍圖無法清楚容納這些工作時，停止臨時細分，提交 `rescope proposal`。Agent 此時只能建議拆出子藍圖；駕駛員確認後，才能在當前執行門外調整藍圖層級。

## 停止條件

- 階段退出條件不清；
- 新事實推翻已確認專案型別或首版合同；
- 需要安裝、金鑰、付費呼叫、真實發布、Git 動作或破壞性遷移；
- 自動化證據和真實宿主證據相互矛盾。

出現停止條件時更新 `NEXT.md` 並回到駕駛員門，不用更多規劃掩蓋阻塞。
