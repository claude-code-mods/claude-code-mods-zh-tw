# E07：世界書最小隔離驗證與觀察記錄

本節沿用 [runtime-debug](../SKILL.md)的真實宿主邊界，不建立另一套驗收工程。先用[共享基礎](../../consult-tavernweave-library/references/sillytavern-runtime-foundations.md)的純文字橋樑回合，再按專案實際採用的能力選擇下表用例。純原生專案不安裝模板或 MVU，純文字專案不必跑全部矩陣。

## 執行前置與當前狀態

- 先完成 [E03](../../sillytavern-api-reference/references/worldbook-version-verification.md)中用例所需的版本、配置、來源與待驗契約；獲得具體環境、匯入/寫入範圍及必要呼叫費用授權。
- 使用新建隔離聊天/測試書和自寫短文，記錄基線與候選的獨立身份。只打開所選依賴；關閉原生遞迴。不把六類 EJS 場景當作唯一實現，也不套用固定 order、品牌深度或關鍵詞數量配額。
- 只執行獲准的自寫隔離材料，不執行外部整卡、預設指令碼或浮動遠端依賴，不改真實存檔製造錯誤。隔離夾具也不是安裝、全卡執行或付費呼叫許可。
- **本次環境未核驗，真實酒館執行待驗證，模型呼叫未進行。** 隨包 [靜態夾具](../tests/fixtures/worldbook-isolated-contract.json)是新寫的 JSON 資料，沒有 EJS、宿主指令碼或遠端匯入；倉庫測試只證明所宣告設計規則自洽，不證明模板執行。

## 最小用例集合

| 用例 | 隔離輸入/變化 | 必須觀察 |
| --- | --- | --- |
| 原生命中/未命中 | 可靠水位事實 + 橋樑規則；一個命中關鍵詞、一個不命中 | 原生入口與最終請求相應片段，未命中不假裝執行條件 |
| 條件真/假/缺值 | 同一已可達入口的水位為漲水、正常、缺失 | 條件值與輸出分別記錄；缺值不自動等同 false 或正常水位 |
| 入口不可達 | 條件材料為真，但入口未被選中 | 條件未執行、沒有輸出；不能只改條件表示式診斷 |
| 顯式讀取 | 明確存在、停用、缺失的三個目標 | 實際書/UID、返回值/失敗、輸出和最終請求；停用讀取不支援就如實記錄 |
| 狀態/聊天衝突 | 狀態指向當前時代，訊息只談另一時代 | 按已選優先順序解釋選中項；不能把提及當作遷移狀態 |
| 初始化與一致性 | 缺值、未開始/待初始化、章節點和時期不符 | 明確阻塞或已批准降級；沒有無意義的動態目標 |
| 寫入失敗 | 在隔離作用域使寫入被拒絕或返回失敗 | 原狀態保留、失敗可見、依賴它的生成停止；生成開始不證明寫成功 |
| 交界重複 | 同義別名、兩個控制器、原生+模板同時候選同一內容 | 全域性身份仲裁後，實際最終請求僅保留應有的一份 |
| 預算 | 可選項超額；必要內容自身超額 | 優先順序與省略原因、完整規則、最終分詞；必要項放不下明確失敗 |
| 只讀投影 | 有效 0、false、缺失以及要摺疊的模組 | 投影保留欄位語義/必要標記，完整儲存前後未變 |

用例可以先驗證請求組裝，不傳送給模型。若宿主不能安全捕獲實際待發送請求，應記錄捕獲受阻；不要把普通頁面預覽當成該請求，也不要擅自觸發收費生成。

採用 MVU 時，還須驗證初始化/schema 成功，並檢查已有狀態的讀取、有效補丁與無效補丁的處理、解析/校驗/回寫各層結果，以及 UI 與下一輪如何使用狀態。schema 拒絕不能寫成“已經更新”。採用 UI 時，只檢查按鈕的動作是頁面切換、寫入還是發訊息，並追蹤其資料鏈；不增加 UI 文案案例。

## 同一觀察記錄貫穿到下一輪

在專案原有證據位置儲存記錄，使用 [空白記錄](../tests/fixtures/worldbook-runtime-observation.pending.json)的欄位或等效格式；每個用例與每次複測有獨立記錄，基線和候選不覆蓋。

| 欄位 | 記錄內容 |
| --- | --- |
| `caseId / artifact / baselineArtifact` | 用例、候選及基線的確定版本/hash；記錄來自哪個入口 |
| `environment / authorization` | 宿主、參與擴充套件版本、瀏覽器、配置，獲准操作/額度；不存憑證 |
| `input` | 狀態快照、實際訊息視窗及角色、會話/訊息/候選身份；用隔離資料 |
| `expected` | 合同要求，與實測嚴格分開；例如缺值時阻塞而非猜水位 |
| `observed.entry / condition / target / read` | 入口到達、條件真/假/缺失/未執行、目標書名/UID/名稱及實際返回/錯誤 |
| `observed.output / finalRequest` | 輸出字元數/標記；真正最終請求的證據引用、接收模型、片段或未捕獲原因；token含分詞器與範圍 |
| `observed.stateBefore / stateAfter / nextRequest` | 寫入前後同域狀態、投影不改儲存證據、下一輪相關輸入 |
| `observed.selectionBefore / selectionAfter / ui` | 當前會話/訊息/swipe、UI讀取的身份與動作性質；不適用寫明原因 |
| `runtimeStatus / runtimeBlockers` | 執行組裝的 `not-run`、`blocked`、`pass`、`fail`與執行側缺口 |
| `modelStatus / modelBlockers` | 模型行為的獨立狀態與模型側缺口，例如等待呼叫授權；不得混入執行側 |

未執行的 observed 欄位保持 null，不能把 expected 複製進去充當實測。空串是一次具體讀取結果，不能與未讀混用。若執行失敗，保留最早失敗的環節，並標出後續未執行的環節，不能把後續全部寫成“不命中”。

兩層各自校驗：本層 `pass` 要求本層阻塞為空，`blocked` 或 `fail` 必須保留本層原因。執行組裝已驗證透過、模型呼叫仍等待授權時，記錄 `runtimeStatus=pass`、`runtimeBlockers=[]`、`modelStatus=blocked`和對應 `modelBlockers`，不刪除真實模型阻塞，也不因此把執行結果改為失敗。原有未分層 `blockers` 要按原因拆分；沒有執行的模型結果仍保持空值。

對專案支援的重生成、swipe、編輯、回退，分別儲存前後選中候選、補丁應用次數、持久狀態、UI讀取和下一輪請求。宣告由誰恢復/重算；不支援某操作就記錄限制，不許推定擴充套件自動回滾。純文字回合只需輸入、請求、輸出、訊息儲存及下一輪證據。

## 靜態檢查與真實結果分開

只有完整 TavernWeave 原始碼檢出才包含下面的倉庫級測試；在倉庫根目錄執行：

```sh
node --test tests/worldbook-runtime-contracts.test.mjs
```

獨立 Skill 安裝也可以執行隨包記錄校驗，將 `<skill-root>` 換成當前 `sillytavern-runtime-debug/SKILL.md` 所在的真實絕對目錄：

```sh
node "<skill-root>/scripts/validate-worldbook-observation.mjs" "<skill-root>/tests/fixtures/worldbook-runtime-observation.pending.json"
```

第一條只測試新寫的目標對映、條件/衝突、去重預算、只讀投影及記錄邊界；內部示意函式不實現或模擬 SillyTavern/EJS/MVU，不匯入外部整卡。第二條只檢查記錄結構與證據等級是否自相矛盾；透過表示記錄合格，**不是 runtime pass**，也不能驗證證據引用內容是否真實。它不採集日誌、不連線酒館、不觸發模型。

真實驗收仍需人工/驅動核對證據：入口→條件→目標→輸出→最終請求；狀態寫入→下一輪消費。UI亮燈、模板未報錯、Node測試透過和模型回答貌似合理均不能替代。模型行為如需比較，使用獲准的相同模型/引數單獨記錄，不從請求組裝結果推出行為保證。
