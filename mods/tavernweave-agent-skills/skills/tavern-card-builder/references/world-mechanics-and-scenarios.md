# 世界因果、玩法與可選事件

用一次過河說明世界規則怎樣影響資源、路線和玩家選擇，也適用於獨立遊戲藍圖。世界創作沿用 [worldbuilding-design.md](worldbuilding-design.md)，條目拆合與載入交給世界書設計入口，狀態如何維護見 [variable-systems.md](variable-systems.md)。這裡不另建排程器或狀態庫，也不另立創作決定。

## 由規則產生一次有意義的選擇

從當前行動出發，追蹤一條已確認規則：條件變化後，哪些資源或路線受限？誰執行這條規則？玩家還可以怎樣做，代價是什麼？寫到足以支援當前選擇即可，不為湊欄目補齊歷史、生態、制度或遠方地區。

世界規則、玩法目標和重大劇情若尚未獲授權，先作為建議提出。一般細節在已授權創作範圍內補足。下面全部名稱、數值和設定是原創教學假設，不會自動寫入使用者作品。

沿用[榆冠王國的石渡](../../worldbook-design-and-writing/references/examples.md#shared-setting-the-kingdom-of-yuguan)。舊橋連著南岸城門與北岸河港；漲水時橋面不再供人通行，船工便開行順水渡船。為避開急流，載客船隻從南岸駛向北岸，空船回拖時不載客。船票代表一個座位；願意花更多時間的人，可以走青岑高地的土路。

此例的通行條件仍是：漲水關閉舊橋，高地道路不受水位影響，但各路段可能臨時封閉。高地有分別核對的往返路線；渡船隻有上述單向載客航線。寫清這些就足以形成選擇，不必再增設船票買賣或完整經濟系統。

本例把玩家已選擇的目標限定為“抵達北岸”，而不是拯救城市或必須參加某條劇情。若玩家尚未選擇目的地，先給選項與後果，不替其設定目標。

## 可操作機制合同

下一位作者應能據此判斷一次操作是否成立、怎樣結算。寫清所需前提、玩家動作、效果與代價，以及失敗或退出時會發生什麼，並讓玩家看得到結果。按機制實際需要組織，不要求固定 YAML 模板或效果數量。

| 動作 | 前提與結算 | 玩家能看到的結果 |
| --- | --- | --- |
| 檢視路線 | 讀取本輪已確認水位、道路封閉資訊和船票；只讀，無移動或扣費 | 可走路線與各自耗時；缺少資訊則說明未核實 |
| 走橋 | 當前在對應起點，低水位且該邊未封閉；成功移動並增加 5 分鐘 | 抵達另一岸；成功前不先寫成已經到達 |
| 乘船 | 在南岸，高水位，至少 1 張船票，航線未封閉；成功移動、扣 1 票並增加 10 分鐘 | 北岸位置、剩餘票數和耗時；沒有反向航線承諾 |
| 繞高地 | 每段 15 分鐘，檢查該段起點和封閉條件；南岸經高地到北岸共 30 分鐘 | 每段成功後的位置與累計耗時；第二段封閉不取消已走的第一段 |
| 等待或放棄 | 等待按本例約定增加 10 分鐘，但不憑空改變水位；放棄不扣票、不移動 | 說明時間變化或本次停止；沒有強制後續任務 |

非法動作或資料不足時說明原因，保留原狀態；不靠“為了推進故事”強行過河。通行前再次核對最新條件，避免把先前可用路線當作永久可用。結算責任由已選實現負責：純文字卡按確認規則與歷史保持連續；結構化狀態卡由已驗證寫入者處理。模型說“已扣票”不證明持久化完成。重複提交、重生成及回退的狀態一致性依原執行檢查，不在本頁另造補丁協議。

## 有向地圖與穩定節點

## 事件圖表達可能性

事件 ID 與地圖位置 ID 分開。邊表示可能到達的後續情境，不表示它已經發生；規劃節點、滿足條件、玩家選擇、結算成功及歷史記錄分別判斷。

在 `event-route-choice`，玩家可以選擇過河，也可以停留；若繞行青岑高地，還能登高檢視河道。走高地不強制觸發觀察，直接乘船也不需要補演這個節點。`event-ridge-observation` 後仍可繼續、返回或停止，實際移動依地圖邊。`event-arrival` 只有結算後確實位於北岸且出現相應到達記錄時成立；“載入了抵達條目”不算到達。返回路線選擇時可以再次使用已有節點，不能因原圖未畫迴圈就禁止合規動作。

節點的作者合同至少能回答當前任務需要的這些問題：

| 責任 | 本例 `event-ridge-observation` |
| --- | --- |
| 啟動條件 | 已在高地且玩家主動檢視；從南岸計劃繞行不算已經到達 |
| 所需材料 | 當前地點、已確認通行規則及可見地形；不要載入其他路線的未來結局 |
| 可用資訊與自由區 | 可描述已確認河道與路徑；水位未知時保持未知，不為氣氛改值 |
| 動作和退出 | 看完可繼續或返回；可直接跳過，不追加新任務或固定劇情 |
| 完成證據及影響 | 本次檢視的實際記錄；檢視本身不扣票、不移動、不強制推進其他節點 |

資訊披露圍繞當前選擇所需事實安排。付票、單向航線和已知封路必須在相關選擇前可見；景觀細節可以在主動檢視時補充。不能為懸念隱藏必需成本，再把後果歸咎於玩家。未證實傳聞保留來源，敘述順序變化不改變事件實際先後。人物心理、對白或弧光不屬於本次方法交接。

故事圈、章節佈局或情節圖只在作者需要時作為檢查因果與節奏的工具；不要求每個場景有轉折、固定階段數或不可逆成長。先檢查某個條件怎樣改變選擇及後果，不能把寫好的綱要提升為壓過玩家行動和世界規則的必然未來。新增重大劇情仍按原創作決定門。

例如可用“看清處境 → 嘗試路線 → 承擔已知代價 → 確認結果”檢查這次短冒險：是否在選船前說明了單向航線與船票，繞行後是否承接真實耗時，到達後是否仍留有下一步選擇。它檢查的是資訊與反饋有沒有缺口；玩家選擇停下時，就沿停止條件結束，不補造失敗、成長或返鄉來湊齊故事圈。

## 交接與反例

向世界書設計者交接“本輪需要哪些共同規則、當前節點資料與條件”，由其結合實際原生/模板能力決定拆合和載入；不把每個地點或事件自動變成一條世界書。向狀態 owner 交接位置、時間、船票及封路的消費需求；能從既有欄位可靠派生的可走路線不再做一個由模型另寫的狀態。向開場作者交接相同起點與初值；向實現者交接動作與失敗反饋。具體 API、模板語法和真實載入證明分別由專項能力負責。

| 檢查輸入 | 應得結果 |
| --- | --- |
| 高水位、有票、人在南岸 | 可選單向渡船或未封閉的高地；舊橋不可走 |
| 高水位、無票 | 不扣成負數；仍可選高地或停止，不能強制安排贈票劇情 |
| 人在北岸、高水位 | 沒有反向渡船；回程檢查高地路線 |
| 高地第二段剛封閉 | 已走的第一段保留；說明前方阻斷，可檢查返回或等待 |
| 水位未知或路徑 ID 不存在 | 不猜水位、不跳到預設節點；只保留條件可確定的選擇 |
| 節點條目被讀取、玩家尚未選擇 | 沒有移動、扣票或事件完成記錄 |
| 改名、調檢視座標、重排列出順序 | 已有 ID 與關聯保持，不改變通行和事件意義 |

隨包測試只驗證這個原創資料例的引用、條件與成本，並用故意改壞的資料檢查反例。它不是生產執行時，不執行預設或卡內指令碼，也不證明實際宿主、模型或存檔已經透過。真實專案仍檢查本輪選擇、結算前後、顯示/儲存/下輪模型可見性，並分別報告證據。
