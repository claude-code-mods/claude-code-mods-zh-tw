# 取樣、專案分工與有界長任務

## 先把取樣做成真實證據

已有專案按其採證方法和驗收題繼續；不要重新爭論長任務自動化是否值得。先選代表材料：普通敘事、別名/多人關係、跨階段或跨版本衝突、源文缺口；聯網/圖片若屬於目標，再加入頁面歸屬和實際影像觀察樣本。樣本數量按用途決定，所用材料和呼叫也須在本輪授權範圍內。

順序處理與宿主原生子 Agent 只在真實可用時對照。記錄模型/宿主、樣本單元、實際嘗試次數、用量來源、輸入/輸出 token、返工、錯誤斷言和檢索題結果。快取與推理欄位按該宿主口徑另記，不重複加進輸入/輸出；本地字元數不能冒充 token。不要用本任務賬戶累計用量或不同材料估算節省百分比。

`measured` 指可核對的宿主/API 回執；`estimated` 是明確標註的估算；`unavailable` 使用空值並說明缺口。工具驗證格式與數值，不認證回執真實性或語義質量。樣本報告必須由執行者回查證據，不能為讓 `plan` 透過而自填成功。

選擇策略需要檢索題透過且無懸而未決的無依據斷言。不一定要多 Agent；若未測出價值，序列是有效選擇。token 不可見時，說明不能實施 token 總量門；只有使用者明確接受後才用呼叫/批次數上限繼續，不能擅自把未知記成零。

## 專案專用路由

在該專案的計劃 `roles` 內記錄實際職責，例如：採集員定位官方文圖；精讀員處理指定章節；人物/關係整理員更新檔案；校核員回查原句與階段；主 Agent 承擔去重、衝突處理、落庫和交付。按當前任務裁剪角色，不強制開滿全部角色。

每個子任務收到：作品版本、改編線、源單元和雜湊、允許讀的既有條目、產出格式、不得寫入的範圍、呼叫/上下文上限、完成/失敗訊號和返回物件。預設子 Agent 返回候選檔案，主 Agent 唯一呼叫 `usage`/`commit`；不同子 Agent 不共同寫記錄、索引或任務賬本。同一實體跨批次保持 ID，以當前檔案雜湊接續。不能為了多 Agent 把整部作品重複塞給每個角色。

沒有原生子 Agent 時按同一合同序列；三席 Soul 不當作三個執行中的子 Agent。後臺/恢復能力逐項觀察，不把可生成批次 JSON 當作宿主已經支援無人值守。

## 批次迴圈與停止條件

`plan` 繫結實際樣本雜湊、當前源集合、選中策略、明確單元列表、使用者範圍說明、專案角色和呼叫/批次上限。計量總數在庫內累積，更換計劃不自動清零。取樣用量獨立儲存在 benchmark，批次計量在任務賬本；報告兩者時分別列出。

1. `next` 分配有界單元。已有 active 時返回同一批，先核對候選和已登記嘗試，不能盲目重發呼叫。`execution_allowed=false` 時只做不新增模型呼叫的校驗/落庫或停下處理。
2. 宿主在實際輸出/呼叫限制內執行分配任務；保留開始/結束狀態。不要聲稱指令碼能強制限制宿主未提供的生成長度。
3. 每次成功、失敗和重試都用獨立 `attempt_id` 呼叫 `usage`；同 ID 同資料重複登記不計兩次。崩潰後無法確定呼叫是否已發生時先核對宿主回執，不能把“沒儲存結果”解釋為“沒花 token”。
4. 校核候選的出處、階段、改編線與矛盾，再 `commit`。批次 ID＋候選雜湊防重複，更新舊條目需要當前 Markdown 雜湊；有衝突保留候選和人的版本。
5. 持續領取下一批，直到本輪單元完成或預算/範圍/質量邊界觸發。正常批次不打斷使用者；完成、失敗、預算不足或需選擇時通知。

token 預留只是下次啟動條件，實際用量可能超出單批預留；真實超額照記並阻止後續啟動，不截斷或隱藏費用。呼叫端需設定實際可用的生成上限；未計量呼叫存在時，token 總量門停止繼續分配。授權範圍變更、材料指紋變化或策略變化時重做受影響的取樣/計劃繫結。

`pause` 阻止繼續領任務，不會遠端取消已經發出的請求；取消要用宿主實際能力並保留不確定結果。`recover` 只補齊已準備的本地寫入；檔案被人改過則報告衝突，不覆蓋。程序退出會釋放本地寫入互斥；本工具不自建後臺模型服務。應用/對話關閉後是否繼續由宿主決定，中斷後從專案賬本恢復。
