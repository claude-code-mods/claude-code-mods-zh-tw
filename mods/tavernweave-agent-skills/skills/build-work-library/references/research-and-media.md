# 聯網與文圖採集

## 先定研究問題

圍繞作品、作者/製作方、版本/地區、改編線、人物/專題和允許劇透範圍收集。已有本地材料先定位缺口，再補網，不要求每次轉庫都重新進行廣泛搜尋。為聯網輪次記錄查詢詞、允許來源/域名、頁面/圖片數量與用量上限；正常範圍內連續推進。

使用宿主實際可用的搜尋、網頁讀取和影像檢視能力。優先原作與官方來源，作品 Wiki、訪談轉述、社群解析和同人作品分別標身份；沒有聯網工具時登記缺口並繼續本地材料，不聲稱已檢索。搜尋命中只生成候選，開啟實際頁面並比對作品版本後才能採納。頁面失效、付費/登入限制、地區版本衝突記錄在懸項裡，不繞過訪問控制。

## 文字來源登記

為每個採納頁面記錄標題、實際來源 URL、作者/機構（可見時）、釋出時間/作品版本、採集時間、原作身份、改編線、使用邊界及必要定位。儲存自己的事實摘要和核驗必需的短摘錄，不整站抓取或複製受限正文；使用者自帶原文與網頁摘錄的可用範圍不同。工具 `add-source` 只儲存提供的 UTF-8 摘錄，不負責獲取頁面。

`kind=web-text`、`realm=reference` 是未能確認官方/原作身份時的常見選擇。不能僅憑搜尋排名或 Wiki 標籤提升為 `canon`。登記一版後保持凍結；內容更新另建來源 ID/edition，重新核對引用與樣本計劃。

## 圖片資料

建立圖片來源卡，包含原始頁面 URL、可用原圖 URL、作者/機構、作品版本、角色/場景、所需視覺特徵、版權/許可證現狀、採集時間、查看回執和預期用途。原圖看不到就標 `not-viewed`，可以儲存候選，不能寫服裝/構圖細節為已經觀察。實際看過後才用 `inspection=viewed` 與非空 `inspection_ref`；這是宿主觀察回執記錄，不是本地指令碼驗證了畫素。

預設 `use=reference-only`：登記來源卡與連結，不下載、裁切或把圖片打進可分發包。長期儲存/視覺庫匯入需要針對實際候選的既有授權；已獲同一範圍授權可連續執行，不重複逐步確認。來源的“可看見”不等於能再分發，許可證未知就保留未知，不能填預設可商用。

MediaWiki 站點可在站點確實開放 API 時使用其 [Imageinfo 介面](https://www.mediawiki.org/wiki/API:Imageinfo)查檔案頁面、URL 和擴充套件元資料；欄位不保證完整，也不代替原圖檢視及許可核對。本能力不固定依賴某站或專用採集服務。

## 採納與二創使用

文字和視覺證據可以連線同一人物/場景，但保持不同來源 ID。官方設定、改編版外觀和同人改繪可以並列檢索，不能混成一個“標準答案”。事實衝突保留各版本說明；可分發的創作資料包只帶獲准內容、自己的整理文字和必要來源連結。圖片生成、編輯、批次下載或實際視覺庫匯入使用對應工具和授權，不由轉庫命令代辦。
