# 按作品搭建前端沙盒：工作流程

TW 提供搭建規範，由 Agent 根據使用者作品的真實原始碼，在專案約定的測試目錄裡實現沙盒。沿用作品的技術棧、預覽服務與視覺風格，直接呈現要除錯的前端，按需要新增除錯控制元件。無需另做 TW 門戶、歡迎頁或通用演示應用。

沙盒是封裝前的可選打磨。複用使用者已有的採用／跳過決定；使用者已經要求搭建時直接推進。明確跳過時不建立沙盒，也不阻塞製作、構建與真實酒館檢查。是否省時、能發現多少問題取決於專案和用法。

## 先確定要看的範圍

1. 讀取專案續接、版本、維護原始碼、構建入口、前端模組、宿主依賴和資料所有權。區分維護源、構建產物和測試副本，列明本次實際執行哪份檔案。缺原始碼時如實說明，不從截圖重畫一個替身冒充原前端。
2. 列出本次範圍內全部模組、子介面、入口、關鍵操作、依賴和事件。選單模組聚焦一處互動，或聯合載入相關模組檢查共享狀態與相互影響；允許在測試中切換範圍並更新記錄。
3. 在專案測試目錄搭建最小宿主適配層：它負責真實原始碼裝載、隔離的狀態讀寫、事件轉發和 UI 引數。先核對專案現有啟動方式，不編造統一命令或固定埠。只服務本次預覽所需檔案，保持私有材料在使用者工作區。

接入要求見[專案適配合同](adapter-contract.md)，場景選擇見[單模組與聯合模擬參考](sandbox-recipes.md)。函式名和頁面佈局按專案決定。

## 一輪打磨

1. **對準原始碼。** 記錄實際執行的入口、版本和檔案 SHA-256；若是測試副本，同時記錄維護源及差異。依賴檔案也進入來源清單。未核對的雜湊記為 `unverified`，不能憑適配層的自報值宣稱校驗透過。
2. **還原執行關係。** 保留模組依賴的頂層視窗、訊息 iframe、blob／srcdoc 層級，以及 API 應在的視窗。除錯控制元件可接在現有模擬頂層；不要因多套一層容器而改變 `top`／`parent` 的含義。缺橋或介面放錯層時，應能觀察到失敗，不能向每一層塞全域性函式掩蓋問題。
3. **確認測試資料。** 初始預設、後續注入、快照恢復和場景重置都先展示來源、批次、目標聊天／樓層、欄位前後差異及預計事件，再明確確認。確認可透過專案介面或可追溯的對話完成，不要求特定按鈕。確認繫結資料內容、作用範圍與狀態版本；等待期間發生變化就作廢舊預覽。完整場景序列確認一次後按已確認步驟執行，出現衝突或失敗就停。
4. **比較實際結果。** 並列保留注入前、待注入、實際提交後的狀態，以及各模組實際觀察的欄位。介面顯示透過專案欄位對映核對，事件按實際發生順序記錄。取消不寫入；提交或恢復失敗保留真實錯誤和可讀回的狀態，不記成成功。
5. **手動調參並回落。** 用專案適合的控制元件調佈局、字號、間距與皮膚；確認選中的效果後寫回真實原始碼，移除臨時覆蓋，再用同一場景檢查。匯出記錄交給構建和實機檢查。

## 全量範圍與能力缺口

“全量”指本次確認範圍內全部模組、入口與能力。清單來自實際工程，不能把範圍縮到碰巧顯示成功的幾項。頁面開啟只證明入口可訪問。

| 狀態 | 記錄要求 |
| --- | --- |
| 已裝載 | 真實入口和必要依賴已掛載，互動與欄位對照另記結果 |
| 未接入／未裝載 | 本次範圍內尚未完成適配或掛載的模組與入口 |
| 暫不支援 | 缺少的介面或宿主能力、原因、後續檢查位置 |
| 本次未測試 | 尚無操作或欄位對映證據，不能計為透過 |
| 失敗 | 實際錯誤、狀態、復現步驟及修復後的複測結果 |

聯合模擬還要檢查共享狀態、事件順序、遮擋、樣式汙染、重複例項、重複訂閱與儲存串用。切聊天再返回時核對各模組的作用範圍和監聽清理。

## 手動調參、基線與結果回落

- 宣告引數名稱、作用模組、範圍、步長和單位。滑條與精確數值輸入共用真實元件引數入口或範圍明確的 CSS 變數；顯示當前值與基線值，提供單項／整組復位、預設、匯出和重新載入。
- 已採用的範圍內，UI 調參即時預覽，每次拖動不用重複確認。業務資料仍走注入確認。驗證 UI 操作沒有寫入業務狀態；若發現越界，停止這條調參路徑，記錄實際狀態並修復適配，不宣稱自動回滾或絕對隔離。
- 支援按住檢視基線、鬆開回到候選。並排對照時，同一原始碼版本建立兩個隔離例項，分別使用狀態、儲存名稱空間、事件匯流排和 UI 引數；兩個標籤頁不代表 localStorage 自動隔離。
- 如需除錯面板，應能移動、收起、隱藏與重新開啟，適配桌面和窄屏。使用者手動調整預覽尺寸時，Agent 不主動改變該視口；自動尺寸檢查使用單獨測試視窗。
- 引數匯出繫結原始碼版本與作用模組。版本不一致先核對差異與遷移，不改版本號繞過檢查。臨時樣式覆蓋明確稱為候選；寫回維護原始碼後移除除錯覆蓋與宿主補丁，再從維護原始碼複測。

## 證據與交接

將原始碼清單、模擬範圍、場景與資料來源、確認記錄、狀態差異、實際事件、UI 引數、復現步驟和未覆蓋項儲存到專案測試目錄，提供 JSON／Markdown 記錄。自動檢查、瀏覽器操作、真實宿主、駕駛員體驗分別列出。

沙盒瀏覽器透過只證明該版本原始碼在本次適配與資料下的表現。真實 SillyTavern、Tavern Helper、MVU、訊息樓層、模型和裝置行為交給 `sillytavern-runtime-debug`，以準確的構建產物複驗；`driverAccepted` 只能由駕駛員明確給出。

公開資料只放合成場景和脫敏機制。私有作品、原聊天、玩家資料與原始日誌保留在專案工作區；需要分享復現時先審查最小材料。
