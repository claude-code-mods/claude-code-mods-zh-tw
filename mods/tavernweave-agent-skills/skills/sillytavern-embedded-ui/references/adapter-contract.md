# 專案沙盒適配合同

本合同供 Agent 在使用者專案中實現沙盒時參考。TW 提供能力要求，函式名、框架、控制元件佈局和啟動入口沿用專案約定；本文中的介面名是說明用法，不代表隨 Skill 附帶可執行工具。

使用者採用後才建立沙盒。跳過就沿原流程繼續。這裡的“隔離”指測試狀態與真實聊天／存檔分開，不是作業系統安全沙盒認證。

## 描述與裝載

從工程入口得到完整模組清單，為每個模組記錄 ID、真實原始碼路徑、執行版本、檔案雜湊、掛載入口、視窗層級、所需介面和未模擬能力。模組 ID 唯一；雜湊待核對時寫 `unverified`。維護源和測試副本的差異另列。

裝載要等待真實入口就緒；失敗清理半裝載資源並保留錯誤。解除安裝要清理節點、訂閱、觀察器、定時器和臨時全域性值。切換單模組／聯合模式或重複裝載時，檢查舊例項確實退出。缺少能力就顯示未接入或不支援，不用空函式、固定成功返回或隱藏模組湊齊清單。

## 隔離狀態與確認

專案可用以下形狀描述狀態讀寫，也可對映到既有介面：

```text
readState() -> { context, revision, data }
commitState(context, expectedRevision, nextState) -> 實際提交結果
```

- `context` 是當前作用範圍，例如測試聊天、訊息樓層、swipe；必須能識別切換後又切回的陳舊確認，可額外記錄會話代次。
- `revision` 在狀態變化時更新。讀取返回副本，避免修改待應用區就直接改到共享狀態。
- 只寫宣告的測試儲存，不能連線玩家存檔、線上世界書或真實訊息傳送介面。真實元件觸發業務寫入時，同樣經過受控測試宿主；適配不能放行未確認的寫入。純導航與 UI 設定按 UI 引數規則處理。
- 空白宿主可有結構性空值。初始測試預設、豐滿角色、歷史資料副本、自動序列的來源與作用範圍先展示並確認；採用沙盒不等於確認任意資料注入。

提交順序：

1. 讀取當前範圍、版本和資料，儲存注入前快照。
2. 生成待應用批次，展示來源、目標、完整欄位增刪改和預計事件；使用者確認繫結這一份內容、範圍與版本。
3. 在實際寫入點重新檢查範圍、版本與批次。編輯待應用內容、切聊天、外部狀態更新都會使舊確認失效；重新生成差異後再確認。拒絕重複提交。
4. 寫入後重新讀取實際資料與版本，再核對模組觀察值；不以請求已傳送當作成功。

取消不寫資料。恢復快照和重置場景也是業務寫入，先說明目標並確認，不能把原聊天快照恢復到另一聊天。重置目標必須明確，不能猜測“重置”就是清空。寫入或恢復失敗如實記錄；部分成功保留實際可讀狀態，不靜默回滾。已確認序列內部不逐步重複詢問，遇到衝突或失敗就停止並記錄完成到哪步。

## 事件與狀態對照

提供事件訂閱與清理路徑，記錄操作、寫入、重新整理、異常的實際型別、順序、作用範圍和狀態版本。預計事件與真實事件分別儲存。

並列呈現注入前、待注入、提交後和各模組觀察到的狀態。專案欄位對映應說明“資料欄位 → 顯示格式 → 實際控制元件”，例如 `health: 76 → 76% → 狀態列文字`。實際值從元件／DOM 讀回，期望值由獨立對映算出，不能把輸入資料直接複製成觀察結果。

模組裝載、狀態一致、瀏覽器操作、人工觀感分開記錄。沒有欄位對映或模組未裝載時，對應觀察為未測試／不可用，不能記為一致。

## UI 引數與對照

每個引數說明名稱、作用模組、範圍、步長、單位、當前值和基線值，接入真實元件引數或區域性 CSS 變數。滑條與精確輸入同步；提供單項／整組復位、預設切換、按住看基線與引數匯出／載入。

UI 調參只改變介面設定，不能寫業務狀態。在已採用範圍內可即時預覽，不逐次請求確認；驗證其影響沒有越過宣告模組。匯出包含原始碼版本、模組與引數值；版本不同先做差異檢查，確認遷移再應用。並排比較時使用相同原始碼的兩個隔離例項，不能共享可變單例或混用儲存。

控制元件安排適應作品頁面和使用者除錯習慣。需要面板時支援移動、收起、隱藏與重新開啟；保留使用者手動調整的視口。把選定引數寫回維護原始碼後，移除臨時覆蓋，重新載入維護原始碼，核對同一場景效果。

## 結果記錄

輸出 JSON／Markdown：原始碼身份、模組與入口範圍、場景和資料來源、確認批次、前後狀態差異、各模組觀察、實際事件、UI 引數、錯誤與復現步驟、未接入／不支援／未測試項。私有材料留在專案測試目錄。

自動檢查、瀏覽器、真實宿主和駕駛員體驗分別給出證據與狀態。未測就寫未測，沙盒透過不能設定 `driverAccepted` 或宣稱實機驗收完成。
