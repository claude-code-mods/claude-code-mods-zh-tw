# 單模組與聯合模擬：場景參考

以下是按真實專案搭建沙盒的參考步驟和合成資料，不是可執行的演示應用。先讀[工作流程](sandbox-workflow.md)與[專案適配合同](adapter-contract.md)，使用使用者作品的真實原始碼、既有技術棧和本機預覽入口。

## 單模組：狀態列

1. 清點狀態列原始碼、構建入口、變數欄位、事件及視窗層級。若結構是“模擬宿主 → 訊息 iframe → blob 前端”，保留三層，變數橋放在原始碼實際訪問的位置。
2. 在專案測試目錄建立原始碼引用或可追溯副本，記錄版本、依賴與雜湊。已有適配能複用就複用；不重寫狀態列業務渲染邏輯。
3. 啟動空白測試宿主，列出已裝載、未接入和未模擬能力。準備合成狀態 `health: 30 → 76`，展示目標聊天／樓層和預計重新整理事件；明確確認後提交。
4. 對照提交後資料、狀態列觀察值與格式對映。先取消一筆修改驗證不寫入，再確認新批次。預覽等待期間切聊天或更改狀態，驗證舊確認被拒絕。
5. 在測試副本中移除必要變數橋、將介面故意放錯視窗層級，檢查失敗是否暴露。修復後重新載入同一原始碼；不向所有視窗鋪同名介面掩蓋問題。
6. 手動調整字號、間距、面板寬度，檢查基線、復位、匯出與重新載入的效果。選定候選後寫回維護原始碼，移除除錯覆蓋再複測。

原始碼雜湊可用專案現有工具核對；Windows 示例：`Get-FileHash -LiteralPath "<實際原始碼絕對路徑>" -Algorithm SHA256`。同時檢查裝載路徑與依賴，不能只核對入口檔案。

## 聯合模擬：狀態列、手機與控制中心

以同一作品的三個真實模組為例：保留各自入口、樣式邊界、事件介面；在宣告的同一測試聊天內使用正確的共享狀態。未接上的模組仍出現在範圍清單中。

| 場景 | 操作與觀察 |
| --- | --- |
| 一次狀態更新 | 準備合成 `health: 76`、`time: 08:30`，確認後讀取三個模組各自實際使用的欄位；沒有相關顯示的模組不硬造對映 |
| 控制中心改資料 | 使用者在真實控制元件編輯後，測試宿主先顯示差異和目標；明確確認才寫測試狀態，其他模組按原事件鏈更新 |
| 取消、失敗與恢復 | 取消前後資料相同；模擬寫入失敗保留錯誤；恢復前說明快照範圍，確認後讀回實際結果 |
| 重複裝載與連續事件 | 解除安裝再載入、連續觸發重新整理，檢查一次操作是否被重複處理、定時器與舊訂閱是否清理 |
| 切聊天再返回 | A/B 使用各自狀態與儲存名稱空間；回到 A 讀回 A，舊資料預覽作廢，不能複用舊確認 |
| 樣式與遮擋 | 更換手機皮膚、展開控制中心，檢查狀態列和彈窗是否受汙染、是否遮住必要操作 |
| 基線與候選並排 | 同一原始碼版本建立兩個隔離例項，用已確認的相同場景對照；引數、儲存與事件匯流排各自獨立 |

如果聯合模擬需要調整宿主適配，只在測試層修正；真實業務缺陷則單獨記錄並按已授權範圍修改維護原始碼。不要為了讓模擬器透過而改壞專案契約。

## 兩個失敗機制參考

- **事件列舉不完整**：適配只提供更新結束事件，元件還依賴更新開始與生成停止。訂閱失敗後清理已有監聽，介面能顯示但停在初值。從原始碼補齊必需事件與順序，保留失敗和修復後的對照。
- **世界書未繫結**：在隔離測試宿主中構造“所需世界書未繫結”，檢查前端是否給出可理解的錯誤及恢復入口。該合成例不證明真實酒館繫結正常；實際繫結和擴充套件行為仍需實機檢查。

## 訊息內容頁與只讀狀態列的補充場景

只選擇實際改動涉及的場景，複用已採用的專案沙盒。下表不要求另建演示應用，也不改變沙盒的可選性質。視覺設計遵循共用[前端質量規範](../../consult-tavernweave-library/references/frontend-design-quality.md)，不能只用測試資料填滿頁面便宣稱美化完成。

| 介面 | 輸入或操作 | 應觀察的結果 |
| --- | --- | --- |
| 訊息內容頁 | 標籤外有正常正文，內部有多條專案 | 只替換約定範圍，逐項顯示已解析的真實內容 |
| 訊息內容頁 | 缺欄位、邊界未閉合、正文含類似標籤的文字 | 按協議處理，不借舊訊息或虛構內容補齊；文字不變成程式碼 |
| 有傳送按鈕的頁面 | 點選後訊息已建立，但生成失敗，再次嘗試 | 顯示實際失敗階段，不重複建立已經存在的玩家訊息 |
| MVU 狀態列 | 合法的 0、false、空集合，以及缺失或非法欄位 | 顯示語義可區分，不把缺失狀態強轉成可信的 0 |
| MVU 狀態列 | 資料重新整理、選中專案被刪除、切換標籤頁 | 保留仍有效的介面狀態；選中項消失按已定規則處理，不改遊戲變數 |
| 兩類介面 | 窄容器、長中文、資源失敗 | 主體可讀，必要控制元件可用，沒有靠縮小文字掩蓋溢位 |

訊息協議方法見[訊息內容頁](message-content-ui.md)，欄位對映見[MVU 狀態列](mvu-statusbar-design.md)。檢查時讀取真實元件輸出，不把輸入值直接充當觀察值。真實訊息傳送只能進入已宣告的測試適配；宿主執行仍交給 `sillytavern-runtime-debug`。
