# E05：世界書目標與狀態消費者合同

本節說明世界書消費者如何沿用既有[變數設計](../../tavern-card-builder/references/variable-systems.md)、[模型與遷移](rolecard-data-model.md)、[樓層繫結](floor-and-ui-binding.md)。繼續只維護已有欄位賬本，不另建 schema，也不因讀取需要自行增加變數。純文字世界書只用目標對映部分。

## 名稱不是實體身份

按實際專案保留一張可核查對映：`別名 → 穩定實體 ID + 類別 → 內容身份 → 書身份 + 條目 UID + 顯示名`。時代/章節可作為已定義實體的限定維度；不能把地圖座標或隨時會改的展示名當成主鍵。UID 仍沿用現有匯出保護，跨書時必須帶書身份，不能把兩本書的同號條目視為相同。

| 原創小例 | 對映與結論 |
| --- | --- |
| “舊橋”“石橋” | 都對映 `bridge-east`，類別 `location`；正文權威為 `fixture-world` 的 UID 101，改顯示名不改身份 |
| “渡橋規程” | 類別 `rule`，正文 UID 102；不是因為名字含橋就同時猜 `location`、`faction` |
| 兩個控制器提到同一橋 | 保留候選來源，按同一內容身份交 [E06](../../sillytavern-rolecard-performance/references/worldbook-output-budget.md)去重；實體的地點介紹與通行規則仍是不同內容 |

構建/審查時展開所有可構造目標，逐項定位。動態字串拼接只能覆蓋已定義的組合；不能為了補全表格發明時代、章節或素材。

為每專案標明確標記以下狀態之一：

- **本書可定位**：書身份、UID、類別和名稱匹配；名稱 API 的精確/模糊行為另經 E03 核驗。
- **外部已核對**：在明確外部書/版本找到目標，且繫結與可達條件有證據。
- **外部待核對**：只猜外部可能補齊，仍是缺口，不能改成已存在。
- **類別或別名不符**：素材存在但對映錯位；修復須回到原對映/元件維護者，不執行多類別碰運氣讀取。
- **缺失/歧義**：找不到或找到多個目標；記錄候選和缺口，按已批准策略跳過可選內容、給缺值提示或停止依賴它的生成。

停用是配置事實，不是上述存在性結論；能否顯式讀取由 [E03](../../sillytavern-api-reference/references/worldbook-version-verification.md)和真實探針決定。未命中、空正文、讀取失敗也要分開，不以“沒有報錯”判斷完整。

## 初始化、寫入、讀取、消費同義同域

沿用原欄位賬本，補清世界書相關欄位從初始化到使用的現有流程：

| 檢查點 | 必須一致的內容 |
| --- | --- |
| schema 與初值 | 路徑、型別、列舉、缺失/null/空值意義、初始化來源與哨兵 |
| 開局與後續寫入者 | 每個階段的唯一所有者、允許寫入的時機、相關欄位的成組變化 |
| 模板/指令碼讀取者 | 同一欄位意義、確切會話/訊息/swipe、快取快照及就緒條件 |
| 模型/UI 消費者 | 實際收到的投影/欄位、缺值策略與重新整理時點，不能只憑介面外觀 |

“待初始化”“未開始”是專案宣告的哨兵，不是正常章節。存在一個字串不代表有效狀態；預設值只補缺失不能修復已有哨兵。選擇章節點時核對其所屬時代和時期。需要成組寫入時，由原所有者完成；回讀確認成功後，才能繼續依賴該狀態的步驟。API 失敗、校驗失敗或寫入未確認時停止依賴的生成，保留原狀態或採用已明確的安全降級，不能靜默編造值。

例如隔離夾具用 `ready=false` 表示尚未開始，時代/時期/章節尚無業務值；`ready=true` 也必須滿足已定義章節與時代/時期的對映。數值 0、布林 false 可能是有效業務值，不能用真假判斷統一當缺失。是否引入 ready 欄位是例子的設計選擇，不能據此替使用者舊卡增加欄位。

重生成/swipe/編輯/回退時，按 [共享基礎](../../consult-tavernweave-library/references/sillytavern-runtime-foundations.md)和 [E07](../../sillytavern-runtime-debug/references/worldbook-isolated-runtime-checks.md)驗證選中訊息、狀態、UI與下一輪請求；狀態讀者不自行修復存檔。

## 自寫隔離例的反向檢查

- “外港”只指向尚未提供的外部書，保持 `external-unverified`；不能憑別名或外部書名稱宣佈目標齊全。
- 把“渡橋規程”的類別誤寫成 `location`，應報類別錯位；規則正文仍存在，不能將其報告成素材丟失。
- `ready=true` 但章節仍是哨兵，或 `return` 章節配著 `early` 時期，均不能進入有效章節點。先檢查狀態合同，不繼續拼接目標名。
- 提議遷入 `return` 時，需要同步 `period=late`；寫入未確認就繼續生成，會消費舊狀態。另一個讀者指向不同訊息/候選時，即使欄位同名也不能宣佈已同步。
- 讀者使用廢棄路徑，而欄位賬本與寫入者使用現行路徑，沒有明確適配就屬於消費者合同缺口；不能因此推斷其他獨立選擇器全部失效。

這些是圍繞橋樑隔離夾具獨立編寫的設計檢查，不是宿主實測結果。變數生命週期沿用既有合同；本節只補充目標定位和跨元件消費檢查，精確 API、匯出與遷移仍由原負責技能處理。
