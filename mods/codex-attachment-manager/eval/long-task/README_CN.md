# 評測：Claude Code 裡一段長任務，壓縮兩次再分叉

[English](README.md) · **簡體中文**

2026-11-01 測試。外掛 0.10.0（釋出前的分支，提交 `b16d202`），對照 0.9.1、快取修復之前的 0.10（提交 `b5e986c`）和不裝外掛。Claude Code 命令列 2.1.314，模型 `claude-haiku-5-5`，推理強度 low，系統 Windows 11。每組正式跑一次；正式之前用 3 輪的短流程試跑過三次，場景裡的幾處問題就是那時改的（見[試跑學到的](#試跑學到的)）。

## 結論

- **壓縮兩次、分叉一次之後，三組外掛都答對 19/20，不裝外掛 20/20。** 各組錯的不是同一題：
  - **0.9.1** 錯在分叉出的新會話裡：那裡看不到壓縮前的圖，它去取的三張圖都“查不到”。0.10 修的就是這個，它在分叉後的請求裡放回了全部 51 張圖的清單，兩次分叉後的兩題都答對了。
  - **快取修復前的 0.10** 錯在 Q7：給了兩個數（90 和 61），又在 Q9 裡自己撤回了這個回答。給出不止一個答案的按“含糊”算，不算對。
  - **0.10** 錯在 M1：問第 2 鏡偏暗的那一版，它答了雨夜街道偏暗的那一版 `s04_v2.png`。壓縮後放回的清單裡，`s02_v1.png` 那一行寫著“暗色調”，資訊在，是模型挑錯了行。
- **不裝外掛也答對 20/20。** Claude Code 壓縮時會去掉圖，但摘要裡留著檔名；模型需要看時，用 Read 把磁碟上的檔案再讀一遍（問題階段讀了 13 次）。這個場景裡的圖，除了兩張簡筆畫，都是磁碟上的檔案，所以測不出外掛在準確度上的差別。
- **花費：修好快取後，0.10 約是不裝外掛的 1.3 倍，修之前約 1.9 倍。** 按 Claude Code 報的 API 價格折算，不裝外掛 $0.036，0.10 $0.047；修之前的 0.10 是 $0.069，0.9.1 是 $0.065。
  - **原來貴在哪：** 外掛每輪把上一輪的圖換成佔位，改動了歷史裡的內容。Claude Code 只在最後兩條訊息上放快取斷點，改動之後這兩個斷點都讀不到之前存的快取，於是每組有 7 到 9 次請求只命中開頭系統提示那一段，後面整段對話要重新寫一遍快取。
  - **怎麼修的：** 引擎自己放斷點：一個放在之前存過快取、又在改動之前的位置，用來讀；一個放在下一張會被換掉的原圖前面，給下一次請求讀。佔位裡的評價和壓縮後的清單也不再跟著後來的回覆變。修好後只命中系統提示的請求從 7 到 9 次降到 1 次，和不裝外掛一樣；從快取讀的比例從 77% 升到 87%（不裝外掛 91%）。
  - **剩下的差距：** 輸出多了約 4,700 token，是模型給每張圖寫的特徵行；寫快取多約 2.5 萬 token；沒走快取的輸入多約 2.4 萬 token，原因還沒細查。
  - 外掛把最大一次請求從 3.3 萬 token 降到了 2.6 萬。這次規模小，Claude Code 的 Read 又已經把圖壓成了小 JPEG，省下的 token 還抵不過多出來的這些。
- **評測中發現並修好兩個問題，都在 0.10 裡。**
  - **新圖有時不帶編號**：Claude Code 有時在把這一輪剛讀的圖寫進記錄檔案之前就發出請求，外掛認不出這幾張圖，它們就不帶編號發出去，模型沒法給它們寫特徵行。0.9.1 第 2 輪有三張圖的編號錯了一位，就是這麼來的。開發機日誌裡，8904 次請求中有 119 次屬於這種情況。現在引擎遇到這種情況會重讀記錄檔案，最多等 1.5 秒。
  - **壓縮後不看新圖**：說明裡那句“不要用其他工具去讀取圖片檔案”，本意是被省略的舊圖要用 `cam_view_image` 取。第一次跑 0.10 時，壓縮後模型把它理解成連新圖也不能看，後面 5 輪使用者讓它看的圖一張都沒讀，答對 18/20（Q9、K1 錯）。現在這句只說被省略的圖，並寫明新圖照常去看；之後兩次 0.10 每輪都照常讀圖。
- **壓縮後放回的清單很短**：33 張約 1.6K token，51 張約 2.4K token，平均每張不到 50 token；這次對話短，它佔壓縮後第一條請求的 10% 到 13%。

## 測試場景

一部短片的關鍵幀和分鏡，中文對話，模仿使用者平時的用法。51 張合成圖，由指令碼繪製：

- **關鍵幀**：10 個鏡頭，每鏡 2 到 3 版，一共 26 張。使用者只說每一鏡在哪、有誰、出了幾版和檔名，從不說各版有什麼不同（偏暗、站位、戴帽子、打傘）：這些只在模型自己看到的東西里。
- **抽幀**：兩段影片，一段 8 幀、一段 6 幀，相鄰兩幀幾乎一樣，只有車或人的位置挪了一點。
- **其他**：4 張設定頁截圖，每張三行數字；4 張三檢視（女主一版、男主兩版、配角一版）；使用者直接發的兩張簡筆畫；使用者重發的一張之前的圖。
- **評價**：說好的（“v2 女主的臉最好，先定它”）、說差的（“太暗，不要了”）、只說一部分的（“衣服和光都對了，但表情不對”）、改主意的（“v2 光太硬，最後用 v3”）。
- **只有原圖才答得出的細節**：每張關鍵幀和三檢視的角落裡有一個淡淡的兩位數。

一共 16 輪，每輪使用者說讓模型看哪些圖，模型用 Read 看（代替生成的圖，省掉生圖的費用）。第 11 輪後（33 張）和第 16 輪後（51 張）各壓縮一次，用 `/compact`，和使用者手打一樣；自動壓縮關掉，各組都在同一處壓縮。每次壓縮後接著問題。最後用 `--resume … --fork-session` 分叉出一個新會話再問兩題，Claude 桌面版在使用者改了之前的某條訊息時就是這樣分叉的。

## 各組和怎麼跑

| | 是什麼 |
|---|---|
| **不裝外掛** | Claude Code 原樣。 |
| **0.9.1** | 上一個釋出版本，用 `git archive v0.9.1` 取出。0.9.1 的 mod 在 Claude Code 2.1.309 起不載入，所以換上了 0.10 的 `hooks/register.js`；兩個版本的 mod 只差這一處，比出來的是壓縮和續接的修復本身。 |
| **0.10（快取修復前）** | 這個分支修快取之前的提交 `b5e986c`。 |
| **0.10** | 這個分支：自動選圖（預設開啟）、特徵行、壓縮後放回的清單、`cam_view_image`，以及快取修復。 |

指令碼用命令列版 Claude Code，一個會話一個程序，像桌面版那樣一條條發訊息（`--input-format stream-json`）。評測用自己的 Claude Code 配置資料夾（`CLAUDE_CONFIG_DIR`），不帶任何人的技能、設定和記錄；外掛用 `--plugin-dir` 載入，每組各用自己的引擎埠和資料資料夾。模型只能用 Read 和 `cam_view_image`；它工作的資料夾在倉庫外面，讀不到倉庫的 CLAUDE.md。

## 花費和 token

一組從第一輪到最後一題的整段會話，含兩次壓縮和分叉。token 和費用都取 Claude Code 自己報的會話總計（`modelUsage`、`total_cost_usd`）。

| | 請求數 | 沒走快取的輸入 | 讀快取 | 寫快取 | 輸出 | 從快取讀的比例 | 只命中系統提示的請求 | 最大一次請求 | 費用 |
|---|---|---|---|---|---|---|---|---|---|
| 不裝外掛 | 56 | 5,946 | 975,343 | 85,827 | 19,801 | 91.4% | 1 | 33,156 | $0.036 |
| 0.9.1 | 56 | 6,103 | 1,026,427 | 198,760 | 29,442 | 83.4% | 7 | 29,309 | $0.065 |
| 0.10（快取修復前） | 52 | 6,089 | 817,710 | 236,367 | 29,016 | 77.1% | 9 | 26,524 | $0.069 |
| 0.10 | 56 | 30,130 | 958,904 | 111,336 | 24,508 | 87.1% | 1 | 25,940 | $0.047 |

“從快取讀的比例”是讀快取佔全部輸入（沒走快取的、讀快取的、寫快取的）的比例。第一次跑 0.10（改措辭前）有 5 輪沒看圖，請求少，不放進比較（$0.0365）。修快取的過程中，前兩版各跑過一次，分別是 $0.047 和 $0.065，單跑一次的波動不小。

壓縮後放回的清單（0.10）：

| | 放回 | 清單約多少 token | 壓縮後第一條請求 | 佔比 |
|---|---|---|---|---|
| 第一次壓縮 | 33 張 | 1,563 | 15,182 | 10.3% |
| 第二次壓縮 | 51 張 | 2,357 | 17,909 | 13.2% |

清單的 token 按 Claude 自己輸出的校準係數估算（一個漢字約 1.3 token，其他字元約 0.45），請求的 token 是 API 報的。

## 試跑學到的

- **角落數字太顯眼**：一開始數字是深色底板上的白字，模型直接把它寫進特徵行，細節題不用取原圖就能答。改成淡淡的小字後，還是有一些特徵行寫了數字，這幾道題就不一定要取圖（上面細節題那張表裡的“憑特徵行”）。
- **只靠色調分不清**：有一題問“暖色調的那一版”，可書房的背景本來就偏暖，模型選了另一版。改成了一眼看得出的區別：偏暗、站位、戴帽子、打傘。
- **新圖不帶編號**：試跑裡有一輪三張圖都沒帶編號，查下來是上面說的寫記錄檔案的時間問題，修在 0.10 裡。

## 侷限

- 每組只跑了一次，談不上統計意義：費用單跑一次的波動就有上面那麼大，三組外掛各錯一題、錯的又不是同一題，也說明不了誰更準。只測了一個小模型（Haiku 5.5，推理強度 low），只測了 Claude Code；Codex 上的同類檢查在倉庫的自測裡，不在這份評測裡。
- 規模小：51 張圖，壓縮兩次。使用者的真實會話一個可能有兩百多張圖，那時不裝外掛的請求會大得多，Claude Code 也會更早自動壓縮；全量清單從多大規模開始不夠用，這次也沒測。
- 圖都是合成的，又小（512×768），Claude Code 讀圖時還會壓成 JPEG，所以圖本身佔的 token 不多。生成的大圖、截圖多的會話，結果可能不同。
- 不裝外掛能答對，是因為圖都在磁碟上、檔名留在摘要裡。直接貼進對話、磁碟上沒有檔案的圖，壓縮後只有外掛能找回原圖；這次關於簡筆畫的題，模型靠它之前說過的話就答對了，沒測到這種情況。

## 另一次測試：真實會話回放

釋出前還用一個真實的長會話做過一次回放（2026-10-31，Claude 桌面版，Sonnet 5.5，推理強度 medium）。素材是使用者自己的專案，不公開，也就沒法復現，這裡只寫數字：照使用者原來的話和原來的圖一輪輪重放，讀了 152 張圖，在真實會話壓縮的兩個位置各壓縮一次（94 張、127 張時），壓縮後問了 12 題，編號全對，沒有取錯一張圖。這次回放找出了三個問題，都已修好：並行讀圖亂序時有的圖沒有編號（0.4 起就有）、評價被截成半句、重發的同一張圖在清單裡列成兩行。

## 自己跑一遍

需要命令列版 Claude Code（`claude` 在 PATH 上）、能用 Haiku 5.5 的 Claude 賬號、Node 24 和這個倉庫的 git 歷史（0.9.1 那組從標籤 `v0.9.1` 取出）。圖片由指令碼現畫，不用下載。先給評測自己的配置資料夾登入一次：

```bash
CLAUDE_CONFIG_DIR=local/eval-long/claude claude auth login
node spike/src/eval-long.ts --label run1
node spike/src/eval-long-summary.ts --label run1 --out eval/long-task/results/<日期>
```

Windows PowerShell 不認第一行的寫法，登入那一步改成這樣（最後一句清掉變數，免得這個終端裡之後的 `claude` 也用評測的配置；跑評測的指令碼自己會設好它）：

```powershell
$env:CLAUDE_CONFIG_DIR = "local/eval-long/claude"; claude auth login; Remove-Item Env:CLAUDE_CONFIG_DIR
```

- `--runs off/haiku,v0.9.1/haiku,v0.10/haiku` 選組（模型也可以是 `sonnet`）；`--effort` 選推理強度（預設 low）；`--quick` 只跑 3 輪、壓縮一次、問 5 題，用來檢查環境。
- 指令碼看著賬號的用量，一週額度用到 90% 就停（`--stop-at` 可改）；5 小時額度快滿時，等它重置再接著跑。
- 三組默認同時跑，一組約 3 到 5 分鐘。

[results/2026-11-01](results/2026-11-01/) 裡是正式執行的彙總：每題的回答、取回了哪些圖、每組的 token 和費用；快取修復後的 0.10 在 [results/2026-11-01-final](results/2026-11-01-final/)。回覆保留原文，去掉了本機路徑。
