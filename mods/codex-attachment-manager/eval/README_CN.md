# 評測：Codex 裡一段關鍵幀對話，裝外掛和不裝外掛

[English](README.md) · **簡體中文**

另見：[Claude Code 裡一段長任務，壓縮兩次再分叉](long-task/README_CN.md)（2026-11-01）。

2026-10-24 測試。外掛 0.9.0，另拿 0.7.1 作對照。Codex 用的是 Codex 桌面版自帶的 app-server（`codex-cli 0.163.0-alpha.11`），模型 `gpt-6-sol`，推理強度 low，系統 Windows 11。這是一次小測試：只有一個場景，每組正式跑了一次，前面另有兩次試跑，場景就是靠它們改出來的。

## 結論

- **不裝外掛時，只要 Codex 需要把整段對話重新發一遍，就發不出去。** 9 張關鍵幀讓整段對話達到 42.4 MB（壓縮後上傳 31.8 MB）。這種情況出現在重啟之後，以及壓縮之後緊接著的那一問。三次執行裡一共遇到 6 次，一次也沒發出去。Codex 先顯示 `Reconnecting... 1/5` 到 `5/5`，之後改走 HTTP，一直重試到我們停下來。
- **裝了外掛，同樣的請求只有 0.12 MB，都發出去了。** 有新圖的那一輪仍然要發新圖，外掛省掉的是之前各輪的圖。
- **找圖：** 0.9.0 在壓縮前 6 題全對，壓縮後 6 題也全對。兩道細節題只有看原圖才答得出，模型每次都只取回了要看的那一張。
- **token 不是主要的收益。** 輸入 token 總量少了 16%，最後一次請求的上下文小了 37%。但沒命中提示快取的 token 多了 36%，所以費用怎麼比，要看快取打幾折：快取按一折計算的話，兩邊差不多。
- **在這麼短的任務裡，特徵行（0.8 加的）沒有顯出差別。** 沒有特徵行的 0.7.1，壓縮後也是 6 題全對。最可能的原因是 Codex 自己壓縮時寫的摘要還記得這 9 張圖。當初加特徵行，是為了長得多的任務，這次沒有測，見[侷限](#侷限)。

## 測試場景

一段中文的短劇關鍵幀對話，模仿使用者平時的用法。9 張合成關鍵幀，1024×1536 的 PNG，每張 3.2–3.9 MB，由指令碼繪製並加了噪點，體積和真實生圖差不多。每張圖的一個角落裡藏著一個數字。使用者每一場都說明是在哪裡，但從不說哪張是哪張；評價圖時按位置說：

| 輪次 | 使用者說 | 圖片 |
|---|---|---|
| 1 | 這部短劇的女主穿紅衣、黑色長髮，男主穿藍衣、棕色短髮。第一場在書房，這是兩張關鍵幀，先簡單看一下。 | S1 女主中景 · S2 男主中景 |
| 2 | 第二場在雨夜的街上，兩張，簡單看一下。 | R1 女主近景（偏暗） · R2 街道空鏡 |
| 3 | 上一輪第一張太暗了，這是重出的一版。 | R3 女主近景 |
| 4 | 第三場在黃昏的海邊，兩張。 | B1 男主中景 · B2 女主近景 |
| 5 | 上一輪第二張，臉是目前最好的。 | – |
| 6 | 第四場在竹林，兩張。 | Z1 女主中景 · Z2 男主近景 |

之後提問，答案事先都定好了。每道題問的是不同的圖，前一題的答案不會幫到後一題：

| | 問題 | 答案 |
|---|---|---|
| F1 | 雨夜街上、畫面裡沒有人的那張空鏡，是哪個檔案？ | R2 |
| F2 | 我說過臉最好的是哪張？ | B2 |
| F3 | 雨夜裡女主的近景有兩版，我要用重出的那一版，是哪個檔案？ | R3 |
| F4 | 書房裡男主的中景是哪個檔案？ | S2 |
| F5 | 海邊男主的中景是哪個檔案？ | B1 |
| F6 | 竹林裡女主的中景是哪個檔案？ | Z1 |
| D1 | 竹林裡男主的近景，角落裡有一個數字，是幾？ | 7 |
| D2 | 書房裡女主的中景，角落裡有一個數字，是幾？ | 4 |
| N1 | 把“今天天氣很好”翻譯成英文。 | （不需要看圖） |

每組用各自的 Codex app-server 跑兩個任務：

- **任務一：** 先跑 6 輪，再問 F1–F5、D1、D2、N1。然後重啟 app-server、恢復這個任務，這時 Codex 必須把整段對話重新發一遍，再問 F6。
- **任務二：** 先跑 6 輪，再壓縮一次（`thread/compact/start`），然後問全部 9 題。

答案按檔名或數字自動判分。某一步失敗，或者 3 分鐘內沒有回答（傳圖那幾輪是 10 分鐘），這個任務就到此結束。

## 三組

| | 怎麼跑 |
|---|---|
| **不裝外掛** | Codex 原樣。中間串著外掛的引擎，只用來統計位元組數，什麼都不改寫，Codex 照常用 WebSocket。 |
| **0.9.0** | 本倉庫現在的外掛：自動選圖（預設開啟）、特徵行、`cam_view_image`。 |
| **0.7.1** | 加特徵行之前的最後一個版本，用 `git archive v0.7.1` 取出：有自動選圖，但佔位裡只有編號、名稱、來源、輪次和尺寸。 |

三組都關掉了會操作電腦的工具，沙箱只讀，測完把測試任務歸檔。

## 結果

### 請求發不發得出去

| | 重啟後（任務一） | 壓縮後（任務二） |
|---|---|---|
| 不裝外掛 | 發不出去：42.4 MB | 壓縮本身成功，緊接著的那一問發不出去：42.4 MB |
| 0.9.0 | 發出去了：0.13 MB | 發出去了：0.12 MB |

不裝外掛時，只要 WebSocket 連線一直開著，Codex 每輪只發新增的內容，所以 6 輪傳圖本身都能過。一旦要整段重發，兩條路都走不通：

- **WebSocket：** 31.9 MB 的訊息每次都在 6–11 秒內被拒。這麼短的時間根本傳不完，看起來是訊息大小有上限。
- **HTTP**（Codex 的退路）：每次傳約 61 秒後被結束通話。

壓縮也幫不上忙。Codex 壓縮時，使用者的訊息連同裡面的圖都原樣保留，只把模型的回覆換成一段加密的摘要，所以壓縮之後的請求裡仍然是 9 張圖。壓縮這一步本身能完成，是因為 WebSocket 連線還開著，Codex 幾乎只需要發一個“開始壓縮”的標記。

![任務二每一步最大的那次請求：完整對話漲到 42.4 MB；外掛只發這一輪的新圖，其餘時候約 0.1 MB](results/2026-10-24/request-size-zh.svg)

### 壓縮前後找圖準不準

| | 壓縮前（任務一） | 壓縮後（任務二） | 角落數字 | 取回的圖 |
|---|---|---|---|---|
| 不裝外掛 | 5/5；重啟後的 F6 沒發出去 | 第一問就沒發出去 | 2/2 | –（每張原圖都看得到） |
| **0.9.0** | **6/6** | **6/6** | **4/4** | 4 張：每道數字題一張，找圖題一張沒取 |
| 0.7.1 | 第 5 輪網路卡住\* | 6/6 | 2/2 | 2 張：每道數字題一張 |

\* 引擎經本機代理連線上游時，連線一直沒建立起來，請求根本沒發出去。這一項不計入結果。

不裝外掛時模型每張原圖都看得到，它在壓縮前的成績相當於上限。裝了外掛，之前的圖都換成了佔位：找圖題模型靠自己記下的內容回答，只有數字題需要的原圖才取回來。

### token

任務一里同樣的 14 步，從第一次傳圖到 N1：

| | 輸入 token | 命中快取 | 沒命中快取 | 輸出 | 最後一次請求的上下文 |
|---|---|---|---|---|---|
| 不裝外掛 | 501,803 | 471,680 | 30,123 | 326 | 38,786 |
| 0.9.0 | 421,870 | 380,928 | 40,942 | 766 | 24,421 |

省掉之前的圖，上下文少了約 1.4 萬 token。但每當某一輪的圖換成佔位，快取的字首就從那裡斷開，沒命中快取的 token 因此變多。輸出多出來的是特徵行。

## 試跑學到的

- **試跑一：** 使用者每次都說清楚哪張是什麼（“第一張是女主中景”）。Codex 壓縮時會保留使用者的訊息，所以壓縮後的找圖題，讀使用者自己的原話就能答，根本沒測到模型記不記得圖。於是改了場景：使用者不再說哪張是哪張。
- **試跑二：** 使用者也不說場景在哪裡。合成的“海邊”只是橙色天空加幾道藍線，“竹林”只是綠色豎條，模型沒認出來，特徵行寫成了“街頭”“綠牆前”。問“海邊男主的中景”時，0.9.0 有兩次回答“沒有這張”，沒有去取原圖核對；那一次 0.7.1 倒是答對了。可見特徵行的質量取決於模型當時看圖看出了什麼；對不上時，模型可能直接說沒有，而不是再看一眼。正式場景按使用者平時的說法，說明了每一場在哪裡。

## 侷限

- 每組只正式跑了一次，談不上統計意義。
- 用的是合成圖。真實關鍵幀更容易認出畫的是什麼，但彼此之間也更像。
- 只測了一個模型（`gpt-6-sol`，推理強度 low），只測了 Codex，沒測 Claude Code。
- 任務很短：9 張圖，壓縮一次。當初加特徵行，是因為一個長任務壓縮後，模型拿了開頭的人物中景，而不是使用者說最好的那張近景。要復現那種情況，需要幾十張圖、壓縮好幾次。後來在 Claude Code 裡測了一段更長的任務（51 張圖，壓縮兩次再分叉），見 [long-task](long-task/README_CN.md)。
- 只在一臺機器上測，上傳經過本機代理：7.8 MB 的 HTTP 請求要 25–65 秒。WebSocket 不管網速，幾秒內就被拒。網速更快時 HTTP 能不能傳完 42 MB，這次沒有測。

## 自己跑一遍

需要 Windows 和 Codex 桌面版（指令碼用它自帶的 app-server）、能用 `gpt-6-sol` 的 ChatGPT 登入，以及 Node 24。指令碼會在你的 Codex 裡建名為 `[CAM測試] 評測 …` 的測試任務，測完自動歸檔。圖片由指令碼現畫，不用下載。

```bash
mkdir -p local/eval/v0.7.1 && git archive v0.7.1 plugin | tar -x -C local/eval/v0.7.1
node spike/src/eval-keyframes.ts --label run1
node spike/src/eval-summary.ts --runs run1 --out eval/results/<日期>
```

`--arms off,on,v07` 和 `--threads X,Y` 用來選組和任務，`--draw` 只畫圖不跑。中途停掉的執行會留下沒歸檔的任務，用 `node spike/scripts/archive-test-threads.ts` 歸檔。

[results/2026-10-24](results/2026-10-24/) 裡是正式執行的每一步：回答、取回了哪張圖、請求大小和 token 數。回覆保留原文，去掉了任務編號和本機路徑。
