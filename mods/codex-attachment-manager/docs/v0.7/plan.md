# v0.7 方案：子代理和旁聊也自動選圖

> 狀態：使用者 2026-10-13 定；開發和實測完成（第 5 節），2026-10-14 釋出 v0.7.0（使用者同意直接釋出）。規格以 [spec.md](../spec.md) 為準，實現見 [design.md](../design.md)。

## 1. 背景與目標

- [Issue #2](https://github.com/chipfighter/context-attachment-manager/issues/2)（2026-10-12，v0.4.0，macOS 上的 Codex 桌面版）：主任務開著自動選圖，它派出去的子代理和在它裡面開的旁聊卻不受管。子代理一個請求帶 26 張圖、47 MB；旁聊只問了一句文字問題，請求卻帶著主任務的 39 張圖、48.75 MB，重連 5 次後報 `Broken pipe`。同一時間主任務自己的請求從 48.7 MB 改寫到 6.3 MB。
- spec 原來寫的是“子代理不單獨處理……其他情況等開源後按使用者反饋再定”（使用者 2026-09-25），這就是等來的反饋。

## 2. 規則（使用者 2026-10-13 定）

1. **開關**：主任務面板加一個開關“子代理和旁聊也自動選圖”，預設開，老任務也一樣。它和主任務自己的自動選圖開關分開：開著時，不管主任務自己開沒開自動選圖，子代理和旁聊都按自動選圖管；關掉就不管，請求原樣發。
2. **旁聊**：用原任務的圖片記錄。從原任務帶過來的圖都換成佔位，原任務裡固定傳送的除外，原任務這一輪正在看的也換掉。模型要看哪張，用 `cam_view_image` 去原任務裡取。
3. **子代理**（啟動時不帶主任務歷史的）：找到它的主任務（子代理再派的子代理也一路找上去），按這個開關管它自己的圖：這一輪看的照發，前幾輪的換成佔位，要看再取。
4. **面板**：主任務面板顯示它的子代理和旁聊，每個一行：名字、幾張圖、上次請求換掉幾張、少發多少、現在按什麼規則管。
5. **不做**：
   - Claude 的子代理：issue 只說了 Codex；Claude 的子代理一般一次跑完、只有一輪，按自動選圖的規則本來就全發。
   - 在主任務面板裡逐張勾子代理和旁聊的圖（只顯示統計和規則）；給每個子代理單獨設開關。
   - 改“這一輪看的圖照發”。
   - 帶著主任務歷史啟動的子代理：照舊按分叉的規則繼承主任務的勾選。
   - Codex 自己的後臺任務（程式碼審查、對話壓縮、記憶整理）不運算元代理。
6. **釋出後**在 issue #2 回覆一條，告訴提問的人 0.7.0 已釋出（使用者 2026-10-13）。

## 3. 事實與依據

2026-10-13，本機 Codex 桌面版自帶的 `codex-cli 0.162.0-alpha.2`，用測試引擎和測試 app-server 實測（`local/v07/probe.ts`）；對照 openai/codex 的原始碼 `codex-rs/core/src/responses_metadata.rs`、`turn_metadata.rs`、`mcp_tool_call.rs`、`tui/src/app/side.rs`。

- **旁聊是不寫進硬碟的分叉**：app-server 的 `thread/fork` 帶 `ephemeral: true`（這個版本還要求 `excludeTurns: true`；終端版的 `/side` 也是這樣開的）。返回的任務有 `forkedFromId`（原任務）、`ephemeral: true`，沒有會話記錄檔案。
- **旁聊的請求**：每個請求（包括開 WebSocket 的那一個）的 `x-codex-turn-metadata` 裡，`thread_id` 和 `session_id` 都是旁聊自己，`forked_from_thread_id` 是原任務。
- **子代理**（`spawn_agent`，`fork_turns: "none"`；這個引數屬於 `multi_agent_v2`，本機預設關著，測試裡開啟）：有自己的會話記錄。`session_meta` 有 `parent_thread_id`（頂層，`source.subagent.thread_spawn` 裡也有）、`depth`、`agent_path`、`agent_nickname`（例如 “Franklin”），沒有 `forked_from_id`。
- **子代理的請求**：`thread_id` 是子代理自己，`session_id` 是主任務，`parent_thread_id` 是父任務，`subagent_kind` 是 `thread_spawn`，`thread_source` 是 `subagent`；請求頭另有 `x-codex-parent-thread-id` 和 `x-openai-subagent: collab_spawn`。
- **模型呼叫工具時**：`_meta.threadId` 是發起呼叫的那個任務（旁聊、子代理自己），`_meta["x-codex-turn-metadata"]` 裡同樣有 `forked_from_thread_id`、`parent_thread_id`。
- **v0.6 的情況**：子代理是新任務，按 v0.6 的預設已經開著自動選圖（測試引擎記下 `auto: true`）；旁聊的請求因為找不到會話記錄被原樣轉發（`thread index: no rollout found`），圖照發，和 issue 說的一樣。
- 歸檔主任務時，它的子代理一起歸檔。

## 4. 做法

- **認出來源**（`proxy.ts` 的 `requestIdentity`）：除了任務、輪次、視窗，再讀 `forked_from_thread_id`、`parent_thread_id`（沒有時看請求頭 `x-codex-parent-thread-id`）、`subagent_kind`，一起記進請求日誌。
- **開關**（`selection.ts`）：記在主任務的選擇檔案裡（`childrenAuto`），沒有就是開。面板用 `cam_set_selection` 改，模型不能改。
- **子代理**（`selection.ts` 的 `effectiveSelection`）：會話記錄裡有父任務、沒有分叉來源的，順著 `parent_thread_id` 找到主任務。子代理自己沒有開關時，看主任務的 `childrenAuto`：開著就是自動選圖，從子代理開始時算起；關著就關。
- **旁聊**（`proxy.ts`、`selection.ts`）：請求所屬的任務沒有會話記錄、請求裡又有 `forked_from_thread_id` 的，算旁聊。開關看原任務所屬的主任務。開著時用原任務的圖片記錄改寫：原任務的各輪都算之前的輪次，固定傳送的照發；關著就原樣轉發，WebSocket 也不攔。
- **取圖**（`plugin-server.ts`）：旁聊裡呼叫 `cam_view_image` 時，按 `_meta` 裡的 `forked_from_thread_id` 去原任務取；開關關著時和自動選圖關著一樣拒絕。
- **登記**（引擎）：看到子代理或旁聊的請求時，記在主任務名下（資料目錄 `state/children/<主任務>.json`），面板按它列出，統計用各自的請求記錄。
- **面板**（`panel.html`、`panel-state.ts`）：有子代理或旁聊時顯示一塊，標題行帶開關，展開後每個一行。做完截圖給使用者看。

## 5. 測試

- 單元測試：請求來源的識別；子代理找到主任務（多層、帶歷史的不算、使用者自己的任務不算）；開關開和關時子代理、旁聊的選擇；旁聊的請求按原任務改寫、開關關著時原樣；旁聊取圖；登記和麵板的列表；面板文字中英文一一對應。
- Codex 自測（`spike/src/v07-children-selftest.ts`，測試引擎 + 測試 app-server，推理強度 low）：
  - 旁聊：主任務看過圖之後開旁聊，問一句文字問題，圖都換成佔位；再問圖裡的細節，模型取回原任務的圖並答對。
  - 子代理：子代理第一輪看圖，第二輪請求裡那張圖換成佔位；問細節時模型取回並答對。第二輪由主任務用 `followup_task` 發起：app-server 不接受直接給 multi_agent_v2 子代理開新的一輪。
  - 開關關掉：旁聊和子代理的請求原樣發。
  - 每個任務最後看面板列出的子代理和旁聊。
- 面板：使用者 2026-10-13 看過截圖（收起、展開，開關開和關，中英文），同意。

結果（2026-10-14，測試引擎，本機 Codex 桌面版自帶的 `codex-cli 0.162.0-alpha.2`；每次 13 項檢查）：

1. 單元測試 206 個全部透過；外掛冒煙測試（Codex 自己的命令列裝外掛、開任務）透過。
2. gpt-6-sol 中文、英文和 gpt-6-astra 中文：13 項全部透過。
   - 旁聊：兩張圖都換成佔位；問文字問題時不取圖；問角落數字時從原任務取回 a.png，答對 7。
   - 子代理：第二輪請求裡它第一輪看的圖換成了佔位，取回後答對 7。
   - 開關關掉：旁聊走 WebSocket 原樣發出；子代理的請求不改寫，帶著它看過的原圖。
   - 面板：每個任務都列出了旁聊和子代理（子代理按 Codex 給的名字，如 Hooke、Galileo），規則和統計對得上。
3. sol 英文第一次跑時，旁聊取圖那一輪的上游連線在 62 秒後中斷，這一輪一直沒結束，等到 20 分鐘超時。同時還有連不上模型列表的超時，按網路問題處理，重跑透過。
4. gpt-6-luna 中文：旁聊和開關關掉的各項透過。子代理那組第三次才測成：第一次 luna 的子代理找不到“當前目錄下的 a.png”，第一輪沒看圖（所以指令碼改成給完整路徑）；第二次主任務的 luna 說沒有 spawn_agent 工具，自己去看了圖。第三次 5 項全部透過。
5. 另跑的一次 sol 中文 12 項透過。沒過的那項是開關關掉的那組：子代理一直沒看那張圖（它的 7 個請求都沒有圖），只按主任務轉給它的說法要 IMG-001；它的請求一個都沒被改寫，取圖也因為沒開自動選圖被拒絕，和開關關掉時應有的一樣。
6. 測出並修好的問題：子代理的第一個請求比它的會話記錄寫好還早約 40 毫秒（引擎 16:03:32.319 收到請求，記錄的第一條寫於 32.358）。原來讀到空檔案就把“不是子代理”快取下來，於是子代理不登記、開關關掉時它照樣被改寫；分叉任務的來源有同樣的隱患。改成讀到第一行才快取，加了復現測試。
7. 測試環境的問題：測試用的 app-server 用的是使用者真實的 Codex 配置，裡面裝著 0.6.0 版外掛，模型在旁聊裡第一次取圖有時調到它，舊版不認識旁聊，呼叫失敗，第二次才調到測試的外掛服務。現在自測把已安裝的外掛關掉，重跑旁聊那組，第一次取圖就成功。

## 6. 驗收

1. 開關預設開：旁聊的請求裡原任務的圖換成佔位，模型要看能取回；子代理前幾輪的圖換成佔位，要看能取回。
2. 開關關掉：子代理和旁聊的請求原樣發。
3. 主任務面板列出子代理和旁聊，統計和規則對得上。
4. 主任務自己的行為不變。
