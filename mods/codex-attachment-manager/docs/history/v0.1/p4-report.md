# 介面 P4 報告

> 2026-09-24，由 Claude 執行。本報告只寫統計和測試任務裡的簡短問答，不含真實對話、圖片和本機路徑。設計見 [plan.md](plan.md) 第 12 節，任務見 [tasks.md](tasks.md)。測試呼叫模型一律用 gpt-6-sol、推理強度 low。

## 1. 結論

- **面板已經嵌進 Codex**：它是 Codex 右側側邊面板裡的一個標籤頁“上下文素材”。使用者在側邊面板的“新建標籤頁 → 外掛和 MCP”裡手動開啟，不經過模型，也不花 token。
- **按使用者定的 MVP 做完**：
  - 按時間順序、按輪次列出任務歷史裡的圖，可以滾動；
  - 顯示縮圖，點開可以看大圖預覽；
  - 勾選後點“確定”儲存，從下一條訊息起生效；
  - 主題、字型和配色跟隨 Codex。
- **在使用者的桌面版上端到端測通**：打開面板，預覽，重新勾選被取消的圖，然後再提問，模型答對了這張圖的內容。

## 2. 入口

- 這一版桌面版允許工具在 `_meta["openai/ui"].entrypoints` 裡宣告入口。宣告成 `thread` 型別後，這個工具的頁面就出現在側邊面板的“新建標籤頁 → 外掛和 MCP”裡。
- 使用者點開後，桌面版用當前任務的編號呼叫這個工具，把結果交給頁面。頁面之後的呼叫也都帶著這個編號，所以面板天然知道自己屬於哪個任務。
- 標題欄沒有給外掛的入口，所以不做外掛視窗。
- 面板的入口工具是 `cam_panel`，列表裡的名字取工具標題“上下文素材”，圖示由外掛服務提供，淺色和深色各一份。

## 3. 面板

- 每張圖顯示：
  - 縮圖、編號、名稱；
  - 來源：使用者上傳、檢視的圖片、生成的圖片或工具返回；
  - 尺寸和大小。
- 狀態標籤：
  - “不傳送”：會換成普通佔位符；
  - “由 IMG-xxx 代替”：會換成指向那張圖的重複佔位符；
  - “與 IMG-xxx 相同”；
  - “模型需要這張”：模型最近一次回覆說了“需要 IMG-xxx”，而這張圖沒勾選；
  - “無法取消”：託管生圖的結果。
- 改動先暫存，被改動的行用藍點標出，底部可以撤銷或確定。代理沒在執行時，面板會提示取消暫時不會生效。
- 面板每 3 秒重新整理一次，新一輪的圖會自動出現，滾動位置保持不變。
- 開發頁 `spike/scripts/panel-dev.ts` 用合成測試圖，在瀏覽器裡扮演 Codex 的側邊面板，用來截圖和除錯，不會出現在 Codex 裡。

## 4. 桌面版實測

測試用 P3-6 那個任務：兩張測試圖 a.png 和 b.png，a.png 之前被取消，模型當時回覆“需要 IMG-002”。

| 步驟 | 結果 |
|---|---|
| 從“外掛和 MCP”開啟“上下文素材” | 列出 2 張圖：b.png 已勾選；a.png（IMG-002）顯示“不傳送”，並標出“模型需要這張”。縮圖正常，淺色主題正常 |
| 查外掛服務日誌和任務記錄 | 面板讀頁面、讀狀態、讀縮圖、定時重新整理，全部是非模型呼叫，沒有報錯；任務記錄裡沒有一條面板呼叫 |
| 預覽 a.png，勾上它，點“確定” | 預覽正常；儲存成功，a.png 的取消記錄清空 |
| 再問 a.png 的背景、形狀和角標 | 這次請求帶 2 張圖，沒有替換；模型回答“a.png 是白色背景，中央有一個紅色正方形，右下角有一個黑色小方塊。” |

這一輪走的是 HTTP。原因是 Codex 啟動時，a.png 還沒勾上，引擎按設計拒絕了 WebSocket 預連線，這個會話之後就一直用 HTTP。結果不受影響，重啟 Codex 後會恢復 WebSocket。

## 5. 順帶修的問題

- **縮圖卡在載入中**：原來縮圖只在“滾動到可見”時才載入。頁面不可見或還沒繪製時，這個判斷不會觸發，縮圖就一直卡著。現在改為全部按順序排隊載入，看得見的優先。
- **日誌太多**：面板每 3 秒重新整理時都會寫一行日誌。現在只記錄勾選變動、模型呼叫和出錯。
