# v0.1 之前的階段驗收標準

> 2026-09-28 整理文件時，從 spec.md 第 4 節原樣移來。這兩組關卡都已透過，結果見 [phase0-report.md](phase0-report.md) 和 [p2-report.md](p2-report.md)。文中提到的 IDEA.md、plan.md 都在本目錄。

### 階段 0：技術驗證

用 IDEA.md 中 2026-09-24 做過只讀檢查的那個斷流任務（原任務及其 fork）做樣本，依次透過下面的關卡。測量方法見 plan.md。

1. **只讀匯入**：列出樣本里全部圖片出現記錄，包括來源、輪次、大小和去重關係；無法識別的項單獨列出。原任務應得到 10 份不同的內聯圖片，fork 的 4 張都能和原任務匹配；如果數字對不上，要解釋原因。操作前後，原始記錄和素材檔案的雜湊不變。
2. **可見、可續**：重建出的新任務能在 Codex 桌面版裡看到、開啟並繼續對話；重啟桌面版後仍能恢復。
3. **能繼續改圖**：選中的圖能在下一輪用於繼續修改；取消過的素材在後面的輪次重新勾選後，模型能正確使用它。
4. **未選不傳送**：未勾選圖片的內容既不出現在新任務的歷史裡，也不出現在實際請求裡。
5. **請求變小**：實際請求位元組數與“文字歷史 + 選中圖片”的估算相符（誤差在 ±20% 以內），並且明顯低於約 43.8 MB 的基線。
6. **佔位符有效**：被問到未提供圖片的畫面細節時，模型不編造，而是說明未提供，並按約定方式索要。

### 代理路線 P2：按勾選改寫

在同一個任務裡：

1. 取消一張圖後，下一次請求裡不再有這張圖的內容（按內容雜湊核對），請求位元組數相應減少。
2. 被取消的圖所在位置是佔位符；本次請求裡有內容相同、仍在傳送的記錄時，是指向它的重複佔位符。
3. 問到被取消的圖的畫面細節時，模型不編造，並按約定索要。
4. 重新勾選後，下一次請求重新帶上這張圖，模型能正確使用它。
5. 對話始終在同一個任務裡，介面上完整可見；過程中沒有報錯或重連。
6. 全部勾選的任務，請求原樣轉發。
7. 原始記錄檔案只讀，不被修改。
