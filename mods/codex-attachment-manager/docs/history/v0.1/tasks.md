- 程式碼放在 `spike/` 下。每個指令碼開頭用註釋寫明用途、輸入和輸出。這是一次性的驗證程式碼，不追求產品化，但必須遵守只讀規則。
- 從真實會話裡提取的圖片、記錄片段、日誌和備份，只放在 `local/`（已被 git 忽略），不提交。
- 標了【需使用者】的步驟，要由使用者在桌面版上操作或做判斷。走到這一步先停下，說清楚需要使用者做什麼。
- 遇到 plan.md 沒有覆蓋的決策，停下來寫進報告，交給使用者決定。這類決策包括：改變路線、擴大範圍、需要直接寫入 `~/.codex`、需要修改使用者配置。
- 其他協作者不修改 `docs/spec.md` 和 `docs/plan.md`（由 Claude 維護，見 AGENTS.md）。發現需要修改的地方，寫進報告。

- [x] **T0 準備**（證據：`spike/package.json`、`spike/tsconfig.json`、`local/phase0-report-draft.md`、`local/protocol-types/`）

  - 記錄桌面版版本，以及桌面版自帶的 `codex.exe` 的路徑和版本。路徑寫成 `%LOCALAPPDATA%\…` 這樣的通用形式。
  - 確認樣本任務（原任務和 fork）的執行緒 ID，以及它們的歷史存在 JSONL 裡還是 SQLite 裡。
  - 用 `codex app-server generate-ts` 生成本機的協議型別。
  - 完成標準：以上資訊都寫進報告草稿。

- [x] **T1 只讀匯入**（關卡 1；證據：`local/assets.json`、`local/assets.md`、`local/phase0-report-draft.md`）

  - 操作前後，對樣本的記錄檔案分別計算雜湊並對比。
