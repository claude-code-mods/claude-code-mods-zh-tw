# 核心完善 P3 報告

> 2026-09-24，由 Claude 執行。本報告只寫統計和測試任務裡的簡短問答，不含真實對話、圖片和本機路徑。設計見 [plan.md](plan.md) 第 11 節，任務見 [tasks.md](tasks.md)。測試呼叫模型一律用 gpt-6-sol、推理強度 low。

## 1. 結論

核心已經可以按“裝好即用”的方式執行，介面之外的部分都已完成並透過自測：

- **引擎（本地代理）**：全機只執行一個，由外掛服務自動拉起，崩潰後自動恢復，隨 Codex 退出。
- **外掛服務**：由 Codex 啟動，負責拉起引擎、充當看門狗，並給面板提供資料。
- **一鍵安裝和恢復**：`cam.ts install` / `uninstall` / `status`。
- **面板資料**：圖片列表、縮圖、勾選和取消（只允許使用者操作）、上次請求統計、模型索要的編號。

還沒做的：使用者可以手動開啟的介面（P4），以及把核心裝進使用者自己的桌面版、實際用一輪（需要使用者配合）。

## 2. 試驗面板（P3-1）

在使用者的桌面版上：

- 面板出現在 Codex 右側的側欄裡，帶標籤頁；頁面顯示、和桌面版握手、回撥外掛服務、data URL 小圖都正常。
- 頁面訪問 `localhost` 被 CSP 攔截，和上游 #45913 一致，所以面板只能經外掛服務拿資料。
- 面板回撥時，桌面版會帶上當前任務的編號。
- 外掛服務的工具不會直接列給模型，要靠模型搜尋；gpt-6-sol 第一次沒找到，點名之後才打開。每次開啟還要花一輪請求。所以介面要由使用者自己開啟（使用者已確認）。

## 3. 穩定性自測（P3-5）

用我們自己啟動的 Codex，環境和桌面版一致，配置與安裝後相同，但透過命令列引數傳入，不改使用者的 `config.toml`。7 項檢查全部透過：

| 場景 | 結果 |
|---|---|
| 外掛服務拉起引擎 | 建好任務後 0.8 秒，引擎就起來了；其他例項發現它在執行，不會重複啟動 |
| 兩個任務同時用 | 只有取消了圖的任務一被改寫；任務二一直原樣轉發（走 WebSocket，沒有收到 426） |
| 引擎崩潰 | 被殺後 1.6 秒由外掛服務拉起，之後的對話正常 |
| 壓縮歷史 | 壓縮請求同樣被改寫；壓縮後再問被取消的圖，模型回答“需要 IMG-001。當前沒有提供 a.png 的畫面，我無法判斷顏色和形狀。” |
| 全部 7 輪對話 | 都完成，沒有報錯和重試 |

## 4. 引擎的生命週期（實驗）

- Codex 會把外掛服務和外掛服務拉起的程序放在一起管理：拉起引擎的那個外掛服務一結束，引擎也跟著結束；Codex 退出時，引擎同樣隨之結束。所以“隨 Codex 退出”是自動實現的。
- 代價是：如果拉起引擎的那個外掛服務例項先被 Codex 結束（多見於 Codex 剛啟動的幾秒），引擎會斷開最多 3 秒，然後由其他例項重新拉起（實驗裡 2.5 秒內完成）。
- 由 `cam.ts install` 在終端里拉起的引擎不受這個影響，它靠自己檢查 Codex 程序，Codex 全部退出 30 秒後自行退出。
- 如果以後這種斷開真的礙事，可以讓引擎徹底脫離 Codex 的管理，例如用 Windows 計劃任務來啟動它。不過這需要在使用者的系統裡註冊一個任務，屆時再請使用者決定。

## 5. 分叉任務的勾選

- 自測發現：分叉出來的任務原本從“全部勾選”開始，所以父任務裡取消的圖，到了分叉任務裡又會照常傳送。
- 使用者決定分叉時沿用父任務的勾選。
- 現在的做法：分叉任務第一次用到時，如果還沒有自己的勾選，就複製父任務在分叉之前取消的那些，存成自己的；之後兩邊各管各的。分叉的分叉會逐層向上找。
- 父任務的編號和分叉時間，取自分叉任務本地記錄的第一行（`forked_from_id`、`timestamp`）。4 個單元測試覆蓋。

## 6. 裝進桌面版實測（P3-6）

用 `cam.ts install` 寫入全部配置（代理地址、`respect_system_proxy`、外掛服務，以及 `.env` 的 `NO_PROXY`，因為使用者的環境變數裡有代理），然後由使用者重啟 Codex：

| 步驟 | 結果 |
|---|---|
| 關閉 Codex | 安裝時啟動的引擎在 Codex 程序全部退出後自己退出（日誌原因：“no Codex process left”） |
| 重新開啟 Codex | 外掛服務由 Codex 自動啟動並拉起引擎。頭 40 秒裡，幾個短命的外掛服務例項先後拉起引擎又隨之結束，引擎來回重啟了 4 次；有一次兩個例項同時去拉起，後到的那個發現埠已被佔用，自行退出了。之後穩定下來 |
| 上傳兩張圖，只回復“收到” | 經過引擎，走 WebSocket |
| 用命令列取消 a.png（IMG-002） | 引擎關掉這個對話空閒的連線 |
| 問 a.png 的顏色和形狀 | 握手收到 426，改走 HTTP；請求被改寫，IMG-002 換成普通佔位符，只發出 1 張圖；模型回覆“需要 IMG-002” |
| 關閉 Codex | 沒有 Codex 程序殘留，引擎隨之結束 |
