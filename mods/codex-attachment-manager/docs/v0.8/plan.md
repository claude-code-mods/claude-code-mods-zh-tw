# v0.8 方案：壓縮後找對圖，面板裡憑印象找圖

> 狀態：使用者 2026-10-18、19 定，已開發完，隨 0.8.0 釋出。規格以 [spec.md](../spec.md) 為準，實現見 [design.md](../design.md)。

## 1. 背景與目標

- 使用者自己遇到的情況（Codex）：會話中間有一張人物近景效果很好，壓縮一次後，模型拿五官參考時卻去取了對話開頭那張人物中景；問它壓縮前中間的某張圖，它也記不清了。原因：
  - 壓縮後，佔位裡只有編號、名稱、來源、輪次和尺寸，看不出是什麼圖；
  - 圖周圍的對話也被壓成了摘要；
  - 模型不知道自己記不清，很確定地拿錯了。
- 大多數使用者一直開著自動選圖，偶爾想從幾十張圖裡憑印象找出某一張（包括當時的廢片）看一眼，再決定要不要帶給模型。他們不想為此去問模型：問它要花 token，壓縮後它也記不清。
- 現在的面板資訊太多；使用者讓 GPT 做的原型分成兩個標籤頁，顯得亂。
- 目標：
  1. 壓縮之後，模型仍然能拿對之前的圖。
  2. 使用者在面板裡能憑印象找回圖片，面板變簡單，用起來讓人覺得本來就該這樣。

## 2. 規則（使用者 2026-10-18、19 定）

### 特徵行

1. 模型第一次看到一張新圖時（使用者上傳的、它生成的、檢視的、工具返回的），寫下一行特徵：先寫場景，再寫看得見的特徵，30 字以內，例如“深藍雨夜｜近景，正臉，霓虹反光”。
   - 同一個場景沿用之前用過的叫法。
   - 不寫“好看”“像誰”這類判斷。
   - 寫一次就不再改。
2. 使用者評價某張圖時，模型照使用者的原話記一條：帶上輪次，15 字以內，按時間累積，每張圖顯示最近 3 條。
   - 不排序，也不替使用者判斷褒貶，模型像看筆記一樣自己讀。
   - 拿不準是哪張時，說出自己選了哪張，或者問使用者。
3. 記錄過程不讓使用者看到：模型在回覆裡不提這件事，面板也不展示這些文字，只拿它們來搜尋和分組。
4. 特徵行和評價寫在這張圖的佔位裡，索引裡記什麼，佔位裡就顯示什麼。照常傳送的圖只帶編號標題，不帶特徵行：模型看得到原圖；不帶也免得每輪去改前面的標題，弄斷快取。模型那邊先不做搜尋工具。
5. 每個佔位第二行那句每張都一樣的說明要縮短，抵掉新增的字數。
6. 長度靠模型自己寫短。超長時，引擎在上限以內最後一個標點處截斷，加上“…”；原話全文留在本機，面板搜尋用全文。
7. 什麼時候寫：
   - 開著自動選圖：從第一張圖開始寫。
   - Claude：自動和手動模式都從第一張圖開始寫，因為 Claude Code 本來每次都發完整的歷史。
   - Codex 的手動模式：從使用者第一次取消勾選開始寫。在那之前，外掛不碰這個任務的請求，請求走 WebSocket；要寫特徵行，就得讓這個任務改走 HTTP，每次請求都重新上傳全部圖片，得不償失。
   - 升級之前已有的圖不補寫。
   - 子代理和旁聊不寫：它們的圖不在主任務的面板裡，而且存在的時間短。旁聊的佔位照樣顯示原任務裡的特徵行。
8. 新圖在它出現的那一輪就標上編號，模型才能當場對上號。現在開著自動選圖時，只有之前各輪固定傳送的圖帶編號標題。

### 面板（使用者 2026-10-19 看過可點選的原型後定）

1. 一屏：
   - 最上面是任務名和重新整理按鈕。
   - Codex 裡，右上角另有“停用外掛”按鈕，點了變成“啟用外掛”，兩個顏色不同；停用後提示重啟 Codex 才生效，隨時可以撤回。這和現在一樣。
2. 請求佔用卡片，樣式借鑑現在的面板，預設收起，底下有“展開詳情”：
   - 收起時也顯示預計請求、全部發送要多大、省了多少、佔用條，以及“下一條訊息：每輪都發 N 張 · 佔位 M 張”。手動模式下這一行是“照常傳送 N 張 · 佔位 M 張”。
   - 展開後多出三項：上一次請求；最近一輪模型取回了哪幾張（編號按鈕，只在自動模式下有）；子代理和旁聊省了多少（只在 Codex 裡有）。
3. 搜尋框，佔位文字是“畫面，或你當時說過的話”。能匹配的內容：特徵行、評價、場景、編號、來源（上傳、生成、PDF、網頁），以及那一輪裡的對話文字。
4. 篩選按鈕一排：
   - 依次是“全部”“上傳”“生成”，一條豎線，再接各個場景標籤。場景就是特徵行的第一段，沒有特徵行的圖歸到“其他”。
   - 一次只能選一個，和搜尋同時生效。
   - “上傳”包括 PDF 頁面和網頁截圖。
5. 縮圖按輪分組，最新一輪在最上面，列數跟著面板寬度變。
   - 縮圖上不寫字，只掛小標記：每輪都發；剛取回（自動模式）；不傳送（手動模式）；無法取消；已不在上下文；壓縮前（Claude）。
   - 右下角的角標：PDF 第 N 頁、網頁（Codex）。
   - 沒傳送的圖是灰色，勾上以後恢復彩色，和 0.7 一樣（使用者 2026-10-19 看過截圖後改）。
   - 每一輪標題線的末尾有一個小方框，點一下整輪勾選或取消，兩種模式都有，和 0.7 一樣（使用者 2026-10-19 看過截圖後改，原來是手動模式下的“整輪不發”“整輪發送”文字按鈕）。
6. 點縮圖開啟預覽：和 0.7.1 一樣佔滿面板，點圖片以外的地方就退出（使用者 2026-10-19 補充）。右下角是一個方框勾選，方框在文字左邊（使用者 2026-10-19 看過截圖後改，原來是滑塊開關）：
   - 自動模式下叫“每輪都發”，就是現在的固定傳送：之後每條訊息都帶上這張圖，直到關掉，其餘的圖照常由模型按需取回。
   - 手動模式下叫“傳送”。
7. 手動模式下，模型要了沒傳送的圖時，頂上出現“模型需要 N 張沒傳送的圖”，後面跟著編號按鈕。勾上那張圖的“傳送”後，它的編號就從提示條裡消失。
8. 點編號按鈕（“模型需要”和“最近一輪模型取回”裡的都一樣）：
   - 列表滾到那張縮圖，讓它停在正中，閃兩下，鍵盤焦點落在它上面；
   - 預覽開著時，先回到列表；
   - 那張圖被搜尋或篩選擋住時，先清掉搜尋和篩選。
9. 引擎沒在執行、請求沒能改寫之類的提示，有事才出現。
10. 底欄是一句說明和“自動選圖”開關。面板上一直顯示的開關只剩這一個。
11. 去掉兩樣東西：
    - 按來源篩選的按鈕（v0.2）；
    - 子代理和旁聊的“也自動選圖”開關（v0.7）。以後子代理和旁聊一律按自動選圖管，0.7 裡關掉過的，升級後也會開啟。
12. Claude 桌面版用同一個面板，有幾處不同：沒有停用/啟用按鈕，沒有子代理和旁聊那一行，沒有 PDF 和網頁的角標；壓縮前的圖照樣標“壓縮前”。

### 不做

- 跨任務、跨會話搜尋；
- 使用者從沒提過的主觀標準：等有人提，或者使用者自己遇到再說；
- 給模型用的搜尋工具；
- 讓使用者填寫或修改特徵行和評價，或者在面板裡顯示這些文字；
- 給升級前已有的圖補寫特徵行；
- Codex 手動模式下，第一次取消勾選之前寫特徵行。以後可以研究直接在 WebSocket 上加說明和編號；
- 子代理和旁聊寫特徵行；
- 其他 agent 平臺（見 spec 第 2 節）。

## 3. 要先驗證的事（關卡）

每個關卡通過了，才做對應的部分；沒透過，就回來和使用者商量。

1. **記錄看不見**（2026-10-19 透過）：讓模型原樣回覆幾種寫法（Codex 裡是 gpt-6-sol，Claude 裡是 Haiku 5.5），本機記錄裡都核對過原文，再由使用者在兩個桌面版裡看：
   - HTML 註釋 `<!-- … -->`：兩邊都原樣顯示，不能用。
   - 連結定義 `[//]: # "…"`：Codex 能藏住。Claude 桌面版會把直引號換成彎引號，這一行就不算連結定義了，整行顯示出來。
   - 連結定義 `[//]: # (…)`：兩邊都藏住了。**就用這種。**
   - 文字放在方括號裡的 `[…]: #`：Codex 能藏住，Claude 顯示出來。
   - 所以每條記錄單獨寫成一行 `[//]: # (cam …)`；括號裡不能有半形括號。終端版還沒看。
   - 補測（2026-10-19，使用者在兩個桌面版裡看）：好幾行連在一起也藏得住；放在回覆開頭、兩段之間也藏得住。但 Claude 桌面版會把**最新那條回覆最後一行**的連結定義原樣顯示出來，等後面有了新訊息又藏住了；Codex 放在哪兒都藏得住。**所以記錄行寫在最後那條回覆的開頭**，空一行再寫正文。
2. **模型會寫**：三個 GPT-6 模型和 Claude Haiku 5.5 都能按說明給新圖寫特徵行、記評價：格式對，編號對，正文裡不提；使用者在兩個桌面版裡看不到這些行。
   - Codex（2026-10-19，`local/v08/gate23-codex.ts`，推理強度 low）：sol、luna、astra 中英文 6 組全部透過。四輪裡，兩張上傳的圖和一張看圖工具開啟的圖都寫了特徵行；"第一張太暗、第二張構圖不錯"記到了對的圖上；正文沒提這些行。最後一輪三張圖都成了佔位，模型不呼叫工具，靠特徵和評價答對了。
     - 第一版說明下，sol 在評價那一輪說了"記下了"（使用者覺得奇怪）。說明改成"不用回應記錄這件事"之後不再說，但偶爾還會說"我會留意……""I'll use those preferences……"。
     - luna 碰到只有評價、沒有問題的那一輪，兩次沒寫正文：一次是整條空訊息（中文），一次只寫了記錄行（英文，介面上看是空回覆）。使用者定：luna 用的人少，措辭不為它改。
   - Claude（Haiku 5.5，2026-10-19，桌面版測試會話，`local/v04/desktop`）：
     - 第一張圖是 Read 讀出來的時候，說明緊跟在工具結果後面，Haiku 把它當成工具返回裡夾帶的指令，不照做，還告訴了使用者。Anthropic 關於對話中途系統訊息的文件也寫明，Sonnet 5.5 和 Haiku 5.5 可能不信任緊跟工具結果的系統訊息。另外，說明裡寫的"使用者不知道有這些記錄"讀起來像在瞞著使用者。
     - 改法（使用者定）：說明放在這一輪使用者那條訊息後面；措辭改成講清楚使用者裝這個工具是為了什麼，不再說"不知道"。改完中英文都照做了：三張圖各寫一行，編號對，寫在開頭。
     - 評價：從別的會話轉過來的訊息，Haiku 不當成使用者本人的評價，不記，這是對的。註明"這是使用者本人的原話，由我代發"之後，中英文都記到了對的圖上，但正文提到了記錄（"按原話對應到 a-red.png 和 b-blue.png"、"Noted: …"）。使用者親手打的評價，在改成"不認同也照記"之前測過一次：Haiku 覺得"並不暗"，問是哪一張，還說"確認後我再記下"。改完之後，使用者親手打的評價還沒測。
     - 最後一輪三張圖都成了佔位，中英文都沒調工具，靠特徵和評價答對了。中文那次開頭多寫了一行空記錄 `[//]: # ()`。
   - 再改兩處（使用者定）：只有評價、沒有要求時，正文簡短回應評價本身，不說明記了什麼、對應到哪張圖；這一輪沒有新圖、也沒有評價時不寫記錄行。改完重測：
     - Codex：6 組裡 5 組透過，評價那一輪的正文都很自然，例如"明白，第一張的顏色偏暗；第二張的構圖你覺得不錯。""Got it. The first feels too dark to you…"。luna 英文連著兩輪各漏記一條評價（這次的正文裡還按使用者 Codex 全域性 AGENTS.md 的要求給了英文表達建議，和外掛無關）。
     - Claude：中文回的是"收到。第一張（a-red.png）顏色太暗，第二張（b-blue.png）構圖不錯。"，沒有空記錄行。英文還是以"Noted:"開頭，其餘都對。評價仍是由我代發的。
   - 還沒驗證：Claude 裡使用者親手打的評價；記錄行寫在開頭時，生成過程中會不會閃一下。這兩項放到釋出後的實測裡（見第 5 節）。
3. **新圖當輪就有編號**：Codex 和 Claude 每一輪發出第一個請求時，看本機記錄裡有沒有這一輪的新圖。
   - 沒有時，按出現的順序推出它們將來的編號。編號只看出現順序，推出來的應該和之後記錄裡的一致，要驗證。
   - Codex（2026-10-19）：透過，6 組都是。新上傳的圖在它那一輪的第一個請求裡就已經在本機記錄裡（Codex 先寫記錄再發請求），不用推編號；看圖工具開啟的圖，在緊接著的下一個請求裡也認得。
   - Claude（2026-10-19）：透過。Read 讀出的圖在工具結果之後的那個請求裡就認得；使用者上傳的圖在它那一輪的請求裡就認得。也不用推編號。
4. **壓縮之後**：
   - Codex 用 app-server 的 `thread/compact/start` 壓縮，壓縮後之前的圖還在請求裡，以佔位的形式出現；
   - Claude 按 v0.5 的做法補在摘要後面；
   - 兩邊的佔位裡都帶著特徵行。
   - Codex（2026-10-19，`local/v08/gate4-codex.ts`，推理強度 low）：使用者的案例，6 組全部選對。開頭上傳同一個角色的半身中景，中間兩張無關的色塊圖，再上傳臉部近景並說"這張最好"；用 `thread/compact/start` 壓縮一次，再問"做五官參考用哪張"。
     - 壓縮後的請求裡 4 張圖都還在，都是帶特徵行的佔位，近景那張還帶著"評價：第 3 輪'這張最好'"。
     - 6 組都答近景那張，都沒調工具，理由是"正面臉部特寫"和"你說過這張最好"。再問壓縮前那兩張色塊圖，也都靠特徵答對了。
     - luna 英文沒記下"this one is the best"（第三次漏記評價），但靠特徵行裡的"臉部近景"照樣選對了。
     - 跑第一次時，經本機代理去上游的一個請求 20 分鐘沒有回應，同一時間 app-server 自己連 chatgpt.com 也失敗了。這是網路的問題，重跑透過。
   - Claude 還沒測：要有人在測試會話裡打 `/compact`，放到釋出後的實測裡（見第 5 節）。

## 4. 做法

- **認記錄**（`thread-index.ts`、`claude-index.ts`）：
  - 只從模型的回覆（assistant 訊息）裡認 `[//]: # (cam …)` 這種記錄行。使用者訊息和工具結果裡出現同樣的字不算，防止網頁內容裡藏著指令。
  - 每條特徵行和評價歸到對應的編號下，評價記下它所在的輪次。
  - 引擎和外掛服務各自從記錄裡算，不共享狀態，也不另存檔案，和編號的做法一樣。
- **搜尋用的文字**：每張圖那一輪裡使用者說的話、生圖提示詞或工具呼叫的引數、模型的回覆（擷取一段），再加上特徵行和評價。這些只給面板用；每張圖截一個長度上限，免得圖多時面板資料太大。
- **發給模型的內容**（`rewrite.ts`、`claude-rewrite.ts`）：
  - 另加一條“特徵行說明”，告訴模型怎麼寫特徵行、怎麼記評價（寫在最後那條回覆的開頭）、不要在正文裡提。它從第一張圖所在的那一輪起插入，只給主任務：Codex 裡放在那一輪之前；Claude 裡放在那一輪使用者那條訊息後面，不緊跟工具結果（見關卡 2）。原來的“上下文管理說明”不變，照舊在有圖被省略時才插入。
  - 每張圖都帶編號標題，這一輪的新圖也帶；“重複”佔位只指向之前各輪的規則不變。
  - 佔位里加上特徵行和評價；第二行改短。
  - 快取：勾選和記錄都不變時，改寫的結果逐位元組相同；這一輪新圖的編號標題，隻影響請求的末尾。後來加的評價會讓那張圖的佔位變一次，快取從那裡往後斷一次，和改一次勾選一樣。在 Claude 新賬號上，照現有的做法，去掉之後對不上的思考記錄。
- **什麼時候改寫**（`proxy.ts` 的 `needsRewrite`、`claudeNeedsRewrite`）：
  - Codex 不變：有取消的圖，或者用過自動選圖，才改寫。
  - Claude 改成：會話裡有圖就改寫。
- **子代理和旁聊**：去掉開關。`selection.ts` 不再讀 `childrenAuto`，`cam_set_selection` 也不再收這個引數，它們一律按自動選圖管。
- **面板**（`panel.html`、`panel-state.ts`）：
