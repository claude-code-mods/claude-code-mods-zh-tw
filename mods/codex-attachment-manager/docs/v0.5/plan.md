# v0.5 方案：Claude Code 壓縮後保留圖片

> 狀態：使用者 2026-10-12 確認；開發和實測完成（第 5 節），2026-10-13 釋出 v0.5.0。規則由使用者 2026-10-12 定（見第 2 節）。規格已寫進 [spec.md](../spec.md)（標著 v0.5），實現見 [design.md](../design.md) 第 12 節。

## 1. 背景與目標

Codex 每次請求都帶著任務裡全部的歷史圖片，外掛在那邊按勾選替換。Claude Code 不一樣：上下文到了壓縮線（手動 `/compact` 或自動壓縮），它把舊歷史換成一段文字摘要，壓縮前的圖一張都不再發給模型；圖太多時還會直接報錯，提示使用者壓縮或開新會話。使用者要求過“只去掉部分圖片、不整段壓縮”，被以不計劃做關閉（anthropics/claude-code#37461，另見 #52224）。

目標：Claude Code 壓縮之後，使用者壓縮前的勾選照樣有效。勾著的圖在壓縮後照樣發給模型，取消的照樣不發；使用者和模型都還能按編號用回壓縮前的圖。不換會話，對話照常進行。

Codex 不變：Codex 不會在壓縮時丟圖。

## 2. 規則（使用者 2026-10-12 定）

1. **保留勾選**：壓縮前勾著的圖，壓縮後照樣傳送；取消的照樣不發。自動選圖開著時，“固定傳送”的圖照樣傳送，其餘的照舊由模型按需取回。使用者在面板裡隨時可以改，從下一條訊息起生效。
2. **補在哪**：照樣傳送的壓縮前的圖，放在壓縮摘要後面，按編號排好、各自標上編號、名字和輪次。位置固定，勾選不變時請求逐位元組相同，快取能續上。實測後（2026-10-12）不發的那些也在這裡放佔位文字，和別處一樣（第 5 節）。
3. **告訴模型有哪些舊圖**：壓縮後附一份壓縮前的圖片清單（編號和名字，不含圖）。模型需要某張沒發的圖時照常寫“需要 IMG-xxx”；開著自動選圖時用 `cam_view_image` 取回（現在就能取，原圖還在本地）。實測後清單和說明放進摘要那條訊息後面的系統訊息，和 v0.4 的說明一樣（第 5 節）。
4. **不替使用者做決定**：不做自動保護。補回的圖太多、請求被拒絕或 Claude Code 又壓縮時，由使用者在面板裡少勾幾張或切到自動選圖；面板照常顯示請求大小的預估。
5. **改一條硬約束**：現在引擎“只替換使用者取消的圖片”。v0.5 起，引擎也會把使用者勾選、但 Claude Code 因壓縮不再發送的圖，從本地會話記錄裡取出來補進請求。其餘內容仍原樣轉發。

## 3. 事實與依據

- **原圖都在本地**（2026-10-11 在使用者本機核對）：Claude Code 的會話記錄只追加不刪除。一個壓縮過兩次的會話記錄裡有 17 張圖，16 張在最近一次壓縮之前，完整的圖片資料都還在。外掛現在就從這裡讀圖：壓縮前的圖在面板裡列著（標“已不在上下文”），自動選圖開著時模型也能按編號取回。Claude Code 只在定期清理舊會話時刪除記錄（第三方資料說預設 30 天），那時會話本身也沒了。
- **壓縮後的記錄**（同一會話）：先是一條壓縮分界（`compact_boundary`，用 `logicalParentUuid` 接上壓縮前的歷史），然後是一條使用者訊息，內容是摘要（`isCompactSummary`），之後是 `/compact` 命令本身的幾條記錄和重新附上的檔案。外掛的索引已經能跨分界編號，壓縮前的圖編號不變、標著 `compacted`。
- **快取**：模型每次請求都重新處理整段上下文，但字首和上一次完全相同時會命中提示快取，按約 1/10 的輸入價計費（Opus 5.5 是 1/20），寫入快取貴一些（5 分鐘 1.25 倍，1 小時 2 倍；Claude Code 用 1 小時）。快取省錢不省空間：補回的圖實打實占上下文視窗。補回的位置固定，所以只在壓縮後的第一次請求按全價算，之後命中快取。
- **新賬號的思考校驗**：補圖是對摘要之後內容的改動，之後產生的思考按 v0.4 的做法處理（引擎記下實際發出的內容，去掉對不上的思考）。
- **已知的顯示問題**（v0.4.0）：壓縮後如果下一條請求裡一張圖都沒有，面板會把壓縮前的圖當成“還會發送”。v0.5 改了壓縮前圖片的顯示，這個問題一併修掉。

## 4. 做法

- **索引和勾選**（`claude-index.ts`、`selection.ts`）：不變。壓縮前後的圖編號、鍵都不變，勾選按鍵儲存，所以壓縮後勾選自然還在。
- **改寫**（`claude-rewrite.ts`、`proxy.ts`）：
  - 認出壓縮後的請求：請求裡有一條使用者訊息的文字等於會話記錄裡最近一次摘要（`isCompactSummary`）的文字，並且最近一次壓縮之前有圖。
  - 在摘要後面插入，就在那條訊息裡、摘要文字之後（實測見第 5 節）：壓縮前的圖按編號排開，照樣傳送的每張前面一行標籤、後面是原圖，不發的是佔位文字。緊接著的系統訊息裡是說明：壓縮前的圖片清單（中英文兩份，跟著現在的語言），這次沒發哪些、怎麼要回；有圖沒發時前面是完整的“上下文管理說明”，後面訊息裡的佔位文字只再跟一段短說明。Claude Code 已在那裡放了系統訊息時並進去。勾選不變時這兩條訊息每次都一樣，位置固定，不碰工具呼叫和結果的配對。
  - Claude Code 自己生成摘要的那個請求不用特別處理：它和普通請求一樣帶著全部歷史和圖，照常改寫（第二次壓縮時，裡面同樣補上第一次壓縮前的圖）。這樣它的字首和上一個請求一致，能命中快取，寫摘要的模型看到的圖也和對話裡一致。
  - 其餘規則照舊：取消的圖換佔位符、說明訊息、思考記錄的處理。
- **面板**（`panel-state.ts`、`panel.html`）：壓縮前的圖照常可以勾選。勾著的顯示為照樣傳送、計入請求預估；取消的顯示“不傳送”。行上加一個“壓縮前”標記，說明它是補在摘要後面發的。介面改完截圖給使用者看。
- **取圖工具**：不變，已經能取壓縮前的圖。

## 5. 實測結果與待確認

2026-10-12 用開發引擎在桌面測試會話裡實測（Claude Code 2.1.295，Haiku 5.5）：讀了三張圖，使用者輸入 `/compact`，再問一句。

1. **壓縮時的請求**：和普通請求一樣帶著系統提示、全部 177 個工具和思考設定，內容是到這時為止的歷史，最後一條使用者訊息末尾加了一段 “CRITICAL: Respond with TEXT ONLY…” 的寫摘要要求。三張圖原樣在裡面，沒有被換成 “[image]”（第三方資料說的去圖，在這個版本上不成立）；最後一條回覆沒帶上。回覆是 `<analysis>` 加 `<summary>` 的摘要。所以寫摘要的模型看著圖寫，這個請求照常改寫即可（第 4 節）。
2. **壓縮後的請求**：第一條是使用者訊息，內容是一整段字串的摘要；接著一條空的系統訊息；然後是壓縮前的最後一條回覆，原樣保留；再往後是新的一輪。一張圖都沒有，模型憑摘要文字回答。補圖的位置定在第一條訊息裡、摘要文字之後。
3. **自動壓縮算不算補回的圖**（觀察，不加保護）：Claude Code 記進會話記錄的用量是 Anthropic 返回的，含補回的圖（英文測試會話最後一次 137,084 個輸入 token，其中快取讀 135,621）。輸入框旁的上下文用量是它自己的分類估算（172,023，其中“Messages”只有 125），不含補回的圖。它按哪個數決定自動壓縮沒有查到，已寫進 README：補回的圖占上下文，Claude Code 的顯示不算它們。
4. **Anthropic 對一個請求的限制**（[官方文件](https://platform.claude.com/docs/en/build-with-claude/vision)，2026-10-12 查）：圖片數 200k 上下文視窗的模型最多 100 張，其他模型 600 張；每張最大 8000×8000 畫素，一個請求超過 20 張圖時每張的尺寸限制更嚴（邊長不超過 2000 畫素就沒問題），歷史裡重發的和工具結果裡的圖都算；每張 base64 後最大 10 MB；整個請求最大 32 MB。已寫進 README。

開發後的實測（2026-10-12，開發引擎，Claude Code 2.1.295，Haiku 5.5；真實圖片的尺寸由測試圖的生成程式碼確定，模型給的數都和它一致）：

5. **第一版的問題**：說明放在摘要那條使用者訊息裡，沒勾選的圖直接不出現。補回過的圖取消勾選後再問，模型說之前的數“沒有依據，應當撤回”，並讓使用者重新提供圖片；說明裡點名“這次沒提供”“不要收回”之後仍然這樣。改成和 v0.4 一樣：沒勾選的放佔位文字，說明作為系統訊息跟在那條訊息後面。在已經收回過的會話裡複測仍然收回：模型照抄自己歷史裡的回覆，那個會話測不出改動，只能在新壓縮的會話裡測。
6. **新壓縮的會話**（中英文各一個，讀三張圖後用戶輸入 `/compact`）：
   - 勾著時問紅方塊邊長：中英文都答 240 畫素（看圖答對）。
   - 取消勾選後問沒描述過的黑色小方塊：都說現在看不到、之前的描述仍然有效，單獨寫一行“需要 IMG-001”/“need IMG-001”，不讓使用者重新上傳。
   - 問 240 還算不算：都說算，是看著原圖說的，沒有收回。
   - 勾回後再問：中文第一次沒看到補回的圖，說“這次訊息裡沒有附上”。全部勾回時不發完整說明，模型不知道勾回的圖回到哪裡；說明裡加上“勾回的圖回到這裡，不會出現在新訊息裡”後，中英文都答 48 畫素（對）。但兩邊都說自己之前那句“需要 IMG-001”是錯的：圖現在排在它之前的回覆前面，它以為一直都在。說明裡又加了一句“當時看不到是因為被省略了”，再改成講清這一段每次請求重新放；複測（這時會話歷史裡已經有這種自我糾正）中英文仍然這樣說。回答本身都對，只是這句話不對，寫進了 CHANGELOG；新壓縮的會話裡還沒測最後這句措辭。
   - 用另一張圖（c-tri.png）再走一遍取消、勾回：取消時中英文都透過；勾回後答對（48 畫素），仍有上面那句自我糾正。
7. **自動選圖**（中文會話）：壓縮前的圖都換成自動版佔位文字，`cam_view_image` 在工具列表裡。第一次問沒測過的細節時，模型照會話裡多次用過的方式寫“需要 IMG-002”，沒有取圖；告訴它可以自己取之後，它呼叫 `cam_view_image` 取回 IMG-002，答對（48 畫素）。下一輪取回的副本換成了“只在那一輪提供”的說明。固定傳送 IMG-001 後，它在摘要後照樣發出；模型又多取了一次這張已經在的圖，答對。v0.4 的中文測試也有過一次多取。
8. **模擬新賬號**（英文會話，推理強度 high，`CAM_EXPERIMENT_BLOCK_BINDING=error`）：第一次被拒（400），引擎去掉 3 段對不上的舊思考後重發，接受；取消一張後直接去掉對不上的思考，第一次就接受；全部勾回後，勾選相同時產生的那段思考對得上、放回去，接受，快取讀 135,621、寫 1,461。回答都對。
9. **請求逐位元組相同**：勾選相同的三個請求，摘要那條訊息和後面的系統訊息雜湊相同；取消一張時不同。
10. **Codex 迴歸**：全部單元測試透過（192 個）；`v01-placeholder-selftest.ts` 中文、gpt-6-sol low 全部檢查透過，測試任務已自動歸檔。v0.5 沒有改 Codex 的措辭。

## 7. 驗收

1. 壓縮前勾著的圖，壓縮後下一條訊息起照樣發給模型，取消的不發；使用者改勾選後從下一條訊息起生效。**透過**（第 5 節 6 項）。
2. 補回的圖在摘要後面，標著編號、名字和輪次；勾選不變時，連續兩次請求的這一段逐位元組相同。**透過**（第 5 節 9 項）。
3. 模型知道壓縮前有哪些圖：需要沒發的圖時按編號要；開著自動選圖時能取回並看圖作答。**透過，有兩點遺留**：勾回後模型有時說自己之前“看不到”是錯的（回答本身對）；手動用了很多次“需要 IMG-xxx”的會話切到自動選圖後，模型先照舊要圖，告訴它可以取之後才取（第 5 節 6、7 項）。
4. 面板正確顯示壓縮前圖片會不會發送，請求預估包含它們。**透過**（截圖見第 6 節 3 項）。
5. 新賬號（模擬）上補圖後對話不中斷。**透過**（第 5 節 8 項）。
6. Codex 的功能和請求不變。**透過**（第 5 節 10 項）。
7. 中英文都實測，真實桌面會話，Haiku 5.5。**透過**。

## 8. 不做

- 自動保護：補回太多時不自動減少，由使用者決定（使用者 2026-10-12 定）。
- `/clear` 或新會話：那是另一個會話，不帶過去的圖。
- 子代理：仍只管主對話。
- 另存一份圖片：直接讀 Claude Code 的會話記錄，不復製圖片。
