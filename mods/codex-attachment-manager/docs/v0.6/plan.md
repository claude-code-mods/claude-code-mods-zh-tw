# v0.6 方案：預設開啟自動選圖；Claude 桌面版自動打開面板

> 狀態：使用者 2026-10-13 定；開發和實測完成（第 5 節），2026-10-13 釋出 v0.6.0（使用者同意直接釋出）。規格以 [spec.md](../spec.md) 為準，實現見 [design.md](../design.md)。

## 1. 背景與目標

- 有些使用者連側邊欄都不會開啟（使用者 2026-10-13）。預設開著自動選圖，不打開面板也能省下之前各輪的圖。
- Claude 桌面版裡，用 `/cam` 開啟的面板有時會自己關掉；使用者希望不用輸入 `/cam`，面板自己開啟並保持開啟，除非使用者自己關掉。
- 使用者還問：自動選圖時模型需要多張圖，會不會都取回？

## 2. 規則（使用者 2026-10-13 定）

1. **預設開啟自動選圖**：所有新任務、新會話，Codex 和 Claude 桌面版都一樣。使用者電腦上已有的任務和會話保持原樣。使用者在面板裡改過的，以使用者的為準。
2. **面板自動開啟**（Claude 桌面版）：只在有圖的會話裡開啟。桌面版自己關掉的，會話再用時重新開啟；使用者自己關掉的，這個會話裡不再自動開啟，直到使用者輸入 `/cam`。

## 3. 事實與依據

- **面板為什麼會自己關**（2026-10-13，Claude 桌面版的日誌 `%LOCALAPPDATA%\Claude\Logs\main.log`）：一輪結束時、或者使用者離開這個會話（切到別的會話）時開始計時（`[WarmLifecycle:preview] Starting idle timeout … 1800s`），使用者回來看時計時停下；使用者不在、30 分鐘裡又沒有新的一輪，就斷開這個會話的自帶瀏覽器（`Idle timeout reached, disconnecting`、`[Preview] Stopped servers for worktree`），面板的標籤頁跟著關掉。Claude Code 程序照常執行，之後的請求照樣經過引擎，Mod 的 `session.start` 不會再執行。沒有設定項能改這個時間，外掛也不該讓會話一直醒著。
- **另一種情況**：記憶體緊張時，桌面版會停掉閒置很久的會話的程序（`[CliGovernor] pressure evicting … (idle 36301s)`），會話再被使用時重新啟動程序（`Resuming session`、`spawn`），這時 `session.start` 會再執行。
- **自帶瀏覽器的工具**（`Claude_Browser`，桌面版給每個 Code 會話的，不是公開給外掛的介面；終端和 VS Code 裡沒有）：`tabs_context` 返回 JSON 加一行文字，列出這個會話的標籤頁和各自的來源（面板是 `http://localhost:<引擎埠>`）；`preview_start` 每呼叫一次就多開一個標籤頁，所以開啟前要先看有沒有。
- **會話的開始時間**：Codex 任務的會話記錄第一條（`session_meta`）帶時間，分叉的任務記著來源；Claude Code 的會話記錄每條都有時間。
- **多張圖**：`cam_view_image` 一次可以取多張（`ids` 是一組編號，沒有張數上限），說明裡寫著“幾張就一次傳幾個”。

## 4. 做法

- **預設開啟自動選圖**（`selection.ts`、`thread-index.ts`、`claude-index.ts`）：
  - 引擎和外掛服務啟動時，在選擇目錄裡寫下這個版本第一次執行的時間（`auto-default.json`，只寫一次，Codex 和 Claude 各一份）。沒有這個檔案時沒有預設值（測試和舊版本都是這樣）。
  - 任務或會話沒有自己的開關時：開始時間不早於那個時間，就當作開著，從開始時算起（`autoSince`）；還沒有會話記錄的算新的。Codex 的分叉任務按它來源的任務算。預設值不寫進檔案，使用者在面板裡一改就寫下來。
  - 讀選擇的地方都經過它：引擎改寫、是否走改寫（Codex 的 WebSocket 改走 HTTP）、面板、取圖工具。
- **面板自動開啟**（`hooks/register.js`）：
  - 只在桌面版（自帶瀏覽器的工具能用）、請求經過引擎時。程序啟動時、每輪開始和結束時檢查：這個會話有圖、面板沒開、使用者沒在這個會話裡關過，就用 `preview_start` 開啟。所以模型讀了圖，那一輪結束時開啟；使用者貼了圖，那一輪開始時開啟。
  - 誰關的，按時間分：桌面版最早在一輪結束 30 分鐘後才關（使用者一直看著這個會話時更晚）。面板在這之前沒了，是使用者關的：記下來（外掛自己的儲存，按會話記，留最近 200 個），之後不再自動開啟。停了 30 分鐘以上，下一輪開始時面板不在，算桌面版關的，重新開啟。為了認出使用者在停頓裡關掉的，一輪結束 25 分鐘後再看一次。剩下認不出的只有停頓的第 25 到 30 分鐘之間被使用者關掉的，按桌面版關的算。
  - 程序被桌面版停掉又重啟的，從頭算：使用者關過的照樣不開，其餘的有圖就開啟。
  - `/cam`：清掉這個記錄，開啟新標籤頁並關掉舊的，只留一個。`/clear`、`/resume` 後，開著的面板換到新會話。
- **多張圖**：不用改；補測（下面）。

## 5. 測試

- 單元測試：預設值的起始時間只寫一次；新任務開、舊任務關、自己的開關優先、沒有記錄的算新的、分叉按來源算；Claude 會話同樣（面板、改寫、取圖工具、改成關之後保持關）；引擎啟動寫下起始時間。
- Mod 測試（`claude plugin test`，用測試時鐘）：有圖才打開、開著就不重開、貼圖的那一輪開始就開啟；停頓 30 分鐘以上被桌面版關掉的，下一輪重新開啟；使用者關掉的（停頓前 25 分鐘裡關的也算）不再開啟，程序重啟後也是，`/cam` 重新開啟並只留一個標籤頁；程序重啟後有圖就開啟；不在桌面版或請求不經過引擎時不開啟。
- Codex 自測（`v03-auto-selftest.ts` 新加任務 D）：不設開關，看新任務是否預設開著；一個問題同時需要兩張沒取過的圖，看模型是否都取回、答對。
- Claude 桌面版實測：新會話預設開著、多張圖一起取回、面板自動開啟和關掉後不再開啟。

結果（2026-10-13，開發引擎）：

1. 單元測試 196 個、Mod 測試 16 個全部透過；Mod 測試在上一版程式碼上跑，新加的 6 個都失敗，確認測得到改動。Claude Code 的外掛檢查（`claude plugin validate`）透過。
2. Codex 任務 D（不設開關）：gpt-6-sol 中英文、gpt-6-luna 和 gpt-6-astra 中文，新任務都預設開著（之前各輪的三張圖都換成了佔位文字），都一次取回了兩張圖。sol 和 astra 答對（7 + 5 = 12）；luna 把紫色圖的 5 讀成了 3，和 v0.3 記下的一樣（小模型讀取回的圖會讀錯小細節）。
3. Claude 桌面版（Haiku 5.5，推理強度 low）：新會話的面板介面返回自動選圖開著。三張圖只描述了背景和形狀之後，問 a-red.png 和 c-tri.png 角落小方塊的位置和顏色，模型一次 `cam_view_image` 取回 IMG-001 和 IMG-003，答對（右下角黑色、右上角橙色）。這個會話的外掛服務是舊的測試副本，所以開關是在面板接口裡寫下的，預設值由引擎給出。
4. 面板自動開啟，桌面版實測（測試副本按版本快取，改完要重新安裝才會被新會話用上；早上的測試會話一直用著 v0.4 時的副本，所以“沒開啟”）：
   - 第一次實測發現：瀏覽器還沒開啟時，`tabs_context` 的回答在 JSON 後面多一行說明，裡面也有花括號（“… navigate with {"url": …} to open it.”），按最後一個右花括號擷取就解析失敗，面板不開。Mod 測試的假瀏覽器原來沒有這一行，所以沒測出來；改成和真實回答一樣後先失敗，按括號配對取開頭的 JSON 後透過。
   - 複測兩個新會話（新會話都預設開著自動選圖，預設值沒有寫進勾選檔案）：模型讀了三張圖，那一輪結束時面板自己開啟（一個 3 秒、一個 34 秒）。
   - 使用者關掉：讓會話的模型用瀏覽器工具關掉面板標籤頁（和使用者點關掉一樣）。那一輪開始時面板還在，結束時不在了，外掛記下“使用者關的”（外掛儲存 `closedPanels`）；下一輪開始和結束都沒有再開啟。
   - 停頓時的檢查：一輪結束 25 分鐘後檢查了一次，面板還在，沒有誤記。
   - 發現桌面版的閒置計時只在使用者不看這個會話時走：使用者離開會話時重新開始計時，看著時不關。所以桌面版最早在一輪結束 30 分鐘後關，判斷規則不變。
   - 桌面版關掉的：使用者 17:29:31 離開會話，桌面版 17:59:31 斷開它的自帶瀏覽器，程序照常。18:59 再發一條訊息：這一輪開始時外掛看到面板不在、距上一輪結束已超過 30 分鐘，按桌面版關的算，沒有記成使用者關的，15 秒後面板重新開啟。這時 `tabs_context` 的說明是 “isn't open yet”，和從沒開啟過的一樣；使用者關掉最後一個標籤頁後是 “is not open.”。外掛沒用這些文字判斷，只記在這裡。

## 6. 驗收

1. 升級之後新開的 Codex 任務和 Claude 會話預設開著自動選圖；之前的保持原樣；面板裡改過的以使用者的為準。
2. 模型需要多張圖時都取回（Codex 和 Claude 都測）。
3. Claude 桌面版裡有圖的會話自動打開面板；被桌面版關掉的，會話再用時重新開啟；使用者關掉的不再自動開啟，`/cam` 能再開啟；只留一個面板標籤頁。
4. 原有測試和 Codex 自測不退化。

## 7. 不做

- 讓會話保持喚醒、改桌面版的閒置時間：那是桌面版的事，也費資源。
- 終端和 VS Code 裡自動打開面板：那裡沒有自帶瀏覽器，照舊用 `/cam`。
