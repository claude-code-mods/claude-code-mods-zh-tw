# 規格：Context Attachment Manager（上下文素材管理器）

> 本檔案是目標、範圍、約束和驗收標準的唯一事實來源（2026-09-24 經使用者、Claude、Codex 三方確認），描述當前版本 v0.11.0，以後隨版本更新。v0.4 加的 Claude 桌面 Code 接入，相關內容都標著“v0.4”；它的關卡、任務和驗收步驟見 [v0.4/](v0.4/)。v0.5 加的 Claude Code 壓縮後保留圖片標著“v0.5”，方案和實測見 [v0.5/plan.md](v0.5/plan.md)。v0.6 的預設開啟自動選圖和 Claude 桌面版自動打開面板標著“v0.6”，見 [v0.6/plan.md](v0.6/plan.md)。v0.7 的 Codex 子代理和旁聊也自動選圖示著“v0.7”，見 [v0.7/plan.md](v0.7/plan.md)。v0.8 的特徵行（壓縮後照樣拿對圖）和重做的面板（憑印象找圖）標著“v0.8”，見 [v0.8/plan.md](v0.8/plan.md)。v0.9 把兩平臺的服務線路分開，並接管相容中轉；技術做法見 [design.md](design.md) 第 2、5、12 節。v0.10 讓兩個平臺在壓縮之後（Claude 還包括續接之後）照樣拿回之前的圖，標著“v0.10”，見 [v0.10/plan.md](v0.10/plan.md)。專案 2026-10-11 由 Codex Attachment Manager 改名，因為不再只給 Codex 用（使用者定）；安裝用的標識（`codex-attachment-manager`）和資料目錄不變，已裝的使用者照常升級。v0.11 把外掛拆成接入層、核心層、面板層，再接入十個只接核心、不帶面板的 Agent 平臺，標著“v0.11”，見 [v0.11/plan.md](v0.11/plan.md)。
> 技術方案見 [design.md](design.md)。v0.1 的開發記錄（原方案、任務記錄、各階段報告、最初的構想）歸檔在 [history/v0.1/](history/v0.1/)，只作參考。

## 1. 目標

做一個開源工具，把某個 Codex 任務裡出現過的素材按時間順序列出來，讓使用者逐輪決定下一輪讓模型看哪些。原始檔案和聊天記錄都留在本地、保持不變；取消勾選隻影響之後傳送的內容，不刪除任何東西。

v0.4：同樣的管理也用在 Claude 桌面應用的 Code 標籤頁裡（本地會話、官方訂閱登入）。做法是把現有外掛的機制逐塊移植過去，不另起架構、不削減功能，只在平臺逼迫的地方改（使用者 2026-10-10 定）。和 Codex 不同的地方見下面“Claude Code（v0.4）”一節。

v0.11（使用者 2026-10-31、11-02 定）：做成所有 Agent 平臺都能輕鬆接進來的多模態上下文管理工具。外掛分三層：每個平臺一份薄的接入層，核心層不認識任何平臺，面板層只經核心的介面拿資料；核心層和麵板層各自獨立維護。第三方照對外的介面文件寫自己平臺的接入，跑契約測試證明能用，再提 PR。面板只在 Codex 桌面版和 Claude 桌面版，以後接的平臺預設不帶面板，除非使用者主動要求。

### 使用者場景

使用者先上傳參考圖 A，Codex 生成圖片 B，使用者再引用 B 要求修改。面板按時間順序列出 A、B，以及 B 再次出現的記錄，預設全部勾選。使用者取消 A 和 B 的再次出現，然後繼續創作：A 換成佔位符，B 的再次出現換成指向 B 的佔位符。之後任何一輪，使用者都可以重新勾選 A，讓它從下一次請求起重新進入上下文。

### 核心概念

- **出現記錄**：一張圖在任務歷史裡出現的一次，例如使用者上傳、工具檢視、生成結果。每條都有穩定編號（例如 `IMG-004`），按在任務裡第一次出現的順序編號，之後不變。記錄名稱、來源、所在輪次、尺寸和內容指紋。
- **內容相同**：兩條出現記錄的位元組完全相同，或者解碼後的畫素完全相同，就算內容相同，與檔名無關。縮放或重新壓縮過的圖不算。
- **勾選狀態**：每個任務各有一套。勾選的圖照常傳送；取消的圖在發出的請求裡換成佔位符。
- **自動選圖**：每個任務各有一個開關。v0.6 起，新任務和新會話預設開著，升級之前就有的任務和會話保持原樣，使用者改過的以使用者的為準（使用者 2026-10-13 定：有些使用者連面板都不會開啟）；之前預設關。開啟後，之前各輪的圖預設不發，模型需要看哪張，就用取圖工具按編號取回原圖，只在這一輪提供；勾選的意思變成“每輪都發”（v0.8 前叫“固定傳送”），預設都不勾，勾上的圖每輪都發（v0.3，使用者 2026-10-06 定：不在模型開口之前替它準備可能要的圖，由它自己按編號要）。
- **子代理和旁聊**（v0.7，Codex）：主任務派出去的子代理和在任務裡開的旁聊，也按自動選圖管。v0.8 起一律如此，主任務面板裡不再有管它們的開關（使用者 2026-10-19 定）。
- **特徵行和評價**（v0.8，使用者 2026-10-18、19 定）：模型第一次看到一張新圖時（使用者上傳的、它生成的、檢視的、工具返回的），在回覆裡給它記一行特徵：先寫地點，再寫看得見的特徵，30 字以內，例如“街頭｜近景，正臉，雨夜，霓虹反光”；同一個地點沿用之前的叫法，不寫“好看”這類判斷，寫一次就不再改。地點是畫面發生在哪兒（使用者 2026-10-21 定：原來叫“場景”，模型在影視任務裡把它當成第幾場，寫成“04場店外線稿”這類，52 張圖分出 28 個場景）：具體到能和別處分開，特寫按知道的寫；場次編號、版本、用途不寫進地點，時間、天氣寫在特徵裡；跨幾個地點的圖（分鏡、抽幀拼圖）寫“多個地點”，不在任何地方的寫它是什麼（角色、物品、文件、網頁）。面板裡的“場景”篩選就是這個地點。使用者評價某張圖時，模型照使用者的原話記一條（15 字以內），記下是第幾輪說的。
  - 這些記錄寫成 Markdown 連結定義 `[//]: # (cam IMG-015 深藍雨夜｜近景，正臉)`，放在模型最後那條回覆的開頭，Codex 和 Claude 的桌面版都不顯示；模型在正文裡也不提這件事。
  - 引擎和外掛服務只從模型自己的回覆裡讀這些記錄，使用者訊息和工具結果裡同樣的字不算。特徵行和評價寫進這張圖的佔位符（見“佔位符”），對話壓縮之後模型照樣認得出每張圖；面板只拿它們來搜尋和分組，不顯示。
  - 升級之前已有的圖不補寫。子代理和旁聊不寫，Codex 手動模式在第一次取消勾選之前也不寫（見“選擇規則”）。
  - v0.10（使用者 2026-10-31 採納）：寫錯的特徵行可以更正：模型照同樣的格式整行重寫，開頭加“更正：”（英文 “corrected:”），替換原來那一行。使用者中途打斷、模型還沒寫特徵行的那一輪，裡面的新圖在下一輪照常再發一次（標籤寫“已提供，還沒有特徵行”），讓模型補寫；之後有一輪正常結束，就不再追。
- **來源**：每條出現記錄屬於一類來源：使用者上傳、PDF 頁面、網頁截圖、檢視的圖片、工具返回、生成的圖片。PDF 頁面和網頁截圖是使用者在 Codex 桌面版裡給 PDF 或網頁加評論時，Codex 隨訊息附上的截圖，靠 Codex 寫在圖前面的固定說明認出（例如 “The next image shows PDF page 3 at the time of Comment 1.”）。PDF 頁面記下頁碼；同一條訊息只提到一個 PDF 時，再記下檔名。認不出的仍算使用者上傳（v0.2，使用者 2026-09-29 定：只做認得準的來源）。

### 免配置

使用者不需要手動編輯任何檔案。工具自動找到 Codex 的目錄（`CODEX_HOME`，沒設時是 `~/.codex`），自動完成接入。每個任務（session）各有一套自己的勾選狀態，互不影響。

代理跟著 Codex 一起啟動、一起退出（使用者 2026-09-24 確認）。只要配置指向代理，代理就必須在執行，否則 Codex 連不上。

登入方式：ChatGPT 賬號登入和 API key 登入都接管（2026-10-22 使用者定）。API key 登入的請求轉給 OpenAI 的 API（`api.openai.com`），也就是沒裝工具時 Codex 自己會去的地方，圖片照常管理；之前裝上工具後這類請求會被轉到 ChatGPT 的後端，連不上。用真 API key 管理圖片還沒實測過，只驗證了請求能到達 OpenAI 的 API。

v0.9（使用者 2026-10-23 定）：兩平臺使用相容中轉時，圖片照樣由外掛管理，請求仍發給使用者原本配置的服務，沿用客戶端的模型、認證方式和其他供應商設定。模型支援圖片還不夠：中轉需要相容對應客戶端的介面、流式響應和工具呼叫；Codex 使用 Responses，Claude Code 使用 Anthropic Messages。外掛不做跨協議轉換。

- Codex 接管使用者級 `config.toml` 裡單行字串形式的 `openai_base_url`、`model_providers.<名稱>.base_url`，支援普通表和點分鍵。原服務地址在原位置保留，停用或解除安裝時，只恢復仍等於外掛所寫地址的設定，使用者後來改過的保留。不能安全改寫的地址寫法，在改配置前明確報錯；外部 profile 檔案和環境變數覆蓋不自動改寫。切換工具後來改了供應商地址時，重新啟用外掛並重啟 Codex，按新地址重新接入。
- 每條中轉線路繫結平臺和原服務地址，保留原地址的協議、埠、路徑字首和查詢引數。圖片改寫按平臺選擇，不依賴官方域名；HTTP 和 WebSocket 都用同一繫結，不能憑路徑或金鑰字首在兩平臺間切換。不能識別、線路失效或平臺標識矛盾時，本機拒絕，不預設轉給 OpenAI。
- 全機仍是同一個引擎程序，只監聽本機：預設 17891 提供面板、登記介面和舊版官方接入，17892 提供已登記線路；自定義引擎埠時，線路用下一個埠。兩種入口互不代轉。這樣只更新一個平臺時，舊外掛拉起的舊引擎不會收到新線路的請求；線路繫結在引擎更新重啟後仍有效。

### 選擇規則

- 新出現的圖預設勾選，照常傳送，包括和前面內容相同的副本（使用者 2026-09-24 決定）。使用者沒有取消任何圖時，請求原樣轉發，Codex 的表現和沒裝工具時一樣。v0.8：這一條在 Codex 手動模式下照舊，所以手動模式要等第一次取消勾選之後才寫特徵行（使用者 2026-10-18 定：在那之前，外掛不碰這個任務的請求，請求走 WebSocket；要寫特徵行，就得改走 HTTP，每次請求都重新上傳全部圖片，得不償失）。開著自動選圖的任務，和 Claude Code 的會話（它本來每次都發完整的歷史），從第一張圖起就寫。
- 任何一條出現記錄都可以在任何一輪取消或重新勾選，從下一次請求起生效，不換任務、不重建。取消的記錄仍留在列表裡。
- 分叉出來的任務，沿用原任務在分叉那一刻的勾選；之後兩邊各管各的（使用者 2026-09-24 決定）。
- 子代理和旁聊（v0.7，使用者 2026-10-13 定，起因是 [issue #2](https://github.com/chipfighter/context-attachment-manager/issues/2)；之前只管帶歷史啟動的子代理，按分叉的規則）：
  - 不管主任務自己開沒開自動選圖，子代理和旁聊都按自動選圖管。v0.7 在主任務面板裡有一個“也自動選圖”開關，v0.8 起去掉（使用者 2026-10-19 定），0.7 裡關掉過的，升級後也按自動選圖管。
  - 旁聊（Codex 只放在記憶體裡的分叉）用原任務的圖：從原任務帶過來的圖都換成佔位，原任務裡每輪都發的照發，原任務這一輪正在看的也換掉；模型要看哪張，用取圖工具去原任務裡取。
  - 啟動時不帶主任務歷史的子代理：按自動選圖管它自己的圖，這一輪看的照發，前幾輪的換成佔位，要看再取。子代理再派的子代理也一樣。子代理自己有開關時以它的為準。
  - 帶著主任務歷史啟動的子代理照舊按分叉的規則繼承勾選；Codex 自己的後臺任務（程式碼審查、對話壓縮、記憶整理）不運算元代理。
- 取消時由工具判斷用哪種佔位符：本次請求裡還有一條內容相同、仍在傳送的記錄，就用“重複”佔位符指向它；沒有，就用普通佔位符。
- 只是看起來相似的圖（例如縮放或重新壓縮過）不算內容相同。
- 工具認不出的圖，或者沒法安全改寫的請求，一律原樣傳送，並記下原因。只有使用者明確取消的圖才會被換掉。
- 自動選圖開著時（v0.3）：
  - 這一輪新進來的圖照常傳送，包括使用者剛上傳的、模型這一輪檢視或生成的；之前各輪的圖換成佔位符，上一輪剛生成的也一樣；勾選的圖每輪都發；工具認不出的圖仍然原樣傳送。
  - 模型需要看被省略的圖時，呼叫取圖工具、傳入編號，原圖隨工具結果回到這一輪；下一輪又換回佔位符，還要就再取。
  - 取回的圖放在這一輪末尾，不放回原來的位置：原來的佔位符不變，前面的歷史一個位元組都不變，不影響快取。
  - 關著時，選擇規則和 v0.2 完全一樣。
  - v0.10：被打斷那一輪裡還沒有特徵行的圖是例外，見“核心概念”裡的特徵行。
- Codex 壓縮之後（v0.10，使用者 2026-10-31 定）：Codex 自己壓縮任務時只留下使用者訊息，工具檢視、生成或返回的圖連佔位一起從請求裡消失。引擎把它們按編號放回壓縮項後面：每輪都發的（手動模式下是勾著的）發原圖，其餘的一張一行，寫編號、名稱、來源、輪次和模型記下的特徵與評價（見“佔位符”）；前面一條開發者訊息說明這些圖當時真實存在、之前的描述仍然有效、怎麼取回。使用者上傳的圖本來就在，照舊。面板上這些圖示“壓縮前”。
- Claude 續接和分叉（v0.10）：在 Claude 桌面版裡改一條之前的訊息再發送（回退）時，桌面版從那裡分叉出一個新會話、新開一個記錄檔案；只是重啟 Claude Code 程序（歸檔再恢復、記憶體緊張時被暫停）用的還是原來的會話和記錄檔案（2026-10-31 桌面版日誌和實測）。新會話還沒有自己的勾選時，沿用它接著的那個會話的勾選、每輪都發和自動選圖開關（只沿用續接或分叉那一刻之前的）；之後各管各的。

### 佔位符

- **普通佔位符**：第一行是編號、名稱、來源、所在輪次和尺寸；最後一行提示需要時回覆“需要 IMG-004”。v0.8 起這一句縮短成“需要重看時，在回覆裡寫“需要 IMG-004”。”，抵掉特徵行增加的字數（使用者 2026-10-18 定）。
- **佔位符裡的特徵行**（v0.8）：模型給這張圖記過特徵行或評價時，第一行後面多一行，例如“特徵：深藍雨夜｜近景，正臉；評價：第 4 輪“臉最好”，第 6 輪“太暗””。評價按時間累積，只顯示最近 3 條，不排序，也不替使用者判斷褒貶；只顯示這張圖出現那一輪及以前記下的（Claude 從 v0.10 起，Codex 從 0.11.2 起：之後記下的評價就在模型自己的回覆裡；佔位符發出後不再變，否則前面的歷史一變，提示快取就從那裡起整段重寫）；Codex 壓縮過的任務裡，壓縮之前的圖顯示壓縮那一刻為止記下的（0.11.2：記著評價的那些回覆，壓縮後已經不在請求裡）；超長時在上限以內最後一個標點處截斷，加“…”。上限按寬度算，和介面語言無關：特徵和評價都是 30 個漢字或 100 個字母（v0.10；原來按介面語言數字符，中文介面裡模型寫的英文特徵行被截到只剩地點，一個真實會話裡 180 條有 51 條截完和別的行一樣；評價原來是 15 個漢字，長會話測試裡一條評價的後半句被截掉了）。除此之外，索引裡記什麼，佔位符裡就顯示什麼。照常傳送的圖只帶編號標籤，不帶特徵行：模型看得到原圖，不帶也免得每輪去改前面的標籤、弄斷快取。
- **特徵行說明**（v0.8，使用者 2026-10-19 定措辭）：從第一張圖所在的那一輪起，插入一條說明，告訴模型怎麼寫特徵行、怎麼記評價：
  - 記錄行寫在每一輪最後那條回覆的開頭（不寫在中途呼叫工具時說的話裡），一張圖一行，和正文之間空一行；這一輪沒有新圖、也沒有評價時不寫；
  - 使用者裝這個工具，是為了讓模型以後（包括壓縮之後）還能認出每張圖、記得使用者的評價；這些行只給工具讀，使用者在介面上看不到，正文照常回答，不提這些行，也不回應記錄這件事（不說“記下了”）；使用者只是評價、沒提要求時，正文簡短回應評價本身；
  - 評價是使用者自己的看法，模型不認同也照記；拿不準是哪一張就不記，可以問使用者是哪一張，但不提記錄的事；
  - 以後被省略的圖，佔位符裡帶著這些特徵和評價；選圖時先看它們，拿不準時先把原圖要回來看，或者問使用者。
  - 位置：Codex 裡是一條開發者訊息，放在那一輪的使用者訊息之前；Claude 裡見“Claude Code（v0.4）”一節。只給主任務。原來的“上下文管理說明”不變，照舊在有圖被省略時才插入。
- **上下文管理說明**：一次請求裡只要有普通佔位符，就在第一張被省略的圖所在那一輪的使用者訊息之前，插入一條開發者訊息，說明：
  - 這些圖在出現的那一輪真實存在，模型當時看過；之前對它們的描述和判斷仍然有效，不要因為現在看不到就當成猜測，也不要收回；
  - 被問到能不能看到某張被省略的圖時，如實說現在看不到（被使用者省略了），之前的描述仍然有效；
  - 不要補充之前沒說過的畫面細節；需要時回覆“需要 IMG-xxx”，使用者可以重新勾選；不要自己用工具去讀取；
  - 使用者重新勾選的圖回到它原來的位置，前面標著“已提供”，不會出現在使用者的新訊息裡；標著“已提供”的圖現在就能看到，被問到時直接看圖回答，不要說看不到（v0.1-25）。
- **為什麼放在開發者訊息裡**：使用者 2026-09-25 發現，佔位符放在原圖的位置，模型會以為自己從沒看過那張圖，於是收回之前看著原圖做出的正確回答。把這些說明寫在佔位符裡也沒用：佔位符屬於使用者內容，模型不把它當成證據。改成開發者訊息後，兩次自測都不再收回（見 [history/v0.1/tasks.md](history/v0.1/tasks.md)）。
- **重複佔位符**：包含編號、名稱、來源、所在輪次和尺寸，說明它和哪一條（編號、名稱、輪次）內容完全相同，那一條照常提供，請參考那一條。內容仍然看得到，不需要上面的說明。
- **“已提供”標籤**：一次請求裡只要有圖被換掉，每張仍在傳送、有編號的圖前面都加一行標籤，寫法和佔位符的第一行一樣，狀態是“已提供”，例如“[圖片 IMG-002（[Image #2]） 已提供｜名稱｜來源｜第 1 輪｜尺寸]”。原因：使用者 2026-09-28 發現，重新勾選的圖回到原來的位置、夾在佔位符中間，而 Codex 自己的“[Image #2]”在每條訊息裡都從 1 開始，模型對不上編號，就說看不到。沒有圖被換掉時不加，請求照舊原樣轉發。v0.8：寫特徵行的任務裡，每張傳送的圖都帶這個標籤，這一輪的新圖也帶，模型才能當場對上編號；新圖在它那一輪的第一個請求裡就已經有編號（Codex 和 Claude 都先把新圖寫進本機記錄，再發請求，2026-10-19 實測）。這一輪新圖的標籤隻影響請求的末尾，不弄斷快取。
- **壓縮後放回的清單**（v0.10）：壓縮之後放回請求、又不發原圖的圖，不再一張一個佔位，而是合成一份清單，一張一行，例如“IMG-101｜alley_v2.png｜檢視｜第 66 輪｜雨後小巷｜路面反光區域性｜評價：第 70 輪“太空了””（沒有名字的寫“-”），清單第一行說明這是壓縮之前的圖、這次沒有附原圖，以及各列是什麼。同一張圖又出現過的（比如使用者重發了一次），後面那行不再重複特徵，寫“同 IMG-108”。清單寫的是壓縮那一刻的特徵和評價（Claude 從 v0.10 起，Codex 從 0.11.2 起）：壓縮之後才記下的在模型那之後的回覆裡，到下一次壓縮再進清單；這樣清單在兩次壓縮之間不變，提示快取接得上。怎麼取回只在說明裡講一次，說明裡也不再把這些圖列一遍。原因：一個有 127 張壓縮前圖片的真實會話，照原來每張一個佔位、說明裡再列一遍的寫法，每條請求多約 1.7–2.0 萬 token；清單加說明約 0.7–0.9 萬（按 Claude 桌面實測校準的係數估；使用者 2026-10-31 定）。
- **“已提供，還沒有特徵行”標籤**（v0.10）：被打斷那一輪裡還沒有特徵行、這一輪再發一次的圖，標籤的狀態寫“已提供，還沒有特徵行”（英文 “included, no feature line yet”），特徵行說明裡告訴模型給它補一行。
- 佔位符裡不寫本地路徑。Codex 附在上傳圖片前後的路徑標籤，也一起換掉。
- PDF 頁面和網頁截圖被取消時，佔位符和使用者上傳的圖一樣，來源寫“使用者上傳”；Codex 寫在圖前面的那句說明原樣保留，模型仍然知道那是哪一頁（v0.2，使用者 2026-09-29 定：不改發給模型的文字）。
- 勾選狀態不變時，佔位符和說明的文字、位置每次都一樣，不影響快取。v0.8 到 0.11.1 的 Codex 任務裡，後來加的評價會讓那張圖的佔位符變一次，快取從那裡往後斷一次，和改一次勾選一樣；0.11.2 起佔位符發出後不再變（見“佔位符裡的特徵行”）。
- 現行措辭見 `plugin/src/rewrite.ts`，佔位符格式使用者 2026-09-24 認可，說明是按使用者 2026-09-25 的要求加的。以後改措辭，要按 AGENTS.md 重新跑自測：三個 GPT-6 模型，中文、英文（`--lang en`）各一次；改特徵行說明時跑 `spike/src/v08-features-selftest.ts`。
- 佔位符和說明跟著介面語言：中文介面用上面這版中文，英文介面用意思相同的英文版，模型需要圖時回覆“need IMG-004”（使用者 2026-09-25 定，避免上下文裡的語言不一致）。
- 自動選圖開著時（v0.3），佔位符和說明換成自動選圖的版本：說明這個任務開著自動選圖、之前各輪的圖預設省略，需要時呼叫取圖工具按編號取回，取回的圖只在這一輪提供，之前說過的內容夠用時不要取；“這些圖當時真實存在、之前的描述仍然有效、不要猜測或補充沒說過的細節”這幾點和手動版一樣。v0.8 起自動版佔位符的最後一行是“需要原圖時呼叫 cam_view_image，傳入“IMG-004”。”。

### 介面

- 位置：Codex 右側側邊面板裡的一個標籤頁“上下文素材”。使用者在側邊面板的“新建標籤頁 → 外掛和 MCP”裡手動開啟，不經過模型，也不花 token（P4 實測透過）。Codex 標題欄沒有給外掛的入口，所以不做外掛視窗。
- 只列這個任務歷史裡已有的圖：使用者上傳的，和模型在這個任務裡檢視、生成的。面板不新增素材。
- v0.8 起是一屏（使用者 2026-10-19 看過可點選的原型和截圖後定，見 [v0.8/plan.md](v0.8/plan.md) 第 2 節）：從上到下是標題行、請求佔用卡片、“模型需要”提示條（只在手動模式下、有事時出現）、搜尋框、篩選按鈕、按輪分組的縮圖，最下面是底欄。
- 勾選和取消（單張或整輪）點一下就儲存，從下一條訊息起生效；沒有“確定”和“撤銷”（使用者 2026-09-28 定：先暫存再確認的操作感受差，也容易出錯）。底欄始終是同一句說明，勾選後不另外提示“已儲存”（使用者 2026-09-28 定）。

- 主題、字型和配色跟隨 Codex。
- **請求佔用卡片**（v0.8）：預設收起，底下有“展開詳情”。
  - 收起時也顯示：預計請求大小、全部發送要多大、省了百分之幾、佔用條，以及“下一條訊息：照常傳送 N 張 · 佔位 M 張”（其中重複幾張、幾張已不在上下文）。預計值以引擎記錄的上一次完整請求為基準，標明是“預計”，不寫成已經發出的請求。
  - 展開後多出三行：上一次請求（時間、替換了幾張、少發多少）；最近一輪模型取回的編號（只在自動模式下有）；子代理和旁聊幾個、上次一共少發多少（只在 Codex 裡、引擎見過它們時有）。

  - 狀態：每輪都發（自動模式）、剛取回（自動模式，最近一輪模型取回的）、不傳送和模型需要（手動模式）、無法取消、已不在上下文、壓縮前（Claude）；

- **整輪勾選**：每一輪的標題線末尾有一個方框，用來整輪勾選或取消（使用者 2026-09-26 定，圖多時成批去掉某一輪的圖；v0.8 照舊，兩種模式都有）：
  - 這一輪能改的圖全勾著時顯示 ✓，點一下全部取消；只勾了一部分時顯示“–”，沒勾的時候是空框，這兩種點一下都是全部勾上；自動模式下勾上就是這一輪全部每輪都發；

  - 搜尋或篩選時，只管這一輪正在顯示的圖；一張都沒顯示的輪次整行隱藏。
- **搜尋和篩選**（v0.8，取代 v0.2 的按來源篩選）：

  - 篩選按鈕一排：“全部”“上傳”“生成”（沒有這類圖時不顯示），一條豎線，再接各個場景，按圖的張數從多到少排；沒有特徵行的圖歸到“其他”。場景就是特徵行的第一段；一張特徵行都沒有時，不顯示場景按鈕。“上傳”包括 PDF 頁面和網頁截圖。
  - 篩選按鈕最多佔兩行（0.8.1，使用者 2026-10-21 定：場景多時，按鈕擠得只剩一小塊地方看圖）：放不下的從末尾收進第二行最後的“更多 N”，點開顯示全部，末尾變成“收起”；選中的那個始終露出來，排在“更多”前面；展開時選中一個，就自動收起。

  - Codex 自己顯示的名字：外掛頁上名稱和一句話簡介用英文（Context Attachment Manager），詳細說明先英文、再附一段中文，因為外掛清單隻能寫一種文字；標籤頁標題跟著語言（“上下文素材”或 Context Assets）。

- 以上是使用者 2026-09-24 定的 MVP，外加 2026-09-25 要求補上的傳送預覽、改寫失敗提示、自動重新整理、這兩個按鈕的位置和名稱、標題裡的任務名、新任務的自動繫結，以及中英文介面；2026-09-26 加了“模型需要”提示條、整輪勾選，以及直接讀 Codex 的語言設定；v0.2 加了 PDF 頁面、網頁截圖兩類來源和按來源篩選（使用者 2026-09-29 定）；v0.3 加了自動選圖（使用者 2026-10-06 定）；v0.8 改成一屏的請求佔用卡片、搜尋、按場景篩選和按輪的縮圖，去掉了按來源篩選和子代理的開關（使用者 2026-10-19 定）。

### Claude Code（v0.4）

這裡只寫和 Codex 不同的地方；編號、內容相同、勾選、佔位符和自動選圖的規則照搬。

- **範圍**：Claude 桌面應用 Code 標籤頁裡的本地會話，包括官方訂閱登入，以及 v0.9 起的 Anthropic Messages 相容服務地址。Claude Code 的會話就相當於 Codex 的任務，每個會話各有一套勾選。普通 Claude Chat 不在接入範圍；Bedrock、Vertex、Foundry 仍不接管。
- **接入**：裝上 Claude 外掛就生效，不用重複填寫中轉地址。外掛在會話啟動時，讀取這個程序原本的 `ANTHROPIC_BASE_URL`（沒有時用 Anthropic 官方地址），先向支援獨立線路的新引擎登記，成功後再把本程序地址指向本機線路，原認證資訊只跟隨對應服務。登記失敗時保持原地址並提示未接管；程序結束時，只還原仍由外掛管理的地址和代理環境變數。改了服務地址後，新開 Code 會話生效。
- **說明的位置**：Anthropic 不允許把系統訊息放在使用者訊息之前，所以“上下文管理說明”放在第一張被省略的圖所在的那條訊息之後，是一條系統訊息。另外，每條含被省略圖片的訊息後面都跟一條簡短說明：這幾張圖當時是原圖，之前的描述仍然有效；被問到要看圖才能回答的細節時，寫出“需要 IMG-xxx”，使用者才知道該勾回哪張。Codex 的措辭不變。
  - v0.8 的特徵行說明也是系統訊息，放在第一張圖所在那一輪的使用者訊息之後，不緊跟工具結果（使用者 2026-10-19 定）：Sonnet 5.5 和 Haiku 5.5 會把緊跟在工具結果後面的系統訊息當成工具結果裡的文字，不信任（Anthropic 的文件這麼寫，2026-10-19 實測 Haiku 也這樣，還把這件事告訴了使用者）。
  - v0.8：會話裡有圖就改寫請求（加特徵行說明和編號標籤），不再等使用者取消勾選。改過的歷史在會核對思考記錄的賬號上，照“思考記錄”一條的做法去掉對不上的那些。
- **思考記錄**（使用者 2026-10-11 定）：Anthropic 會核對每段思考前面的內容是否和它產生時一樣。2026-08-31 起註冊的賬號對不上就拒絕請求，更早的賬號放行。
  - 賬號放行時，思考塊原樣轉發，和 Codex 一樣。
  - 賬號拒絕時，引擎去掉和實際發出的歷史對不上的思考記錄，再按勾選發出：取消勾選照樣生效，取消之後新產生的思考保留；全部勾回後，取消之前的思考放回去，取消期間產生的去掉。模型會少一些之前的思路，可能要重新思考、多用一些 token；面板提示這一次去掉了幾段（Anthropic 文件要求代理不要把這件事藏起來）。
  - 還不行時才改發原始請求，面板提示這次沒能按勾選改寫，這一次也不算取消成功。對話不中斷，也不會因為記錄不全而卡住：記錄不全時寧可多去掉思考。
- **面板**：和 Codex 是同一個面板頁面（使用者 2026-10-10 要求兩邊一致）。Claude Code 不給使用者開啟外掛的 MCP 應用，外掛自己的小面板（Mod 面板）也放不進網頁，所以面板由本機引擎作為網頁提供：
  - 使用者輸入 `/cam`，面板在 Claude 桌面自帶的瀏覽器裡開啟，就在對話旁邊（使用者 2026-10-10 選定）。
  - v0.6（使用者 2026-10-13 定）：不用輸入 `/cam`，會話裡有了圖，面板就自己在自帶的瀏覽器裡開啟（模型讀了圖，那一輪結束時；使用者貼了圖，那一輪開始時）。使用者離開會話約 30 分鐘（期間沒有新的一輪），Claude 桌面會關掉會話的自帶瀏覽器，面板跟著關掉，下一輪開始時重新開啟。使用者自己關掉的，這個會話裡不再自動開啟，直到使用者輸入 `/cam`。只在 Claude 桌面版裡，終端和 VS Code 照舊用 `/cam`。
  - 只有兩種情況才彈出外掛的小面板：自帶瀏覽器打不開時（終端、VS Code，或呼叫失敗），給出面板連結和“複製連結”按鈕；這個會話的請求沒經過引擎、勾選不會生效時，提醒使用者。
  - 新會話的第一條輸入就是 `/cam` 時，輸入框會提示命令不存在，但發出後照常開啟：Claude 桌面要等第一條輸入才啟動會話的程序，外掛這時才註冊 `/cam`。保持現狀，在使用者文件裡寫明（使用者 2026-10-10 定）。
  - 沒有 Codex 特有的“啟用外掛 / 停用外掛”按鈕和新任務繫結；v0.8 起也沒有子代理和旁聊那一行，沒有 PDF 和網頁的角標；壓縮前的圖照樣標“壓縮前”（使用者 2026-10-19 定：Claude 桌面版用同一個面板）。
  - 語言跟著外掛，和發給模型的說明一致，不跟著瀏覽器。
- **取圖工具**：模型呼叫 `cam_view_image` 不彈許可權確認，和 Codex 版的自動批准一樣；使用者自己的鉤子或設定拒絕、或要求詢問時，照舊按它們來（使用者 2026-10-10 同意）。
- **壓縮之後**（v0.5，使用者 2026-10-12 定）：Claude Code 壓縮對話（手動 `/compact` 或自動壓縮）時，把舊歷史換成一段摘要，壓縮前的圖不再發給模型。Codex 的做法見“選擇規則”裡的“Codex 壓縮之後”（v0.10）。
  - 壓縮前的勾選照樣有效：勾著的圖（開著自動選圖時是每輪都發的圖）照樣發給模型，取消的照樣不發；使用者隨時可以改，從下一條訊息起生效。原圖從本地會話記錄裡讀，不另存一份。
  - 位置：壓縮前的圖放在摘要後面（摘要所在的那條使用者訊息裡）：照樣發的帶“已提供”標籤和原圖；不發的，v0.10 起合成一份清單，一張一行（見“佔位符”），v0.5 到 v0.9 是每張一個佔位。勾選不變時這一段逐位元組相同，快取能續上。
  - 說明：摘要那條訊息後面跟一條系統訊息，說清摘要之前有多少張圖（v0.10 起只寫數量和編號範圍，不再列一遍）、哪些這次沒發、怎麼要回（手動時寫“需要 IMG-xxx”，自動選圖時用 `cam_view_image`）；有圖沒發時，前面是完整的“上下文管理說明”，後面訊息裡的佔位文字只再跟一段短說明。說明放在訊息裡面時模型不信，會收回之前看著原圖做出的回答（2026-10-12 實測），所以和 v0.4 一樣放在系統訊息裡。
  - 壓縮時保留的訊息（v0.10）：Claude Code 2.1.304 起壓縮時原樣保留最後幾條訊息，讀記錄時把它們接到摘要後面；外掛照同樣的規則連對話鏈，壓縮前的歷史照舊算“壓縮前”。之前外掛按檔案裡的原樣連，有的壓縮認不出來，壓縮前的圖一張都沒放回（2026-10-31 真實會話：94 張）。
  - 續接之後（v0.10）：Claude 桌面版續接後的新會話，記錄檔案從最近一次壓縮開始，前面的歷史在壓縮發生的那個記錄檔案裡。外掛順著摘要裡 Claude Code 寫的原記錄路徑（找不到時，在同一個專案資料夾裡找含同一個壓縮點的記錄）一層層接回去：編號和續接前一樣，壓縮前的圖照樣放回，舊檔案只讀，裡面的圖片資料用到時再從檔案讀。修復之前，續接後編號從頭重排，按舊編號寫下的特徵行和評價會掛到別的圖上；這些記錄行按“當時寫它的程序用的編號”換算回來（這個版本第一次執行之後寫的不用換算）。
  - 並行讀圖（v0.10）：模型同時呼叫幾次工具、結果回來的順序亂了時，每個結果裡的圖照樣編號。修復之前，有的圖因此沒有編號：每輪照發原圖，壓縮後丟失。補上編號以後，排在它後面的圖編號後移，修復之前寫下的記錄行同樣按當時的編號換算回來。Claude Code 把後面的呼叫掛在前一個結果（或結果後的圖片說明）下面時也一樣（2026-11-12 修，面板裡少圖就是這個原因）；模型當時給沒編號的圖接著往下數的編號，也換算到那些圖上。
  - 不替使用者做決定：不做自動保護。補回的圖太多、請求被拒或 Claude Code 又壓縮時，由使用者少勾幾張或切到自動選圖。Claude Code 自己的上下文用量顯示不含補回的圖，Anthropic 返回的用量含。

## 2. 非目標

v0.1 到 v0.3 都不做下面這些。其中音訊和其他語言已確認是後續方向。

- 圖片以外的檔案型別（使用者 2026-09-29 查證後定）：
  - 音訊：等 Codex 裡有能直接聽音訊的模型再做。Codex 從 2026-07 起能把音訊發給模型（使用者附加的音訊、工具返回的音訊，格式和圖片幾乎一樣），但現有的模型（GPT-6、GPT-5.6、GPT-5.5）只收文字和圖片，Codex 在傳送前把音訊換成一句“不支援音訊輸入”的說明，請求裡沒有音訊可管。開始做的條件：Codex 的模型清單（`~/.codex/models_cache.json` 裡的 `input_modalities`）出現 `audio`。
  - PDF 和影片：Codex 不把這兩種檔案本身發給模型。模型要先把它們轉成文字（抽取文字）或圖片（渲染頁面、抽幀）才看得到，轉成的圖片按普通圖片管理。
  - md、docx、xlsx、程式碼這類能轉成文字而不丟資訊的檔案：它們以文字進入上下文，不在管理範圍內。
- 簡體中文和英文以外的語言，以及面板裡手動切換語言（使用者 2026-09-25 定：等有使用者反饋再說）；
- 整個任務一鍵全選或全不選，以及跨任務的素材庫（使用者 2026-09-26 定：成批勾選只按輪次做；全選用處不大，因為預設就是全部發送，一鍵全不選又容易誤操作）；
- 猜模型自己渲染或抽幀的圖來自哪個 PDF 或影片、按原檔案歸組，以及在面板裡預覽原來的 PDF 和影片（使用者 2026-09-29 定：只做認得準的來源；原檔案本身不進上下文）；
- 儲存清理；
- coding agent 場景，例如省略模型已讀過的程式碼檔案；
- 修改或刪除原生 Codex 任務裡已有的歷史；
- 在 Codex 對話裡把模型要的圖的編號做成可點的引用，點了打開面板或原圖（使用者 2026-09-26 看過調研結果後決定不做，收益不值得；原因見 [history/v0.1/plan.md](history/v0.1/plan.md) 第 18 節）。
- v0.4 也不做（使用者 2026-10-10 確認的方案）：其他模型供應商、雲端會話、跨會話素材庫、新的常駐系統服務；也不因為換了客戶端，就把原生 PDF、文件、音訊、影片和普通文字檔案納入管理。
- v0.5 也不做（使用者 2026-10-12 定）：補回的圖太多時自動減少（由使用者決定）；`/clear` 或新會話帶上過去的圖（那是另一個會話）；子代理的請求（仍只管主對話）。
- v0.7 也不做（使用者 2026-10-13 定）：Claude Code 的子代理（它們一般一次跑完、只有一輪，按自動選圖的規則本來就全發）；在主任務面板裡逐張勾選子代理和旁聊的圖；給每個子代理單獨設開關；改“這一輪看的圖照發”的規則。
- v0.8 也不做（使用者 2026-10-18、19 定）：
  - 跨任務、跨會話搜尋；
  - 使用者從沒提過的主觀標準（例如“五官最清楚”）：等有人提，或者使用者自己遇到再說；
  - 給模型用的搜尋工具：特徵行已經寫在佔位符裡，模型直接看；
  - 讓使用者填寫或修改特徵行和評價，或者在面板裡顯示這些文字；
  - 給升級前已有的圖補寫特徵行；
  - Codex 手動模式下，第一次取消勾選之前寫特徵行（以後可以研究直接在 WebSocket 上加說明和編號）；
  - 子代理和旁聊寫特徵行：它們的圖不在主任務的面板裡，存在的時間也短；旁聊的佔位符照樣顯示原任務裡的特徵行。

  - 瀏覽器和電腦操作截圖的專門規則（例如同一輪只發最近幾張）：另議。
- v0.11 也不做：
  - 新平臺的面板（使用者 2026-11-02 定：預設不帶，使用者主動要求時再接）；
  - 讓模型請求經過不了引擎、自己也沒有能改歷史的外掛的客戶端：省略舊圖要麼讓引擎站在客戶端和模型 API 之間，要麼用客戶端自己的外掛改歷史（DeepSeek Harness）；MCP 只能給模型加取圖工具，不能從客戶端發出的歷史裡刪圖；
  - Antigravity 和其他閉源平臺（使用者 2026-11-02 定，暫時不支援）；Roo Code（倉庫已歸檔）；
  - 跨請求格式的轉換：翻譯器只改圖片相關的幾處，請求照原格式發往原服務（v0.9 的規則不變）；
  - 拆成多個倉庫（使用者 2026-11-02 定；拆成多個包以後看情況）。

## 3. 硬約束

- 原始對話記錄和素材檔案始終只讀，不修改、不移動、不刪除。不直接寫入 `~/.codex` 下的任何檔案，只有四個例外：
  - 透過 Codex 自己的命令列登記外掛市場、安裝和解除安裝外掛時，Codex 對 `config.toml` 和外掛快取的正常寫入（P5）；v0.9 安裝時先保留外掛程式檔案副本，安裝後補回仍可能被舊程序使用的版本，失敗時恢復原有程式檔案，不先刪除可用副本；不復制會話和素材；
  - 官方 app-server 在建立和執行任務時自己產生的正常寫入；
  - 為接入本地代理和麵板服務，工具可以修改 `config.toml` 裡由它自己管理、帶標記的設定（使用者 2026-09-24 授權）。改之前先備份，能一鍵恢復，其他設定一律不動。只在這些時候改：使用者執行安裝或解除安裝命令；使用者在面板裡點“啟用”或“停用”；外掛被移除或關掉、又沒先停用時，引擎把 Codex 恢復直連（v0.1）；
  - 為讓生圖和改圖也能連到本地代理，工具可以在 `~/.codex/.env` 裡寫一段帶標記的 `NO_PROXY`，只含本機地址，並保留使用者自己的條目（使用者 2026-09-24 同意）。`.env` 可能含金鑰，工具不復制、不輸出它，只增刪自己的那一段；檔案裡只剩這一段時，恢復時連檔案一起刪掉。
- v0.4：Claude Code 的會話記錄（`~/.claude/projects/` 下）同樣只讀。工具不直接寫 `~/.claude` 下的檔案，Claude 外掛的登記、安裝和解除安裝都由 Claude Code 自己的外掛命令完成。外掛只改它所在的那個 Claude Code 程序裡的 `ANTHROPIC_BASE_URL` 和 `NO_PROXY`，程序結束時還原。
- 真實資料不進倉庫：從真實會話和使用者素材裡提取的圖片、記錄片段、日誌和備份，只能放在本機，開發時放在 `local/` 目錄（已被 git 忽略），裝好的外掛放在資料目錄（Windows 是 `%USERPROFILE%\.codex-attachment-manager`，macOS 是 `~/Library/Application Support/codex-attachment-manager`，Linux 是 `~/.local/share/codex-attachment-manager`）；任何時候都不提交。倉庫裡的樣例資料只能是合成的或脫敏的。Windows 的資料目錄 2026-09-25 從 `%LOCALAPPDATA%` 下挪出來（使用者同意）：Codex、Claude 這類微軟商店應用啟動的程式在 AppData 裡新建的檔案，會被轉存到各應用的私有目錄，外掛服務、引擎和命令列看到的資料就不一樣了。
- 倉庫裡的文件和程式碼不寫使用者本機的具體路徑（例如個人專案資料夾）。`~/.codex`、`%LOCALAPPDATA%` 這類通用位置可以寫。本專案以後會開源。
- 不改寫原生任務的歷史記錄。
- 代理只替換使用者取消的圖片，連同 Codex 附在它前後的路徑標籤；自動選圖開著時，還替換之前各輪沒有勾“每輪都發”的圖（v0.3）。有圖片被省略時，另外插入一條“上下文管理說明”開發者訊息（使用者 2026-09-25 要求告訴模型原因，見第 1 節“佔位符”），並在仍傳送的圖前面加“已提供”標籤（v0.1-25）。v0.8：寫特徵行的任務裡，還插入一條“特徵行說明”，每張傳送的圖都帶“已提供”標籤，佔位符裡帶著模型記下的特徵行和評價（見第 1 節“佔位符”）。請求裡的其他內容原樣轉發。v0.4：Claude 的請求裡，說明是系統訊息（位置見第 1 節“Claude Code（v0.4）”）；思考塊原樣轉發，只在賬號拒絕時去掉對不上的那些，不關掉思考（使用者 2026-10-11 定）。v0.5：Claude Code 壓縮之後，引擎還把壓縮前的圖從本地會話記錄裡取出來，補在摘要後面（使用者勾選或每輪都發的發原圖，其餘放佔位文字，v0.10 起是一份一張一行的清單），並跟一條說明（使用者 2026-10-12 定，見第 1 節“壓縮之後”）。v0.10：Codex 壓縮之後，引擎同樣把它沒保留的圖放回壓縮項後面（每輪都發或勾著的發原圖，其餘寫進清單），前面一條開發者訊息說明（見第 1 節“選擇規則”）；被打斷那一輪裡還沒有特徵行的圖，下一輪再發一次。往請求里加圖只有這幾處，其餘內容仍原樣轉發。

2. Codex 和 Claude 的行為不變：原有單元測試和冒煙測試全過；各種勾選組合下改寫結果和拆之前逐位元組相同；模型自測不退化（gpt-6-sol，中英文）。
3. 有對外的接入介面文件（英文）和契約測試；面板在文件裡是可選的一節，新平臺預設不接。
4. 其他平臺只接核心、不帶面板：WorkBuddy、OpenCode、Gemini CLI、pi、Qwen Code、Cline、Kilo Code、goose、Cherry Studio 的請求經過引擎，之前各輪的圖按自動選圖省略，模型能按編號取回；DeepSeek Harness 用頂替官方外掛的 dsh 外掛，新一輪開始時解除安裝之前各輪的圖。使用者 2026-11-02 定不在本機實跑：按各平臺的程式碼和文件寫接入，用合成請求測試，README 的平臺表標明沒實測，等使用者反饋。
5. README 用平實的工具寫法（使用者 2026-11-07 定：名字改回 Context Attachment Manager，不再用 FrameKeeper 和多模態稅的口徑），底部有平臺表（簡介和接入情況，沒實測的標“未實測”，歡迎在用的人反饋）；`ADAPTERS.md` 寫各平臺的接法和怎麼加新平臺。
6. 安裝：使用者把 README 裡那句話發給所在平臺的 Agent，Agent 照 INSTALL.md 裝對平臺。平臺由各平臺給命令設的環境變數認出（`cam detect`），認不出或認出多個就問使用者；只接核心的平臺由 `cam connect <平臺> --apply` 改設定（記下改了哪幾項、原來是什麼；不復制檔案，因為裡面常有 API key），`cam disconnect` 撤回，使用者之後改過的設定不動。
7. Codex 被換模型的工具（如 cc-switch）改寫服務地址後，引擎重新接上，請求經過引擎發往使用者新選的服務商；使用者停用了外掛就不再接。

## 5. 待定問題

- 在外掛頁面移除或關掉外掛、沒先在面板裡停用時，代理設定還在：
  - macOS、Linux 上，引擎會發現這一點，把 Codex 恢復直連，下次啟動 Codex 時生效。
  - Windows 上，引擎隨外掛服務一起被結束（Codex 的 Job 限制，見 [design.md](design.md) 第 5 節），Codex 會連不上，要執行解除安裝命令恢復。面板、外掛說明和安裝說明（INSTALL.md）都提示“先停用再移除”。
  - 要不要讓引擎不依賴外掛啟動（例如用 Windows 計劃任務），需要使用者同意在系統裡註冊任務，之後再定。
