# v0.4 驗收標準

> 狀態：v0.4.0 釋出時的驗收記錄見文末（2026-10-11）。方案見 [plan.md](plan.md)，執行見 [tasks.md](tasks.md)。現行 v0.3 行為引用 [spec.md](../spec.md)，不另定義一套行為。
> 必須區分：本機模擬、終端、真實桌面訂閱、使用者介面確認。前者透過不能自動替代後者。

## A04-01 官方訂閱接入

真實 Claude 桌面 Code 的本地會話，保持官方訂閱登入，不填 API key、不換賬號。正式安裝後無需手改配置，啟用後請求經本機引擎到 Anthropic，回覆完整；停用後恢復原始地址。

檢查 OAuth capability 與認證透傳、無意外 API key，以及實際安裝副本和會話載入。原樣文字探針已透過的是入口部分；正式安裝、自動啟動與恢復仍待驗。

## A04-02 無選擇變化時原樣傳送

沒有取消項、自動模式未使用時，轉發的請求正文與原始正文逐位元組一致。必要的 HTTP 傳輸頭處理單獨比較；認證、版本和 beta 保留。錯誤狀態/正文、查詢串與 SSE 完整透傳，取消客戶端請求時上游結束。

圖片不需要替換時，不重排訊息、不重編碼圖片、不增加佔位說明、不改工具呼叫或思考塊。

## A04-03 同一會話取消與恢復

用合成圖 A、B 和 A 的重複出現，先確認模型看到它們，再取消指定出現記錄並繼續同一個會話：

1. 下一次請求中只有指定目標變成正確佔位符，其他圖仍在。
2. 普通與重複佔位符按本次仍傳送的圖決定，不因同內容而合併使用者選擇。
3. 重新勾選後，下一次請求恢復對應原圖，模型可以讀取測試標記；不另開會話或重建歷史。
4. 新出現圖按現行手動規則預設傳送；選擇不變時改寫結果穩定。
5. 原始素材與已有歷史保持只讀，按 A04-09 取證。

同時檢查使用者圖和工具結果圖，不能只憑模型說“看不到”證明圖片已刪，必須檢查發出的請求。

## A04-04 思考相容與模型行為

**G04-1 前置子集**：模型用 Haiku 5.5，執行次數先與使用者確認。在真實桌面訂閱、正常使用的思考配置下，歷史中確實已有思考塊後執行 A04-03，並用最小工具取回實驗覆蓋工具圖及取回副本下一輪省略；不要求先完成完整自動模式。

- 賬號放行時，改寫後的請求正常完成，模型按 A04-03 的要求回答。賬號拒絕（400）時，包括用 `prefix_mismatch_behavior: "error"` 模擬的新賬號，引擎去掉對不上的思考記錄、照樣按勾選發出，取消之後新產生的思考保留，全部勾回後也被接受，面板提示去掉了幾段；還不行時原樣重發、對話不斷，面板提示，且不計入取消成功。記錄真實模型、思考配置、賬號表現及請求診斷。
- 引擎不關思考、不加 `drop_block`，只去掉對不上的思考塊（使用者 2026-10-11 看過實驗證據後定，見 plan.md D04-03）。
- 未修改圖片的文字往返、沒有實際思考塊的測試不能證明相容；使用者賬號放行之外，必須再測一次模擬新賬號的拒絕路徑。官方文件不能替代桌面訂閱實測。

**正式模型行為驗收**：T04-05 覆蓋手動模式，T04-08 覆蓋完整自動模式。模型不收回之前看原圖的有效描述，不補充現在看不到的新細節；手動按編號要圖、恢復後能看圖；自動模式該取圖時取，不需要時不取。專項自測覆蓋中英文，模型範圍與成本上限先確定；Codex 的 GPT 自測不能代替它。

G04-1 只記錄前置子集透過，不提前勾整項 A04-04；正式模型行為和思考相容均通過後，此項才算完成。

## A04-05 索引、來源與編號

能按時間/輪次列出客戶端實際支援的使用者上傳、工具檢視/返回和生成圖片的每次出現，展示穩定編號、名稱、尺寸、大小和可靠來源。位元組/畫素相同的重複關係按現行規則判斷；同圖每次出現仍獨立編號。

繼續會話、重新開啟、外掛過載後編號不亂。模型取回的副本不增加新的素材行。認不準的來源不猜，Claude 沒有的 Codex 專屬來源不偽造；無法安全對應的圖片保留並提示原因。

## A04-06 桌面內面板（前置關卡）

在真實 Code 介面中顯示多張真實縮圖，能放大預覽、單張勾選、儲存與當前會話對應，操作無需模型參與。使用者自己輸入 `/cam`，面板在 Claude 桌面自帶的瀏覽器裡開啟，不要求模型幫忙開啟（D04-04）。

介面宣告、示意圖、終端介面或外部瀏覽器開發頁均不能替代桌面內驗收。關鍵節點由 Claude 截圖檢查並交使用者反饋，反饋未解決時不勾完成。

## A04-07 完整互動與雙語

按現行規格逐項檢查：整輪勾選、來源篩選、編號定位、傳送預覽/上一次實際統計、任務名、自動重新整理、預覽、啟停、主題和中英文文字。

篩選隻影響顯示；整輪選擇只作用於該輪顯示項；跳轉隱藏項時按現行規則顯示和定位。預估明確標為預估，不把請求大小或圖片數量等同於已節省的模型 token。實際無法改寫時在面板提示原因。

## A04-08 自動選圖

預設關，任務各管各的。開啟後按現行 v0.3 語義：歷史未固定圖省略、本輪新圖照常、固定圖每輪發；手動勾選與固定傳送分開儲存。

模型按 IMG 編號取到原圖，實際讀出合成圖隨機標記；這份副本僅在本輪提供，下一輪不再發送，原位置佔位符和前面的歷史文字保持穩定。副本不另佔列表行，不改變使用者勾選或開關。面板顯示最近取回編號和行標記；關閉自動後手動選擇恢復。

覆蓋中英文的需要圖/不需要圖場景，並透過 A04-04 的思考相容檢查。工具註冊或返回一段 base64 文字不算模型已看到圖。

## A04-09 原始資料只讀與隱私

原始素材前後雜湊不變；選擇操作不改已有會話歷史。對正在繼續的會話，核對原有歷史字首或靜態快照不變，並區分 Claude 自身正常追加記錄，不能把官方追加誤算成外掛改寫。

外掛只寫工具資料目錄和自管安裝配置；恢復不覆蓋使用者其他設定。日誌不含認證值、原始圖片和聊天正文，真實證據只在 `local/` 或工具資料目錄。提交只含合成/脫敏樣例，無使用者具體路徑和私有會話標識。

## A04-10 生命週期、隔離與失敗恢復

驗證兩個同時執行的會話、繼續/分叉、子代理、壓縮與回退、過載、桌面重啟、服務失敗、停用/解除安裝、登入重新整理和外掛更新，以及只開 Claude 不開 Codex、兩邊同時使用同一個引擎。不會串勾選狀態，不覆蓋其他服務地址，不留下指向已停止服務的配置；只開 Claude 時引擎不因沒有 Codex 程序而退出，兩份外掛副本不來回讓對方的引擎退役。啟用前服務就緒，恢復後真實請求可直連正常回答。

未識別、無法解析或不能安全改寫的請求原樣傳送並提示原因；不靜默傳送後宣稱已取消，也不把回退計入 A04-03/A04-08 的成功次數。自動恢復和平臺限制按實測範圍如實說明。

## A04-11 Codex 迴歸

現有 v0.1–v0.3 的相關單元、自測、安裝/解除安裝冒煙透過；無取消、手動和自動模式語義不變。共享執行程式碼或文字修改時，按 AGENTS.md 跑對應自測並重新安裝，驗證實際安裝副本。

Windows 優先。macOS/Linux 的 CI 與桌面實測分別記錄，不將“CI 能啟動”寫成“桌面功能全透過”。

## A04-12 交付與證據

每項驗收有對應任務、執行環境、最後相關改動後的結果、證據位置和審閱結論。介面關鍵節點與終端使用者驗收有反饋記錄；全部通過後才更新正式支援宣告和釋出。

由 Claude 將確認結果更新到現行規格和方案，保持當前事實與版本一致。英文 README/CHANGELOG、中文說明與實際能力一致，不以本機探針或 API key 模式冒充官方訂閱完整支援。
