# v0.4 變更方案：Claude 桌面 Code 接入

> 狀態：隨 v0.4.0 釋出（2026-10-11）。2026-10-09 按使用者要求整理；2026-10-10 使用者確認：按現有外掛的機制逐塊移植，只在平臺逼迫時改動（見第 1 節）；2026-10-11 使用者定：新賬號校驗思考記錄時，由引擎去掉對不上的思考（D04-03），並授權不等稽核直接釋出。
> 當前版本的唯一規格仍是 [spec.md](../spec.md)，現有實現見 [design.md](../design.md)。本目錄記錄 v0.4 的增量變更、關卡和開發任務，不另複製一套現行規格。
> 執行順序：本方案 → [任務清單](tasks.md) → [驗收標準](acceptance.md)。每個任務都要有對應驗收和證據；透過路由實驗不等於透過完整遷移。

## 1. 目標與範圍

使用者已明確的目標：在 **Claude 桌面應用的 Code 標籤頁、本地會話、官方訂閱登入** 下使用當前素材管理能力。繼續在同一個會話逐輪取消和恢復圖片，原始對話與素材只讀。只支援 API key、只支援終端，或只能轉發文字，都不能滿足該目標。

v0.4 按現行 v0.3 的圖片管理語義驗收：穩定編號、每次出現獨立選擇、重複關係、整輪勾選、來源篩選、傳送預覽、模型要圖定位、自動選圖和按需取回、中英文、面板與安裝啟停。各項詳細行為引用現行規格，不在此重寫。Claude 沒有的 Codex 專屬來源不偽造；只識別有可靠依據的來源。

按現有外掛的機制逐塊移植到 Claude（使用者 2026-10-10 定）：同倉新增 Claude 接入、保留 Codex 實現，不另起架構，不削減 v0.3 的功能。只有平臺逼迫的地方才改，並寫明原因；對應關係見下表。正式實現前由規格維護者將確認內容寫回現有規格和方案。已有 Codex 功能保持可用是本方案的迴歸要求。

| 現有機制（見 design.md） | Claude 上的對應 |
| --- | --- |
| 本機引擎改寫請求，同一個任務，歷史不動 | 同一個引擎增加 `/v1/messages` 轉發，上游固定為 `api.anthropic.com` |
| `config.toml` 裡帶標記的 `openai_base_url` | 平臺逼迫：桌面版不認 settings 裡的地址，由外掛裡的 Mod 用 `$.env.set` 切換（D04-01） |
| 外掛的 MCP 服務拉起、看守引擎，給面板提供資料 | Claude 外掛同樣帶這個 MCP 服務拉起、看守引擎；面板的資料改由引擎的本機介面提供（D04-04）；Mod 負責切地址和 `/cam`（D04-01、D04-04） |
| 請求頭 `x-codex-turn-metadata` 認出任務 | 請求頭 `x-claude-code-session-id`（D04-02） |
| 從本地記錄只讀編號，只追加；引擎和外掛服務各自計算，不共享狀態 | 從 Claude Code 的本地會話記錄只讀編號，做法相同（D04-02） |
| 按條目 `id` 對齊請求和記錄，沒有就用 `call_id`，再沒有就用型別、輪次和內容雜湊 | 訊息塊沒有 `id`：工具圖用 `tool_use_id`，使用者圖用最後一檔（D04-02） |
| 佔位符、重複佔位符、“已提供”標籤；勾選不變時逐位元組相同 | 照搬（D04-03） |
| “上下文管理說明”開發者訊息，插在第一張被省略的圖所在那一輪的使用者訊息之前 | 平臺逼迫：改用 `role: "system"` 訊息，放在那條使用者訊息之後（D04-03） |
| WebSocket 握手回 426，讓 Codex 改走 HTTP | 不需要：Claude Code 本來就走 HTTP 和 SSE |
| 改寫不了就原樣傳送，面板提示原因 | 照搬；賬號拒絕改過歷史之後的思考時，先去掉對不上的思考記錄、照樣按勾選傳送，還不行才原樣傳送（D04-03） |
| 面板是 MCP 應用，使用者自己開啟，不經過模型 | 平臺逼迫：使用者打不開外掛的 MCP 應用，Mod 面板放不進網頁。同一份 `panel.html` 改由引擎作為本機頁面提供，使用者輸入 `/cam` 後在 Claude 桌面自帶的瀏覽器裡開啟，仍不經過模型（D04-04） |
| 自動選圖：`cam_view_image` 按編號取圖，取回的圖放在本輪末尾，副本下一輪換成說明 | 照搬，取圖工具由同一個 MCP 服務提供（D04-05） |

本輪不擴大素材範圍：原生 PDF/document、音訊、影片和普通文字檔案不因為換客戶端就自動進入管理範圍。工具渲染出的圖片仍按圖片處理。暫不增加其他模型供應商、雲端會話、跨會話素材庫或新的常駐系統服務。

## 2. 事實、證據與未知項

### 2.1 已實測

驗證環境：Windows；Claude 桌面應用 2.26454.2.0，自帶 Claude Code 2.1.293。結論只覆蓋該環境，更新後需重跑相關驗證。

- 專案 settings 中的 `ANTHROPIC_BASE_URL` 不能覆蓋桌面宿主啟動時傳入的同名變數。
- Mod 的 `$.env.set()` 可以在會話執行時切換地址。真實桌面 Code 會話經過本機透明探針，保留 Bearer/OAuth capability、無 API key，請求帶 `x-claude-code-session-id`，Anthropic 返回 HTTP 200，主回覆流完整結束。
- 使用者實際執行開啟、傳送訊息、關閉命令，並確認了可見回覆和恢復提示。
- 本機探針的透明轉發、認證頭、SSE、取消和恢復共 9 項迴歸測試透過；桌面自帶命令列校驗實際安裝副本透過。這些是實驗工具證據，不是正式 v0.4 功能驗收。
- 只寫 `enabledPlugins` 不完成安裝；必須實際登記並安裝外掛，再載入到目標會話。首次命令缺失由漏安裝造成，補安裝後已解決。
- 面板（2026-10-10 桌面實測）：Mod 面板只能畫 Claude 自帶的元素，放不進網頁；Claude Code 不登記只給應用呼叫的工具，使用者打不開外掛的 MCP 應用。Mod 面板裡的連結，點開交給系統預設瀏覽器。Mod 用 `$.mcp.call("Claude_Browser", "preview_start", { url })` 能在桌面自帶的瀏覽器裡開啟本機頁面，預設許可權模式下也不彈確認；這是桌面版給模型用的工具，不是公開給外掛的介面，終端和 VS Code 裡沒有。
- 桌面版的新會話，發出第一條輸入時才啟動 Claude Code 程序。Mod 註冊的命令在那之前不在輸入框的命令列表裡：輸入時提示命令不存在，發出後照常執行。外掛自帶的命令檔案一律帶外掛名字首（`/codex-attachment-manager:cam`）。
- 圖片與思考（2026-10-10，T04-01，Haiku 5.5，推理強度 low，桌面訂閱會話，工具檢視的圖，中英各 3 次）：使用者自己的賬號接受改過的歷史連同思考記錄（全部 200）。全部省略後，模型不收回之前的描述、不猜新細節、不自己重讀檔案，勾回後看圖答對；逐條說明寫明何時寫“需要 IMG-xxx”後，中英都 3/3 按編號要圖。模擬新賬號（`CAM_EXPERIMENT_BLOCK_BINDING=error`）時，改寫後的請求得到 400，引擎改發原始請求得到 200，對話不斷，面板提示。自動選圖：需要看圖時都用 `cam_view_image` 取回並答對；不需要時，中文有 1 次多取，英文都不取；取回的副本下一輪換回說明。
- 新賬號的思考校驗（2026-10-10 至 11，Claude Code 2.1.295，Haiku 5.5，推理強度 high 和 max，模擬新賬號）：
  - 引擎去掉對不上的思考（D04-03 現行做法）：取消勾選後的第一個請求被拒，去掉 1 段對不上的思考後重發成功，之後同一會話直接這樣發、不再被拒；取消之後新產生的思考在後面的請求裡保留並被接受；全部勾回後，取消之前的思考放回去、取消期間產生的去掉，被接受。回答全部正確。面板提示去掉了幾段（最終實測截圖在驗證機的 `local/v04/shots/`）。
  - 實驗中發現並修好兩個問題：比較歷史時把字串內容和同樣文字的文字塊當成不同（Claude Code 的末尾系統訊息就是這樣變的），多去掉了本該保留的思考；記錄不全時（換了雜湊寫法）把取消期間產生的思考當成對得上，請求被拒，最後的原樣請求在真正的新賬號上也會被拒，會話會卡住。現在記錄不全時寧可多去掉。舊做法（被拒就原樣傳送）也有這個卡住的問題：新賬號上改過的請求成功過一次，之後全部勾回，原樣請求就被拒。
  - 對照組 `drop_block`（服務端丟掉對不上的思考）：只丟對不上的那段，之後新產生的思考保留。效果和引擎自己去掉相同，但要在正式請求裡帶 beta 請求頭，有些思考設定下不能用，沒采用。
  - 代價：丟掉舊思路後模型要重新想。同一個追問，舊思考在時用 29 個思考 token，被去掉後用 2,422 個；推理強度 low 時模型很少在看圖之後思考，這個問題很少觸發。
- 並行呼叫工具時，Claude Code 把除最後一個以外的結果掛在各自的呼叫記錄下面，不在沿父記錄回溯出的鏈上（2026-10-10 在測試中發現並修復）。
- 安裝（2026-10-10，在隔離的配置目錄裡）：從倉庫匯出的外掛市場新增、安裝到使用者範圍後，外掛服務能起來；用 Codex 帶的 Node，或只有系統的 Node 24，都能執行。

私有實驗記錄位於驗證機的 `local/claude-live-routing/`；不得把原始記錄、憑據、圖片或本機路徑複製到提交中。倉庫只保留上述脫敏結論和實驗方法。該目錄被忽略，克隆倉庫後無需存在。

### 2.2 已查證的平臺約束，仍需在訂閱鏈路實測

2026-10-09 查官方文件（連結見第 8 節）和桌面自帶 Claude Code 2.1.293 的 Mod 型別定義。文件說的是 API 行為，訂閱鏈路的實際表現以實測為準。

- 桌面啟動的環境變數過濾，與 Mod 執行時設定是不同入口；正式生命週期是否一直保持有效，不能從一次文字請求推斷。
- **思考簽名**：Fable 5.1、Opus 5.5、Sonnet 5.5、Haiku 5.5 做字首校驗。替換歷史裡的一張圖、縮短一個工具結果，或增刪 `tools` 裡的工具，都會讓之後所有的思考塊失效。2026-08-31 起註冊的賬號預設返回 400；更早的賬號照樣校驗，但放行給模型。加 beta 頭 `thinking-binding-controls-2026-08-01` 並設 `thinking.block_binding.prefix_mismatch_behavior: "error"`，老賬號也按新賬號拒絕，可用於實驗；只加 beta 頭、不設該欄位，響應會列出放行的失效塊。文件明說代理自己的改寫也算編輯。服務端上下文編輯只能按規則清掉最早的工具結果，不能指定某張圖，也碰不到使用者訊息裡的圖。2026-10-10 實測（見 2.1）：訂閱鏈路接受該 beta 頭；400 由引擎接住，Claude Code 看不到；使用者自己的賬號是放行的那種。2026-10-11 查證：比較的是值，不看 JSON 寫法和鍵的順序；400 寫明第一個失效的塊和前面第一處不同的位置；去掉開頭或末尾的思考可以，去掉中間的會讓後面的失效，把去掉過的放回去，會讓它不在期間產生的失效；文件要求代理去掉思考重試時不要藏起來。
- **說明訊息的位置**：對話中途可以放 `role: "system"` 訊息，不需要 beta 頭，但它必須緊跟在使用者訊息之後，後面是助手訊息或已是最後一條。所以 Codex 的位置（那一輪使用者訊息之前）在 Claude 上不合法。2026-10-10 實測：訂閱鏈路接受，效果見 2.1。
- `turn.step` 只能改模型和推理強度，不是歷史訊息改寫介面，不能替代請求改寫引擎。

## 4. 設計邊界

### D04-01 接入與透明轉發

沿用已驗證的會話內 Mod 接入路徑：先確認本機引擎就緒，再切換當前 Code 程序地址；儲存原值，停用時恢復。Mod 負責切地址，以及 `/cam` 打開面板（D04-04）。只繫結本機地址，保留系統代理和使用者已有的 `NO_PROXY` 設定。引擎就是現有引擎，增加 `/v1/messages` 轉發，固定官方 Anthropic 上游，不提供任意目的地轉發。

照原機制，由外掛的 MCP 服務拉起並看守引擎（見 design.md 第 5 節）。Codex 與 Claude 共用這個引擎，引擎的退出條件和替換規則改為同時考慮兩邊（現在只看有沒有 Codex 程序）。OAuth、版本、beta 和會話相關請求頭需要透傳，認證值不得進入日誌。查詢串、錯誤響應和 SSE 都須保留；客戶端取消時關閉上游請求。正文無需改寫時保留原始位元組。MCP 服務在 Claude 下的 Node 執行環境在 T04-03 中確定，不把實驗埠或本機安裝路徑寫死進正式安裝包。

### D04-02 Claude 圖片與會話適配

照原機制新增 Claude 的會話讀取：從 Claude Code 的本地會話記錄只讀、增量地找圖和編號，只追加，已有編號不變；引擎和外掛服務各自計算，不共享狀態。Mod 的讀取介面只在 Claude Code 程序裡，引擎拿不到，不作為編號依據。不寫回原始會話。

區分直接圖片塊和巢狀工具結果中的圖片；原生 document 等未知結構保留。編號對應每次出現，不能把圖片雜湊當作唯一出現編號。相同內容、不同出現、工具取回副本需要分別處理。對齊沿用原機制的順序：訊息塊沒有條目 `id`，工具結果裡的圖用 `tool_use_id`（相當於 `call_id`），使用者訊息裡的圖用型別、輪次和內容雜湊。歷史儲存與發出請求可能有預處理差異，必須用實驗確定匹配方式，無法可靠對應就原樣放行並提示。

會話按每個請求的 `x-claude-code-session-id` 認出，不只在外掛載入時快取。Codex 與 Claude 的狀態隔離；並行會話、續聊、分叉和子代理不能誤用另一會話的選擇。壓縮（`/compact` 與自動壓縮）和 `/rewind` 回退之後，已有編號不變、選擇不串。

### D04-03 Claude 請求改寫與思考相容

單獨適配 Anthropic Messages。只修改確定的目標圖片塊及必要的佔位說明，保留工具容器、呼叫配對、訊息順序和未觸碰欄位。不得把整份請求轉成 OpenAI Responses 再轉回來。上下文管理說明改用 `role: "system"` 訊息，放在第一張被省略的圖所在那條使用者訊息之後（Anthropic 不允許放在使用者訊息之前）；它和改圖在同一處，不擴大思考失效的範圍。訂閱鏈路是否接受、Claude 模型的效果在 T04-01 中驗證。

保留現行選擇與佔位語義，Claude 措辭需分別跑中英文模型驗收。選擇不變時輸出穩定；自動取圖不能反覆修改前面的佔位文字。

思考塊原樣轉發，不關思考。賬號放行時效果與 Codex 相同。賬號拒絕改過歷史之後的思考時（2026-08-31 起註冊的賬號），引擎去掉和實際發出的歷史對不上的思考記錄，照樣按勾選發出；之後新產生的思考保留；面板提示去掉了幾段。這是使用者 2026-10-11 看過實驗證據（見 2.1）後選定的降級：模型少了被改位置之後的那部分舊思路。還不行時才按“改寫不了就原樣傳送”處理，面板提示，這一次不計作取消成功。服務端上下文編輯不能指定某張圖，`drop_block` 要在正式請求裡帶 beta 頭，都不採用。做法見 design.md 第 12 節。

### D04-04 面板與業務規則複用

面板與 Codex 一致（使用者 2026-10-10 要求）：複用同一份 `panel.html` 和麵板資料，使用者自己開啟，不經過模型。平臺逼迫的改動（見 2.1）：使用者打不開外掛的 MCP 應用，Mod 面板放不進網頁，所以由引擎在本機提供面板頁（`/__cam/panel?session=<會話 id>`），頁面前加一段橋接指令碼代替 MCP 應用宿主，把面板的呼叫轉成引擎的本機介面；Codex 特有的啟用、停用和新任務繫結不出現。頁面和介面只接受用本機名字訪問、不來自其他網站的請求。

使用者輸入 `/cam`，面板就在 Claude 桌面自帶的瀏覽器裡開啟，在對話旁邊（使用者 2026-10-10 選定）。只有兩種情況彈出 Mod 小面板：自帶瀏覽器打不開（終端、VS Code 或呼叫失敗）時，給出面板連結和複製按鈕；本會話的請求沒經過引擎、勾選不會生效時，提醒使用者。新會話的第一條輸入就是 `/cam` 時，輸入框會提示命令不存在，發出後照常開啟；保持現狀，在使用者文件裡寫明（使用者 2026-10-10 定）。

複用候選包括選擇狀態、圖片指紋、重複關係、縮圖處理、編號識別和麵板資料欄位。先做單圖，再做多圖的桌面內面板實驗，驗證縮圖、放大預覽、勾選、狀態儲存與當前會話繫結。驗收在 Claude 桌面裡用 `/cam` 開啟的面板上做；在外部瀏覽器裡開啟同一頁面只用於除錯。關鍵介面節點按 AGENTS.md 截圖給使用者，等待反饋後繼續介面開發。

### D04-05 自動取圖

先完成手動閉環，再接自動模式。保留當前預設關閉、手動與固定傳送分開、當前輪新圖照常傳送、歷史未固定圖省略、取回只用於本輪、下一輪省略副本的規則。取圖工具照原機制由外掛的 MCP 服務提供，始終註冊、不隨開關增刪：增刪 `tools` 裡的工具也會讓之後的思考失效。

工具註冊成功不代表圖片已到模型。必須檢查模型實際看到原圖中的合成標記，並檢查下一輪請求。思考相容關卡也覆蓋工具圖及副本省略。模型無權修改使用者選擇或開關。

### D04-06 安裝、恢復與迴歸

Claude 外掛入口與 Codex 入口分別安裝；只提取確實需要共享的規則，不先重構為通用供應商框架。Claude 外掛的內容是 MCP 服務（與 Codex 共用 `plugin/src` 的執行程式碼）加一個 Mod（切地址、`/cam` 打開面板）。執行程式碼在 `plugin/src`，測試與實驗在 `spike`，安裝指令碼在 `scripts`；Claude 外掛的目錄與清單由 T04-03 確定。

安裝必須校驗實際安裝副本和目標會話載入，不能只寫啟用配置。恢復隻影響工具自管的地址/設定，不覆蓋使用者的其他配置。驗證解除安裝、過載、桌面重啟、引擎失敗、登入重新整理和版本更新；不新增系統計劃任務等常駐機制。

Codex 現有自測、安裝和解除安裝保持可用；共享執行程式碼變化後重新執行 `cam install`。不因新文件提前修改外掛版本、README 支援宣告或 Release。

## 6. 文件與開發紀律

- `docs/spec.md`、`docs/design.md` 按 AGENTS.md 繼續由 Claude 維護。正式實現前將確認的 v0.4 增量寫回原文；未釋出時清楚區分當前已實現與計劃內容，不另儲存 old/new 兩套規格。
- 任務按順序執行，每項標明依賴、驗收與證據。可自動化的行為按 TDD；未知原因的失敗先按 systematic-debugging 復現和定位。
- 完成前按 verify-before-done 核驗證據；跨模組、認證與服務邊界按 code-review 審閱。文件改動只檢查結構、連結、事實與狀態，不為文件造執行測試。
- 在短分支工作；提交、合併和釋出遵循 AGENTS.md。未驗收的專案不勾完成。
- Codex 模型自測繼續遵守 AGENTS.md 的模型、推理強度和雙語矩陣。Claude 專項驗收必須使用真實 Claude 桌面訂閱模型；自動化前需確定模型範圍和成本上限，不能用 GPT 自測替代，也不要求 API key。
- 真實證據只在 `local/` 或工具資料目錄；可提交測試樣例必須合成或脫敏。Windows 優先，其他平臺的 CI 與桌面實測範圍分別說明。
