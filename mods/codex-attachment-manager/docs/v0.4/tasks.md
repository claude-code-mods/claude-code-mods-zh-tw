## G04-1：核心可行性

- [x] **T04-01 歷史圖片取消/恢復與思考相容**。依賴 T04-00。
  - 模型用 Haiku 5.5（使用者 2026-10-10 定），思考用 Claude Code 的預設配置，先確認請求裡確有思考塊；執行次數在開始前與使用者確認。
  - 用合成圖 A、B 和一份重複出現，在同一桌面訂閱會話中完成上傳、看圖、取消 A、繼續對話、恢復 A、再繼續；覆蓋工具圖片和實際出現過思考塊的歷史。
  - 確認本地出現記錄與發出的圖片塊能夠可靠對齊；同時檢查被取消圖確實未發、未取消圖保留、恢復圖回到應有位置。
  - 用最小取回工具在本輪提供原圖、下一輪用實驗改寫省略副本，檢查思考相容；不要求先實現 T04-08 的完整自動模式。
  - 思考塊原樣轉發。記錄：賬號放行還是返回 400；加 beta 頭 `thinking-binding-controls-2026-08-01` 並設 `prefix_mismatch_behavior: "error"` 模擬新賬號的結果；訂閱鏈路是否接受該 beta 頭；被拒後原樣重發能否接上，Claude Code 自己怎麼處理 400。沒有實際思考塊的文字測試不能覆蓋簽名約束。beta 頭和診斷引數只用於實驗，不加入正式請求。
  - 上下文管理說明用 `role: "system"` 放在第一張被省略的圖所在那條使用者訊息之後，驗證訂閱鏈路接受、模型不收回之前的回答；先做最小改寫，不提前搬整套引擎。
  - 關聯：R04-02、R04-05；A04-02、A04-03、A04-04 的 G04-1 子集、A04-09。透過本任務不勾整項 A04-04。
  - 證據：本機脫敏請求差異、回應狀態、只讀檢查、合成圖的模型回答；失敗時儲存根因與選項。

- [x] **T04-02 桌面內縮略圖面板實驗**。依賴 T04-00，可與 T04-01 並行。
  - 面板形式見 plan.md 的 D04-04（使用者 2026-10-10 定）：同一份 `panel.html` 由引擎在本機提供，`/cam` 在 Claude 桌面自帶的瀏覽器裡開啟。
  - 在真實 Code 中先顯示一張、再顯示多張合成圖；驗證縮圖、單張勾選、放大預覽、儲存和當前會話繫結，不透過模型執行操作。在外部瀏覽器開啟同一頁面只用於除錯，不計桌面驗收。
  - 關聯：R04-04；A04-06。
  - 證據：Claude 自行檢查截圖；關鍵節點截圖給使用者，按現有規矩等待反饋。

- [x] **T04-02a 核心關卡結論與規格同步**。依賴 T04-01、T04-02。
  - 將已驗證、失敗和待定項分別記錄；在本輪實驗約定的基礎上，固化正式專項驗收的模型範圍與成本上限。
  - 由 Claude 將確認的目標、約束、驗收與採用方案寫回現行 `docs/spec.md`、`docs/design.md`，保持唯一事實來源。
  - 若需要功能/思考降級或改變桌面互動目標，先取得使用者對具體取捨的確認；未確認不得開始正式適配。
  - 關聯：全部 R04；G04-2 的進入條件。
  - 證據：關卡報告、文件差異和相關使用者反饋，不用一條“可以用”代替完整結論。

## G04-2：正式手動模式

- [x] **T04-03 Claude 接入與執行入口**。依賴 T04-02a。
  - 照原機制：Claude 外掛帶 MCP 服務（與 Codex 共用 `plugin/src`），由它拉起並看守引擎；Mod 負責切地址（先確認引擎就緒再切，儲存並恢復原值）和 `/cam`。確定 Claude 外掛的目錄與清單、MCP 服務在 Claude 下的 Node 執行環境和安裝副本檢查。
  - Codex 和 Claude 共用一個引擎：現在引擎在沒有 Codex 程序時自己退出（`engine.ts` 的 `watchForCodex`），要改成兩邊都不在用時才退出；替換規則要避免兩份外掛副本版本相同、程式碼不同時來回讓對方的引擎退役。改的是共用程式碼，改完重新 `cam install`，確認 Codex 照常能連上。
  - 覆蓋 HTTP 查詢、認證、系統代理、SSE、上游錯誤、取消；無改寫路徑保持原始正文。
  - 關聯：R04-01、R04-07；A04-01、A04-02、A04-10、A04-11。
  - 證據：迴歸測試和真實桌面訂閱冒煙；不以實驗外掛代替正式包。

- [x] **T04-04 會話索引與圖片出現記錄**。依賴 T04-02a。
  - 照原機制從 Claude Code 的本地會話記錄只讀、增量地找圖和編號，引擎和外掛服務各自計算；穩定編號、輪次、尺寸、重複關係與來源；處理直接圖、工具圖和取回副本。會話按 `x-claude-code-session-id` 認出。
  - 對齊按原機制的順序：工具圖用 `tool_use_id`，使用者圖用型別、輪次和內容雜湊；核對歷史預處理與傳送塊的差異；狀態按客戶端和會話隔離，未知結構保留。
  - 關聯：R04-02、R04-03；A04-03、A04-05、A04-09。
  - 證據：合成 fixtures 的單元測試，真實桌面只讀核對；提交中不含真實會話樣本。

- [x] **T04-05 Claude 手動請求改寫**。依賴 T04-03、T04-04。
  - 只替換確定的授權圖片，保留訊息/工具結構與其餘欄位；普通/重複佔位符、已提供標籤、中英文照原機制實現，上下文管理說明用 `role: "system"` 放在那條使用者訊息之後；思考塊原樣轉發，賬號拒絕改過歷史之後的思考時，去掉對不上的思考記錄、照樣按勾選發出並提示，還不行才原樣重發（使用者 2026-10-11 定，見 plan.md D04-03）。
  - 選擇不變時改寫穩定；無法安全改寫時原樣轉發並給出可見原因，回退不算取消成功。
  - 關聯：R04-02、R04-06；A04-02、A04-03、A04-04、A04-09。
  - 證據：先失敗再透過的單元測試、請求差異、同會話桌面取消/恢復及雙語模型自測。

- [ ] **T04-06 續聊、分叉與多會話**。依賴 T04-04、T04-05。
  - 識別當前會話變更、續聊、分叉與子代理；保留編號，按分叉時點繼承並分別管理。壓縮（`/compact` 與自動壓縮）和 `/rewind` 回退之後，已有編號不變、選擇不串。
  - 不只依賴 `session.start` 更新會話狀態；核對真實事件時序。
  - 關聯：R04-03；A04-05、A04-10。
  - 證據：兩會話隔離、過載、續聊、分叉、壓縮、回退、工具中間請求的迴歸與桌面記錄。
  - 進度（2026-10-11）：已測兩個會話同時執行、勾選不同，各按各的改寫（引擎日誌）；會話在引擎重啟後、閒置幾小時後續聊正常；同一輪裡工具呼叫之間的請求照樣改寫。壓縮分界和回退分支有單元測試。還沒在桌面裡測：分叉、`/compact`、`/rewind`、子代理。

- [x] **T04-07 完整手動面板**。依賴 T04-02、T04-04、T04-05。
  - 接入完整列表、預覽、整輪勾選、來源篩選、傳送預估/實際統計、需要編號定位、任務名、重新整理、啟停、主題和雙語。
  - 逐項引用現行 v0.3 的行為；篩選不改變傳送，整輪選擇按顯示項處理。複用 `panel.html`（D04-04）。
  - 關聯：R04-04、R04-06；A04-06、A04-07。
  - 證據：互動檢查、雙語截圖、使用者在關鍵節點的反饋；介面差異與降級不能隱瞞。

## G04-3：自動模式
